პოზიციური ოპერატორები ელემენტებს **ითვლიან**. ხშირად კი უფრო ბუნებრივია, ფილტრაცია **პირობაზე** ან **დროზე** დავამყაროთ: „მანამ, სანამ მომხმარებელი ღილაკს არ დააჭერს", „პირველი ათი წამის განმავლობაში".

## `TakeWhile` და `SkipWhile`

პირობაზე დაფუძნებული ვარიანტები. `TakeWhile` ატარებს ელემენტებს მანამ, სანამ პრედიკატი მართალია, და **პირველივე ცრუზე სრულდება**.

```csharp
// გაზომვები, სანამ ტემპერატურა ნორმაშია
IObservable<Reading> normalPeriod =
    sensor.Readings.TakeWhile(r => r.Temperature < 80);
```

`SkipWhile` პირიქით: აგდებს ელემენტებს, სანამ პრედიკატი მართალია, და **პირველივე ცრუს შემდეგ ყველაფერს ატარებს**, თუნდაც პრედიკატი ისევ გახდეს მართალი.

> [!IMPORTANT] ეს `Where` არ არის
> `SkipWhile(x => x < 5)` **არ** ნიშნავს „მხოლოდ 5-ზე მეტები". როგორც კი პრედიკატი ერთხელ დაირღვევა, **ყველაფერი** გადის, მათ შორის მომდევნო პატარა რიცხვებიც. თუ ყოველი ელემენტის ცალკე შემოწმება გინდათ, `Where` გჭირდებათ.

## `TakeUntil` და `SkipUntil`

ეს ოპერატორები **სხვა observable-ს** იყენებენ სიგნალად. `TakeUntil(other)` ატარებს ელემენტებს მანამ, სანამ `other` **პირველ რამეს არ გასცემს**, და მაშინვე სრულდება.

```csharp
// კურსორის მოძრაობა, სანამ ღილაკს არ აუშვებენ
IObservable<Point> drag = mouseMoves.TakeUntil(mouseUp);
```

ეს Rx-ის ერთ-ერთი ყველაზე გამომხატველი შაბლონია: **„აკეთე ეს, სანამ ის არ მოხდება"** ერთ სტრიქონად იწერება, ყოველგვარი დროშებისა და გამოწერების ხელით მართვის გარეშე.

`SkipUntil(other)` პირიქით: **არაფერს** ატარებს, სანამ `other` სიგნალს არ მოგვცემს, და შემდეგ ყველაფერს ატარებს.

```csharp
// ჩანაწერები მხოლოდ იმის შემდეგ, რაც სისტემა მზადყოფნას გამოაცხადებს
IObservable<LogEntry> afterReady = logs.SkipUntil(systemReady);
```

> [!TIP] დროზე დაფუძნებული გადატვირთვები
> ორივეს აქვს `DateTimeOffset`-იანი და `TimeSpan`-იანი ვარიანტები, სადაც სიგნალის როლს **დრო** ასრულებს:
> ```csharp
> source.TakeUntil(DateTimeOffset.Now.AddMinutes(5));   // ხუთი წუთის განმავლობაში
> source.SkipUntil(DateTimeOffset.Now.AddSeconds(10));  // პირველი ათი წამის გამოტოვება
> ```

## რომელი ავირჩიოთ

| მინდა… | ოპერატორი |
|---|---|
| ყოველი ელემენტი ცალკე შევამოწმო | `Where` |
| პირველი n ელემენტი | `Take(n)` |
| სანამ პირობა სრულდება | `TakeWhile` |
| სანამ სხვა მოვლენა არ მოხდება | **`TakeUntil(other)`** |
| გარკვეული დროის განმავლობაში | `TakeUntil(deadline)` |
| განმეორებების გამოტოვება | `DistinctUntilChanged` |

> [!WARNING] `TakeUntil`-ის ერთი ნიუანსი
> თუ `other` **დასრულდება მნიშვნელობის გაცემის გარეშე**, `TakeUntil` წყაროს **გაჩერებას არ დაიწყებს**: ის მხოლოდ `OnNext`-ს რეაგირებს. ეს ხშირად სასურველია, მაგრამ თუ `other`-ად `Observable.Empty`-ს გადასცემთ, შედეგი ისეთივე იქნება, თითქოს ფილტრი საერთოდ არ გვქონოდა.
