ლოგიკური აგრეგატები თანმიმდევრობაზე **კითხვას სვამენ** და `IObservable<bool>`-ს აბრუნებენ.

| ოპერატორი | კითხვა | როდის იცის პასუხი |
|---|---|---|
| `Any()` | არის თუ არა **თუნდაც ერთი** ელემენტი? | **პირველივე ელემენტზე** |
| `Any(p)` | არის თუ არა ელემენტი, რომელიც `p`-ს აკმაყოფილებს? | პირველივე დამთხვევაზე |
| `All(p)` | **ყველა** ელემენტი აკმაყოფილებს `p`-ს? | პირველივე **დარღვევაზე** |
| `Contains(v)` | გვხვდება თუ არა მნიშვნელობა `v`? | პირველივე დამთხვევაზე |
| `IsEmpty()` | ცარიელია თუ არა? | პირველივე ელემენტზე |

## ზოგი მათგანი დასრულებას **არ** ელოდება

ეს ამ ოპერატორების ყველაზე სასარგებლო თვისებაა და [[თავი 6.1 რიცხვითი აგრეგირება|6.1]]-ის მთავარი წესის გამონაკლისია.

> [!IMPORTANT] ადრეული პასუხი
> `Sum`-მა შედეგი რომ თქვას, **ყველა** ელემენტი სჭირდება. `Any`-ს კი პასუხი უკვე **პირველივე ელემენტზე** აქვს: თუ ერთი მაინც მოვიდა, პასუხი „დიახაა", და დანარჩენს ლოდინი აღარ სჭირდება.
>
> ამიტომ `Any` **უსასრულო წყაროზეც მუშაობს**, `Sum` კი არა.

*ნახაზი 6.2: `Any` და `All` ადრე ჩერდებიან, ამიტომ წყაროსაც ათავისუფლებენ.*

## ცარიელ წყაროზე

```csharp
Observable.Empty<int>().Any();        // false
Observable.Empty<int>().All(x => x > 0);   // true
Observable.Empty<int>().IsEmpty();    // true
```

> [!NOTE] რატომ არის `All` ცარიელზე `true`
> ეს **ცარიელი ჭეშმარიტების** მათემატიკური კონვენციაა: „ყველა ელემენტი აკმაყოფილებს პირობას" ცარიელ სიმრავლეზე ავტომატურად მართალია, რადგან **ვერცერთი ვერ არღვევს** მას. იგივე ქცევა აქვს LINQ to Objects-ის `All`-საც.

## `SequenceEqual`

ორი თანმიმდევრობის შედარება: აბრუნებს `true`-ს, თუ ორივე **ერთსა და იმავე ელემენტებს, ერთივე რიგით** გასცემს და ერთნაირად სრულდება.

```csharp
IObservable<bool> same = expected.SequenceEqual(actual);
```

> [!TIP] ტესტებში გამოსადეგია
> ეს ოპერატორი მოსახერხებელია მოსალოდნელი და რეალური ნაკადების შესადარებლად. თუმცა ის **ორივე თანმიმდევრობის დასრულებას ელოდება**, ამიტომ ტესტში წყაროები სასრული უნდა იყოს (ან `Take`-ით შეზღუდული).

## პრაქტიკული მაგალითი

```csharp
// ჰქონია თუ არა მოწყობილობას კრიტიკული შეცდომა ბოლო საათში
IObservable<bool> hadCritical =
    device.Events
        .TakeUntil(DateTimeOffset.Now.AddHours(1))
        .Any(e => e.Severity == Severity.Critical);
```

აქ `TakeUntil` უსასრულო ნაკადს დროში ზღუდავს, `Any` კი პასუხს **პირველივე კრიტიკულ შეცდომაზე** გასცემს და აღარ დაელოდება საათის გასვლას.
