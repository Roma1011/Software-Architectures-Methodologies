`TestScheduler` მოწინავე შესაძლებლობებსაც იძლევა: შეტყობინებების **ჩაწერას** და ტესტისთვის მზა `hot`/`cold` წყაროების **აწყობას**.

## `Start`: ჩაწერა და მართული სიცოცხლე

`Start`-ს სამი გადატვირთვა აქვს (უპარამეტრო `Start`-ისგან სრულიად განსხვავებული), რომლებიც observable-ს დანიშნულ დროს უშვებს, მის შეტყობინებებს **იწერს** და გამოწერას დანიშნულ დროს ხურავს. ყველა `ITestableObserver<T>`-ს აბრუნებს:

```csharp
public interface ITestableObserver<T> : IObserver<T>
{
    IList<Recorded<Notification<T>>> Messages { get; }
}
```

ყველაზე დეტალური გადატვირთვა ოთხ პარამეტრს იღებს (დრო ticks-ში):

```csharp
public ITestableObserver<T> Start<T>(
    Func<IObservable<T>> create,  // წყაროს ფაბრიკა
    long created,                 // როდის შეიქმნას
    long subscribed,              // როდის გამოიწეროს
    long disposed);              // როდის დაიხუროს
```

```csharp
var scheduler = new TestScheduler();

var testObserver = scheduler.Start(
    () => Observable.Interval(TimeSpan.FromSeconds(1), scheduler).Take(4),
    created: 0,
    subscribed: 0,
    disposed: TimeSpan.FromSeconds(5).Ticks);

foreach (var msg in testObserver.Messages)
    Console.WriteLine($"{msg.Value} @ {msg.Time}");
```

გამოტანა (`ITestableObserver` `OnNext`-საც იწერს და `OnCompleted`-საც):

```text
OnNext(0) @ 10000001
OnNext(1) @ 20000001
OnNext(2) @ 30000001
OnNext(3) @ 40000001
OnCompleted() @ 40000001
```

> [!IMPORTANT] გამოწერის დროს მნიშვნელობა აქვს
> `Observable.Interval` `cold`-ია, ამიტომ **შექმნის** ვირტუალურ დროს მნიშვნელობა არ აქვს, მაგრამ **გამოწერის** დროს აქვს. თუ გამოწერას 2 წამზე გადავიტანთ და დახურვას 5 წამზე დავტოვებთ, ბოლო შეტყობინებებს **გამოვტოვებთ** (`Interval` მე-3 და მე-4 წამზე გამოსცემს, დახურვა 5 წამზეა, ამიტომ დანარჩენი ორი `OnNext` და `OnCompleted` აღარ ჩაიწერება).

> [!NOTE] მოკლე გადატვირთვები: 100, 200, 1000
> ორი უფრო მოკლე გადატვირთვა ნაგულისხმევ დროებს იყენებს: შექმნა t=100-ზე, გამოწერა t=200-ზე, დახურვა t=1000-ზე. Rx.NET-ის საკუთარი ათასობით ტესტი სწორედ ამ კონვენციას იყენებს: „შექმნა 100-ზე, გამოწერა 200-ზე, ყველაფერი 1000-მდე შეამოწმე".

## `CreateColdObservable` და `CreateHotObservable`

ჩაწერის საპირისპიროდ, შეგვიძლია წინასწარ ჩაწერილი შეტყობინებების ნაკრები **დავუკრათ**. `CreateColdObservable` `Recorded<Notification<T>>`-ის მასივს იღებს:

```csharp
var scheduler = new TestScheduler();

var source = scheduler.CreateColdObservable(
    new Recorded<Notification<long>>(10_000_000, Notification.CreateOnNext(0L)),
    new Recorded<Notification<long>>(20_000_000, Notification.CreateOnNext(1L)),
    new Recorded<Notification<long>>(30_000_000, Notification.CreateOnNext(2L)),
    new Recorded<Notification<long>>(40_000_000, Notification.CreateOnCompleted<long>()));

var testObserver = scheduler.Start(() => source, 0, 0, TimeSpan.FromSeconds(5).Ticks);
```

> [!NOTE] `ITestableObservable` გამოწერებსაც იწერს
> ორივე მეთოდი `ITestableObservable<T>`-ს აბრუნებს, რომელიც `IObservable<T>`-ს ორ სიას უმატებს: `Messages` (რას გამოსცემს) და `Subscriptions` (როდის გამოიწერეს და დახურეს). ეს გაძლევს საშუალებას, შეამოწმო არა მხოლოდ **რა** გამოვიდა, არამედ **როდის** გამოიწერა ოპერატორმა წყარო.
