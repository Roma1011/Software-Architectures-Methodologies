Rx-ის თანმიმდევრობას სამი სახის შეტყობინება აქვს: `OnNext`, `OnError` და `OnCompleted`. ჩვეულებრივ ისინი **სხვადასხვა არხითაა**: მნიშვნელობები ერთი გზით მოდის, დასრულება და შეცდომა კი სხვებით.

**`Materialize`** სამივეს **ერთ არხში** აქცევს: ის აბრუნებს `IObservable<Notification<T>>`-ს, სადაც ყოველი შეტყობინება ჩვეულებრივ **მნიშვნელობად** არის ქცეული.

```csharp
IObservable<Notification<int>> asData = source.Materialize();
```

*ნახაზი 5.3: სამივე შეტყობინება ერთ ნაკადში ხვდება.*

`Materialize`-ის შედეგი **ყოველთვის ნორმალურად სრულდება**, მაშინაც კი, როცა წყარო შეცდომით დასრულდა: შეცდომა უბრალოდ **ერთ-ერთი მნიშვნელობა** ხდება.

```csharp
foreach (var n in notifications)
{
    switch (n.Kind)
    {
        case NotificationKind.OnNext:      Console.WriteLine($"მნიშვნელობა: {n.Value}"); break;
        case NotificationKind.OnError:     Console.WriteLine($"შეცდომა: {n.Exception}"); break;
        case NotificationKind.OnCompleted: Console.WriteLine("დასრულდა"); break;
    }
}
```

**`Dematerialize`** საპირისპიროს აკეთებს: `Notification<T>`-ების ნაკადს ისევ ჩვეულებრივ თანმიმდევრობად აქცევს.

```csharp
IObservable<int> restored = asData.Dematerialize();
```

## სად გამოგვადგება

**1. ლოგირება და დიაგნოსტიკა.** როცა გვინდა, დავინახოთ არა მხოლოდ მნიშვნელობები, არამედ **როგორ დასრულდა** ნაკადი:

```csharp
source.Materialize()
      .Subscribe(n => logger.LogInformation("შეტყობინება: {Kind}", n.Kind));
```

**2. ტესტირება.** ტესტში ხშირად გვინდა შევამოწმოთ **მთელი** სცენარი, დასრულების ჩათვლით. `Materialize`-ის შემდეგ ყველაფერი ჩვეულებრივ სიად გვექცევა და შედარება ადვილდება.

**3. შეცდომის „გადატანა" ბარიერზე.** როცა ერთი ნაკადის შეცდომა მეორეს არ უნდა დაამხოს, შეცდომის მნიშვნელობად ქცევა საშუალებას გვაძლევს, ის ჩვეულებრივ მონაცემებთან ერთად გავატაროთ, გავფილტროთ ან დავაჯგუფოთ, და შემდეგ სადმე შორს `Dematerialize`-ით აღვადგინოთ.

> [!TIP] მსგავსი იდეა სხვაგანაც
> ეს იმავე პრინციპზეა აგებული, რაზეც „სარკინიგზო" პროგრამირება: **შეცდომა მნიშვნელობად აქციე და ჩვეულებრივ მონაცემებთან ერთად ატარე**, იმის ნაცვლად, რომ მთელი კონვეიერი შეწყვიტო.

> [!WARNING] ზედმეტად ხშირად არ გამოიყენოთ
> `Materialize` მოსახერხებელია, მაგრამ ის **Rx-ის ბუნებრივ სემანტიკას აუქმებს**: ოპერატორები, რომლებიც შეცდომას სპეციალურად ამუშავებენ (`Catch`, `Retry`), მატერიალიზებულ ნაკადში **ვეღარაფერს დაინახავს**, რადგან იქ შეცდომა უკვე ჩვეულებრივი მნიშვნელობაა. ამიტომ ის უმეტესად დიაგნოსტიკისა და ტესტებისთვის ღირს.
