## პრობლემა: ნელი და არასტაბილური ტესტები

წარმოიდგინე თანმიმდევრობა, რომელიც წამში ერთ მნიშვნელობას აწარმოებს, ხუთი წამის განმავლობაში:

```csharp
IObservable<long> interval = Observable
    .Interval(TimeSpan.FromSeconds(1))
    .Take(5);
```

გულუბრყვილო ტესტს, რომელიც შეამოწმებდა, რომ ხუთი მნიშვნელობა წამიან ინტერვალებში მოდის, **ხუთი წამი** დასჭირდებოდა. ეს ცუდია: გვინდა, ასობით ან ათასობით ტესტი ხუთ წამში გაეშვას.

კიდევ უფრო ცუდია timeout-ის ტესტი:

```csharp
var never = Observable.Never<int>();
bool exceptionThrown = false;

never.Timeout(TimeSpan.FromMinutes(1))
    .Subscribe(_ => { }, ex => exceptionThrown = true);

// უნდა დაველოდოთ მთელ წუთს?!
Assert.IsTrue(exceptionThrown);
```

## გამოსავალი: scheduler-ი დროს აკონტროლებს

როგორც [[თავი 9.2 Scheduler-ები|scheduler-ების თავში]] ვნახეთ, **scheduler აკონტროლებს დროზე დამოკიდებულ ყველა ქცევას**. ჩვეულებრივი scheduler-ები სამუშაოს **ნამდვილ** დროზე უშვებენ. მაგრამ თუ scheduler-ს ვირტუალურ დროს დავაპროგრამებინებთ, შეგვიძლია მისი „დროის აღქმა" გავაკონტროლოთ: დავწეროთ ტესტი, რომელიც **ლოგიკურად** წამებს ითვლის, მაგრამ **რეალურად** მიკროწამებში სრულდება.

> [!IMPORTANT] ეს არის ტესტირებადობის საფუძველი
> რაკი ყველა დროზე დამოკიდებული ოპერატორი (`Interval`, `Timer`, `Delay`, `Timeout`, `Throttle`…) დროს **scheduler-იდან** იღებს და არა პირდაპირ სისტემური საათიდან, საკმარისია ტესტში საკუთარი scheduler გადავცეთ. სწორედ ამისთვისაა შექმნილი `TestScheduler` ([[თავი 14.2 TestScheduler|14.2]]): ის დროს „გააჩერებს" მანამ, სანამ ჩვენ არ ვეტყვით, რომ წინ წავიდეს.
