`Multicast` და მასზე აგებული ოპერატორები (`Publish`, `Replay`) `IConnectableObservable<T>`-ს აბრუნებს, რომელზეც `Connect` ხელით უნდა გამოიძახოთ. ხშირად კი გვინდა, გამოწერა **ავტომატურად** დაიწყოს. სწორედ ამას აკეთებს `RefCount` და `AutoConnect`.

## `RefCount`: გამომწერების დათვლა

`RefCount` აქტიური გამომწერების რაოდენობას ითვლის და `Connect`-ს **ავტომატურად** იძახებს, როგორც კი პირველი გამომწერი გამოჩნდება. ნამდვილ წყაროს ის მაინც მხოლოდ **ერთხელ** გამოიწერს.

```csharp
IObservable<int> rc = src
    .Publish()      // RefCount-ს IConnectableObservable<T> სჭირდება
    .RefCount();
```

> [!IMPORTANT] რატომ `Publish()` ჯერ
> `RefCount` `IConnectableObservable<T>`-ს ელოდება, ამიტომ ჯერ `Publish` (ან სხვა multicast ოპერატორი) უნდა გამოიძახოთ. `RefCount` `Connect`-ს პირველი გამომწერის მოსვლისთანავე იძახებს.

## ავტომატური გათიშვა

სახელიც ამაზე მიგვანიშნებს: `RefCount` (reference count) **მიმართვების რაოდენობას ითვლის**. თუ აქტიური გამომწერების რაოდენობა **0-მდე** ჩამოვა, ის `Dispose`-ს იძახებს იმ ობიექტზე, რომელიც `Connect`-მა დააბრუნა, ანუ ნამდვილი წყაროს გამოწერას აუქმებს. ახალი გამომწერის მოსვლისას კი ყველაფერს **თავიდან** იწყებს.

> [!NOTE] `disconnectDelay`
> `RefCount`-ს აქვს გადატვირთვები `disconnectDelay`-ით: როცა გამომწერების რაოდენობა 0-მდე ჩამოვა, ის გათიშვამდე მითითებულ დროს **ელოდება**, ხომ არ მოვა ახალი გამომწერი. თუ ეს დრო ისე გავიდა, რომ არავინ მოვიდა, მაინც გათიშავს.

> [!TIP] სად გამოგადგებათ
> `RefCount` კარგი არჩევანია ბიბლიოთეკისთვის, რომელიც გარე სერვისს უკავშირდება (მაგალითად, გემების მდებარეობის მონაცემებს): გამომწერი შეიძლება ბევრი იყოს, მაგრამ სერვისს მხოლოდ **ერთხელ** უნდა დაუკავშირდეთ, და **მხოლოდ მაშინ**, როცა ერთი გამომწერი მაინც არის.

## `AutoConnect`: ერთხელ ერთვება, აღარ თიშავს

`AutoConnect` `RefCount`-ს ჰგავს იმით, რომ `Connect`-ს პირველ გამომწერზე იძახებს. განსხვავება: ის **არ** ამოწმებს, გამომწერების რაოდენობა 0-მდე ხომ არ ჩამოვიდა. როგორც კი დაუკავშირდა, **უსასრულოდ** რჩება დაკავშირებული, თუნდაც გამომწერი აღარ ჰყავდეს.

> [!WARNING] `AutoConnect` შეიძლება გაჟონოს
> რაკი `AutoConnect` თავისით არასდროს თიშავს კავშირს, ის რესურსის გაჟონვის მიზეზი შეიძლება გახდეს. კავშირის დახურვა მაინც შესაძლებელია: `AutoConnect` არასავალდებულო `Action<IDisposable>` პარამეტრს იღებს და პირველი დაკავშირებისას მას `Connect`-ის დაბრუნებულ `IDisposable`-ს გადასცემს. კავშირს მასზე `Dispose`-ის გამოძახებით დახურავთ.

## RefCount vs AutoConnect

| | `RefCount` | `AutoConnect` |
|---|---|---|
| **პირველ გამომწერზე** | `Connect` | `Connect` |
| **0 გამომწერზე** | თიშავს (`Dispose`) | რჩება დაკავშირებული |
| **ხელახლა ერთვება?** | დიახ, ახალ გამომწერზე | არა (ერთხელ) |
| **გაჟონვის რისკი** | დაბალი | მაღალი (ხელით უნდა დახუროთ) |
