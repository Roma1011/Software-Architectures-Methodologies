*ნახაზი 7.4: `Buffer` ნაწილის დასრულებას ელოდება, `Window` კი ნაწილს მაშინვე ხსნის.*

## როდის რომელი

> [!IMPORTANT] მარტივი წესი
> - თუ **მთელი ნაწილი ერთად** გჭირდებათ (ჯამი, საშუალო, ჯგუფური ჩაწერა) → **`Buffer`**
> - თუ ელემენტებზე **რეაგირება ნაწილის დასრულებამდე** გინდათ → **`Window`**

`Window`-ის შედეგთან მუშაობა `SelectMany`-ს მოითხოვს, რადგან ჩადგმული ნაკადებია:

```csharp
IObservable<string> live =
    source
        .Window(TimeSpan.FromSeconds(10))
        .SelectMany((window, index) =>
            window.Select(value => $"ფანჯარა {index}: {value}"));
```

## `Window` და მიმდინარე აგრეგატები

ყველაზე ხშირად `Window` მაშინ გამოგადგებათ, როცა ნაწილის **მიმდინარე** მდგომარეობის ჩვენება გინდათ:

```csharp
// წუთის მიმდინარე ჯამი, რომელიც ყოველ ელემენტზე განახლდება
IObservable<int> runningPerMinute =
    amounts
        .Window(TimeSpan.FromMinutes(1))
        .SelectMany(window => window.Scan(0, (sum, x) => sum + x));
```

`Buffer`-ით იგივეს გაკეთება **შეუძლებელი იქნებოდა**: ჯამი მხოლოდ წუთის ბოლოს გამოჩნდებოდა.

> [!WARNING] ფანჯრის გამოწერა აუცილებელია
> თუ `Window`-ის მიერ გაცემულ ნაკადს **არ გამოიწერთ**, მისი ელემენტები **დაიკარგება**. `Buffer`-ისგან განსხვავებით, აქ მონაცემები არსად ინახება: ისინი გაივლის, მიუხედავად იმისა, უსმენს თუ არა ვინმე.
>
> ამიტომ `Window`-ის შედეგზე თითქმის ყოველთვის მაშინვე მოდის `SelectMany` ან `Subscribe`.

## საზღვრები სხვა ნაკადით

`Buffer`-ის მსგავსად, ფანჯრის საზღვარი სხვა observable-ითაც განისაზღვრება, რაც დინამიკურ დაყოფას იძლევა:

```csharp
// ახალი ფანჯარა ყოველი „დაწყების" სიგნალზე
IObservable<IObservable<Telemetry>> perSession =
    telemetry.Window(sessionStarted);
```
