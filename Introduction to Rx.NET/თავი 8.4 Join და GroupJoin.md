[[თავი 8.3 წყვილებად შეერთება|8.3]]-ის ოპერატორები ელემენტებს **პოზიციით** ან **უახლესობით** აკავშირებენ. `Join` და `GroupJoin` კი მათ **დროის ფანჯრების გადაფარვით** აწყვილებს. ეს Rx-ის ყველაზე რთული ოპერატორებია, სამაგიეროდ ყველაზე ზოგადიც.

## იდეა: ყოველ ელემენტს თავისი „სიცოცხლე" აქვს

`Join` ოთხ არგუმენტს იღებს:

```csharp
left.Join(
    right,
    leftItem => /* რამდენ ხანს ცოცხლობს მარცხენა ელემენტი */,
    rightItem => /* რამდენ ხანს ცოცხლობს მარჯვენა ელემენტი */,
    (l, r) => /* რას ვაწარმოებთ, როცა ორი ცოცხალი ელემენტი შეხვდება */);
```

ხანგრძლივობა **observable-ით** განისაზღვრება: ელემენტი ცოცხალია მანამ, სანამ მისი „ხანგრძლივობის" ნაკადი პირველ რამეს არ გასცემს. ჩვეულებრივ ეს `Observable.Timer`-ია.

წყვილი მაშინ იქმნება, როცა მარცხენა და მარჯვენა ელემენტის ფანჯრები **ერთმანეთს გადაფარავს**.

## პრაქტიკული მაგალითი

დავუშვათ, გვინდა დავაკავშიროთ მოთხოვნები და პასუხები, მაგრამ მხოლოდ მაშინ, თუ პასუხი **ხუთ წამში** მოვიდა:

```csharp
IObservable<(Request Req, Response Resp)> matched =
    requests.Join(
        responses,
        req => Observable.Timer(TimeSpan.FromSeconds(5)),   // მოთხოვნა 5 წამს ცოცხლობს
        resp => Observable.Empty<Unit>(),                   // პასუხი მყისიერია
        (req, resp) => (req, resp));
```

> [!TIP] ხანგრძლივობა ნებისმიერი observable-ია
> ის **ტაიმერი არ არის ვალდებული იყოს**. შეიძლება იყოს სხვა მოვლენა („სანამ სესია არ დაიხურება"), ან `Observable.Never`, რაც ნიშნავს **„სამუდამოდ ცოცხალი"**.

## `GroupJoin`

იგივე ლოგიკა, ოღონდ წყვილების ნაცვლად ყოველი მარცხენა ელემენტისთვის **მთელ ნაკადს** გვაძლევს იმ მარჯვენა ელემენტებისა, რომლებიც მის ფანჯარაში მოხვდა:

```csharp
IObservable<TResult> GroupJoin<TLeft, TRight, TLeftDur, TRightDur, TResult>(
    ...
    Func<TLeft, IObservable<TRight>, TResult> resultSelector);
```

ანუ შედეგის შემრჩევი ერთი მარჯვენა ელემენტის ნაცვლად `IObservable<TRight>`-ს იღებს:

```csharp
// ყოველი სესიისთვის მისი მოვლენების ნაკადი
IObservable<SessionActivity> activity =
    sessionStarts.GroupJoin(
        events,
        session => sessionEnds.Where(e => e.Id == session.Id),
        _ => Observable.Empty<Unit>(),
        (session, evts) => new SessionActivity(session, evts));
```

> [!IMPORTANT] `GroupJoin` ყველაზე ზოგადია
> მისგან სხვა ოპერატორების **აგება** შესაძლებელია: `Join` არის `GroupJoin`, რომელსაც შედეგად ჩადგმული ნაკადი „გაბრტყელებული" აქვს, და თვით `CombineLatest`-იც შეიძლება მასზე დაიწეროს. სწორედ ამიტომ ითვლება ის Rx-ის გაერთიანების ოპერატორების **ფუნდამენტად**.

## საჭიროა თუ არა ეს ოპერატორები

> [!WARNING] იშვიათად გამოიყენება
> პრაქტიკაში `Join`-სა და `GroupJoin`-ს **ძალიან იშვიათად** შეხვდებით: უმეტეს ამოცანას `CombineLatest`, `WithLatestFrom`, `Window` ან `GroupBy` უფრო მარტივად წყვეტს. მათი ცოდნა მაინც ღირს, რადგან ისინი აჩვენებს, რამდენად ღრმად არის **დროის ცნება** Rx-ის მოდელში ჩაშენებული.
