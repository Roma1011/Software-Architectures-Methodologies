`Merge` ელემენტებს უბრალოდ **ერთ ღერძზე ალაგებს**. ხშირად კი გვინდა, ორი ნაკადის ელემენტები **ერთმანეთს დავუკავშიროთ** და მათგან ახალი მნიშვნელობა ავაგოთ. ამის სამი გზაა, და მათ შორის განსხვავება მხოლოდ ერთ კითხვამდე დადის: **როდის გამოვიდეს შედეგი**.

## `Zip`: ინდექსების დაწყვილება

აერთიანებს **პირველს პირველთან, მეორეს მეორესთან** და ასე შემდეგ. თუ ერთი წყარო წინ გაიჭრა, `Zip` მის ელემენტებს **ბუფერში ინახავს** და მეორეს ელოდება.

```csharp
IObservable<(string Name, decimal Price)> products = names.Zip(prices, (n, p) => (n, p));
```

## `CombineLatest`: ყოველი ცვლილება

გასცემს შედეგს **ყოველთვის, როცა ერთ-ერთი წყარო რამეს გამოსცემს**, და იყენებს **თითოეულის უახლეს** მნიშვნელობას.

```csharp
IObservable<bool> canSubmit =
    isFormValid.CombineLatest(isNotBusy, (valid, notBusy) => valid && notBusy);
```

## `WithLatestFrom`: ერთი მთავარია

შუალედური ვარიანტი: შედეგი გამოდის **მხოლოდ მაშინ, როცა მთავარი (მარცხენა) წყარო გამოსცემს**, და მეორედან უახლესი მნიშვნელობა აიღება.

```csharp
// ღილაკზე დაჭერისას ვიღებთ ფორმის მიმდინარე შიგთავსს
IObservable<Form> submissions = submitClicks.WithLatestFrom(formState, (_, form) => form);
```

ეს ზუსტად ის სემანტიკაა, რომელიც ინტერფეისში გვჭირდება: **ქმედება** ერთი ნაკადიდან მოდის, **კონტექსტი** კი მეორედან.

## რომელი ავირჩიოთ

| | როდის გამოდის შედეგი | ელემენტი ხელახლა გამოიყენება? |
|---|---|---|
| **`Zip`** | როცა **ორივეს** აქვს ახალი ელემენტი | არა, ყოველი ზუსტად ერთხელ |
| **`CombineLatest`** | როცა **ნებისმიერი** გამოსცემს | დიახ |
| **`WithLatestFrom`** | როცა **მარცხენა** გამოსცემს | დიახ, მარჯვენადან |

> [!TIP] მარტივი მინიშნება
> - მონაცემებს **აწყვილებთ** (მოთხოვნა ↔ პასუხი) → `Zip`
> - **მდგომარეობებს აერთიანებთ** (ორივე პირობა სრულდება?) → `CombineLatest`
> - **მოვლენას კონტექსტს უმატებთ** (დაჭერა + მიმდინარე მნიშვნელობა) → `WithLatestFrom`
