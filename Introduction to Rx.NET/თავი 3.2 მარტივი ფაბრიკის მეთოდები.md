პირველი კატეგორია იმ ფაბრიკებისაა, რომლებიც **მაქსიმუმ ერთ** შედეგს აწარმოებს. ისინი ტრივიალურად გამოიყურება, მაგრამ პრაქტიკაში მუდმივად გვჭირდება: ტესტებში, ნაგულისხმევ მნიშვნელობებად და უფრო რთული მოთხოვნების „ბოლო წერტილებად".

## `Observable.Return`

იღებს `T` ტიპის მნიშვნელობას და აბრუნებს `IObservable<T>`-ს, რომელიც ამ ერთ მნიშვნელობას გასცემს და შემდეგ სრულდება. გარკვეული აზრით, ის მნიშვნელობას observable-ში **ახვევს**: კონცეპტუალურად იგივეა, რაც `new[] { value }`, ანუ ერთელემენტიანი თანმიმდევრობა.

```csharp
IObservable<string> single = Observable.Return("გამარჯობა");
```

ტიპის პარამეტრის აშკარად მითითება საჭირო არ არის, რადგან კომპილატორი მას არგუმენტიდან დაასკვნის.

> [!NOTE] `Return` არის `cold`
> ყოველი გამომწერი მნიშვნელობას **გამოწერისთანავე** მიიღებს, მიუხედავად იმისა, როდის გამოიწერა ([[თავი 2.1 IObservable ინტერფეისი|2.1]]).

## `Observable.Empty`

ცარიელი თანმიმდევრობა. პრაქტიკაში ეს ის წყაროა, რომელიც ყოველ გამომწერს **მაშინვე `OnCompleted`-ს** უძახებს.

```csharp
IObservable<string> nothing = Observable.Empty<string>();
```

აქ ტიპის პარამეტრი **აუცილებელია**, რადგან კომპილატორს დასაკვირვებელი არგუმენტი არ აქვს.

## `Observable.Throw`

აბრუნებს თანმიმდევრობას, რომელიც ყოველ გამომწერს მაშინვე შეცდომას ატყობინებს.

```csharp
IObservable<string> failed =
    Observable.Throw<string>(new TimeoutException("სერვისი არ პასუხობს"));
```

`T`-ს აქაც ხელით ვუთითებთ: `T` ტიპის მნიშვნელობა არასდროს გაიცემა, მაგრამ `IObservable<T>`-ის ეგზემპლარი კონკრეტული ტიპის გარეშე ვერ იარსებებს.

> [!TIP] სად გამოგვადგება ეს სამი
> **ტესტებში**, დამოკიდებულებების ჩასანაცვლებლად: `Return` წარმატებული პასუხისთვის, `Throw` შეცდომის გზის შესამოწმებლად, `Empty` ცარიელი შედეგისთვის. ასევე რეალურ კოდში, სადაც მეთოდმა `IObservable<T>` უნდა დააბრუნოს, მაგრამ შედეგი უკვე ხელთაა.

## `Observable.Never`

ეს ყველაზე უცნაურად გამოიყურება: თანმიმდევრობა, რომელიც **არაფერს აკეთებს**. ის არც `OnNext`-ს იძახებს, არც `OnCompleted`-ს და არც `OnError`-ს. `Empty` მაშინვე სრულდება, `Never` კი **უსასრულო ხანგრძლივობისაა**.

```csharp
IObservable<string> silence = Observable.Never<string>();
```

რატომ გვჭირდება ასეთი რამ? ორი ტიპური სცენარია.

**1. ტესტირება.** მისით ვიმიტირებთ წყაროს, რომელიც მნიშვნელობებს **არ აწარმოებს**, რომ, მაგალითად, timeout-ის ლოგიკა შევამოწმოთ ([[თავი 10.5 Timeout|10.5]]).

**2. დროის გამოსახვა.** Rx-ში ხშირად observable მხოლოდ **დროის ნიშნულად** გამოიყენება: მნიშვნელობა არ გვაინტერესებს, მხოლოდ ის, **როდის** მოხდა რაღაც. ასეთ კონტექსტში `Never` ნიშნავს **„ეს არასდროს მოხდება"**.

მაგალითად, თუ ბიბლიოთეკა timeout-ს observable-ის სახით იღებს, და თქვენ timeout საერთოდ არ გინდათ, `Observable.Never`-ის გადაცემა ზუსტად იმას ნიშნავს, რომ **უსასრულოდ ველოდებით**.

> [!IMPORTANT] `Empty` და `Never` ერთი და იგივე არ არის
> ორივე არცერთ მნიშვნელობას არ გასცემს, მაგრამ `Empty` **სრულდება**, `Never` კი არა. ეს გადამწყვეტია იმ ოპერატორებისთვის, რომლებიც დასრულებას ელოდებიან: `Empty`-ს მიბმული `Concat` მაშინვე გადავა შემდეგზე, `Never`-ს მიბმული კი **სამუდამოდ გაიჭედება**.
