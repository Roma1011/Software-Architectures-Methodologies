ზოგჯერ ელემენტს **შიგთავსის** მიხედვით კი არ ვარჩევთ, არამედ **პოზიციის** მიხედვით: პირველი, ბოლო, პირველი სამი, ყველა გარდა პირველი ორისა.

## რატომ აქვთ `Async` სუფიქსი

LINQ to Objects-ში `First()` **თავად მნიშვნელობას** აბრუნებს. Rx-ში ეს შეუძლებელია: მნიშვნელობა ჯერ არ არსებობს, და მისი ლოდინი ნაკადს დაბლოკავდა. ამიტომ Rx-ის ვარიანტები **`IObservable<T>`-ს აბრუნებს**, რომელიც ერთ ელემენტს გასცემს და სრულდება, და სახელს `Async` სუფიქსი აქვს:

```csharp
IObservable<Order> firstBigOrder =
    orders.Where(o => o.Total > 1000).FirstAsync();
```

> [!NOTE] ეს მაინც observable-ია
> `FirstAsync()` **არ არის** `await`-ადი მეთოდი ჩვეულებრივი აზრით: ის `IObservable<T>`-ს აბრუნებს. თუმცა Rx-ის თანმიმდევრობის `await`-ი შესაძლებელია ([[თავი 11.1 async და await-თან ინტეგრაცია|11.1]]), ამიტომ `await orders.FirstAsync()` მუშაობს.

## პირველი და ბოლო

| ოპერატორი | რას აბრუნებს | ცარიელ წყაროზე |
|---|---|---|
| `FirstAsync()` | პირველ ელემენტს | **შეცდომა** (`InvalidOperationException`) |
| `FirstOrDefaultAsync()` | პირველ ელემენტს | ტიპის **ნაგულისხმევ** მნიშვნელობას |
| `LastAsync()` | ბოლო ელემენტს | **შეცდომა** |
| `LastOrDefaultAsync()` | ბოლო ელემენტს | ნაგულისხმევ მნიშვნელობას |
| `SingleAsync()` | ერთადერთ ელემენტს | **შეცდომა**; ერთზე მეტზეც **შეცდომა** |
| `ElementAt(n)` | n-ურ ელემენტს | **შეცდომა**, თუ ასეთი არ არსებობს |

ყველა მათგანს პრედიკატიანი გადატვირთვაც აქვს: `FirstAsync(x => x > 10)` იგივეა, რაც `Where(x => x > 10).FirstAsync()`.

> [!IMPORTANT] `LastAsync` დასრულებას ელოდება
> `FirstAsync` პასუხს **მაშინვე** გასცემს, როგორც კი პირველი ელემენტი მოვა. `LastAsync` კი ვერ იცის, რომელია ბოლო, სანამ წყარო არ დასრულდება. ამიტომ **უსასრულო წყაროზე `LastAsync` არასდროს არაფერს გასცემს**.

## `Take` და `Skip`

`Take(n)` პირველ n ელემენტს ტოვებს და დანარჩენს აგდებს. `Skip(n)` პირიქით: პირველ n-ს აგდებს და დანარჩენს ატარებს.

```csharp
IObservable<int> firstThree = source.Take(3);
IObservable<int> afterThree = source.Skip(3);
```

> [!TIP] `Take` წყაროს **ათავისუფლებს**
> როგორც კი `Take(n)` n-ურ ელემენტს მიიღებს, ის `OnCompleted`-ს გასცემს **და წყაროს გამოეწერება**. ეს მნიშვნელოვანია: უსასრულო წყაროზე `Take` მუშაობს და რესურსსაც ათავისუფლებს.

> [!NOTE] `Take` არ ჩივის, თუ ელემენტი არ ეყო
> თუ წყარო n ელემენტამდე დასრულდა, `Take(n)` **შეცდომას არ ისვრის**: ის უბრალოდ იმას გადასცემს, რაც მიიღო, და სრულდება. სწორედ ამიტომ `Take(1)` „პირველი ან არაფრის" სემანტიკას გვაძლევს, განსხვავებით `FirstAsync`-ისგან, რომელიც ცარიელ წყაროზე შეცდომას ისვრის.

## `TakeLast` და `SkipLast`

ბოლოდან მუშაობა უფრო ძვირია, რადგან Rx-მა წინასწარ არ იცის, სად არის ბოლო.

```csharp
IObservable<int> lastThree = source.TakeLast(3);
IObservable<int> allButLastTwo = source.SkipLast(2);
```

> [!WARNING] `TakeLast` აგროვებს და ელოდება
> `TakeLast(n)` იძულებულია, **ბოლო n ელემენტი ბუფერში ინახოს** და **არაფერი გასცეს, სანამ წყარო არ დასრულდება**. უსასრულო წყაროზე ის არასდროს არაფერს გასცემს, სამაგიეროდ მეხსიერებას მუდმივად იკავებს.
>
> `SkipLast(n)` უფრო რბილია: ისიც n ელემენტს აყოვნებს ბუფერში, მაგრამ ელემენტებს **გზადაგზა გასცემს** (უბრალოდ n ბიჯით დაგვიანებით), ამიტომ უსასრულო წყაროზეც მუშაობს.

## პრაქტიკული კომბინაცია

ეს ოპერატორები ერთმანეთს კარგად ერწყმის. მაგალითად, „მეორედან მეხუთემდე":

```csharp
IObservable<LogEntry> page = entries.Skip(1).Take(4);
```

ან „ბოლო გაზომვა, მაგრამ მაქსიმუმ ხუთი წამის ლოდინით":

```csharp
IObservable<Reading> latest =
    sensor.Readings
        .TakeUntil(DateTimeOffset.Now.AddSeconds(5))
        .LastOrDefaultAsync();
```

> [!IMPORTANT] ოპერატორებს „ტემპერატურა" არ აქვთ
> ამ თავის ოპერატორები (და Rx-ის უმეტესობა) **თავისთავად არც `hot`-ია და არც `cold`**: ისინი წყაროს ტემპერატურას იმეორებენ. თუ წყარო `hot`-ია, `source.Take(1)`-იც `hot` იქნება ([[თავი 2.1 IObservable ინტერფეისი|2.1]]).
