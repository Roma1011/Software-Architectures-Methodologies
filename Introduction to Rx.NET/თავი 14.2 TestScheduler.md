`TestScheduler` არის scheduler, რომელიც დროს სრულიად სხვანაირად ამუშავებს: ის **ვირტუალურ** დროს იყენებს და ლოდინის ნაცვლად ჩვენ გვაძლევს დროის მართვის სახელურებს.

> [!NOTE] სად ცხოვრობს `TestScheduler`
> ის მთავარ `System.Reactive` პაკეტში **არ** არის. საჭიროა `Microsoft.Reactive.Testing` პაკეტის დამატება.

## ერთეული: ticks

`TestScheduler` `TimeSpan.Ticks`-ის იმავე ერთეულებში მუშაობს. ერთი tick = 100 ნანოწამი, ამიტომ 1 წამი = 10,000,000 tick. დროის წინ წასაწევად:

```csharp
scheduler.AdvanceBy(TimeSpan.FromSeconds(1).Ticks);
```

ნებისმიერ scheduler-ს აქვს დაგეგმილი მოქმედებების რიგი, თითო დანიშნულ დროსთან. `TestScheduler` თითქოს დროს **აჩერებს**, სანამ ჩვენ არ ვეტყვით, რომ წინ წავიდეს.

```csharp
var scheduler = new TestScheduler();
var wasExecuted = false;

scheduler.Schedule(() => wasExecuted = true);
Assert.IsFalse(wasExecuted);   // ჯერ არაფერი შესრულებულა

scheduler.AdvanceBy(1);        // ერთი tick წინ
Assert.IsTrue(wasExecuted);    // ახლა შესრულდა
```

## `AdvanceTo`, `AdvanceBy`, `Start`

| მეთოდი | რას აკეთებს |
|---|---|
| **`AdvanceTo(t)`** | ვირტუალურ დროს **აბსოლუტურ** `t` tick-ზე აყენებს და ასრულებს ყველა მოქმედებას ამ დრომდე |
| **`AdvanceBy(d)`** | დროს **მიმდინარიდან** `d` tick-ით წინ წევს |
| **`Start()`** | ასრულებს **ყველაფერს**, რაც დაგეგმილია, დროს საჭიროებისამებრ წევს წინ |
| **`Stop()`** | აჩერებს `Start`-ს: `IsEnabled`-ს `false`-ზე აყენებს |

```csharp
var scheduler = new TestScheduler();
scheduler.Schedule(() => Console.WriteLine("A"));                       // მაშინვე
scheduler.Schedule(TimeSpan.FromTicks(10), () => Console.WriteLine("B"));
scheduler.Schedule(TimeSpan.FromTicks(20), () => Console.WriteLine("C"));

scheduler.AdvanceTo(1);    // A
scheduler.AdvanceTo(10);   // B
scheduler.AdvanceTo(15);   // (არაფერი: 15-ზე ვერაფერია დაგეგმილი)
scheduler.AdvanceTo(20);   // C
```

> [!IMPORTANT] `Start` ავტომატურად ჩერდება
> `Start()` მთელ რიგს ასრულებს, შემდეგ ვირტუალური საათი **ბოლო** დაგეგმილ დროს უტოლდება (ზემოთ, t=20). თუ `Start`-ის შემდეგ ახალ მოქმედებას დაგეგმავ, მისთვის ისევ `Start` (ან `AdvanceTo`/`AdvanceBy`) უნდა დაიძახო. `Stop()` სავალდებულო არაა: ის მხოლოდ მაშინ გჭირდება, თუ `Start`-ის შუა გზაზე შეჩერება გინდა.

> [!NOTE] ერთდროული მოქმედებები (collision)
> თუ რამდენიმე მოქმედება **ერთსა და იმავე** დროზეა დაგეგმილი, `TestScheduler` მათ **დაგეგმვის რიგით** ასრულებს, როცა საათი ამ წერტილს მიაღწევს.

## რეალური ტესტი

TestScheduler-ს ოპერატორს scheduler-ის პარამეტრად გადავცემთ:

```csharp
[TestMethod]
public void Interval_წარმოქმნის_ხუთ_მნიშვნელობას()
{
    var expected = new long[] { 0, 1, 2, 3, 4 };
    var actual = new List<long>();
    var scheduler = new TestScheduler();

    Observable.Interval(TimeSpan.FromSeconds(1), scheduler)
        .Take(5)
        .Subscribe(actual.Add);

    scheduler.Start();          // ვირტუალურად "5 წამი" გადის მყისვე

    CollectionAssert.AreEqual(expected, actual);
    // სრულდება 0.01 წამზე ნაკლებში
}
```

> [!TIP] ოქროს წესი ტესტირებადი Rx-კოდისთვის
> **ნუ დაუძახებ scheduler-ს პირდაპირ კოდში.** სანაცვლოდ, scheduler-ი **პარამეტრად** მიიღე (dependency injection). წარმოებაში ჩვეულებრივ scheduler-ს გადასცემ, ტესტში კი `TestScheduler`-ს. ასე იგივე კოდი წარმოებაშიც მუშაობს და ტესტშიც მყისიერად სრულდება.
