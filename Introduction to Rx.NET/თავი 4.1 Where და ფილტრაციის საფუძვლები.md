> [!INFO] მე-2 ნაწილის შესახებ
> პირველ ნაწილში ვისწავლეთ, **საიდან** მოდის მოვლენები. ახლა ვისწავლით, **რა ვუყოთ მათ**: როგორ გავფილტროთ, გარდავქმნათ, დავაჯგუფოთ და გავაერთიანოთ ისე, რომ ნედლი ნაკადიდან ღირებულ დასკვნამდე მივიდეთ.
>
> ყველა ეს ოპერატორი ერთ საერთო თვისებას იზიარებს: **ისინი `IObservable<T>`-ს იღებენ და `IObservable<T>`-ს აბრუნებენ**. სწორედ ეს ხდის მათ თავისუფლად კომპოზირებადს.

## `Where`

ყველაზე ნაცნობი ოპერატორი: ტოვებს მხოლოდ იმ ელემენტებს, რომლებიც პირობას აკმაყოფილებს.

```csharp
IObservable<Reading> alarms =
    sensor.Readings.Where(r => r.Temperature > 80);
```

> [!NOTE] დროის ნიშნულები არ იცვლება
> `Where` **არაფერს აყოვნებს**: გატარებული ელემენტი ზუსტად იმ მომენტში გამოდის, როცა წყაროდან მოვიდა. ის მხოლოდ ზოგიერთს **აქრობს**.

`Where`-ს ინდექსიანი გადატვირთვაც აქვს, სადაც პრედიკატი ელემენტის რიგით ნომერსაც იღებს:

```csharp
// ყოველი მეორე ელემენტი
source.Where((value, index) => index % 2 == 0);
```

## `IgnoreElements`

გადაატარებს **მხოლოდ** დასრულებასა და შეცდომას, ყველა მნიშვნელობას კი აქრობს. ეს იმის ტოლფასია, რომ `Where`-ს მუდამ `false` დაგვებრუნებინა.

```csharp
IObservable<Unit> justTheEnd = source.IgnoreElements();
```

> [!TIP] რატომ გვჭირდება ასეთი რამ
> როცა მხოლოდ **„როდის დასრულდა"** გვაინტერესებს და არა თავად მონაცემები. მაგალითად, გვინდა დავიცადოთ, სანამ ხანგრძლივი ნაკადი დამთავრდება, მაგრამ მისი ელემენტები არაფრად გვჭირდება.

## `OfType`

ზოგი წყარო **სხვადასხვა ტიპის** ელემენტს აწარმოებს. კარგი მაგალითია სენსორული სისტემა, სადაც ერთი ნაკადით მოდის როგორც გაზომვები, ისე დიაგნოსტიკური და კონფიგურაციის შეტყობინებები, ყველა ერთი საერთო საბაზისო ინტერფეისით.

`OfType<T>` ტოვებს მხოლოდ იმ ელემენტებს, რომლებიც მითითებულ ტიპს ეკუთვნის, და შედეგსაც უკვე ამ ტიპისას აბრუნებს:

```csharp
IObservable<IDeviceMessage> all = hub.Messages;

IObservable<TemperatureReading> temperatures = all.OfType<TemperatureReading>();
```

> [!IMPORTANT] `OfType` და `Cast`
> `OfType<T>` **ფილტრავს**: შეუსაბამო ტიპის ელემენტებს უბრალოდ აგდებს. `Cast<T>` კი **ყველას** გადაიყვანს და შეუსაბამობისას **შეცდომას** ისვრის. თუ დარწმუნებული ხართ, რომ ყველა ელემენტი სწორი ტიპისაა, `Cast` უფრო გამომხატველია, რადგან შეცდომა დაფარული არ დარჩება.

## ორივე ბოლოს გამორიცხვა: `Distinct`

`Distinct` ტოვებს მხოლოდ იმ მნიშვნელობებს, რომლებიც **აქამდე არ უნახავს**:

```csharp
IObservable<string> uniqueVisitors = requests.Select(r => r.UserId).Distinct();
```

> [!WARNING] `Distinct` მეხსიერებას აგროვებს
> იმისთვის, რომ იცოდეს, რა ნახა, `Distinct` **ყველა ნანახ მნიშვნელობას ინახავს**. უსასრულო წყაროზე ეს მეხსიერების ზრდას ნიშნავს.

უფრო ხშირად სასურველია **`DistinctUntilChanged`**, რომელიც მხოლოდ **ზედიზედ განმეორებულ** მნიშვნელობებს აქრობს და მეხსიერებაში მხოლოდ ბოლოს ინახავს:

```csharp
// შეტყობინება მხოლოდ მაშინ, როცა სტატუსი მართლა შეიცვალა
IObservable<Status> changes = device.Status.DistinctUntilChanged();
```
