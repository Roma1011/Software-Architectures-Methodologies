ზოგჯერ Rx-ის წყარო არა `await`-ისთვის, არამედ სხვა სამყაროსთვის უნდა მოვამზადოთ: `Task<T>`-ს მოელოდება ერთი API, .NET-ის მოვლენას კი მეორე. ამისთვის `ToTask` და `ToEvent` გვაქვს.

## `ToTask`: `Task<T>`-ის მიღება

მართალია, `await`-ს პირდაპირ `IObservable<T>`-ზეც იყენებ, მაგრამ ზოგჯერ **ნამდვილი `Task<T>`** გჭირდება, რადგან API სწორედ მას ელოდება. `ToTask()` ნებისმიერ `IObservable<T>`-ს გამოიწერს და `Task<T>`-ს აბრუნებს, რომელიც წყაროს დასრულებისას სრულდება და **ბოლო** მნიშვნელობას აბრუნებს შედეგად.

```csharp
IObservable<long> source = Observable.Interval(TimeSpan.FromSeconds(1)).Take(5);

Task<long> resultTask = source.ToTask();
long result = await resultTask;   // ~5 წამი დასჭირდება
Console.WriteLine(result);        // 4
```

> [!NOTE] namespace და დეტალები
> `ToTask` `System.Reactive.Threading.Tasks` namespace-შია.
> - თუ წყარო ელემენტის გარეშე დასრულდა, `Task` **ჩავარდნილ** მდგომარეობაში გადადის `InvalidOperationException`-ით („თანმიმდევრობა ცარიელია").
> - შეგიძლია `CancellationToken` გადასცე: თუ დასრულებამდე გააუქმებ, Rx გამოეწერება წყაროს და `Task`-ს გაუქმებულ მდგომარეობაში გადაიყვანს.
> - როგორც კი `Task` გაქვს, TPL-ის ყველა შესაძლებლობა (მაგალითად, `ContinueWith`) ხელმისაწვდომია.

> [!TIP] `ToTask` vs პირდაპირი `await`
> პირდაპირ `await source` მოსახერხებელია, როცა შენ თავად ელოდები შედეგს. `ToTask` მაშინ სჯობს, როცა `Task<T>`-ის **ობიექტად გადაცემა** გჭირდება: სხვა მეთოდისთვის, კოლექციაში შესანახად ან `Task.WhenAll`-ისთვის.

## `ToEvent`: observable → .NET მოვლენა

როგორც `FromEventPattern`-ით მოვლენა observable-ის წყაროდ გვექცა, `ToEvent`-ით საპირისპიროსაც ვაკეთებთ: observable-ს ჩვეულებრივ .NET მოვლენად ვაქცევთ. `ToEvent` აბრუნებს `IEventSource<T>`-ს, რომელსაც ერთი წევრი აქვს: `OnNext` მოვლენა.

```csharp
var source = Observable.Interval(TimeSpan.FromSeconds(1)).Take(5);

var evt = source.ToEvent();
evt.OnNext += val => Console.WriteLine(val);
```

## `ToEventPattern`: სტანდარტული მოდელი

`ToEvent` უმარტივესი გზაა, მაგრამ ის .NET-ის **სტანდარტულ** მოვლენის მოდელს არ მიჰყვება (`sender`, `EventArgs`). თუ სტანდარტული ხელმოწერა გინდა, `ToEventPattern` გამოიყენე. ის `IObservable<EventPattern<TEventArgs>>`-ს ელოდება, ამიტომ ჯერ `Select`-ით უნდა შეფუთო:

```csharp
IObservable<EventPattern<MyEventArgs>> wrapped =
    Observable.Interval(TimeSpan.FromSeconds(1))
        .Select(i => new EventPattern<MyEventArgs>(this, new MyEventArgs(i)));

IEventPatternSource<MyEventArgs> result = wrapped.ToEventPattern();
result.OnNext += (sender, e) => Console.WriteLine(e.Value);
```

> [!IMPORTANT] რატომ ჯობია Rx მოვლენებს
> სანამ .NET მოვლენებში დაბრუნდები, გახსოვდეს, რატომ არის observable უკეთესი მოდელი:
> - მოვლენების **კომპოზიცია** ძნელია;
> - მოვლენას ვერ გადასცემ არგუმენტად და ვერ შეინახავ ველში;
> - მოვლენებზე დროში მოთხოვნის დაწერა რთულია;
> - მოვლენებს არ აქვთ **შეცდომის** და **დასრულების** სტანდარტული მოდელი;
> - მოვლენები კონკურენტულობაში თითქმის არ გეხმარება.
