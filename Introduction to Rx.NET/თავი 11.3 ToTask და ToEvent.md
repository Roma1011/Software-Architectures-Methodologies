ზოგჯერ Rx-ის წყაროს შედეგი `await`-ით კი არ გვჭირდება, არამედ სხვა API-სთვის: ერთი `Task<T>`-ს ელოდება, მეორე კი .NET-ის მოვლენას. ამისთვის არსებობს `ToTask` და `ToEvent`.

## `ToTask`: `Task<T>`-ის მიღება

მართალია, `await` პირდაპირ `IObservable<T>`-ზეც მუშაობს, მაგრამ ზოგჯერ **ნამდვილი `Task<T>`** გჭირდებათ, რადგან API სწორედ მას ელოდება. `ToTask()` ნებისმიერ `IObservable<T>`-ს გამოიწერს და `Task<T>`-ს აბრუნებს, რომელიც წყაროს დასრულებისას სრულდება და **ბოლო** მნიშვნელობას აბრუნებს შედეგად.

```csharp
IObservable<long> source = Observable.Interval(TimeSpan.FromSeconds(1)).Take(5);

Task<long> resultTask = source.ToTask();
long result = await resultTask;   // ~5 წამი დასჭირდება
Console.WriteLine(result);        // 4
```

> [!NOTE] namespace და დეტალები
> `ToTask` `System.Reactive.Threading.Tasks` namespace-შია.
> - თუ წყარო ელემენტის გარეშე დასრულდა, `Task` **ჩავარდნილ** მდგომარეობაში გადადის `InvalidOperationException`-ით („თანმიმდევრობა ცარიელია").
> - შეგიძლიათ `CancellationToken` გადასცეთ: თუ ოპერაციას დასრულებამდე გააუქმებთ, Rx წყაროს გამოწერას გააუქმებს და `Task`-ს გაუქმებულ (canceled) მდგომარეობაში გადაიყვანს.
> - როგორც კი `Task` გაქვს, TPL-ის ყველა შესაძლებლობა (მაგალითად, `ContinueWith`) ხელმისაწვდომია.

> [!TIP] `ToTask` vs პირდაპირი `await`
> პირდაპირ `await source` მოსახერხებელია, როცა შედეგს თავად ელოდებით. `ToTask` მაშინ სჯობს, როცა `Task<T>` **ობიექტად** უნდა გადასცეთ: სხვა მეთოდისთვის, კოლექციაში შესანახად ან `Task.WhenAll`-ისთვის.

## `ToEvent`: observable → .NET მოვლენა

`FromEventPattern` მოვლენას observable-ად აქცევს, `ToEvent` კი საპირისპიროს აკეთებს: observable-ს ჩვეულებრივ .NET მოვლენად აქცევს. `ToEvent` აბრუნებს `IEventSource<T>`-ს, რომელსაც ერთი წევრი აქვს: `OnNext` მოვლენა.

```csharp
var source = Observable.Interval(TimeSpan.FromSeconds(1)).Take(5);

var evt = source.ToEvent();
evt.OnNext += val => Console.WriteLine(val);
```

## `ToEventPattern`: სტანდარტული მოდელი

`ToEvent` უმარტივესი გზაა, მაგრამ ის .NET-ის **სტანდარტულ** მოვლენის ნიმუშს (`sender`, `EventArgs`) არ მიჰყვება. თუ სტანდარტული ხელმოწერა გჭირდებათ, `ToEventPattern` გამოიყენეთ. ის `IObservable<EventPattern<TEventArgs>>`-ს ელოდება, ამიტომ მნიშვნელობები ჯერ `Select`-ით `EventPattern`-ად უნდა გარდაქმნათ:

```csharp
IObservable<EventPattern<MyEventArgs>> wrapped =
    Observable.Interval(TimeSpan.FromSeconds(1))
        .Select(i => new EventPattern<MyEventArgs>(this, new MyEventArgs(i)));

IEventPatternSource<MyEventArgs> result = wrapped.ToEventPattern();
result.OnNext += (sender, e) => Console.WriteLine(e.Value);
```

> [!IMPORTANT] რატომ ჯობია Rx მოვლენებს
> სანამ .NET მოვლენებს დაუბრუნდებით, გაიხსენეთ, რატომ არის observable უკეთესი მოდელი:
> - მოვლენების ერთმანეთთან **კომბინირება** ძნელია;
> - მოვლენას ვერ გადასცემთ არგუმენტად და ვერ შეინახავთ ველში;
> - მოვლენებზე დროის გათვალისწინებით მოთხოვნის დაწერა რთულია;
> - მოვლენებს არ აქვთ **შეცდომისა** და **დასრულების** შეტყობინების სტანდარტული საშუალება;
> - მოვლენები კონკურენტულობის მართვაში თითქმის არ გეხმარებათ.
