`await`-სა და `ForEachAsync`-ზე ერთი ნაბიჯით შორს მიდის მთელი თანმიმდევრობის **ჩვეულებრივ კოლექციად** გადაქცევა, რომ მასთან `foreach`-ით ან ინდექსით ვიმუშაოთ.

## `ToEnumerable`: `foreach`-ით მოხმარება

`ToEnumerable` მთელ observable თანმიმდევრობას `IEnumerable<T>`-ად აქცევს, რომ ჩვეულებრივი `foreach`-ით გადავუაროთ:

```csharp
var period = TimeSpan.FromMilliseconds(200);
IObservable<long> source = Observable.Timer(TimeSpan.Zero, period).Take(5);

IEnumerable<long> result = source.ToEnumerable();

foreach (long value in result)
{
    Console.WriteLine(value);
}
Console.WriteLine("დასრულდა");
```

> [!IMPORTANT] ბლოკირება და ცალკე ნაკადის საჭიროება
> გამოწერა **გადავადებულად** ხდება: მაშინ, როცა ჩამოთვლას იწყებთ. თუ ელემენტი ჯერ არ არის, `MoveNext` ნაკადს **დაბლოკავს**, სანამ წყარო ახალ ელემენტს არ მოგვაწვდის. ამიტომ ეს მიდგომა იმაზეა დამოკიდებული, რომ წყარო ელემენტებს **სხვა ნაკადიდან** აწარმოებდეს (ზემოთ `Timer` ნაგულისხმევად `DefaultScheduler`-ს, ე.ი. ნაკადების აუზს იყენებს).
>
> **საშიშროება:** თუ წყარო და `foreach` ერთსა და იმავე ნაკადზე მუშაობს და `foreach` ყველა უკვე მიღებულ ელემენტს დაამუშავებს, deadlock მოხდება: ნაკადი ახალ ელემენტს ელოდება, რომელიც იმავე ნაკადმა უნდა აწარმოოს.

თუ წყარო შეცდომით სრულდება, `ToEnumerable` გამონაკლისს ჩვეულებრივად ისვრის, ამიტომ ჩვეულებრივი `try/catch` მუშაობს:

```csharp
try
{
    foreach (long value in result)
        Console.WriteLine(value);
}
catch (Exception e)
{
    Console.WriteLine(e.Message);
}
```

## ერთ კოლექციად შეკრება

ზოგჯერ ყველა ელემენტი **ერთ სიაში** გჭირდებათ, მაგალითად, როცა ადრე მიღებულ ელემენტებს უნდა მიუბრუნდეთ. ამას ოთხი ოპერატორი აკეთებს. ყველა ისევ `IObservable<T>`-ს აბრუნებს (მაგალითად, `IObservable<int[]>`), მაგრამ ეს **ერთელემენტიანი** წყაროებია: წყაროს დასრულებას ელოდებიან, შემდეგ მთელ კოლექციას ერთ მნიშვნელობად აწვდიან და მაშინვე სრულდებიან. ამიტომ შედეგს `await`-ით მარტივად მიიღებთ.

| ოპერატორი | აბრუნებს | აღწერა |
|---|---|---|
| **`ToArray`** | `IObservable<T[]>` | ყველა ელემენტი მასივში |
| **`ToList`** | `IObservable<List<T>>` | ყველა ელემენტი `List<T>`-ში |
| **`ToDictionary`** | `IObservable<IDictionary<K,V>>` | გასაღები → **ერთი** მნიშვნელობა |
| **`ToLookup`** | `IObservable<ILookup<K,V>>` | გასაღები → **მრავალი** მნიშვნელობა |

```csharp
TimeSpan period = TimeSpan.FromMilliseconds(200);
IObservable<long> source = Observable.Timer(TimeSpan.Zero, period).Take(5);

long[] result = await source.ToArray();

foreach (long value in result)
    Console.WriteLine(value);
```

> [!WARNING] შეცდომისას მნიშვნელობები იკარგება
> თუ წყარო ჯერ ელემენტებს აწვდის და მერე შეცდომით სრულდება, **ვერცერთ** მათგანს ვერ მიიღებთ: ამ მომენტამდე დაგროვილი ყველაფერი გაუქმდება და ოპერატორი `OnError`-ს დაუძახებს (ზემოთ მაგალითში ეს `await`-იდან სროლას ნიშნავს). ეს ქცევა ოთხივე ოპერატორისთვის ერთნაირია.

> [!NOTE] `ToDictionary` vs `ToLookup`
> ორივე იგივე მიდგომას იყენებს, რაც `ToArray`/`ToList`. სხვაობა LINQ-ის მსგავსია: `Dictionary` ერთ გასაღებს **ერთ** მნიშვნელობას აბამს, ხოლო `ILookup` ერთ გასაღებს **ნებისმიერ რაოდენობას**.
