> [!INFO] გამოქვეყნების (publishing) ოპერატორები
> `hot` წყარომ მოვლენები რამდენიმე გამომწერს უნდა მიაწოდოს. გამომწერების თვალყურის დევნა თავად რომ არ დაგვჭირდეს, Rx გვთავაზობს **multicast** ოპერატორებს: ისინი ერთი გამომწერისთვის დაწერილ მარტივ წყაროსაც კი მრავალგამომწერიან `hot` წყაროდ აქცევს.

## `Multicast`: საერთო მექანიზმი

Rx სამ ოპერატორს გვთავაზობს, რომ წყაროს ერთი გამოწერით რამდენიმე გამომწერი მოვემსახუროთ: **`Publish`**, **`PublishLast`** და **`Replay`**. სამივე `Multicast`-ზეა აგებული, რომელიც მათ საერთო მექანიზმს წარმოადგენს.

`Multicast` ნებისმიერ `IObservable<T>`-ს `IConnectableObservable<T>`-ად აქცევს, რომელიც უბრალოდ `Connect` მეთოდს ამატებს:

```csharp
public interface IConnectableObservable<out T> : IObservable<T>
{
    IDisposable Connect();
}
```

რაკი ის `IObservable<T>`-ის მემკვიდრეა, მასზე `Subscribe`-ს გამოიძახებთ, მაგრამ `Multicast` **ნამდვილ წყაროს არ გამოიწერს** მანამ, სანამ `Connect`-ს არ გამოიძახებთ.

```csharp
IObservable<int> src = Observable.Create<int>(obs =>
{
    Console.WriteLine("Create callback გაეშვა");
    obs.OnNext(1);
    obs.OnNext(2);
    obs.OnCompleted();
    return Disposable.Empty;
});

IConnectableObservable<int> m = src.Multicast(new Subject<int>());

m.Subscribe(x => Console.WriteLine($"Sub1: {x}"));
m.Subscribe(x => Console.WriteLine($"Sub2: {x}"));
m.Subscribe(x => Console.WriteLine($"Sub3: {x}"));

m.Connect();   // მხოლოდ ახლა ხდება ნამდვილი წყაროს ერთადერთი გამოწერა
```

გამოტანა:

```text
Create callback გაეშვა
Sub1: 1
Sub2: 1
Sub3: 1
Sub1: 2
Sub2: 2
Sub3: 2
```

`Create`-ის callback მხოლოდ **ერთხელ** გაეშვა, თუმცა `Subscribe` სამჯერ გამოვიძახეთ. `Multicast` შიგნით `Subject`-ს იყენებს: ნამდვილ წყაროს ის ერთადერთ `IObserver<T>`-ად გადასცემს, და იგივე subject ყველა გამომწერის სიას ინახავს.

## `Publish`, `PublishLast`, `Replay`: სამი subject

სამივე ოპერატორი `Multicast`-ს სხვადასხვა subject-ით იძახებს:

| ოპერატორი | subject | ეფექტი |
|---|---|---|
| **`Publish`** | `Subject<T>` | `Connect`-ის შემდეგ ყოველი ახალი მოვლენა ყველა გამომწერამდე მიდის. გვიან მოსული გამომწერი მხოლოდ **შემდგომ** მოვლენებს ხედავს (`hot`) |
| **`PublishLast`** | `AsyncSubject<T>` | ყველა გამომწერი მხოლოდ **ბოლო** მნიშვნელობას იღებს, გამოწერის დროის მიუხედავად |
| **`Replay`** | `ReplaySubject<T>` | გვიან მოსული გამომწერი ჯერ **გამოტოვებულ** მოვლენებს იღებს (subject მათ ინახავს), შემდეგ კი ახლებს |

```csharp
// Publish: hot; გვიან გამომწერს წარსული აკლდება
IConnectableObservable<long> hot = Observable
    .Interval(TimeSpan.FromSeconds(1)).Take(4)
    .Publish();

// Replay: გვიან მოსული გამომწერი გამოტოვებულსაც მიიღებს
IConnectableObservable<long> replayed = Observable
    .Interval(TimeSpan.FromSeconds(1)).Take(4)
    .Replay();
```

> [!NOTE] `Publish` საწყისი მნიშვნელობით
> `Publish`-ს აქვს გადატვირთვა საწყისი მნიშვნელობით, რომელიც `Subject<T>`-ის ნაცვლად `BehaviorSubject<T>`-ს იყენებს: ყოველი გამომწერი გამოწერისთანავე იღებს **უახლეს** მნიშვნელობას (ან საწყისს, თუ წყაროს ჯერ არაფერი უწარმოებია).

> [!WARNING] `Replay` მეხსიერებას ხარჯავს
> `ReplaySubject<T>` მოვლენებს მეხსიერებაში **ინახავს**. თუ წყარო ბევრ ელემენტს აწარმოებს, ეს პრობლემად იქცევა. `Replay`-ს აქვს გადატვირთვები, სადაც ბუფერის ზომას ან დროის ლიმიტს უთითებთ.

> [!TIP] multicast ერთი მოთხოვნის შიგნით (Zip-ის ხაფანგი)
> თუ ერთსა და იმავე წყაროს მოთხოვნაში **ორჯერ** იყენებთ (მაგალითად, `src.Zip(src.Skip(1))` მეზობელი წყვილებისთვის), ნამდვილი წყარო **ორჯერ** გამოიწერება. ამის ასაცილებლად `Multicast`/`Publish`-ს აქვს გადატვირთვა ფუნქციით: `src.Publish(s => s.Zip(s.Skip(1)))` ერთ გამოწერას უზრუნველყოფს და `Connect` აღარ სჭირდება.
