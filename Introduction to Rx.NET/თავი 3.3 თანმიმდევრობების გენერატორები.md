აქამდე ნანახი ფაბრიკები ან ძალიან მარტივ თანმიმდევრობებს ქმნიდა, ან მთლიანად ჩვენს კოდს ეყრდნობოდა. ახლა ორ მეთოდს განვიხილავთ, რომლებსაც **გრძელი თანმიმდევრობების** წარმოება შეუძლიათ.

## `Observable.Range`

უმარტივესი გენერატორი: აწარმოებს მთელი რიცხვების დიაპაზონს. პირველი არგუმენტი საწყისი მნიშვნელობაა, მეორე კი **რაოდენობა** (და არა დასასრული):

```csharp
IObservable<int> floors = Observable.Range(1, 12);   // 1-დან 12-მდე

floors.Subscribe(
    n => Console.WriteLine($"სართული {n}"),
    () => Console.WriteLine("შენობა დასრულდა"));
```

> [!WARNING] მეორე არგუმენტი რაოდენობაა
> `Observable.Range(10, 15)` **არ** ნიშნავს „10-დან 15-მდე". ის 15 მნიშვნელობას გასცემს, 10-იდან დაწყებულს, ანუ **10-დან 24-მდე**.

## რატომ არ კმარა `Create`

დავუშვათ, `Range`-ის დაწერა `Create`-ით გვინდა:

```csharp
// ✘ არასრულფასოვანი ვარიანტი
IObservable<int> MyRange(int start, int count) =>
    Observable.Create<int>(observer =>
    {
        for (int i = 0; i < count; ++i)
            observer.OnNext(start + i);

        observer.OnCompleted();
        return Disposable.Empty;
    });
```

ეს **იმუშავებს**, მაგრამ **გამოწერის გაუქმებას არ ითვალისწინებს**. პირდაპირი ზიანი არ მოჰყვება, რადგან Rx გაუქმებას ამჩნევს და ზედმეტ მნიშვნელობებს უბრალოდ იგნორირებას გაუკეთებს. მაგრამ პროცესორის დროს მაინც ვხარჯავთ იმაზე, რასაც უკვე აღარავინ უსმენს.

რამდენად ცუდია ეს, დიაპაზონის სიგრძეზეა დამოკიდებული. მაგრამ **წარმოიდგინეთ უსასრულო თანმიმდევრობა**: მარტივი რიცხვები ან ფიბონაჩის მიმდევრობა. `Create`-ით ასეთი წყარო საერთოდ ვერ გაჩერდებოდა, რადგან ჩვენი მარყუჟი მართვას არასდროს დააბრუნებდა.

## `Observable.Generate`

`Generate` სწორედ ამ პრობლემას წყვეტს. ის მარყუჟს **ნაწილებად** შლის და ყოველ ბიჯზე თავად ამოწმებს, ჯერ კიდევ უსმენს თუ არა ვინმე.

```csharp
public static IObservable<TResult> Generate<TState, TResult>(
    TState initialState,                  // საწყისი მდგომარეობა
    Func<TState, bool> condition,         // როდის გავაგრძელოთ
    Func<TState, TState> iterate,         // შემდეგი მდგომარეობა
    Func<TState, TResult> resultSelector) // მდგომარეობიდან შედეგი
```

ოთხი ნაწილი ზუსტად იმას შეესაბამება, რასაც ჩვეულებრივ `for` მარყუჟში ვწერთ:

*ნახაზი 3.3: `Generate`-ის ოთხი არგუმენტი.*

მაგალითად, კვადრატები:

```csharp
IObservable<int> Squares(int upTo) =>
    Observable.Generate(
        1,                  // საწყისი მდგომარეობა
        n => n <= upTo,     // სანამ ეს მართალია, ვაგრძელებთ
        n => n + 1,         // შემდეგი მდგომარეობა
        n => n * n);        // რას ვაქვეყნებთ
```

### უსასრულო თანმიმდევრობა

უსასრულო წყაროს მისაღებად საკმარისია, პირობამ **არასდროს** თქვას „მორჩა". მდგომარეობა შეიძლება რთულიც იყოს, მაგალითად ორეულის სახით:

```csharp
IObservable<BigInteger> Fibonacci() =>
    Observable.Generate(
        (previous: BigInteger.Zero, current: BigInteger.One),
        _ => true,                                   // არასდროს მთავრდება
        s => (s.current, s.previous + s.current),    // წყვილი წინ იწევს
        s => s.current);
```

ასეთი წყარო **სამუდამოდ** გასცემდა მნიშვნელობებს, მაგრამ `Generate` ყოველ ბიჯზე ამოწმებს, ცოცხალია თუ არა გამოწერა, ამიტომ `Dispose`-ის გამოძახებისთანავე ჩერდება.

> [!TIP] მდგომარეობა ნებისმიერი ტიპისაა
> `TState` შეიძლება იყოს რიცხვი, ორეული, ჩანაწერი ან საკუთარი კლასი. სწორედ ეს ხდის `Generate`-ს ასეთ მოქნილს: მასში იმდენი კონტექსტი ჩავტიოთ, რამდენიც შემდეგი ელემენტის გამოსათვლელად გვჭირდება.

> [!IMPORTANT] `Generate` ყოველთვის `cold`-ია
> მდგომარეობა **თითოეული გამოწერისთვის ცალკე** იქმნება. ორი გამომწერი ერთსა და იმავე თანმიმდევრობას მიიღებს, თავიდან დაწყებულს.
