> [!INFO] შეცდომების დამუშავება Rx-ში
> გამონაკლისები გარდაუვალია. ზოგი ჩვენი შეცდომაა (მაგალითად, `DivideByZeroException`), ზოგი კი გარემოზეა დამოკიდებული და თავს ვერ ავარიდებთ (`FileNotFoundException`, `TimeoutException`). `IObserver<T>`-ის `OnError` საშუალებას აძლევს წყაროს, შეცდომა შეგვატყობინოს, მაგრამ ეს **ასრულებს** თანმიმდევრობას და თავისთავად არ გვეუბნება, რა ვქნათ შემდეგ. ამ თავის ოპერატორები სწორედ ამ ხარვეზს ავსებს.

## `Catch`: try/catch-ის ანალოგი

`Catch`-ის სახელი განზრახ მოგვაგონებს C#-ის `try/catch`-ს, რადგან ის Rx-წყაროდან მოსულ შეცდომას მსგავსად ამუშავებს. ორ რეჟიმში მუშაობს:
1. **ფუნქციას გადასცემ**, რომელსაც Rx შეცდომას გადააწვდის; ფუნქცია `IObservable<T>`-ს აბრუნებს და `Catch` ამის შემდეგ მისგან ატარებს ელემენტებს.
2. **სათადარიგო თანმიმდევრობებს გადასცემ**; ყოველ ჩავარდნაზე `Catch` შემდეგზე გადადის.

## გამონაკლისის შემოწმება

გადატვირთვა, რომელიც შეცდომის დამმუშავებელ ფუნქციას იღებს:

```csharp
public static IObservable<TSource> Catch<TSource, TException>(
    this IObservable<TSource> source,
    Func<TException, IObservable<TSource>> handler)
    where TException : Exception;
```

ეს კონცეპტუალურად C#-ის `catch` ბლოკს ჰგავს: შეგვიძლია შევხედოთ შეცდომას და გადავწყვიტოთ, როგორ გავაგრძელოთ. ტიპსაც ვირჩევთ, ისევე როგორც `catch`-ში:

```csharp
// TimeoutException-ზე ცარიელ თანმიმდევრობას ვაბრუნებთ შეცდომის ნაცვლად
IObservable<int> result =
    source.Catch<int, TimeoutException>(_ => Observable.Empty<int>());
```

> [!IMPORTANT] მხოლოდ მითითებული ტიპი იჭერს
> `Catch` ფუნქციას მხოლოდ მაშინ გამოიძახებს, თუ გამონაკლისი **მითითებული ტიპისაა** (ან მისგან მემკვიდრეობითი). სხვა ტიპის შეცდომა **დაუჭერელი** გაივლის გამომწერამდე. `Observable.Empty`-ის დაბრუნება C#-ში გამონაკლისის „ჩაყლაპვის" ტოლფასია: მოსალოდნელ შეცდომაზე ეს გამართლებულია, მაგრამ ბაზისურ `Exception` ტიპზე ამის კეთება ცუდი იდეაა.

შეცდომის **შიგთავსის** მიხედვითაც შეგვიძლია გადაწყვეტა:

```csharp
IObservable<string> result = source.Catch(
    (FileNotFoundException x) => x.FileName == "settings.txt"
        ? Observable.Return(DefaultSettings)
        : Observable.Throw<string>(x));   // დანარჩენს ხელახლა ვისვრით
```

> [!NOTE] `Observable.Throw` = ხელახალი სროლა
> `Observable.Throw<T>(x)`-ის დაბრუნება (სადაც `x` თავდაპირველი შეცდომაა) C#-ის `catch`-ში `throw`-ს ჰგავს. C#-ში `throw;`-სა და `throw x;`-ს შორის მნიშვნელოვანი სხვაობაა (stack trace-ის დაჭერის გამო), მაგრამ Rx-ში `OnError` stack trace-ს არ იჭერს, ამიტომ აქ ეს განსხვავება არ არსებობს.

## Fallback: სათადარიგო წყაროები

`Catch`-ის სხვა გადატვირთვები უფრო „ბრმაა": ერთ ან რამდენიმე დამატებით თანმიმდევრობას გადასცემ, და ყოველ ჩავარდნაზე `Catch` შემდეგზე გადადის. რაკი შეცდომას ვერასდროს ნახავ, ვერ გაიგებ, მოსალოდნელი იყო თუ სრულიად მოულოდნელი, ამიტომ ამ ფორმას ჩვეულებრივ თავს არიდებ.

```csharp
IObservable<string> settings = settingsSource1.Catch(settingsSource2);

// იგივე, params-მასივით ნებისმიერ რაოდენობაზე:
IObservable<string> many = Observable.Catch(source1, source2, source3);
```
