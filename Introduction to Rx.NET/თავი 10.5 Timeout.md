`Timeout` თანმიმდევრობას **შეცდომით ასრულებს**, თუ წყარო მოცემული პერიოდის განმავლობაში საერთოდ არ პასუხობს (არცერთ შეტყობინებას არ გამოსცემს). პერიოდი შეიძლება მიუთითოთ ან მოცურავე ფანჯრად (`TimeSpan`), ან აბსოლუტურ ვადად, რომლამდეც თანმიმდევრობა უნდა დასრულდეს (`DateTimeOffset`).

## მოცურავე ფანჯარა (`TimeSpan`)

თუ `TimeSpan`-ს გადასცემთ და ამ დროში ვერცერთი მნიშვნელობა ვერ გამოვა, თანმიმდევრობა `TimeoutException`-ით სრულდება:

```csharp
var source = Observable.Interval(TimeSpan.FromMilliseconds(100))
    .Take(5)
    .Concat(Observable.Interval(TimeSpan.FromSeconds(2)));

source.Timeout(TimeSpan.FromSeconds(1))
    .Subscribe(
        Console.WriteLine,
        ex => Console.WriteLine($"შეცდომა: {ex.Message}"),
        () => Console.WriteLine("დასრულდა"));
```

თავიდან წყარო ელემენტებს (0-დან 4-მდე) საკმაოდ ხშირად აწარმოებს, ამიტომ `Timeout` მათ უბრალოდ გაატარებს. მაგრამ როგორც კი წყარო ორწამიან პაუზაზე გადადის, ერთწამიანი ლიმიტი გადაცდება და მივიღებთ `OnError`-ს:

```text

1
2
3
4
System.TimeoutException: The operation has timed out.
```

## აბსოლუტური ვადა (`DateTimeOffset`)

აქ მთელი თანმიმდევრობა უნდა **დასრულდეს** მითითებულ მომენტამდე, თორემ შეცდომა დაბრუნდება:

```csharp
var dueDate = DateTimeOffset.UtcNow.AddSeconds(4);

Observable.Interval(TimeSpan.FromSeconds(1))
    .Timeout(dueDate)
    .Subscribe(
        Console.WriteLine,
        ex => Console.WriteLine($"შეცდომა: {ex.Message}"),
        () => Console.WriteLine("დასრულდა"));
```

```text
0
1
2
System.TimeoutException: The operation has timed out.
```

## შეცდომის ნაცვლად სათადარიგო წყარო

`Timeout`-ს აქვს გადატვირთვები, სადაც `TimeoutException`-ის ნაცვლად **ალტერნატიულ თანმიმდევრობაზე** გადაერთვება:

```csharp
IObservable<string> primary = GetLiveFeed();
IObservable<string> fallback = GetCachedFeed();

primary
    .Timeout(TimeSpan.FromSeconds(5), fallback)
    .Subscribe(Console.WriteLine);
```

თუ `primary` ხუთ წამში არ პასუხობს, `Timeout` ჩუმად გადადის `fallback`-ზე შეცდომის სროლის ნაცვლად. ეს გამოგადგებათ, როცა სწრაფი პასუხი (თუნდაც ქეშიდან) ნელი ცოცხალი წყაროს ლოდინს გირჩევნიათ.

> [!TIP] `Timeout` vs `Delay`
> `Delay` თანმიმდევრობას დროში **წინ ანაცვლებს** ([[თავი 10.2 Delay|10.2]]); `Timeout` კი **ლოდინის დროს ზღუდავს** და ერევა, როცა დაყოვნება ზღვარს გადააჭარბებს. ერთი დაყოვნებას ამატებს, მეორე ზედმეტ დაყოვნებას აფიქსირებს.
