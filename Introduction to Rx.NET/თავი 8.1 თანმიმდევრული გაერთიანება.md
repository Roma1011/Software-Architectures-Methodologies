## `Concat`

უკავშირებს ნაკადებს **ერთმანეთის მიყოლებით**: მეორეს გამოიწერს **მხოლოდ მას შემდეგ**, რაც პირველი დასრულდება.

```csharp
IObservable<Reading> all = archived.Concat(live);
```

> [!WARNING] ორი მნიშვნელოვანი შედეგი
> **1. თუ პირველი არასდროს სრულდება, მეორე არასდროს გაეშვება.** `liveData.Concat(somethingElse)` უსასრულო წყაროზე უაზრობაა.
>
> **2. `hot` წყაროსთან ელემენტები იკარგება.** სანამ პირველი მუშაობს, მეორეზე **ჯერ არავინ არის გამოწერილი**, ამიტომ მისი მოვლენები უბრალოდ გაივლის. ეს ნახაზზე „x"-ის დაკარგვით ჩანს.

`Concat`-ს რამდენიმე წყაროც შეუძლია მიიღოს, და `IObservable<IObservable<T>>`-იც:

```csharp
IObservable<int> chained = Observable.Concat(first, second, third);
```

## `StartWith` და `Append`

მარტივი, მაგრამ ხშირად გამოსადეგი: ნაკადის დასაწყისში ან ბოლოში მზა მნიშვნელობების ჩამატება.

```csharp
// ინტერფეისს მაშინვე სჭირდება საწყისი მდგომარეობა
IObservable<Status> withInitial = statusChanges.StartWith(Status.Unknown);

IObservable<int> withFinal = source.Append(-1);
```

> [!TIP] `StartWith` და `BehaviorSubject`
> `StartWith` ხშირად იმავე პრობლემას წყვეტს, რასაც `BehaviorSubject` ([[თავი 3.6 Subject-ები|3.6]]): გამომწერს **მაშინვე** რაღაც უნდა მიეცეს, სანამ ნამდვილი მოვლენა მოვა. თუ საწყისი მნიშვნელობა ცნობილია, `StartWith` უფრო მარტივი და დეკლარაციულია.

## `Repeat`

დასრულების შემდეგ **ხელახლა გამოიწერს** იმავე წყაროს.

```csharp
IObservable<int> threeTimes = source.Repeat(3);
IObservable<int> forever = source.Repeat();
```

> [!IMPORTANT] `Repeat` მხოლოდ `cold` წყაროზეა აზრიანი
> ხელახალი გამოწერა მხოლოდ მაშინ იძლევა რაიმეს, თუ წყარო **თავიდან იწყებს**. `hot` წყაროზე ხელახალი გამოწერა უბრალოდ იმას ნიშნავს, რომ იმავე მიმდინარე ნაკადს ისევ მივუერთდებით.

> [!WARNING] უსასრულო ციკლის საფრთხე
> თუ წყარო **მაშინვე** სრულდება (მაგალითად, `Observable.Empty`), `Repeat()` პროცესორს დაბლოკავს უსასრულო ციკლში. პრაქტიკაში `Repeat` თითქმის ყოველთვის დროით ან რაოდენობით უნდა შეიზღუდოს.

## `Retry`

`Repeat`-ის „ნათესავი": ხელახლა იწყებს არა დასრულების, არამედ **შეცდომის** შემდეგ. ის შეცდომების დამუშავების ოპერატორია და დეტალურად [[თავი 12.3 Retry|12.3]]-შია განხილული.
