`Subject<T>` ერთდროულად **წყაროც არის და დამკვირვებელიც**: ის ერთსა და იმავე დროს ახორციელებს `IObservable<T>`-სა და `IObserver<T>`-ს. ანუ მასზე ხელით შეგვიძლია `OnNext`-ის, `OnError`-ისა და `OnCompleted`-ის გამოძახება, ხოლო ის ამ გამოძახებებს **ყველა გამომწერს გადასცემს**.

```csharp
Subject<string> alerts = new();

alerts.Subscribe(msg => Console.WriteLine($"ლოგი: {msg}"));
alerts.Subscribe(msg => Console.WriteLine($"ეკრანი: {msg}"));

alerts.OnNext("დისკი ივსება");
alerts.OnCompleted();
```

> [!WARNING] Subject-ები ბოლო არჩევანი უნდა იყოს
> `Subject<T>` ყველაზე ადვილად გასაგები ტიპია, და სწორედ ამიტომ **ზედმეტად ხშირად იყენებენ**. ის ფაქტობრივად „საშვია" Rx-ის დეკლარაციული სამყაროდან იმპერატიულ კოდში: მნიშვნელობებს **ხელით** უბიძგებთ, იმის ნაცვლად, რომ წყაროსგან გამომდინარეობდნენ.
>
> სანამ `Subject<T>`-ს გამოიყენებთ, შეამოწმეთ, არ ჯდება თუ არა უკეთ [[თავი 3.5 არსებული ტიპების ადაპტაცია|3.5]]-ის ხიდები ან [[თავი 3.1 საკუთარი წყაროს აგება|3.1]]-ის `Create`. Subject-ები ყველაზე მეტად **ექსპერიმენტებსა და ტესტებში** გამოგადგებათ.

*ნახაზი 3.6: ოთხი Subject და მათი მეხსიერება.*

### `ReplaySubject<T>`

**ყველა** ნანახ მნიშვნელობას იმახსოვრებს. ახალი გამომწერი მთელ ისტორიას მიიღებს, და მხოლოდ შემდეგ განაგრძობს ახალი მოვლენების მიღებას.

> [!WARNING] მეხსიერების საფრთხე
> თუ `ReplaySubject<T>` ყველაფერს იმახსოვრებს, მისი გამოყენება **უსასრულო წყაროებთან დაუშვებელია**: ადრე თუ გვიან მეხსიერება ამოიწურება.

ამიტომ მას ქეშის შეზღუდვის კონსტრუქტორები აქვს:

```csharp
ReplaySubject<int> lastThree = new(bufferSize: 3);                       // ბოლო სამი
ReplaySubject<int> lastMinute = new(window: TimeSpan.FromMinutes(1));    // ბოლო წუთი
```

### `BehaviorSubject<T>`

იმახსოვრებს **ზუსტად ერთ** მნიშვნელობას, მაგრამ ეს არ არის იგივე, რაც ერთბუფერიანი `ReplaySubject<T>`: `BehaviorSubject<T>` **ყოველთვის** ფლობს მნიშვნელობას, ამიტომ საწყისი მნიშვნელობა კონსტრუქტორში უნდა მივაწოდოთ.

```csharp
BehaviorSubject<string> status = new("იწყება");

Console.WriteLine(status.Value);            // ბეჭდავს "იწყება"
status.Subscribe(s => Console.WriteLine(s)); // მაშინვე იღებს მიმდინარე მნიშვნელობას

status.OnNext("მუშაობს");
```

> [!TIP] ეს „observable თვისებაა"
> `BehaviorSubject<T>` შეიძლება წარმოვიდგინოთ როგორც **თვისება, რომელიც ცვლილებებსაც ატყობინებს**. ჩვეულებრივი თვისების მსგავსად, მნიშვნელობას ნებისმიერ მომენტში გვაძლევს (`Value`-ს გავლით), მაგრამ დამატებით ყოველ ცვლილებაზე გვატყობინებს. სწორედ ამიტომ გამოიყენება ის ხშირად ViewModel-ებში.

> [!IMPORTANT] დასრულებისას ანალოგია ირღვევა
> თუ `OnCompleted`-ს გამოიძახებთ, ყველა გამომწერი მაშინვე დასრულდება, და **ახალი გამომწერიც პირდაპირ დასრულებას მიიღებს**: ბოლო მნიშვნელობა მას აღარ მიეწოდება. იგივე ეხება `OnError`-ს.

### `AsyncSubject<T>`

გამომწერებს **მხოლოდ ბოლო** მნიშვნელობას აწვდის. რაკი მას ვერ ეცოდინება, რომელია ბოლო, სანამ `OnCompleted` არ გამოიძახება, ის **არაფერს გასცემს დასრულებამდე**.

```csharp
AsyncSubject<int> result = new();

result.Subscribe(x => Console.WriteLine($"შედეგი: {x}"));

result.OnNext(1);
result.OnNext(2);
result.OnNext(3);
result.OnCompleted();        // მხოლოდ აქ დაიბეჭდება "შედეგი: 3"
```

თუ `OnCompleted`-მდე `OnNext` საერთოდ არ გამოძახებულა, ბოლო მნიშვნელობა არ არსებობს და გამომწერები უბრალოდ დასრულდებიან.

> [!NOTE] სად ხვდებით მას ირიბად
> `AsyncSubject<T>`-ს ხშირად პირდაპირ არ იყენებთ, მაგრამ ის **`await`-თან Rx-ის ინტეგრაციის საფუძველია**: როცა observable თანმიმდევრობას `await`-ავთ, შედეგად მისი **ბოლო** მნიშვნელობა გიბრუნდებათ ([[თავი 11.1 async და await-თან ინტეგრაცია|11.1]]).

## შეჯამების ცხრილი

| ტიპი | რას იმახსოვრებს | როდის გასცემს | ტიპური გამოყენება |
|---|---|---|---|
| `Subject<T>` | არაფერს | მაშინვე | მარტივი მაუწყებლობა, ტესტები |
| `ReplaySubject<T>` | ისტორიას (შეზღუდვადს) | მაშინვე + ისტორია | გვიან მოსული გამომწერები |
| `BehaviorSubject<T>` | ბოლო მნიშვნელობას | მაშინვე, ყოველთვის | მიმდინარე მდგომარეობა, ViewModel |
| `AsyncSubject<T>` | ბოლო მნიშვნელობას | **მხოლოდ დასრულებისას** | ერთჯერადი შედეგი, `await` |
