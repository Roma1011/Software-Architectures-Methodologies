
წინა თავში თქვენ ისწავლეთ **domain model pattern-ის შესახებ**: მისი **building blocks**, მიზანი და გამოყენების კონტექსტი.

**Event-sourced domain model pattern** ეფუძნება **იგივე საფუძველს**, რასაც domain model pattern.

ისევ, **ბიზნეს ლოგიკა არის კომპლექსური და ეკუთვნის core subdomain-ს**.

გარდა ამისა, ის იყენებს **იგივე tactical patterns-ს**, რასაც domain model:

- **value objects**
- **aggregates**
- **domain events**

ამ იმპლემენტაციის პატერნებს შორის განსხვავება მდგომარეობს **იმაში, თუ როგორ ინახება aggregate-ის მდგომარეობა (state)**.

**Event-sourced domain model** იყენებს **event sourcing pattern-ს**, რათა მართოს aggregate-ის მდგომარეობა.

**aggregate-ის მდგომარეობის შენახვის ნაცვლად**, მოდელი **აგენერირებს domain events-ს**, რომლებიც აღწერს **თითოეულ ცვლილებას**, და იყენებს მათ **როგორც truth-ის წყაროს (source of truth) aggregate-ის მონაცემებისთვის**.

ეს თავი იწყება **event sourcing-ის ცნების წარმოდგენით**.

შემდეგ ის განიხილავს, **როგორ შეიძლება event sourcing-ის გაერთიანება domain model pattern-თან**, რის შედეგადაც მივიღებთ **event-sourced domain model-ს**.
