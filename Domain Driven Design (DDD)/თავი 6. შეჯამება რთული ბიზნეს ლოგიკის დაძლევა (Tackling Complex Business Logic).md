
**Domain model pattern** მიმართულია იმ შემთხვევებისთვის, სადაც არსებობს **კომპლექსური ბიზნეს ლოგიკა**.

ის შედგება **სამი ძირითადი building block-ისგან**:

---
## Value objects

ბიზნეს დომენის კონცეფციები, რომლებიც შეიძლება **იდენტიფიცირდეს მხოლოდ მათი მნიშვნელობებით** და ამიტომ **არ საჭიროებენ explicit ID ველს**.

რადგან **ერთ-ერთი ველის ცვლილება სემანტიკურად ქმნის ახალ მნიშვნელობას**, value objects არიან **immutable**.

value objects მოდელირებენ არა მხოლოდ **მონაცემებს**, არამედ **ქცევასაც**:  
მეთოდებს, რომლებიც **მანიპულირებენ მნიშვნელობებით და შედეგად ინიციალიზებენ ახალ value objects-ს**.


---

## Aggregates

**Entities-ის იერარქია**, რომლებიც იზიარებენ **ერთ ტრანზაქციულ საზღვარს**.

aggregate-ის საზღვარში არსებული **ყველა მონაცემი უნდა იყოს strongly consistent**, რათა შესაძლებელი იყოს მისი **ბიზნეს ლოგიკის იმპლემენტაცია**.

aggregate-ის მდგომარეობა, და მისი **შიდა ობიექტების მდგომარეობაც**, შეიძლება შეიცვალოს **მხოლოდ მისი public interface-ის საშუალებით**, aggregate-ის **commands-ის შესრულებით**.

მონაცემთა ველები **read-only არის გარე კომპონენტებისთვის**, იმის უზრუნველსაყოფად, რომ aggregate-სთან დაკავშირებული **ყველა ბიზნეს ლოგიკა განთავსდეს მის საზღვრებში**.

aggregate მოქმედებს როგორც **ტრანზაქციული საზღვარი**.

მისი **ყველა მონაცემი**, მათ შორის **მისი შიდა ობიექტებიც**, უნდა დაიკომიტოს მონაცემთა ბაზაში **როგორც ერთი ატომური ტრანზაქცია**.

aggregate შეუძლია **გარე entity-ებთან კომუნიკაცია domain events-ის გამოქვეყნებით** შეტყობინებები, რომლებიც აღწერს **მნიშვნელოვან ბიზნეს მოვლენებს aggregate-ის lifecycle-ში**.

სხვა კომპონენტებს შეუძლიათ **გამოიწერონ ეს მოვლენები და გამოიყენონ ისინი ბიზნეს ლოგიკის შესრულების ტრიგერად**.

---
## Domain services

**Stateless ობიექტი**, რომელიც შეიცავს **ბიზნეს ლოგიკას**, რომელიც ბუნებრივად **არ ეკუთვნის domain model-ის არცერთ aggregate-ს ან value object-ს**.

Domain model-ის **building blocks** უმკლავდება ბიზნეს ლოგიკის სირთულეს იმით, რომ **ენკაფსულირებს მას value objects-ისა და aggregates-ის საზღვრებში**.

ობიექტების მდგომარეობის **გარედან შეცვლის შეუძლებლობა უზრუნველყოფს**, რომ ყველა შესაბამისი ბიზნეს ლოგიკა **იმპლემენტირებული იყოს aggregates-ისა და value objects-ის საზღვრებში** და **არ დუბლირდეს application layer-ში**.
