# Testing Pyramid

კლასიკური **testing pyramid** დიდ ყურადღებას ამახვილებს:

- **unit tests-ზე**
- შედარებით ნაკლებ **integration tests-ზე**
- და კიდევ უფრო ნაკლებ **end-to-end tests-ზე**.

**Domain model pattern-ის ორივე ვარიანტი** საუკეთესოდ შეესაბამება **testing pyramid-ს**.

**Aggregates** და **value objects** წარმოადგენენ **იდეალურ unit-ებს ბიზნეს ლოგიკის ეფექტური ტესტირებისთვის**.

---
# Testing Diamond

**Testing diamond** ყველაზე დიდ ყურადღებას ამახვილებს **integration tests-ზე**.

როდესაც გამოიყენება **active record pattern**, სისტემის **business logic განსაზღვრის მიხედვით გადანაწილებულია როგორც service layer-ში, ასევე business logic layer-ში**.

ამიტომ, **ამ ორი layer-ის ინტეგრაციაზე ფოკუსირებისთვის**, **testing diamond უფრო ეფექტური არჩევანია**.

---

# Reversed Testing Pyramid

**Reversed testing pyramid** ყველაზე დიდ ყურადღებას უთმობს **end-to-end tests-ს**:

ანუ **აპლიკაციის workflow-ის შემოწმებას თავიდან ბოლომდე**.

ასეთი მიდგომა საუკეთესოდ შეესაბამება **კოდბეისებს, რომლებიც იყენებენ transaction script pattern-ს**.

ამ შემთხვევაში:

- ბიზნეს ლოგიკა **მარტივია**
- layer-ების რაოდენობა **მინიმალურია**

რაც უფრო ეფექტურს ხდის **სისტემის end-to-end flow-ის შემოწმებას**.
