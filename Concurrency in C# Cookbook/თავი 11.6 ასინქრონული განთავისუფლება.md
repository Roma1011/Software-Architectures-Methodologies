## პრობლემა

გაქვთ ტიპი, რომელსაც ასინქრონული ოპერაციები აქვს, მაგრამ ასევე რესურსების **განთავისუფლების (disposal)** საშუალებაც სჭირდება.

## გადაწყვეტა

ეგზემპლარის განთავისუფლებისას არსებულ ოპერაციებთან გასამკლავებლად ორი გავრცელებული ვარიანტია:

1. განთავისუფლება **გაუქმების მოთხოვნად** მივიჩნიოთ, რომელიც ყველა არსებულ ოპერაციაზე გავრცელდება;
2. ნამდვილი **ასინქრონული განთავისუფლება** განვახორციელოთ.

### ვარიანტი 1: განთავისუფლება = გაუქმება

განთავისუფლების გაუქმებად მიჩნევას Windows-ზე ისტორიული პრეცედენტი აქვს: ფაილის ნაკადებისა და სოკეტების მსგავსი ტიპები დახურვისას აუქმებს ყველა არსებულ კითხვასა თუ წერას. საკუთარი **კერძო** `CancellationTokenSource`-ის განსაზღვრითა და ამ token-ის შიდა ოპერაციებზე გადაცემით, .NET-ში ძალიან მსგავს რამეს გავაკეთებთ. ქვემოთ `Dispose` **გააუქმებს** ოპერაციებს, მაგრამ მათ დასრულებას **არ დაელოდება**:

```csharp
class MyClass : IDisposable
{
    private readonly CancellationTokenSource _disposeCts =
        new CancellationTokenSource();

    public async Task<int> CalculateValueAsync()
    {
        await Task.Delay(TimeSpan.FromSeconds(2), _disposeCts.Token);
        return 13;
    }

    public void Dispose()
    {
        _disposeCts.Cancel();
    }
}
```

ეს კოდი `Dispose`-ის ძირითად შაბლონს აჩვენებს. ნამდვილ აპლიკაციაში უნდა დაამატოთ შემოწმებები, რომ ობიექტი უკვე განთავისუფლებული არ არის, და მომხმარებელს საკუთარი `CancellationToken`-ის მიწოდების საშუალებაც მისცეთ ([[თავი 10.8 გაუქმების მოთხოვნების ინექცია|10.8]]-ის ტექნიკით):

```csharp
public async Task<int> CalculateValueAsync(CancellationToken cancellationToken)
{
    using CancellationTokenSource combinedCts = CancellationTokenSource
        .CreateLinkedTokenSource(cancellationToken, _disposeCts.Token);

    await Task.Delay(TimeSpan.FromSeconds(2), combinedCts.Token);
    return 13;
}
```

გამომძახებელ კოდს `Dispose`-ის გამოძახებისას ყველა არსებული ოპერაცია გაუუქმდება:

```csharp
async Task UseMyClassAsync()
{
    Task<int> task;
    using (var resource = new MyClass())
    {
        task = resource.CalculateValueAsync(default);
    }

    // ისვრის OperationCanceledException-ს.
    var result = await task;
}
```

ზოგიერთი ტიპისთვის `Dispose`-ის გაუქმების მოთხოვნად განხორციელება კარგად მუშაობს (მაგალითად, `HttpClient`-ს სწორედ ასეთი სემანტიკა აქვს). თუმცა სხვა ტიპებს უნდა იცოდნენ, **როდის დასრულდა ყველა ოპერაცია**. მათთვის ასინქრონული განთავისუფლებაა საჭირო.

### ვარიანტი 2: `IAsyncDisposable`

ასინქრონული განთავისუფლება C# 8.0-სა და .NET Core 3.0-ში შემოვიდა. BCL-მა შემოიტანა ახალი **`IAsyncDisposable`** ინტერფეისი, რომელიც `IDisposable`-ის ასინქრონული ეკვივალენტია. ენამ ამავე დროს შემოიტანა **`await using`** ოპერატორი, რომელიც `using`-ის ასინქრონული ეკვივალენტია:

```csharp
class MyClass : IAsyncDisposable
{
    public async ValueTask DisposeAsync()
    {
        await Task.Delay(TimeSpan.FromSeconds(2));
    }
}
```

`DisposeAsync`-ის დასაბრუნებელი ტიპი **`ValueTask`**-ია და არა `Task`, მაგრამ სტანდარტული `async` და `await` საკვანძო სიტყვები `ValueTask`-თან ისევე კარგად მუშაობს, როგორც `Task`-თან.

`IAsyncDisposable`-ის განმახორციელებელი ტიპები, როგორც წესი, `await using`-ით მოიხმარება:

```csharp
await using (var myClass = new MyClass())
{
    // ...
} // DisposeAsync აქ გამოიძახება (და მას ელოდებიან).
```

თუ `ConfigureAwait(false)`-ით კონტექსტის არიდება გჭირდებათ, ესეც შესაძლებელია, მაგრამ ცოტა უხერხულია, რადგან ცვლადი `await using`-ის **გარეთ** უნდა გამოაცხადოთ:

```csharp
var myClass = new MyClass();
await using (myClass.ConfigureAwait(false))
{
    // ...
} // DisposeAsync აქ გამოიძახება ConfigureAwait(false)-ით.
```

## განხილვა

ასინქრონული განთავისუფლება ნამდვილად უფრო ადვილია, ვიდრე `Dispose`-ის გაუქმების მოთხოვნად განხორციელება, და უფრო რთული მიდგომა მხოლოდ მაშინ უნდა გამოიყენოთ, როცა ის მართლა გჭირდებათ. სინამდვილეში, დროის უმეტეს ნაწილში **საერთოდ არაფრის განთავისუფლებით** გამოძვრებით, რაც, რა თქმა უნდა, ყველაზე ადვილი მიდგომაა, რადგან არაფრის გაკეთება არ გიწევთ.

ამ რეცეპტს განთავისუფლების ორი შაბლონი აქვს, და **ორივეს** გამოყენებაც შესაძლებელია. ორივეს გამოყენება თქვენს ტიპს `await using`-ისას სუფთა შეჩერების სემანტიკას მისცემდა, ხოლო `Dispose`-ისას „გაუქმებისას". ავტორი ამას ზოგადად არ გირჩევთ, მაგრამ ეს ვარიანტია.

> [!TIP] `await foreach` და `IAsyncDisposable`
> `await foreach` მარყუჟი ასინქრონული ნაკადის ჩამთვლელს ავტომატურად ასინქრონულად ათავისუფლებს. სწორედ ამიტომ მუშაობს `try`/`finally` სწორად ასინქრონულ იტერატორებში ([[თავი 3.1 ასინქრონული ნაკადების შესავალი|3.1]]).

> [!NOTE] DI კონტეინერები და `IAsyncDisposable`
> თანამედროვე DI კონტეინერები (მაგალითად, `Microsoft.Extensions.DependencyInjection`) `IAsyncDisposable`-ს იცნობს, მაგრამ მხოლოდ მაშინ იძახებს `DisposeAsync`-ს, თუ scope თავად ასინქრონულად განთავისუფლდა (`await serviceProvider.DisposeAsync()`). სინქრონული `Dispose()` სერვისზე, რომელიც მხოლოდ `IAsyncDisposable`-ია, **გამონაკლისს ისვრის**.
