## პრობლემა

dataflow ბადეებს იყენებთ და გაუქმების მხარდაჭერა გჭირდებათ.

## გადაწყვეტა

კოდში გაუქმების მხარდაჭერის საუკეთესო გზაა `CancellationToken`-ის გაუქმებად API-ზე გადაცემა. dataflow ბადის **ყოველი ბლოკი** უჭერს მხარს გაუქმებას თავისი `DataflowBlockOptions`-ის ნაწილად. თუ საკუთარ dataflow ბლოკს გაუქმების მხარდაჭერით გინდათ გააფართოვოთ, ბლოკის პარამეტრებში `CancellationToken` თვისება დააყენეთ:

```csharp
IPropagatorBlock<int, int> CreateMyCustomBlock(
    CancellationToken cancellationToken)
{
    var blockOptions = new ExecutionDataflowBlockOptions
    {
        CancellationToken = cancellationToken
    };

    var multiplyBlock = new TransformBlock<int, int>(item => item * 2,
        blockOptions);
    var addBlock = new TransformBlock<int, int>(item => item + 2,
        blockOptions);
    var divideBlock = new TransformBlock<int, int>(item => item / 2,
        blockOptions);

    var flowCompletion = new DataflowLinkOptions
    {
        PropagateCompletion = true
    };
    multiplyBlock.LinkTo(addBlock, flowCompletion);
    addBlock.LinkTo(divideBlock, flowCompletion);

    return DataflowBlock.Encapsulate(multiplyBlock, divideBlock);
}
```

ამ მაგალითში `CancellationToken` ბადის **ყოველ** ბლოკზეა გამოყენებული, რაც მკაცრად აუცილებელი არ არის. რადგან დასრულებაც ვრცელდება ბმულებზე, შეიძლებოდა ის მხოლოდ **პირველ** ბლოკზე გამოგვეყენებინა და დანარჩენებზე გავრცელებას დავლოდებოდით. გაუქმება შეცდომის განსაკუთრებულ ფორმად ითვლება, ამიტომ მილსადენში ქვემოთ მყოფი ბლოკები **შეცდომით** დასრულდებოდნენ ამ შეცდომის გავრცელებისას. თუმცა, თუ ბადეს ვაუქმებ, შეიძლება ყველა ბლოკი **ერთდროულად** გავაუქმო, ამიტომ ამ შემთხვევაში ავტორი ჩვეულებრივ `CancellationToken` პარამეტრს ყველა ბლოკზე აყენებს.

## განხილვა

> [!WARNING] გაუქმება არ არის „გამორეცხვა (flush)"
> dataflow ბადეებში გაუქმება **გამორეცხვის ფორმა არ არის**. როცა ბლოკი უქმდება, ის **მთელ თავის შესავალს აგდებს** და უარს ამბობს ახალი ელემენტების მიღებაზე. ასე რომ, თუ ბლოკს მუშაობის დროს გააუქმებთ, **მონაცემებს დაკარგავთ**.

თუ დარჩენილი ელემენტების დამუშავება გჭირდებათ და მხოლოდ ახლების მიღება არ გინდათ, გაუქმების ნაცვლად `Complete()` გამოიყენეთ და `Completion`-ს დაელოდეთ: ეს ბადეს **სუფთად** ასრულებს.

| მოქმედება | რიგში დარჩენილი ელემენტები | ახალი ელემენტები |
|---|---|---|
| `block.Complete()` | დამუშავდება | არ მიიღება |
| `cts.Cancel()` | **გადაიგდება** | არ მიიღება |
| `block.Fault(ex)` | **გადაიგდება** | არ მიიღება |

> [!TIP] `Encapsulate`-ის შემდეგ
> `DataflowBlock.Encapsulate` მხოლოდ პირველსა და ბოლო ბლოკს აერთიანებს ერთ ინტერფეისში. შუა ბლოკები დანარჩენ სამყაროს არ უჩანს, ამიტომ მათზე token-ის ხელით დაყენება (ან დასრულების გავრცელება) სწორედ ბადის ავტორის პასუხისმგებლობაა ([[თავი 5.6 საკუთარი ბლოკების შექმნა|5.6]]).
