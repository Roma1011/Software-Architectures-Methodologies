## პრობლემა

გაქვთ მდგომარეობის ცვლადები, რომლებზეც წვდომა **გამოძახების სტეკის სხვადასხვა წერტილში** გჭირდებათ. მაგალითად, გაქვთ მიმდინარე ოპერაციის იდენტიფიკატორი, რომელიც ლოგირებისთვის გინდათ გამოიყენოთ, მაგრამ არ გინდათ, ის **ყოველ მეთოდს** პარამეტრად დაამატოთ.

## გადაწყვეტა

> [!IMPORTANT] ჯერ სხვა გზები განიხილეთ
> საუკეთესო გადაწყვეტაა, **პარამეტრები დაამატოთ** მეთოდებს, მონაცემები **კლასის წევრებად** შეინახოთ, ან **დამოკიდებულებების ინექცია** გამოიყენოთ. თუმცა ზოგიერთ სიტუაციაში ეს კოდს ზედმეტად გაართულებდა.

**`AsyncLocal<T>`** ტიპი საშუალებას გვაძლევს, მდგომარეობას ობიექტი მივცეთ, სადაც ის **ლოგიკურ „კონტექსტში"** იცოცხლებს:

```csharp
private static AsyncLocal<Guid> _operationId = new AsyncLocal<Guid>();

async Task DoLongOperationAsync()
{
    _operationId.Value = Guid.NewGuid();

    await DoSomeStepOfOperationAsync();
}

async Task DoSomeStepOfOperationAsync()
{
    await Task.Delay(100); // რაღაც ასინქრონული სამუშაო

    // აქ ლოგირება.
    Trace.WriteLine("ოპერაციაში: " + _operationId.Value);
}
```

### რთული მდგომარეობა: უცვლელი სტეკი

ხშირად სასარგებლოა ერთ `AsyncLocal<T>` ეგზემპლარში უფრო რთული მონაცემთა სტრუქტურა (მაგალითად, მნიშვნელობების სტეკი). ეს შესაძლებელია, ერთი გაფრთხილებით:

> [!WARNING] მხოლოდ უცვლელი მონაცემები
> `AsyncLocal<T>`-ში **მხოლოდ უცვლელი (immutable)** მონაცემები უნდა შეინახოთ. როცა მონაცემების განახლება გჭირდებათ, არსებული მნიშვნელობა **მთლიანად უნდა გადააწეროთ**.

ხშირად გამოსადეგია `AsyncLocal<T>`-ის დამხმარე ტიპში დამალვა, რომელიც უზრუნველყოფს, რომ შენახული მონაცემები უცვლელია და სწორად ახლდება:

```csharp
internal sealed class AsyncLocalGuidStack
{
    private readonly AsyncLocal<ImmutableStack<Guid>> _operationIds =
        new AsyncLocal<ImmutableStack<Guid>>();

    private ImmutableStack<Guid> Current =>
        _operationIds.Value ?? ImmutableStack<Guid>.Empty;

    public IDisposable Push(Guid value)
    {
        _operationIds.Value = Current.Push(value);
        return new PopWhenDisposed(this);
    }

    private void Pop()
    {
        ImmutableStack<Guid> newValue = Current.Pop();
        if (newValue.IsEmpty)
            newValue = null;
        _operationIds.Value = newValue;
    }

    public IEnumerable<Guid> Values => Current;

    private sealed class PopWhenDisposed : IDisposable
    {
        private AsyncLocalGuidStack _stack;

        public PopWhenDisposed(AsyncLocalGuidStack stack) =>
            _stack = stack;

        public void Dispose()
        {
            _stack?.Pop();
            _stack = null;
        }
    }
}
```

გამოყენება:

```csharp
private static AsyncLocalGuidStack _operationIds = new AsyncLocalGuidStack();

async Task DoLongOperationAsync()
{
    using (_operationIds.Push(Guid.NewGuid()))
        await DoSomeStepOfOperationAsync();
}

async Task DoSomeStepOfOperationAsync()
{
    await Task.Delay(100); // რაღაც ასინქრონული სამუშაო

    // აქ ლოგირება.
    Trace.WriteLine("ოპერაციაში: " +
        string.Join(":", _operationIds.Values));
}
```

გარსი-ტიპი უზრუნველყოფს, რომ ქვემდებარე მონაცემები უცვლელია და ახალი მნიშვნელობები სტეკზე იწყობა. ის ასევე მოსახერხებელ `IDisposable` გზას გვთავაზობს მნიშვნელობების სტეკიდან მოსახსნელად.

## განხილვა

ძველი კოდი შეიძლება **`ThreadStatic`** ატრიბუტს იყენებდეს სინქრონული კოდის კონტექსტური მდგომარეობისთვის. ძველი კოდის ასინქრონულად გადაყვანისას **`AsyncLocal<T>` `ThreadStaticAttribute`-ის მთავარი ჩამნაცვლებელია**. `AsyncLocal<T>` სინქრონულ და ასინქრონულ კოდში ერთნაირად მუშაობს, და თანამედროვე აპლიკაციებში იმპლიციტური მდგომარეობისთვის **ნაგულისხმევი არჩევანი** უნდა იყოს.

> [!IMPORTANT] მიმართულება მხოლოდ „ქვემოთ"
> `AsyncLocal<T>`-ის მნიშვნელობა **გამოძახების სტეკში ქვემოთ** მიედინება (გამომძახებლიდან გამოძახებულზე). თუ მნიშვნელობას **გამოძახებულ** მეთოდში შეცვლით, ეს ცვლილება **გამომძახებელს არ დაუბრუნდება**: ყოველი ასინქრონული ოპერაცია მდგომარეობის საკუთარ „კოპიო-ჩაწერისას" ასლს იღებს. სწორედ ამიტომ არის `using`-ის შაბლონი ზემოთ ასე მოწყობილი.

> [!TIP] პრაქტიკული გამოყენება
> `AsyncLocal<T>` არის ის, რაზეც აგებულია ASP.NET Core-ის `HttpContextAccessor`, `Activity.Current` (OpenTelemetry-ის ტრეისინგი) და ლოგირების ბიბლიოთეკების „scope"-ები. ანუ თქვენ, სავარაუდოდ, უკვე იყენებთ მას, თუნდაც არაპირდაპირ.
