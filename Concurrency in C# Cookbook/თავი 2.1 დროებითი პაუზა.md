> ეს თავი `async`/`await`-ის საფუძვლებს ეხება. აქ მხოლოდ **ბუნებრივად ასინქრონულ** ოპერაციებზეა საუბარი: HTTP მოთხოვნები, ბაზის ბრძანებები, ვებ-სერვისების გამოძახებები.

## პრობლემა

გჭირდებათ გარკვეული დროით **ასინქრონული** ლოდინი. ეს ხშირად გვჭირდება ერთეულოვან ტესტებში, ხელახალ მცდელობებს შორის დაყოვნების ჩასამატებლად და მარტივი timeout-ების დასაწერად.

## გადაწყვეტა

`Task` ტიპს აქვს სტატიკური მეთოდი **`Delay`**, რომელიც აბრუნებს task-ს, რომელიც მითითებული დროის შემდეგ სრულდება.

### ასინქრონული ოპერაციის იმიტაცია

როცა ასინქრონულ ოპერაციას ვიმიტირებთ, მნიშვნელოვანია სამივე შემთხვევის შემოწმება: **სინქრონული წარმატება**, **ასინქრონული წარმატება** და **ასინქრონული შეცდომა**. ქვემოთ მოცემული მაგალითი ასინქრონულ წარმატებას იმიტირებს:

```csharp
async Task<T> DelayResult<T>(T result, TimeSpan delay)
{
    await Task.Delay(delay);
    return result;
}
```

### ექსპონენციური უკუსვლა (exponential backoff)

**ექსპონენციური უკუსვლა** სტრატეგიაა, სადაც ყოველი ხელახალი მცდელობის წინ დაყოვნება ორმაგდება. ის ვებ-სერვისებთან მუშაობისას გამოგვადგება: თუ სერვისი ისედაც გადატვირთულია, ზედიზედ მცდელობები მას მხოლოდ დაამძიმებს.

```csharp
async Task<string> DownloadStringWithRetries(HttpClient client, string uri)
{
    // ჯერ 1 წამის შემდეგ, მერე 2 წამის, მერე 4 წამის შემდეგ
    TimeSpan nextDelay = TimeSpan.FromSeconds(1);
    for (int i = 0; i != 3; ++i)
    {
        try
        {
            return await client.GetStringAsync(uri);
        }
        catch
        {
        }

        await Task.Delay(nextDelay);
        nextDelay = nextDelay + nextDelay;
    }

    // ბოლო მცდელობა: აქ უკვე შეცდომა თავისუფლად გავრცელდეს
    return await client.GetStringAsync(uri);
}
```

### მარტივი timeout `Task.Delay`-ით

`Task.Delay`-ით მარტივი timeout-იც კეთდება. იდეა ისაა, რომ **ორ task-ს ერთმანეთს ვაჯიბრებთ**: ერთი ნამდვილი ოპერაციაა, მეორე კი ტაიმერი. რომელიც ადრე დასრულდება, ის გვეუბნება, რა მოხდა.

ტაიმერად უმარტივესი ვარიანტი იქნებოდა `Task.Delay(TimeSpan.FromSeconds(3))`. მაგრამ თუ ჩამოტვირთვა ერთ წამში მორჩა, ასეთი ტაიმერი მაინც განაგრძობს მუშაობას დარჩენილი ორი წამის განმავლობაში. ამის ასარიდებლად `CancellationTokenSource`-ს ვიყენებთ ([[თავი 10.3 გაუქმება timeout-ის გამო|10.3]]):

- **`new CancellationTokenSource(TimeSpan.FromSeconds(3))`** თავისით გაუქმდება სამ წამში;
- **`Task.Delay(Timeout.InfiniteTimeSpan, cts.Token)`** ჩვეულებრივ სამუდამოდ იცდიდა, მაგრამ token-ის გაუქმებისთანავე **მთავრდება**. ანუ ეს ზუსტად ის task-ია, რომელიც სამ წამში სრულდება;
- **`using`**-ის წყალობით, როცა მეთოდი დასრულდება, `cts` განთავისუფლდება და ტაიმერიც მაშინვე ითიშება, მაშინაც კი, თუ ჩამოტვირთვა ადრე მორჩა.

ბოლოს `Task.WhenAny` გვეუბნება, რომელი დასრულდა პირველი ([[თავი 2.5 ნებისმიერი Task-ის დასრულების ლოდინი|2.5]]):

```csharp
async Task<string> DownloadStringWithTimeout(HttpClient client, string uri)
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(3));

    Task<string> downloadTask = client.GetStringAsync(uri);
    Task timeoutTask = Task.Delay(Timeout.InfiniteTimeSpan, cts.Token);

    Task completedTask = await Task.WhenAny(downloadTask, timeoutTask);
    if (completedTask == timeoutTask)
        return null;

    return await downloadTask;
}
```

> [!WARNING] ეს timeout ოპერაციას არ აჩერებს
> თუ timeout ამოიწურა, ოპერაცია **არ უქმდება**: ზემოთ მოცემულ მაგალითში ჩამოტვირთვა გრძელდება და პასუხს ბოლომდე ჩამოტვირთავს, თუმცა ეს პასუხი უკვე აღარავის სჭირდება.
>
> უკეთესია, **გაუქმების token** პირდაპირ ოპერაციას გადავცეთ (`GetStringAsync`-ს), რომ ის მართლა შეწყდეს. მაგრამ ზოგი ოპერაცია გაუქმებას საერთოდ არ უჭერს მხარს, და სწორედ ასეთ შემთხვევაში გვაძლევს `Task.Delay` საშუალებას, კოდმა ისე მოიქცეს, თითქოს დრო ამოიწურა.

## განხილვა

`Task.Delay` კარგად გამოდგება ასინქრონული კოდის ტესტირებისთვისა და ხელახალი მცდელობების ლოგიკისთვის. timeout-ისთვის კი, როგორც წესი, `CancellationToken` სჯობს, რადგან ის ოპერაციას მართლა აჩერებს და არა მხოლოდ ლოდინს.

> [!NOTE] თანამედროვე .NET
> - **`PeriodicTimer`** (.NET 6) პერიოდული ამოცანებისთვის `Task.Delay`-ის ციკლს სჯობს: ის დროის „დრეიფს" (drift) არიდებს თავს.
> - **`Task.WaitAsync(TimeSpan)`** (.NET 6) ზემოთ ნაჩვენებ `WhenAny` + `Delay` ნიმუშს ერთ გამოძახებად აქცევს: `await downloadTask.WaitAsync(TimeSpan.FromSeconds(3));` timeout-ის შემთხვევაში `TimeoutException`-ს ისვრის.
> - **`Task.Delay`-ის სიზუსტე** სისტემის ტაიმერზეა დამოკიდებული: ის მითითებულ დროზე **ნაკლებს არასოდეს** დაელოდება, მაგრამ ცოტა მეტს შეიძლება.
