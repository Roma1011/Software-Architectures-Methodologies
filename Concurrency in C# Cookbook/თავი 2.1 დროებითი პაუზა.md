## პრობლემა

გჭირდებათ გარკვეული დროით **ასინქრონული** ლოდინი. ეს ხშირია ერთეულოვან ტესტებში, ხელახალი მცდელობების (retry) დაყოვნების იმპლემენტაციისას და მარტივი timeout-ების წერისას.

## გადაწყვეტა

`Task` ტიპს აქვს სტატიკური მეთოდი **`Delay`**, რომელიც აბრუნებს task-ს, რომელიც მითითებული დროის შემდეგ სრულდება.

### ასინქრონული ოპერაციის იმიტაცია

ასინქრონული ოპერაციის „გაყალბებისას" მნიშვნელოვანია, ვტესტოთ სინქრონული წარმატება, ასინქრონული წარმატება **და** ასინქრონული წარუმატებლობა. ეს მაგალითი ასინქრონული წარმატების შემთხვევას აბრუნებს:

```csharp
async Task<T> DelayResult<T>(T result, TimeSpan delay)
{
    await Task.Delay(delay);
    return result;
}
```

### ექსპონენციალური უკუსვლა (exponential backoff)

**ექსპონენციალური უკუსვლა** სტრატეგიაა, სადაც ხელახალ მცდელობებს შორის დაყოვნება იზრდება. ის ვებ-სერვისებთან მუშაობისას გამოგვადგება, რომ სერვერს მცდელობების ნიაღვარი არ დავატეხოთ:

```csharp
async Task<string> DownloadStringWithRetries(HttpClient client, string uri)
{
    // ჯერ 1 წამის შემდეგ, მერე 2 წამის, მერე 4 წამის შემდეგ
    TimeSpan nextDelay = TimeSpan.FromSeconds(1);
    for (int i = 0; i != 3; ++i)
    {
        try
        {
            return await client.GetStringAsync(uri);
        }
        catch
        {
        }

        await Task.Delay(nextDelay);
        nextDelay = nextDelay + nextDelay;
    }

    // ბოლო მცდელობა: შეცდომას გავრცელების უფლებას ვაძლევთ
    return await client.GetStringAsync(uri);
}
```

### „რბილი" timeout

`Task.Delay` შეიძლება მარტივ timeout-ადაც გამოვიყენოთ. Timeout-ის ჩვეულებრივი საშუალება `CancellationTokenSource`-ია ([[თავი 10.3 გაუქმება timeout-ის გამო|10.3]]). გაუქმების ტოკენი შეიძლება უსასრულო `Task.Delay`-ში „გავახვიოთ" და მივიღოთ task, რომელიც მითითებული დროის შემდეგ უქმდება. შემდეგ ეს ტაიმერის task `Task.WhenAny`-სთან ერთად გამოვიყენოთ ([[თავი 2.5 ნებისმიერი Task-ის დასრულების ლოდინი|2.5]]):

```csharp
async Task<string> DownloadStringWithTimeout(HttpClient client, string uri)
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(3));

    Task<string> downloadTask = client.GetStringAsync(uri);
    Task timeoutTask = Task.Delay(Timeout.InfiniteTimeSpan, cts.Token);

    Task completedTask = await Task.WhenAny(downloadTask, timeoutTask);
    if (completedTask == timeoutTask)
        return null;

    return await downloadTask;
}
```

> [!WARNING] „რბილი" timeout-ის შეზღუდვა
> თუ ოპერაცია დროს გადააჭარბებს, ის **არ უქმდება**. ზემოთ მოცემულ მაგალითში ჩამოტვირთვა გრძელდება და სრულ პასუხს ჩამოტვირთავს, სანამ ის გადაიგდება. სასურველი მიდგომაა, **გაუქმების ტოკენი** timeout-ად გამოვიყენოთ და პირდაპირ ოპერაციას გადავცეთ (`GetStringAsync`-ს). თუმცა ზოგჯერ ოპერაცია გაუქმებადი არ არის, და მაშინ `Task.Delay` საშუალებას გვაძლევს, კოდმა ისე მოიქცეს, თითქოს ოპერაციამ დრო გადააჭარბა.

## განხილვა

`Task.Delay` კარგი ვარიანტია ასინქრონული კოდის ერთეულოვანი ტესტირებისთვის ან ხელახალი მცდელობების ლოგიკისთვის. მაგრამ თუ timeout გჭირდებათ, `CancellationToken`, როგორც წესი, უკეთესი არჩევანია.

> [!NOTE] თანამედროვე .NET
> - **`PeriodicTimer`** (.NET 6) პერიოდული ამოცანებისთვის `Task.Delay`-ის ციკლს სჯობს: ის დროის „დრეიფს" (drift) არიდებს თავს.
> - **`Task.WaitAsync(TimeSpan)`** (.NET 6) ზემოთ ნაჩვენებ `WhenAny` + `Delay` ნიმუშს ერთ გამოძახებად აქცევს: `await downloadTask.WaitAsync(TimeSpan.FromSeconds(3));` timeout-ის შემთხვევაში `TimeoutException`-ს ისვრის.
> - **`Task.Delay`-ის სიზუსტე** სისტემის ტაიმერზეა დამოკიდებული: ის მითითებულ დროზე **ნაკლებს არასოდეს** დაელოდება, მაგრამ ცოტა მეტს შეიძლება.
