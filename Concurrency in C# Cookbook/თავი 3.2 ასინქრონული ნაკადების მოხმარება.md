## პრობლემა

გჭირდებათ ასინქრონული ნაკადის (ასინქრონული enumerable-ის) შედეგების დამუშავება.

## გადაწყვეტა

ასინქრონული ოპერაციის მოხმარება `await`-ით ხდება, enumerable-ის მოხმარება კი, როგორც წესი, `foreach`-ით. ასინქრონული enumerable-ის მოხმარება ამ ორის გაერთიანებაა: **`await foreach`**.

```csharp
IAsyncEnumerable<string> GetValuesAsync(HttpClient client);

public async Task ProcessValuesAsync(HttpClient client)
{
    await foreach (string value in GetValuesAsync(client))
    {
        Console.WriteLine(value);
    }
}
```

კონცეპტუალურად აქ ხდება შემდეგი: `GetValuesAsync` გამოიძახება და `IAsyncEnumerable<T>`-ს აბრუნებს. `foreach` ამ ასინქრონული enumerable-იდან **ასინქრონულ enumerator**-ს ქმნის. ასინქრონული enumerator-ები ლოგიკურად ჩვეულებრივ enumerator-ებს ჰგავს, ოღონდ მათი „მომდევნო ელემენტის მიღების" ოპერაცია შეიძლება ასინქრონული იყოს. ამიტომ `await foreach` დაელოდება, სანამ მომდევნო ელემენტი მოვა ან enumerator დასრულდება. თუ ელემენტი მოვიდა, ციკლის სხეული შესრულდება; თუ enumerator დასრულდა, ციკლი გამოვა.

### ასინქრონული დამუშავება ციკლის სხეულში

ბუნებრივია, თითოეული ელემენტის დამუშავებაც ასინქრონული იყოს:

```csharp
public async Task ProcessValuesAsync(HttpClient client)
{
    await foreach (string value in GetValuesAsync(client))
    {
        await Task.Delay(100);        // ასინქრონული სამუშაო
        Console.WriteLine(value);
    }
}
```

ამ შემთხვევაში `await foreach` შემდეგ ელემენტზე არ გადავა, სანამ ციკლის სხეული არ დასრულდება. ანუ: ასინქრონულად მიიღება პირველი ელემენტი, ასინქრონულად შესრულდება მისი დამუშავება, ასინქრონულად მიიღება შემდეგი ელემენტი, ასინქრონულად შესრულდება მისი დამუშავება, და ასე შემდეგ.

### `ConfigureAwait(false)`

`await foreach`-ში **დამალული `await`-ია**: „მომდევნო ელემენტის მიღების" ოპერაციას ველოდებით. ჩვეულებრივი `await`-ის მსგავსად, კონტექსტის იმპლიციტური დაჭერა `ConfigureAwait(false)`-ით შეიძლება ავიცილოთ ([[თავი 2.7 კონტექსტის არიდება გაგრძელებებისთვის|2.7]]). ასინქრონული ნაკადებიც უჭერს მხარს `ConfigureAwait(false)`-ს, რომელიც სწორედ ამ დამალულ `await`-ებს გადაეცემა:

```csharp
public async Task ProcessValuesAsync(HttpClient client)
{
    await foreach (string value in GetValuesAsync(client).ConfigureAwait(false))
    {
        await Task.Delay(100).ConfigureAwait(false);
        Console.WriteLine(value);
    }
}
```

## განხილვა

`await foreach` ასინქრონული ნაკადების მოხმარების ყველაზე ბუნებრივი გზაა. ენა `ConfigureAwait(false)`-საც უჭერს მხარს კონტექსტის ასარიდებლად.

**გაუქმების ტოკენის გადაცემაც** შესაძლებელია. ეს ცოტა უფრო რთულია ასინქრონული ნაკადების სპეციფიკის გამო, ამიტომ მას [[თავი 3.4 ასინქრონული ნაკადები და გაუქმება|3.4]] ეძღვნება.

**LINQ.** `await foreach`-ის გარდა, ასინქრონული LINQ ოპერატორების მდიდარი ბიბლიოთეკაც არსებობს. ყველაზე პოპულარულებს [[თავი 3.3 LINQ ასინქრონულ ნაკადებთან|3.3]] განიხილავს.

**სინქრონული და ასინქრონული სხეული.** `await foreach`-ის სხეული შეიძლება იყოს სინქრონულიც და ასინქრონულიც. ასინქრონული შემთხვევა განსაკუთრებით მნიშვნელოვანია: სხვა ნაკადურ აბსტრაქციებთან, მაგალითად `IObservable<T>`-თან, სწორად გაკეთება გაცილებით რთულია, რადგან **observable-ის გამოწერები სინქრონული უნდა იყოს**. `await foreach` კი ბუნებრივ ასინქრონულ დამუშავებას უშვებს.

**ორი დამალული `await`.** `await foreach` ქმნის `await`-ს „მომდევნო ელემენტის მიღების" ოპერაციისთვის, და კიდევ ერთს enumerable-ის **ასინქრონულად განთავისუფლებისთვის** (`DisposeAsync`, [[თავი 11.6 ასინქრონული განთავისუფლება|11.6]]).

> [!TIP] `break`, `return` და გასუფთავება
> როცა `await foreach`-იდან `break`-ით ან `return`-ით გამოხვალთ, კომპილატორი ავტომატურად იძახებს `DisposeAsync`-ს. მწარმოებელ მეთოდში `try`/`finally` ბლოკის `finally` ნაწილი ამ დროს შესრულდება, ამიტომ რესურსების გასუფთავება უსაფრთხოა:
> ```csharp
> async IAsyncEnumerable<string> ReadLinesAsync(string path)
> {
>     using var reader = new StreamReader(path);      // DisposeAsync-ზე დაიხურება
>     while (await reader.ReadLineAsync() is string line)
>         yield return line;
> }
> ```
