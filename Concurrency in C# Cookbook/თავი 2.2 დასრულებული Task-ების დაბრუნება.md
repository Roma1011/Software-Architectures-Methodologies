## პრობლემა

გჭირდებათ **სინქრონული** მეთოდის იმპლემენტაცია **ასინქრონული ხელმოწერით**. ეს მაშინ ხდება, როცა ასინქრონულ ინტერფეისს ან საბაზო კლასს მემკვიდრეობით იღებთ, მაგრამ იმპლემენტაცია სინქრონული გინდათ. ტექნიკა განსაკუთრებით სასარგებლოა ასინქრონული კოდის ერთეულოვან ტესტირებაში, როცა ასინქრონული ინტერფეისის მარტივი stub ან mock გჭირდებათ.

## გადაწყვეტა

### `Task.FromResult`

`Task.FromResult` ქმნის და აბრუნებს ახალ `Task<T>`-ს, რომელიც უკვე **დასრულებულია** მითითებული მნიშვნელობით:

```csharp
interface IMyAsyncInterface
{
    Task<int> GetValueAsync();
}

class MySynchronousImplementation : IMyAsyncInterface
{
    public Task<int> GetValueAsync()
    {
        return Task.FromResult(13);
    }
}
```

### `Task.CompletedTask`

მეთოდებისთვის, რომლებიც მნიშვნელობას არ აბრუნებს, არსებობს `Task.CompletedTask`: ქეშირებული, წარმატებით დასრულებული `Task`:

```csharp
class MySynchronousImplementation : IMyAsyncInterface
{
    public Task DoSomethingAsync()
    {
        return Task.CompletedTask;
    }
}
```

### `Task.FromException` და `Task.FromCanceled`

`Task.FromResult` მხოლოდ **წარმატებულ** შედეგებს იძლევა. თუ სხვა სახის შედეგი გჭირდებათ, მაგალითად, `NotImplementedException`-ით დასრულებული task:

```csharp
Task<T> NotImplementedAsync<T>()
{
    return Task.FromException<T>(new NotImplementedException());
}
```

ანალოგიურად, `Task.FromCanceled` ქმნის task-ს, რომელიც მოცემული `CancellationToken`-ით უკვე გაუქმებულია:

```csharp
Task<int> GetValueAsync(CancellationToken cancellationToken)
{
    if (cancellationToken.IsCancellationRequested)
        return Task.FromCanceled<int>(cancellationToken);

    return Task.FromResult(13);
}
```

### თუ სინქრონულმა კოდმა შეიძლება ჩაარდეს

თუ თქვენს სინქრონულ იმპლემენტაციას შეცდომა შეიძლება მოუვიდეს, exception უნდა დაიჭიროთ და `Task.FromException`-ით დააბრუნოთ:

```csharp
class MySynchronousImplementation : IMyAsyncInterface
{
    public Task DoSomethingAsync()
    {
        try
        {
            DoSomethingSynchronously();
            return Task.CompletedTask;
        }
        catch (Exception ex)
        {
            return Task.FromException(ex);
        }
    }
}
```

ასე exception `Task`-ზე აღმოჩნდება და არა პირდაპირ გამომძახებელზე, რაც ასინქრონული მეთოდის მოსალოდნელი ქცევაა.

## განხილვა

> [!WARNING] არ დაბლოკოთ
> თუ ასინქრონულ ინტერფეისს სინქრონული კოდით ახორციელებთ, **ნებისმიერ ბლოკირებას** მოერიდეთ. ცუდია, როცა ასინქრონული მეთოდი ჯერ ბლოკავს და მერე დასრულებულ task-ს აბრუნებს, თუ მისი ასინქრონულად იმპლემენტაცია შესაძლებელია.
>
> უარყოფითი მაგალითია .NET BCL-ის კონსოლის წამკითხველები: `Console.In.ReadLineAsync` სინამდვილეში **ბლოკავს** გამომძახებელ ნაკადს, სანამ ხაზს წაიკითხავს, და მხოლოდ შემდეგ აბრუნებს დასრულებულ task-ს. ეს არაინტუიციური ქცევა ბევრი დეველოპერისთვის მოულოდნელი აღმოჩნდა. თუ ასინქრონული მეთოდი ბლოკავს, ის გამომძახებელ ნაკადს სხვა ამოცანების დაწყების საშუალებას აცლის, რაც კონკურენტულობას უშლის ხელს და deadlock-იც კი შეიძლება გამოიწვიოს.

### ქეშირება

თუ `Task.FromResult`-ს რეგულარულად ერთი და იმავე მნიშვნელობით იყენებთ, დაფიქრდით თავად task-ის ქეშირებაზე. მაგალითად, თუ ნულოვანი შედეგის `Task<int>`-ს ერთხელ შექმნით, თავიდან აიცილებთ ზედმეტ ეგზემპლარებს, რომლებსაც garbage collector მოუწევს შეაგროვოს:

```csharp
private static readonly Task<int> ZeroTask = Task.FromResult(0);

Task<int> GetValueAsync()
{
    return ZeroTask;
}
```

### კავშირი `TaskCompletionSource<T>`-თან

ლოგიკურად, `Task.FromResult`, `Task.FromException` და `Task.FromCanceled` დამხმარე მეთოდები და მალსახმობებია უფრო ზოგადი **`TaskCompletionSource<T>`**-ისთვის. ეს უფრო დაბალი დონის ტიპია, რომელიც ასინქრონული კოდის სხვა ფორმებთან თავსებადობისთვის გამოგვადგება ([[თავი 8.3 ნებისმიერი შეტყობინების async გარსი|8.3]]).

> [!IMPORTANT] წესი
> **უკვე დასრულებული** task-ისთვის გამოიყენეთ მალსახმობები (`Task.FromResult` და სხვ.). task-ისთვის, რომელიც **მომავალში** დასრულდება, გამოიყენეთ `TaskCompletionSource<T>`.

> [!NOTE] თანამედროვე .NET
> თუ მეთოდი ხშირად სინქრონულად სრულდება და მისი გამოძახება ძალიან ხშირია, `Task.FromResult`-ის ნაცვლად **`ValueTask<T>`**-ის დაბრუნება მეხსიერების გამოყოფას მთლიანად აქრობს: `return new ValueTask<int>(13);` ([[თავი 2.10 ValueTask-ის შექმნა|2.10]]).
