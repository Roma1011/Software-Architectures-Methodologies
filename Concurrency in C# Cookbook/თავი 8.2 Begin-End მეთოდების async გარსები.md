## პრობლემა

ძველი ასინქრონული შაბლონი იყენებს მეთოდების წყვილს სახელებით `BeginOperation` და `EndOperation`, სადაც `IAsyncResult` ასინქრონულ ოპერაციას წარმოადგენს. გაქვთ ოპერაცია, რომელიც ამ ძველ შაბლონს მიჰყვება, და გსურთ მისი მოხმარება `await`-ით.

> [!TIP] APM
> `BeginOperation`/`EndOperation` შაბლონს **Asynchronous Programming Model (APM)** ჰქვია. ჩვენ მას `Task`-ის დამბრუნებელ, **TAP**-ის მიმდევარ მეთოდში გავახვევთ.

## გადაწყვეტა

APM-ის გახვევის საუკეთესო მიდგომაა `TaskFactory` ტიპის **`FromAsync`** მეთოდებიდან ერთ-ერთის გამოყენება. `FromAsync` შიგნით `TaskCompletionSource<TResult>`-ს იყენებს, მაგრამ APM-ის გახვევისას `FromAsync` გაცილებით მოსახერხებელია.

მაგალითი `WebRequest`-ისთვის გაფართოების მეთოდს განსაზღვრავს, რომელიც HTTP მოთხოვნას აგზავნის და პასუხს იღებს. `WebRequest` ტიპი განსაზღვრავს `BeginGetResponse`-სა და `EndGetResponse`-ს:

```csharp
public static Task<WebResponse> GetResponseAsync(this WebRequest client)
{
    return Task<WebResponse>.Factory.FromAsync(
        client.BeginGetResponse,
        client.EndGetResponse,
        null);
}
```

## განხილვა

`FromAsync`-ს **დამაბნეველად ბევრი გადატვირთვა** აქვს!

ზოგადი წესი: სჯობს `FromAsync` ისე გამოვიძახოთ, როგორც მაგალითშია.

1. ჯერ გადავცეთ `BeginOperation` მეთოდი (**გამოძახების გარეშე**).
2. შემდეგ `EndOperation` მეთოდი (**გამოძახების გარეშე**).
3. შემდეგ ყველა არგუმენტი, რომელსაც `BeginOperation` იღებს, **გარდა** ბოლო `AsyncCallback` და `object` არგუმენტებისა.
4. ბოლოს გადავცეთ `null`.

კერძოდ, **არ გამოიძახოთ `BeginOperation` მეთოდი `FromAsync`-ის გამოძახებამდე**. შეგიძლიათ `FromAsync` გამოიძახოთ და `BeginOperation`-იდან მიღებული `IAsyncResult` გადასცეთ, მაგრამ ასეთ შემთხვევაში `FromAsync` **ნაკლებად ეფექტური** იმპლემენტაციის გამოყენებას იძულებულია.

### რატომ `null` ბოლოში

`FromAsync` `Task` ტიპთან ერთად .NET 4.0-ში გამოჩნდა, `async`-ის არსებობამდე. იმ დროს ჩვეულებრივი იყო **მდგომარეობის ობიექტების** გამოყენება ასინქრონულ callback-ებში, და `Task` ტიპი ამას თავისი `AsyncState` წევრით უჭერს მხარს. ახალ `async` შაბლონში მდგომარეობის ობიექტები აღარ არის საჭირო, ამიტომ ნორმალურია, რომ state პარამეტრად ყოველთვის `null` გადავცეთ. დღეს state მხოლოდ იმისთვის გამოიყენება, რომ მეხსიერების ოპტიმიზაციისას **closure-ის ეგზემპლარს** ავარიდოთ თავი.

> [!NOTE] თანამედროვე .NET
> - `WebRequest` და `HttpWebRequest` დღეს **მოძველებულია** (.NET 6-დან `[Obsolete]`). ახალ კოდში `HttpClient` გამოიყენეთ.
> - საპირისპირო გარდაქმნაც არსებობს: `TaskToAsyncResult.Begin`/`End` (.NET 8+), როცა TAP მეთოდი APM API-სთვის უნდა გამოამჟღავნოთ.
> - APM-ის მოხმარების კიდევ ერთი გზაა `TaskFactory.FromAsync`-ის ნაცვლად `AsyncCallback`-ის ხელით დაწერა `TaskCompletionSource`-თან, მაგრამ ამის საჭიროება თითქმის არასდროსაა.
