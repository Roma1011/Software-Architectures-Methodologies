## პრობლემა

გაქვთ რამდენიმე task და გჭირდებათ რეაგირება მხოლოდ **ერთ** მათგანზე, რომელიც პირველი დასრულდება. ეს ყველაზე ხშირად მაშინ ხდება, როცა ერთ ოპერაციას რამდენიმე დამოუკიდებელი მცდელობა აქვს, „პირველი იღებს ყველაფერს" სტრუქტურით. მაგალითად, აქციების კოტირებას რამდენიმე ვებ-სერვისს ერთდროულად ვთხოვთ, მაგრამ მხოლოდ პირველი პასუხი გვაინტერესებს.

## გადაწყვეტა

გამოიყენეთ **`Task.WhenAny`**. ის task-ების თანმიმდევრობას იღებს და აბრუნებს task-ს, რომელიც მაშინ სრულდება, როცა **რომელიმე** მათგანი დასრულდება. დაბრუნებული task-ის **შედეგი** არის ის task, რომელიც დასრულდა. თუ ეს დამაბნეველად ჟღერს, კოდზე უფრო ადვილი გასაგებია:

```csharp
// აბრუნებს პირველი მოპასუხე URL-ის მონაცემების ზომას
async Task<int> FirstRespondingUrlAsync(HttpClient client, string urlA, string urlB)
{
    // ორივე ჩამოტვირთვას ერთდროულად ვიწყებთ
    Task<byte[]> downloadTaskA = client.GetByteArrayAsync(urlA);
    Task<byte[]> downloadTaskB = client.GetByteArrayAsync(urlB);

    // ველოდებით, რომელიმე მათგანი დასრულდეს
    Task<byte[]> completedTask = await Task.WhenAny(downloadTaskA, downloadTaskB);

    // ვაბრუნებთ ამ URL-იდან მიღებული მონაცემების სიგრძეს
    byte[] data = await completedTask;
    return data.Length;
}
```

## განხილვა

### გარე და შიდა task

`Task.WhenAny`-ის დაბრუნებული task **არასოდეს** სრულდება faulted ან canceled მდგომარეობაში. ეს „გარე" task **ყოველთვის წარმატებით** სრულდება, და მისი შედეგია პირველი დასრულებული `Task` („შიდა" task). თუ შიდა task exception-ით დასრულდა, ეს exception **გარე** task-ზე არ გადადის. ამიტომ, როგორც წესი, დასრულებულ შიდა task-ს **`await`** უნდა გაუკეთოთ, რომ exception-ები დანახული (observed) იყოს.

### დარჩენილი task-ები

როცა პირველი task სრულდება, დაფიქრდით, გააუქმოთ თუ არა დანარჩენები. თუ სხვა task-ები არ გაუქმდა და მათ `await`-იც არასოდეს გაუკეთდა, ისინი **მიტოვებულია (abandoned)**. მიტოვებული task-ები ბოლომდე შესრულდება, მათი შედეგები უგულებელყოფილი იქნება, და მათი exception-ებიც. თუ ისინი არ გაუქმდა, ისინი აგრძელებენ მუშაობას და ზედმეტად ხარჯავენ რესურსებს: HTTP კავშირებს, ბაზის კავშირებს, ტაიმერებს.

```csharp
async Task<int> FirstRespondingUrlAsync(HttpClient client, string urlA, string urlB)
{
    using var cts = new CancellationTokenSource();

    Task<byte[]> taskA = client.GetByteArrayAsync(urlA, cts.Token);
    Task<byte[]> taskB = client.GetByteArrayAsync(urlB, cts.Token);

    Task<byte[]> completed = await Task.WhenAny(taskA, taskB);
    cts.Cancel();                      // მეორეს ვაუქმებთ

    byte[] data = await completed;
    return data.Length;
}
```

### ანტი-ნიმუშები

> [!WARNING] `WhenAny` timeout-ისთვის
> `Task.WhenAny`-ით timeout-ის იმპლემენტაცია შესაძლებელია (მაგალითად, `Task.Delay` ერთ-ერთ task-ად), მაგრამ **არ არის რეკომენდებული**. timeout-ის გამოხატვა უფრო ბუნებრივია **გაუქმებით**, რომელსაც დამატებითი უპირატესობაც აქვს: ის ოპერაციას რეალურად აუქმებს ([[თავი 10.3 გაუქმება timeout-ის გამო|10.3]]).

> [!WARNING] `WhenAny` ციკლში
> მეორე ანტი-ნიმუშია task-ების დამუშავება დასრულების მიხედვით `WhenAny`-ის ციკლით: სია გვაქვს, `WhenAny`-ს ვიძახებთ, დასრულებულს სიიდან ვშლით და ისევ ვიმეორებთ. ეს **O(N²)** დროში სრულდება, მაშინ როცა **O(N)** ალგორითმიც არსებობს. სწორი მიდგომა [[თავი 2.6 Task-ების დამუშავება დასრულების მიხედვით|2.6]]-შია.

> [!NOTE] თანამედროვე .NET
> .NET 6-იდან `Task.WhenAny`-ს აქვს გადატვირთვა ორი task-ისთვის, რომელიც მასივს არ ქმნის. ასევე, timeout-ისთვის `WaitAsync(TimeSpan)` სჯობს `WhenAny` + `Delay` კომბინაციას.
