## პრობლემა

დამუშავების მიმდინარეობისას გჭირდებათ dataflow-ის სტრუქტურის **დინამიკურად შეცვლა**. ეს რთული სცენარია, რომელიც იშვიათად თუ დაგჭირდებათ.

## გადაწყვეტა

dataflow ბლოკების დაკავშირება და გათიშვა **ნებისმიერ მომენტშია** შესაძლებელი: მონაცემები თავისუფლად შეიძლება მიედინებოდეს ბადეში და დაკავშირება/გათიშვა მაინც უსაფრთხო იქნება. ორივე ოპერაცია **სრულად ნაკადებისთვის უსაფრთხოა**.

ბმულის შექმნისას შეინახეთ `IDisposable`, რომელსაც `LinkTo` აბრუნებს, და გაათავისუფლეთ ის, როცა ბლოკების გათიშვა გინდათ:

```csharp
var multiplyBlock = new TransformBlock<int, int>(item => item * 2);
var subtractBlock = new TransformBlock<int, int>(item => item - 2);

IDisposable link = multiplyBlock.LinkTo(subtractBlock);

multiplyBlock.Post(1);
multiplyBlock.Post(2);

// ბლოკების გათიშვა.
// ზემოთ გაგზავნილმა მონაცემებმა შეიძლება უკვე გაიარეს ბმული, შეიძლება არა.
// რეალურ კოდში Dispose-ის ნაცვლად using ბლოკი განიხილეთ.
link.Dispose();
```

## განხილვა

თუ ვერ გარანტირებთ, რომ ბმული **უმოქმედოა**, გათიშვისას რბოლის მდგომარეობები (race conditions) იქნება. მაგრამ ეს რბოლები, როგორც წესი, საფრთხეს არ წარმოადგენს: მონაცემი ან ბმულის გაწყვეტამდე გაივლის, ან არა. **არ არსებობს რბოლა, რომელიც მონაცემების დუბლირებას ან დაკარგვას გამოიწვევდა.**

გათიშვა რთული სცენარია, მაგრამ რამდენიმე სიტუაციაში სასარგებლოა:

- **ფილტრის შეცვლა.** ბმულის ფილტრის შეცვლა შეუძლებელია. არსებული ბმულის ფილტრის შესაცვლელად ძველი უნდა გათიშოთ და ახალი ფილტრით ახალი ბმული შექმნათ (საჭიროებისამებრ `DataflowLinkOptions.Append`-ის `false`-ზე დაყენებით).
- **ბადის დაპაუზება.** სტრატეგიულ წერტილში გათიშვა dataflow ბადის დროებით შესაჩერებლად შეიძლება გამოვიყენოთ.

> [!TIP] `MaxMessages`
> `DataflowLinkOptions.MaxMessages` ბმულს ავტომატურად წყვეტს მითითებული რაოდენობის შეტყობინების გატარების შემდეგ. ეს „ერთჯერადი" ბმულებისთვის გამოდგება, ხელით `Dispose`-ის გარეშე.
