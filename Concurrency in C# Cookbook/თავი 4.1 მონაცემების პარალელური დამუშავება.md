> [!INFO] მე-4 თავის შესახებ
> ეს თავი პარალელური პროგრამირების ნიმუშებს ეხება. პარალელური პროგრამირება **პროცესორზე დამოკიდებული (CPU-bound)** სამუშაოს ნაწილებად დაყოფასა და ნაკადებზე გადანაწილებას ემსახურება. ამ თავის რეცეპტები **მხოლოდ CPU-ზე დამოკიდებულ** სამუშაოს განიხილავს. თუ ბუნებრივად ასინქრონული ოპერაციები გაქვთ (I/O), რომელთა პარალელურად შესრულებაც გინდათ, იხილეთ [[თავი 2.4 Task-ების ნაკრების დასრულების ლოდინი|მე-2 თავი, განსაკუთრებით 2.4]].
>
> აქ განხილული აბსტრაქციები **Task Parallel Library (TPL)**-ის ნაწილია, რომელიც .NET-ში ჩაშენებულია.

## პრობლემა

გაქვთ მონაცემების კოლექცია, და თითოეულ ელემენტზე ერთი და იგივე ოპერაცია უნდა შეასრულოთ. ეს ოპერაცია CPU-ზეა დამოკიდებული და შეიძლება დრო წაიღოს.

## გადაწყვეტა

`Parallel` ტიპს აქვს **`ForEach`** მეთოდი, სპეციალურად ამ პრობლემისთვის. მაგალითი მატრიცების კოლექციას იღებს და ყველას აბრუნებს:

```csharp
void RotateMatrices(IEnumerable<Matrix> matrices, float degrees)
{
    Parallel.ForEach(matrices, matrix => matrix.Rotate(degrees));
}
```

*ნახაზი 4.1: `Parallel.ForEach` სამუშაოს დინამიკურად ანაწილებს thread pool-ის ნაკადებზე.*

### ციკლის ნაადრევი შეჩერება

ზოგჯერ ციკლის ნაადრევად შეჩერება გვინდა, მაგალითად, არასწორი მნიშვნელობის აღმოჩენისას:

```csharp
void InvertMatrices(IEnumerable<Matrix> matrices)
{
    Parallel.ForEach(matrices, (matrix, state) =>
    {
        if (!matrix.IsInvertible)
            state.Stop();
        else
            matrix.Invert();
    });
}
```

კოდი `ParallelLoopState.Stop`-ს იყენებს, რომ ციკლი გაჩერდეს და სხეულის ახალი გამოძახებები აღარ მოხდეს.

> [!WARNING] მიმდინარე გამოძახებები გრძელდება
> ეს **პარალელური** ციკლია, ამიტომ სხეულის სხვა გამოძახებები შეიძლება უკვე მიმდინარეობდეს, მათ შორის მიმდინარე ელემენტის **შემდეგი** ელემენტებისთვისაც. თუ მესამე მატრიცა შეუქცევადია, ციკლი გაჩერდება და ახალი მატრიცები აღარ დამუშავდება, მაგრამ მეოთხე და მეხუთე შეიძლება უკვე მუშავდებოდეს.

> [!TIP] `Stop` და `Break`
> `state.Stop()` ციკლს რაც შეიძლება სწრაფად აჩერებს. `state.Break()` კი ამბობს: „მიმდინარე ინდექსამდე ყველა ელემენტი დამუშავდეს, შემდეგი კი აღარ". `Break` მაშინ გამოიყენება, როცა ელემენტების **თანმიმდევრობას** აქვს მნიშვნელობა.

### გაუქმება

უფრო გავრცელებული სიტუაციაა პარალელური ციკლის **გაუქმება**. ეს შეჩერებისგან განსხვავდება: ციკლი **შიგნიდან** ჩერდება და **გარედან** უქმდება. მაგალითად, „გაუქმების" ღილაკი `CancellationTokenSource`-ს აუქმებს:

```csharp
void RotateMatrices(IEnumerable<Matrix> matrices, float degrees, CancellationToken token)
{
    Parallel.ForEach(matrices,
        new ParallelOptions { CancellationToken = token },
        matrix => matrix.Rotate(degrees));
}
```

### გაზიარებული მდგომარეობა

გასათვალისწინებელია, რომ თითოეული პარალელური ამოცანა შეიძლება **სხვა ნაკადზე** შესრულდეს, ამიტომ ნებისმიერი გაზიარებული მდგომარეობა დაცული უნდა იყოს. მაგალითი მატრიცებს აქცევს და ითვლის, რამდენი მათგანი ვერ შებრუნდა:

```csharp
// შენიშვნა: ეს ყველაზე ეფექტიანი იმპლემენტაცია არ არის.
// ეს მხოლოდ საკეტით გაზიარებული მდგომარეობის დაცვის მაგალითია.
int InvertMatrices(IEnumerable<Matrix> matrices)
{
    object mutex = new object();
    int nonInvertibleCount = 0;

    Parallel.ForEach(matrices, matrix =>
    {
        if (matrix.IsInvertible)
        {
            matrix.Invert();
        }
        else
        {
            lock (mutex)
            {
                ++nonInvertibleCount;
            }
        }
    });

    return nonInvertibleCount;
}
```

უფრო ეფექტიანი მიდგომა ლოკალური მნიშვნელობებით აგრეგირებაა ([[თავი 4.2 პარალელური აგრეგირება|4.2]]).

## განხილვა

`Parallel.ForEach` მნიშვნელობების თანმიმდევრობის პარალელურ დამუშავებას იძლევა. მსგავსი გადაწყვეტაა **Parallel LINQ (PLINQ)**, რომელიც თითქმის იმავე შესაძლებლობებს LINQ-ის სტილში გვთავაზობს ([[თავი 4.5 Parallel LINQ|4.5]]).

> [!IMPORTANT] `Parallel` თუ PLINQ
> მთავარი განსხვავება: **PLINQ ვარაუდობს, რომ კომპიუტერის ყველა ბირთვის გამოყენება შეუძლია**, `Parallel` კი პროცესორის მდგომარეობის ცვლილებაზე დინამიკურად რეაგირებს. სერვერზე ან სხვა პროცესებთან თანაცხოვრებისას `Parallel` უფრო „თავაზიანია".

`Parallel.ForEach` პარალელური `foreach` ციკლია. თუ პარალელური `for` ციკლი გჭირდებათ, `Parallel` კლასს აქვს **`Parallel.For`**. ის განსაკუთრებით სასარგებლოა, როცა რამდენიმე მასივი გაქვთ და ყველა ერთი და იმავე ინდექსს იყენებს.

> [!NOTE] თანამედროვე .NET
> `Parallel.ForEachAsync` (.NET 6) **ასინქრონულ** დელეგატს იღებს და I/O-სთვის განკუთვნილია, არა CPU-ზე მძიმე სამუშაოსთვის. მისი `MaxDegreeOfParallelism` ერთდროულობას ზღუდავს:
> ```csharp
> await Parallel.ForEachAsync(urls,
>     new ParallelOptions { MaxDegreeOfParallelism = 8 },
>     async (url, token) => await DownloadAsync(url, token));
> ```
