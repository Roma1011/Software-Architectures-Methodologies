## პრობლემა

გჭირდებათ ასინქრონული ნაკადების **გაუქმების** საშუალება.

## გადაწყვეტა

ყველა ასინქრონულ ნაკადს გაუქმება არ სჭირდება. ხშირად საკმარისია **იტერაციის შეწყვეტა**, როცა პირობა შესრულდება. თუ მხოლოდ ასეთი „გაუქმებაა" საჭირო, ნამდვილი გაუქმება ზედმეტია:

```csharp
await foreach (int result in SlowRange())
{
    Console.WriteLine(result);
    if (result >= 8)
        break;
}

async IAsyncEnumerable<int> SlowRange()
{
    for (int i = 0; i != 10; ++i)
    {
        await Task.Delay(i * 100);
        yield return i;
    }
}
```

მიუხედავად ამისა, ხშირად ასინქრონული ნაკადის გაუქმება სასარგებლოა, რადგან ზოგი ოპერატორი გაუქმების ტოკენს **წყარო ნაკადს გადასცემს**. ასეთ სცენარში `CancellationToken` გვჭირდება, რომ `await foreach` **გარე კოდიდან** გავაჩეროთ.

### `[EnumeratorCancellation]`

`IAsyncEnumerable<T>`-ის დამბრუნებელ `async` მეთოდს გაუქმების ტოკენის მიღება შეუძლია პარამეტრით, რომელიც **`EnumeratorCancellation`** ატრიბუტითაა მონიშნული. შემდეგ ის ამ ტოკენს ჩვეულებრივად იყენებს, ანუ სხვა API-ებს გადასცემს:

```csharp
using var cts = new CancellationTokenSource(500);
CancellationToken token = cts.Token;

await foreach (int result in SlowRange(token))
{
    Console.WriteLine(result);
}

async IAsyncEnumerable<int> SlowRange(
    [EnumeratorCancellation] CancellationToken token = default)
{
    for (int i = 0; i != 10; ++i)
    {
        await Task.Delay(i * 100, token);
        yield return i;
    }
}
```

## განხილვა

ზემოთ მოცემული გადაწყვეტა `CancellationToken`-ს **პირდაპირ** გადასცემს იმ მეთოდს, რომელიც ასინქრონულ enumerator-ს აბრუნებს. ეს ყველაზე გავრცელებული გამოყენებაა.

### `WithCancellation`

არსებობს სხვა სცენარებიც, სადაც თქვენს კოდს **მზა** ასინქრონული enumerable გადაეცემა და მას გაუქმების ტოკენის მიბმა სჭირდება. გაუქმების ტოკენები enumerable-ის **ახალი იტერაციის დაწყებისას** გამოიყენება, ამიტომ ლოგიკურია, რომ ტოკენი სწორედ ამ დროს მიებას.

მნიშვნელოვანი დეტალი: **გაუქმებადი არა თავად enumerable-ია, არამედ მისგან შექმნილი enumerator.** `SlowRange` მეთოდი enumerable-ს განსაზღვრავს, მაგრამ ის არ იწყება, სანამ არ მოიხმარენ. ზოგჯერ ერთი და იმავე enumerable-ის სხვადასხვა იტერაციას სხვადასხვა ტოკენიც კი უნდა გადაეცეს.

სწორედ ამიტომ არსებობს **`WithCancellation`** გაფართოების მეთოდი, რომელიც `CancellationToken`-ს ასინქრონული ნაკადის **კონკრეტულ იტერაციას** აბამს:

```csharp
async Task ConsumeSequence(IAsyncEnumerable<int> items)
{
    using var cts = new CancellationTokenSource(500);
    CancellationToken token = cts.Token;

    await foreach (int result in items.WithCancellation(token))
    {
        Console.WriteLine(result);
    }
}

await ConsumeSequence(SlowRange());
```

*ნახაზი 3.5: ერთი enumerable, სხვადასხვა iteration, სხვადასხვა ტოკენი.*

`[EnumeratorCancellation]` ატრიბუტის წყალობით კომპილატორი თავად ზრუნავს, რომ ტოკენი `WithCancellation`-იდან ატრიბუტით მონიშნულ პარამეტრს გადასცეს. გაუქმების მოთხოვნისას `await foreach` პირველი რამდენიმე ელემენტის დამუშავების შემდეგ **`OperationCanceledException`**-ს ისვრის.

### `WithCancellation` და `ConfigureAwait`

`WithCancellation` არ უშლის ხელს `ConfigureAwait(false)`-ს. ორივე გაფართოების მეთოდი ერთმანეთს ჯაჭვურად ერთვის:

```csharp
await foreach (int result in items
    .WithCancellation(token)
    .ConfigureAwait(false))
{
    Console.WriteLine(result);
}
```

> [!TIP] რჩევა ავტორებისთვის
> თუ `IAsyncEnumerable<T>`-ის დამბრუნებელ მეთოდს წერთ, **ყოველთვის** დაამატეთ `[EnumeratorCancellation] CancellationToken token = default` პარამეტრი და ტოკენი გადასცეთ ყველა შიდა ასინქრონულ გამოძახებას. ეს კლიენტს ორივე ვარიანტს აძლევს: ტოკენი პირდაპირ გადასცეს ან `WithCancellation` გამოიყენოს.
