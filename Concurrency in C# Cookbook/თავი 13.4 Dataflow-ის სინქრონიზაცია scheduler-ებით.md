## პრობლემა

გჭირდებათ კონტროლი იმაზე, როგორ სრულდება კოდის ცალკეული ნაწილები **dataflow** კოდში.

## გადაწყვეტა

როგორც კი შესაბამის `TaskScheduler` ეგზემპლარს შექმნით ([[თავი 13.2 კოდის შესრულება Task Scheduler-ით|13.2]]), მას იმ პარამეტრებში ჩართავთ, რომლებსაც dataflow ბლოკს გადასცემთ.

ქვემოთ მოცემული კოდი, როცა UI ნაკადიდან იძახება, dataflow ბადეს ქმნის, რომელიც ყველა შემავალ მნიშვნელობას ორზე ამრავლებს (thread pool-ის გამოყენებით) და შემდეგ მიღებულ მნიშვნელობებს სიის ელემენტებს ამატებს (**UI ნაკადზე**):

```csharp
var options = new ExecutionDataflowBlockOptions
{
    TaskScheduler = TaskScheduler.FromCurrentSynchronizationContext(),
};

var multiplyBlock = new TransformBlock<int, int>(item => item * 2);
var displayBlock = new ActionBlock<int>(
    result => ListBox.Items.Add(result), options);

multiplyBlock.LinkTo(displayBlock);
```

## განხილვა

`TaskScheduler`-ის მითითება განსაკუთრებით სასარგებლოა **თქვენი dataflow ბადის სხვადასხვა ნაწილში მყოფი ბლოკების მოქმედებების კოორდინირებისთვის**. მაგალითად, `ConcurrentExclusiveSchedulerPair.ExclusiveScheduler`-ით უზრუნველყოფთ, რომ A და C ბლოკებმა **არასდროს** შეასრულონ კოდი ერთდროულად, ხოლო B ბლოკს შესრულების უფლება ჰქონდეს, როცა უნდა.

> [!IMPORTANT] მხოლოდ შესრულებისას
> გახსოვდეთ, რომ `TaskScheduler`-ით სინქრონიზაცია მოქმედებს **მხოლოდ მაშინ, როცა კოდი სრულდება**. მაგალითად, თუ გაქვთ action ბლოკი, რომელიც ასინქრონულ კოდს უშვებს, და ექსკლუზიურ scheduler-ს ადებთ, კოდი **შესრულებადად არ ითვლება, სანამ ის `await`-ის მდგომარეობაშია**.

`TaskScheduler`-ს **ნებისმიერი სახის** dataflow ბლოკისთვის მიუთითებთ. მიუხედავად იმისა, რომ ბლოკმა შეიძლება თქვენი კოდი საერთოდ არ შეასრულოს (მაგალითად, `BufferBlock<T>`), მას მაინც აქვს **სამეურნეო (housekeeping)** ამოცანები, და ყველა შიდა სამუშაოსთვის მიწოდებულ `TaskScheduler`-ს გამოიყენებს.

> [!TIP] UI და dataflow
> `TaskScheduler.FromCurrentSynchronizationContext()` მხოლოდ მაშინ მუშაობს, როცა ის **UI ნაკადიდან იძახება**. თუ ბადეს ფონურ ნაკადზე აგებთ, scheduler წინასწარ, UI ნაკადზე უნდა დაიჭიროთ და შემდეგ გადასცეთ.

> [!NOTE] `MaxDegreeOfParallelism` და `TaskScheduler` ერთად
> თუ ბლოკს ორივე აქვს მითითებული, რეალური პარალელურობა **ორივე ლიმიტის მინიმუმია**. მაგალითად, `MaxDegreeOfParallelism = 10` scheduler-ზე, რომელიც მხოლოდ 4-ს უშვებს, რეალურად 4-ს მოგცემთ.
