## პრობლემა

პარალელურ კოდს იყენებთ და გაუქმების მხარდაჭერა გჭირდებათ.

## გადაწყვეტა

გაუქმების მხარდაჭერის უმარტივესი გზაა `CancellationToken`-ის პარალელურ კოდში გადაცემა. პარალელური მეთოდები ამას **`ParallelOptions`** ეგზემპლარის მიღებით უჭერს მხარს:

```csharp
void RotateMatrices(IEnumerable<Matrix> matrices, float degrees,
    CancellationToken token)
{
    Parallel.ForEach(matrices,
        new ParallelOptions { CancellationToken = token },
        matrix => matrix.Rotate(degrees));
}
```

ალტერნატივად, `CancellationToken`-ს პირდაპირ მარყუჟის სხეულშიც დააკვირდებით:

```csharp
void RotateMatrices2(IEnumerable<Matrix> matrices, float degrees,
    CancellationToken token)
{
    // გაფრთხილება: არარეკომენდებული, იხილეთ ქვემოთ.
    Parallel.ForEach(matrices, matrix =>
    {
        matrix.Rotate(degrees);
        token.ThrowIfCancellationRequested();
    });
}
```

*ნახაზი 10.5: რატომ სჯობს token პარამეტრად.*

ალტერნატიული მეთოდი **მეტ სამუშაოს** მოითხოვს და **ცუდად კომპოზირდება**, რადგან პარალელური მარყუჟი `OperationCanceledException`-ს `AggregateException`-ში გაახვევს. გარდა ამისა, თუ `CancellationToken`-ს `ParallelOptions`-ის ნაწილად გადასცემთ, `Parallel` კლასს უფრო **გონივრული გადაწყვეტილებების** მიღება შეუძლია იმის შესახებ, რამდენად ხშირად შეამოწმოს token. ამ მიზეზებით სჯობს, token პარამეტრად გადასცეთ. თუ token პარამეტრად გადასცემთ, შეგიძლიათ მარყუჟის სხეულშიც გადასცეთ, მაგრამ **მხოლოდ** სხეულში გადაცემა არასწორია.

### PLINQ

Parallel LINQ-საც აქვს გაუქმების ჩაშენებული მხარდაჭერა, **`WithCancellation`** ოპერატორით:

```csharp
IEnumerable<int> MultiplyBy2(IEnumerable<int> values,
    CancellationToken cancellationToken)
{
    return values.AsParallel()
        .WithCancellation(cancellationToken)
        .Select(item => item * 2);
}
```

## განხილვა

პარალელური სამუშაოსთვის გაუქმების მხარდაჭერა მომხმარებლის კარგი გამოცდილებისთვის **მნიშვნელოვანია**. თუ აპლიკაცია პარალელურ სამუშაოს ასრულებს, ის CPU-ს დიდ ნაწილს გამოიყენებს, სულ მცირე მოკლე დროით. CPU-ს მაღალი დატვირთვა ისეთი რამეა, რასაც მომხმარებლები **ამჩნევენ**, მაშინაც კი, თუ ის იმავე მანქანაზე სხვა აპლიკაციებს ხელს არ უშლის. ამიტომ ავტორი გირჩევთ, გაუქმებას მაშინაც უჭერდეთ მხარს, როცა პარალელურ გამოთვლას (ან სხვა CPU-ინტენსიურ სამუშაოს) ასრულებთ, მაშინაც კი, თუ CPU-ს მაღალ დატვირთვაზე დახარჯული საერთო დრო ძალიან დიდი არ არის.

> [!NOTE] `Parallel.ForEachAsync`
> .NET 6-დან `Parallel.ForEachAsync` `CancellationToken`-ს **პირდაპირ პარამეტრად** იღებს და თითოეულ სხეულს თავად გადასცემს:
> ```csharp
> await Parallel.ForEachAsync(urls, cancellationToken, async (url, token) =>
> {
>     await ProcessAsync(url, token);
> });
> ```

> [!WARNING] `AggregateException` და გაუქმება
> როცა `Parallel` მარყუჟი token-ით უქმდება, ის **სუფთა** `OperationCanceledException`-ს ისვრის და არა `AggregateException`-ს. მაგრამ თუ მარყუჟის სხეულმა **სხვა** გამონაკლისი ისროლა, ისინი `AggregateException`-ში გაიხვევა. ამიტომ `catch (OperationCanceledException)` და `catch (AggregateException)` ორივე უნდა გქონდეთ, თუ ორივე შემთხვევა შესაძლებელია.
