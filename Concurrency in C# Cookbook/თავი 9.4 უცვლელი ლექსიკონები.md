## პრობლემა

გჭირდებათ **გასაღები/მნიშვნელობის** კოლექცია, რომელიც ხშირად არ იცვლება და რომელზეც მრავალი ნაკადიდან უსაფრთხო წვდომაა შესაძლებელი. მაგალითად, შეიძლება გინდოდეთ **საცნობარო მონაცემების** შენახვა საძიებო კოლექციაში: საცნობარო მონაცემები იშვიათად იცვლება, მაგრამ სხვადასხვა ნაკადისთვის ხელმისაწვდომი უნდა იყოს.

## გადაწყვეტა

უცვლელი ლექსიკონის ორი ტიპი არსებობს: `ImmutableDictionary<TKey, TValue>` და `ImmutableSortedDictionary<TKey, TValue>`. როგორც სახელებიდან მიხვდებით, `ImmutableDictionary`-ის ელემენტების თანმიმდევრობა არაპროგნოზირებადია, `ImmutableSortedDictionary` კი უზრუნველყოფს, რომ მისი ელემენტები **დალაგებულია**.

ორივე ტიპს ძალიან მსგავსი წევრები აქვს:

```csharp
ImmutableDictionary<int, string> dictionary =
    ImmutableDictionary<int, string>.Empty;

dictionary = dictionary.Add(10, "ათი");
dictionary = dictionary.Add(21, "ოცდაერთი");
dictionary = dictionary.SetItem(10, "diez");

// გამოიტანს "10diez"-სა და "21ოცდაერთი"-ს არაპროგნოზირებადი თანმიმდევრობით.
foreach (KeyValuePair<int, string> item in dictionary)
    Trace.WriteLine(item.Key + item.Value);

string ten = dictionary[10];
// ten == "diez"

dictionary = dictionary.Remove(21);
```

ყურადღება მიაქციეთ **`SetItem`**-ის გამოყენებას. ცვალებად ლექსიკონში დაწერდით `dictionary[key] = item`-ს, მაგრამ უცვლელმა ლექსიკონებმა **განახლებული უცვლელი ლექსიკონი** უნდა დააბრუნონ, ამიტომ ისინი `SetItem` მეთოდს იყენებს.

```csharp
ImmutableSortedDictionary<int, string> sortedDictionary =
    ImmutableSortedDictionary<int, string>.Empty;

sortedDictionary = sortedDictionary.Add(10, "ათი");
sortedDictionary = sortedDictionary.Add(21, "ოცდაერთი");
sortedDictionary = sortedDictionary.SetItem(10, "diez");

// გამოიტანს "10diez"-ს და შემდეგ "21ოცდაერთი"-ს.
foreach (KeyValuePair<int, string> item in sortedDictionary)
    Trace.WriteLine(item.Key + item.Value);

string ten = sortedDictionary[10];
// ten == "diez"

sortedDictionary = sortedDictionary.Remove(21);
```

დაულაგებელ და დალაგებულ ლექსიკონებს მსგავსი წარმადობა აქვთ, მაგრამ ავტორი გირჩევთ, **დაულაგებელი** გამოიყენოთ, თუ ელემენტების დალაგება არ გჭირდებათ. დაულაგებელი ლექსიკონები საერთო ჯამში ოდნავ უფრო სწრაფია. გარდა ამისა, დაულაგებელი ლექსიკონები **ნებისმიერი** გასაღების ტიპთან მუშაობს, დალაგებული ლექსიკონები კი მოითხოვს, რომ მათი გასაღების ტიპი **სრულად შედარებადი** იყოს.

## განხილვა

ავტორის გამოცდილებით, ლექსიკონები აპლიკაციის მდგომარეობასთან მუშაობისას გავრცელებული და სასარგებლო ინსტრუმენტია. ისინი ნებისმიერი სახის გასაღები/მნიშვნელობის ან საძიებო სცენარში გამოიყენება.

სხვა უცვლელი კოლექციების მსგავსად, უცვლელ ლექსიკონებსაც **builder**-ის მექანიზმი აქვთ ეფექტური აგებისთვის, თუ ლექსიკონი ბევრ ელემენტს შეიცავს. მაგალითად, თუ საწყის საცნობარო მონაცემებს გაშვებისას ტვირთავთ, builder-ის მექანიზმი უნდა გამოიყენოთ საწყისი უცვლელი ლექსიკონის ასაგებად. მეორე მხრივ, თუ საცნობარო მონაცემები **თანდათან** გროვდება აპლიკაციის მუშაობის დროს, ჩვეულებრივი `Add` მეთოდის გამოყენება, სავარაუდოდ, მისაღებია.

> [!TIP] პაკეტი
> `ImmutableDictionary<TK, TV>` და `ImmutableSortedDictionary<TK, TV>` `System.Collections.Immutable` NuGet პაკეტშია.

> [!NOTE] O(log N) ყველგან
> ჩვეულებრივი `Dictionary<TK,TV>`-ისგან განსხვავებით, სადაც საშუალო წვდომა **O(1)**-ია, უცვლელი ლექსიკონის წვდომა **O(log N)**-ია, რადგან ისიც ხეზეა აგებული. პრაქტიკაში ეს იშვიათად პრობლემაა, მაგრამ ცხელ ციკლში გასათვალისწინებელია.
