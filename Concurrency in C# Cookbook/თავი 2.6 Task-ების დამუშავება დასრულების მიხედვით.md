## პრობლემა

გაქვთ task-ების კოლექცია, რომლებსაც უნდა დაელოდოთ, და თითოეულის დასრულების შემდეგ რაღაც დამუშავება გინდათ. ოღონდ დამუშავება თითოეულისთვის უნდა მოხდეს **მისი დასრულებისთანავე**, სხვების მოცდის გარეშე.

შემდეგი კოდი სამ დაყოვნების task-ს იწყებს და თითოეულს რიგრიგობით ელოდება:

```csharp
async Task<int> DelayAndReturnAsync(int value)
{
    await Task.Delay(TimeSpan.FromSeconds(value));
    return value;
}

// ამჟამად ეს მეთოდი ბეჭდავს "2", "3", "1".
// სასურველი ქცევაა: "1", "2", "3".
async Task ProcessTasksAsync()
{
    Task<int> taskA = DelayAndReturnAsync(2);
    Task<int> taskB = DelayAndReturnAsync(3);
    Task<int> taskC = DelayAndReturnAsync(1);
    Task<int>[] tasks = new[] { taskA, taskB, taskC };

    // თითოეულს რიგის მიხედვით ველოდებით
    foreach (Task<int> task in tasks)
    {
        var result = await task;
        Trace.WriteLine(result);
    }
}
```

კოდი task-ებს **თანმიმდევრობის რიგით** ელოდება, თუმცა მესამე task სრულდება პირველი. გვინდა, რომ დამუშავება (`Trace.WriteLine`) თითოეული task-ის დასრულებისთანავე მოხდეს, სხვების მოცდის გარეშე.

## გადაწყვეტა

პრობლემის გადაჭრის რამდენიმე გზა არსებობს. აქ აღწერილი პირველი მიდგომა **რეკომენდებულია**, მეორე „განხილვის" ნაწილშია.

უმარტივესი გადაწყვეტაა კოდის **რესტრუქტურიზაცია**: შემოვიღოთ უფრო მაღალი დონის `async` მეთოდი, რომელიც task-ის ლოდინსაც და შედეგის დამუშავებასაც აერთიანებს. როცა დამუშავება ცალკე მეთოდში გამოვიტანთ, კოდი მნიშვნელოვნად მარტივდება:

```csharp
async Task<int> DelayAndReturnAsync(int value)
{
    await Task.Delay(TimeSpan.FromSeconds(value));
    return value;
}

async Task AwaitAndProcessAsync(Task<int> task)
{
    int result = await task;
    Trace.WriteLine(result);
}

// ახლა ეს მეთოდი ბეჭდავს "1", "2", "3".
async Task ProcessTasksAsync()
{
    Task<int> taskA = DelayAndReturnAsync(2);
    Task<int> taskB = DelayAndReturnAsync(3);
    Task<int> taskC = DelayAndReturnAsync(1);
    Task<int>[] tasks = new[] { taskA, taskB, taskC };

    IEnumerable<Task> taskQuery = from t in tasks select AwaitAndProcessAsync(t);
    Task[] processingTasks = taskQuery.ToArray();

    // ველოდებით, სანამ მთელი დამუშავება დასრულდება
    await Task.WhenAll(processingTasks);
}
```

იგივე შეიძლება უფრო კომპაქტურადაც დაიწეროს:

```csharp
async Task ProcessTasksAsync()
{
    Task<int>[] tasks = new[]
    {
        DelayAndReturnAsync(2),
        DelayAndReturnAsync(3),
        DelayAndReturnAsync(1)
    };

    Task[] processingTasks = tasks.Select(async t =>
    {
        var result = await t;
        Trace.WriteLine(result);
    }).ToArray();

    await Task.WhenAll(processingTasks);
}
```

ეს რეფაქტორინგი ამ პრობლემის ყველაზე სუფთა და გადატანადი გადაწყვეტაა.

> [!WARNING] ერთი განსხვავება
> ეს გადაწყვეტა საწყისი კოდისგან ოდნავ განსხვავდება: დამუშავება **კონკურენტულად** ხდება, მაშინ როცა საწყისი კოდი მას სათითაოდ აკეთებდა. ჩვეულებრივ ეს პრობლემა არ არის, მაგრამ თუ თქვენს სიტუაციაში მიუღებელია, გამოიყენეთ საკეტები ([[თავი 12.2 ასინქრონული ბლოკირებები|12.2]]) ან ქვემოთ აღწერილი ალტერნატივა.

## განხილვა: `OrderByCompletion`

თუ რეფაქტორინგი მისაღები არ არის, ალტერნატივაც არსებობს. Stephen Toub-მა და Jon Skeet-მა შექმნეს გაფართოების მეთოდი, რომელიც აბრუნებს task-ების მასივს, რომლებიც **დასრულების რიგით** სრულდება.

> [!TIP] AsyncEx
> `OrderByCompletion` გაფართოების მეთოდი ხელმისაწვდომია ღია კოდის **AsyncEx** ბიბლიოთეკაში (`Nito.AsyncEx` NuGet პაკეტი).

```csharp
// ახლა ეს მეთოდი ბეჭდავს "1", "2", "3".
async Task UseOrderByCompletionAsync()
{
    Task<int>[] tasks = new[]
    {
        DelayAndReturnAsync(2),
        DelayAndReturnAsync(3),
        DelayAndReturnAsync(1)
    };

    // თითოეულს ველოდებით მათი დასრულების რიგით
    foreach (Task<int> task in tasks.OrderByCompletion())
    {
        int result = await task;
        Trace.WriteLine(result);
    }
}
```

`OrderByCompletion`-ის მსგავსი გაფართოების მეთოდი საწყის კოდში ცვლილებებს მინიმუმამდე ამცირებს. მისი იმპლემენტაცია შიგნით `TaskCompletionSource<T>`-ების მასივს და `ContinueWith`-ს იყენებს, ამიტომ **O(N)** სირთულისაა, `WhenAny`-ის ციკლის O(N²)-ისგან განსხვავებით.

> [!NOTE] თანამედროვე .NET
> თუ `IAsyncEnumerable<T>` ხელმისაწვდომია, იგივე შედეგი ასინქრონული ნაკადითაც მიიღწევა: შედეგებს დასრულების მიხედვით ვაბრუნებთ (`yield return`), და გამომძახებელი მათ `await foreach`-ით ამუშავებს ([[თავი 3.2 ასინქრონული ნაკადების მოხმარება|3.2]]). ასევე, `Channel<T>`-ის მწარმოებელ-მომხმარებლის ნიმუშიც გამოდგება ([[თავი 9.8 ასინქრონული რიგები|9.8]]).
