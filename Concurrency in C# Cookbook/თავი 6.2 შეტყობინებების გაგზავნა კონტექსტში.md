## პრობლემა

`System.Reactive` ცდილობს, **ნაკადებისადმი აგნოსტიკური** იყოს: ის შეტყობინებებს (მაგალითად, `OnNext`) იმ ნაკადზე ისვრის, რომელიც მიმდინარე აღმოჩნდება. ყოველი `OnNext` თანმიმდევრულად ხდება, მაგრამ **სულაც არა აუცილებლად ერთსა და იმავე ნაკადზე**.

ხშირად გვინდა, რომ ეს შეტყობინებები კონკრეტულ კონტექსტში მოხდეს. მაგალითად, UI ელემენტები მხოლოდ იმ UI ნაკადიდან უნდა შეიცვალოს, რომელსაც ისინი ეკუთვნის. ამიტომ, თუ UI-ს thread pool-ის ნაკადზე მოსულ შეტყობინებაზე პასუხად ვანახლებთ, **UI ნაკადზე გადასვლა** დაგვჭირდება.

## გადაწყვეტა

`System.Reactive` გვთავაზობს **`ObserveOn`** ოპერატორს, რომელიც შეტყობინებებს სხვა **scheduler**-ზე გადაიტანს.

განვიხილოთ მაგალითი, სადაც `Interval` ოპერატორი წამში ერთხელ `OnNext` შეტყობინებას ქმნის:

```csharp
private void Button_Click(object sender, RoutedEventArgs e)
{
    Trace.WriteLine($"UI ნაკადია {Environment.CurrentManagedThreadId}");

    Observable.Interval(TimeSpan.FromSeconds(1))
        .Subscribe(x => Trace.WriteLine(
            $"Interval {x} ნაკადზე {Environment.CurrentManagedThreadId}"));
}
```

შედეგი:

```
UI ნაკადია 9
Interval 0 ნაკადზე 10
Interval 1 ნაკადზე 10
Interval 2 ნაკადზე 11
Interval 3 ნაკადზე 11
Interval 4 ნაკადზე 10
```

რადგან `Interval` ტაიმერზეა აგებული (კონკრეტული ნაკადის გარეშე), შეტყობინებები **thread pool-ის ნაკადზე** ისვრება და არა UI ნაკადზე. თუ UI ელემენტის განახლება გჭირდებათ, შეტყობინებები `ObserveOn`-ში უნდა გაატაროთ და UI ნაკადის სინქრონიზაციის კონტექსტი გადასცეთ:

```csharp
private void Button_Click(object sender, RoutedEventArgs e)
{
    SynchronizationContext uiContext = SynchronizationContext.Current;

    Observable.Interval(TimeSpan.FromSeconds(1))
        .ObserveOn(uiContext)
        .Subscribe(x => Trace.WriteLine(
            $"Interval {x} ნაკადზე {Environment.CurrentManagedThreadId}"));
}
```

### UI ნაკადიდან გასვლა და დაბრუნება

`ObserveOn`-ის კიდევ ერთი გავრცელებული გამოყენებაა **UI ნაკადიდან გასვლა**, როცა ეს საჭიროა. დავუშვათ, თაგვის ყოველ მოძრაობაზე მძიმე CPU გამოთვლა გვჭირდება. ნაგულისხმევად ყველა მოძრაობა UI ნაკადზე ისვრება, ამიტომ `ObserveOn`-ით შეტყობინებებს thread pool-ზე გადავიტანთ, გამოთვლას იქ გავაკეთებთ, და შედეგებს UI ნაკადზე დავაბრუნებთ:

```csharp
SynchronizationContext uiContext = SynchronizationContext.Current;

Observable.FromEventPattern<MouseEventHandler, MouseEventArgs>(
        handler => (s, a) => handler(s, a),
        handler => MouseMove += handler,
        handler => MouseMove -= handler)
    .Select(evt => evt.EventArgs.GetPosition(this))
    .ObserveOn(Scheduler.Default)                 // → thread pool
    .Select(position =>
    {
        // რთული გამოთვლა
        Thread.Sleep(100);
        return position.X + position.Y;
    })
    .ObserveOn(uiContext)                         // → უკან UI-ზე
    .Subscribe(x => Trace.WriteLine(
        $"შედეგი {x} ნაკადზე {Environment.CurrentManagedThreadId}"));
```

თუ ამ მაგალითს გაუშვებთ, დაინახავთ, რომ გამოთვლები thread pool-ის ნაკადზე ხდება, შედეგები კი UI ნაკადზე იბეჭდება. მაგრამ ასევე შეამჩნევთ, რომ **გამოთვლები და შედეგები შემავალ მონაცემებს ჩამორჩება**: ისინი რიგში დგება, რადგან თაგვის პოზიცია 100 მილიწამზე უფრო ხშირად განახლდება. Rx-ს ამის რამდენიმე გადაწყვეტა აქვს, ყველაზე გავრცელებული **დროსელირებაა** ([[თავი 6.4 მოვლენების ნაკადის დამორჩილება|6.4]]).

## განხილვა

`ObserveOn` სინამდვილეში შეტყობინებებს `System.Reactive`-ის **scheduler**-ზე გადააქვს. ამ რეცეპტში ნაგულისხმევი (thread pool) scheduler და UI scheduler-ის შექმნის ერთი გზა განვიხილეთ. `ObserveOn`-ის ყველაზე გავრცელებული გამოყენებაა UI ნაკადზე გადასვლა და მისგან გასვლა, მაგრამ scheduler-ები სხვა სცენარებშიც სასარგებლოა. უფრო რთული მაგალითია **დროის გასვლის იმიტაცია ერთეულოვან ტესტებში** ([[თავი 7.6 System.Reactive-ის ტესტირება scheduler-ით|7.6]]).

> [!TIP] კიდევ ერთხელ: `ObserveOn` ≠ `SubscribeOn`
> **`ObserveOn`** observable-ის **შეტყობინებების** კონტექსტს აკონტროლებს. **`SubscribeOn`** კი იმ კოდის კონტექსტს, რომელიც event handler-ებს ამატებს და აშორებს ([[თავი 6.1 .NET მოვლენების გარდაქმნა|6.1]]).

> [!NOTE] UI scheduler-ები
> `SynchronizationContext.Current`-ის გადაცემის ნაცვლად, პლატფორმის სპეციფიკური scheduler-ებიც არსებობს: `DispatcherScheduler.Current` (WPF), `ControlScheduler` (WinForms), `CoreDispatcherScheduler` (UWP). ისინი `System.Reactive`-ის შესაბამის პაკეტებშია.
