## პრობლემა

გჭირდებათ მონაცემთა სტრუქტურა, რომელსაც **დუბლიკატების** შენახვა არ სჭირდება, ხშირად არ იცვლება და რომელზეც მრავალი ნაკადიდან უსაფრთხო წვდომაა შესაძლებელი.

მაგალითად, ფაილიდან ამოღებული სიტყვების ინდექსი სიმრავლის კარგი გამოყენების შემთხვევაა.

## გადაწყვეტა

უცვლელი სიმრავლის **ორი** ტიპი არსებობს: `ImmutableHashSet<T>` უნიკალური ელემენტების კოლექციაა, ხოლო `ImmutableSortedSet<T>` უნიკალური ელემენტების **დალაგებული** კოლექცია. ორივეს მსგავსი ინტერფეისი აქვს:

```csharp
ImmutableHashSet<int> hashSet = ImmutableHashSet<int>.Empty;
hashSet = hashSet.Add(13);
hashSet = hashSet.Add(7);

// გამოიტანს "7"-სა და "13"-ს არაპროგნოზირებადი თანმიმდევრობით.
foreach (int item in hashSet)
    Trace.WriteLine(item);

hashSet = hashSet.Remove(7);
```

მხოლოდ დალაგებული სიმრავლე უშვებს სიის მსგავს ინდექსირებას:

```csharp
ImmutableSortedSet<int> sortedSet = ImmutableSortedSet<int>.Empty;
sortedSet = sortedSet.Add(13);
sortedSet = sortedSet.Add(7);

// გამოიტანს "7"-ს და შემდეგ "13"-ს.
foreach (int item in sortedSet)
    Trace.WriteLine(item);

int smallestItem = sortedSet[0];
// smallestItem == 7

sortedSet = sortedSet.Remove(7);
```

*ნახაზი 9.3: დალაგებული და დაულაგებელი სიმრავლის არჩევანი.*

ავტორი გირჩევთ, **დაულაგებელი** სიმრავლე გამოიყენოთ, თუ დარწმუნებული არ ხართ, რომ დალაგება გჭირდებათ. ბევრი ტიპი მხოლოდ ძირითად **ტოლობას** უჭერს მხარს და არა სრულ **შედარებას**, ასე რომ დაულაგებელი სიმრავლე გაცილებით მეტ ტიპთან გამოიყენება.

დალაგებულ სიმრავლეზე ერთი მნიშვნელოვანი შენიშვნა: მისი ინდექსირება **O(log N)-ია და არა O(1)**, ისევე როგორც `ImmutableList<T>`-ის ([[თავი 9.2 უცვლელი სიები|9.2]]). ეს ნიშნავს, რომ იგივე გაფრთხილება მოქმედებს: `ImmutableSortedSet<T>`-თან, სადაც შესაძლებელია, **`for`-ის ნაცვლად `foreach`** გამოიყენეთ.

## განხილვა

უცვლელი სიმრავლეები სასარგებლო მონაცემთა სტრუქტურებია, მაგრამ **დიდი** უცვლელი სიმრავლის შევსება შეიძლება ნელი იყოს. უცვლელ კოლექციებს უმეტესად აქვთ სპეციალური **builder**-ები, რომლებითაც მათ სწრაფად, ცვალებადი გზით ავაგებთ და შემდეგ უცვლელ კოლექციად გადავაქცევთ. ეს ბევრ უცვლელ კოლექციაზე ვრცელდება, მაგრამ ავტორისთვის ისინი სწორედ **უცვლელ სიმრავლეებთან** აღმოჩნდა ყველაზე სასარგებლო.

```csharp
// ეფექტური აგება builder-ით
ImmutableHashSet<string>.Builder builder = ImmutableHashSet.CreateBuilder<string>();
foreach (string word in words)
    builder.Add(word);          // ცვალებადი, სწრაფი

ImmutableHashSet<string> index = builder.ToImmutable();
```

> [!TIP] პაკეტი
> `ImmutableHashSet<T>` და `ImmutableSortedSet<T>` `System.Collections.Immutable` NuGet პაკეტშია.

> [!NOTE] სიმრავლის ოპერაციები
> ორივე ტიპი `Union`, `Intersect`, `Except`, `SymmetricExcept`, `IsSubsetOf`, `Overlaps` და სხვა ჩვეულებრივ სიმრავლურ ოპერაციებს უჭერს მხარს, და ისინიც ახალ უცვლელ სიმრავლეს აბრუნებს.
