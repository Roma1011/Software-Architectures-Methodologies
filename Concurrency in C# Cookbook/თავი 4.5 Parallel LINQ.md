## პრობლემა

გჭირდებათ მონაცემების თანმიმდევრობის პარალელური დამუშავება, რომ ახალი თანმიმდევრობა ან ამ მონაცემების შეჯამება მიიღოთ.

## გადაწყვეტა

დეველოპერების უმეტესობა იცნობს LINQ-ს, რომლითაც თანმიმდევრობებზე **pull**-ზე დაფუძნებულ გამოთვლებს ვწერთ. **Parallel LINQ (PLINQ)** ამ მხარდაჭერას პარალელურ დამუშავებას ამატებს.

PLINQ კარგად მუშაობს **ნაკადურ** სცენარებში, როცა შემავალი თანმიმდევრობა გაქვთ და გამომავალს აწარმოებთ. მარტივი მაგალითი თითოეულ ელემენტს ორზე ამრავლებს (რეალურ სცენარებში დამუშავება გაცილებით მძიმე იქნება):

```csharp
IEnumerable<int> MultiplyBy2(IEnumerable<int> values)
{
    return values.AsParallel().Select(value => value * 2);
}
```

ეს მაგალითი შედეგებს **ნებისმიერი თანმიმდევრობით** შეიძლება აწარმოებდეს: ეს PLINQ-ის ნაგულისხმევი ქცევაა. თანმიმდევრობის შენარჩუნებაც შეიძლება მივუთითოთ. კოდი მაინც პარალელურად მუშავდება, მაგრამ საწყის რიგს ინარჩუნებს:

```csharp
IEnumerable<int> MultiplyBy2(IEnumerable<int> values)
{
    return values.AsParallel().AsOrdered().Select(value => value * 2);
}
```

PLINQ-ის კიდევ ერთი ბუნებრივი გამოყენებაა მონაცემების პარალელური აგრეგირება ან შეჯამება:

```csharp
int ParallelSum(IEnumerable<int> values)
{
    return values.AsParallel().Sum();
}
```

## განხილვა

`Parallel` კლასი ბევრ სცენარში კარგია, მაგრამ **PLINQ-ის კოდი უფრო მარტივია**, როცა აგრეგირებას ან ერთი თანმიმდევრობის მეორედ გარდაქმნას ვაკეთებთ.

> [!WARNING] სერვერზე სიფრთხილე
> გაითვალისწინეთ, რომ `Parallel` კლასი სისტემის სხვა პროცესებს **უფრო თავაზიანად** ეპყრობა, ვიდრე PLINQ. ეს განსაკუთრებით მნიშვნელოვანია, თუ პარალელური დამუშავება **სერვერზე** ხდება.

PLINQ ოპერატორების ფართო სპექტრის პარალელურ ვერსიებს იძლევა: ფილტრაცია (`Where`), პროექცია (`Select`), და აგრეგირების მრავალი სახე (`Sum`, `Average`, უფრო ზოგადი `Aggregate`). ზოგადად, რაც ჩვეულებრივი LINQ-ით შეგიძლიათ, პარალელურადაც შეგიძლიათ PLINQ-ით. ამიტომ PLINQ განსაკუთრებით მაშინ გამოგადგებათ, როცა LINQ კოდი უკვე დაწერილი გაქვთ და მისი პარალელურად გაშვებას აზრი აქვს.

| საშუალება | უპირატესობა |
|---|---|
| `Parallel.ForEach` | სისტემის დატვირთვაზე რეაგირებს, `Stop`/`Break`, ლოკალური აგრეგირება |
| PLINQ | კომპოზიციური, გამომსახველი, ბუნებრივი აგრეგირება და გარდაქმნა |

> [!TIP] PLINQ-ის სასარგებლო ოპერატორები
> - **`WithDegreeOfParallelism(n)`**: ერთდროულად მომუშავე ამოცანების მაქსიმალური რაოდენობა.
> - **`WithCancellation(token)`**: მოთხოვნის გაუქმება ([[თავი 10.5 პარალელური კოდის გაუქმება|10.5]]).
> - **`AsSequential()`**: პარალელური მუშაობიდან სინქრონულზე დაბრუნება მოთხოვნის შუაში.
> - **`ForAll(action)`**: შედეგების პარალელურად დამუშავება გაერთიანების გარეშე (როცა დასაბრუნებელი თანმიმდევრობა არ გჭირდებათ).

> [!WARNING] როდის არ ღირს PLINQ
> თუ თითოეულ ელემენტზე სამუშაო **ძალიან მცირეა** (მაგალითად, უბრალო გამრავლება), დანაწილებისა და გაერთიანების ხარჯი მოგებას გადააჭარბებს, და PLINQ ჩვეულებრივ LINQ-ზე **ნელი** იქნება. ასევე, PLINQ **I/O-სთვის არ არის**: იქ `async` და `Task.WhenAll` ან `Parallel.ForEachAsync` სჭირდება.
