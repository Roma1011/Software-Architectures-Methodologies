## პრობლემა

გჭირდებათ არხი, რომლითაც შეტყობინებებს ან მონაცემებს კოდის ერთი ნაწილიდან მეორეს გადასცემთ **პირველი შემოსული, პირველი გამოსული** წესით, **ნაკადების დაბლოკვის გარეშე**.

მაგალითად, კოდის ერთი ნაწილი მონაცემებს ტვირთავს და ჩატვირთვისთანავე არხში აგდებს. ამავდროულად, UI ნაკადი მონაცემებს იღებს და აჩვენებს.

## გადაწყვეტა

გჭირდებათ რიგი **ასინქრონული API**-თ. .NET-ის ბირთვში ასეთი ტიპი არ არის, მაგრამ NuGet-ში რამდენიმე ვარიანტია.

### ვარიანტი 1: Channels

პირველი ვარიანტია **Channels**. ეს არის ასინქრონული მწარმოებელი/მომხმარებლის კოლექციების თანამედროვე ბიბლიოთეკა, რომელიც განსაკუთრებულ ყურადღებას უთმობს **მაღალ წარმადობას** დიდი მოცულობის სცენარებში. მწარმოებლები ელემენტებს არხში `WriteAsync`-ით წერენ, და როცა ყველა დაასრულებს წარმოებას, ერთ-ერთი მათგანი `Complete`-ს იძახებს:

```csharp
Channel<int> queue = Channel.CreateUnbounded<int>();

// მწარმოებლის კოდი
ChannelWriter<int> writer = queue.Writer;
await writer.WriteAsync(7);
await writer.WriteAsync(13);
writer.Complete();

// მომხმარებლის კოდი
// გამოიტანს "7"-ს და შემდეგ "13"-ს.
ChannelReader<int> reader = queue.Reader;
await foreach (int value in reader.ReadAllAsync())
    Trace.WriteLine(value);
```

მომხმარებლის ეს, უფრო ბუნებრივი კოდი **ასინქრონულ ნაკადებს** იყენებს ([[თავი 3.1 ასინქრონული ნაკადების შესავალი|3.1]]). ძველ პლატფორმებზე შემდეგი შაბლონი გამოიყენება:

```csharp
// მომხმარებლის კოდი (ძველი პლატფორმები)
// გამოიტანს "7"-ს და შემდეგ "13"-ს.
ChannelReader<int> reader = queue.Reader;
while (await reader.WaitToReadAsync())
    while (reader.TryRead(out int value))
        Trace.WriteLine(value);
```

### ვარიანტი 2: `BufferBlock<T>`

მწარმოებელი/მომხმარებლის რიგის კიდევ ერთი ვარიანტია `BufferBlock<T>` TPL Dataflow ბიბლიოთეკიდან. ის არხს საკმაოდ ჰგავს:

```csharp
var _asyncQueue = new BufferBlock<int>();

// მწარმოებლის კოდი
await _asyncQueue.SendAsync(7);
await _asyncQueue.SendAsync(13);
_asyncQueue.Complete();

// მომხმარებლის კოდი
// გამოიტანს "7"-ს და შემდეგ "13"-ს.
while (await _asyncQueue.OutputAvailableAsync())
    Trace.WriteLine(await _asyncQueue.ReceiveAsync());
```

> [!WARNING] `OutputAvailableAsync` მხოლოდ ერთი მომხმარებლისთვის
> მომხმარებლის მაგალითი `OutputAvailableAsync`-ს იყენებს, რაც სინამდვილეში მხოლოდ მაშინაა სასარგებლო, თუ **ერთადერთი** მომხმარებელი გყავთ. თუ რამდენიმეა, შესაძლებელია, `OutputAvailableAsync`-მა `true` დააბრუნოს ერთზე მეტი მომხმარებლისთვის, მაშინაც კი, როცა მხოლოდ ერთი ელემენტია. თუ რიგი დასრულებულია, `ReceiveAsync` `InvalidOperationException`-ს ისვრის.

რამდენიმე მომხმარებლის შემთხვევაში კოდი, როგორც წესი, ასე გამოიყურება:

```csharp
while (true)
{
    int item;
    try
    {
        item = await _asyncQueue.ReceiveAsync();
    }
    catch (InvalidOperationException)
    {
        break;
    }
    Trace.WriteLine(item);
}
```

### ვარიანტი 3: `AsyncProducerConsumerQueue<T>`

`Nito.AsyncEx` ბიბლიოთეკის ტიპიც გამოდგება. API მსგავსია, მაგრამ არა იდენტური:

```csharp
var _asyncQueue = new AsyncProducerConsumerQueue<int>();

// მწარმოებლის კოდი
await _asyncQueue.EnqueueAsync(7);
await _asyncQueue.EnqueueAsync(13);
_asyncQueue.CompleteAdding();

// მომხმარებლის კოდი
// გამოიტანს "7"-ს და შემდეგ "13"-ს.
while (await _asyncQueue.OutputAvailableAsync())
    Trace.WriteLine(await _asyncQueue.DequeueAsync());
```

ესეც `OutputAvailableAsync`-ს იყენებს და იგივე პრობლემები აქვს, რაც `BufferBlock<T>`-ს. რამდენიმე მომხმარებლის შემთხვევაში:

```csharp
while (true)
{
    int item;
    try
    {
        item = await _asyncQueue.DequeueAsync();
    }
    catch (InvalidOperationException)
    {
        break;
    }
    Trace.WriteLine(item);
}
```

## განხილვა

ავტორი გირჩევთ, ასინქრონული მწარმოებელი/მომხმარებლის რიგებისთვის, სადაც შესაძლებელია, **Channels** გამოიყენოთ. მათ დროსელირების გარდა შერჩევის რამდენიმე ვარიანტი აქვთ და მაღალოპტიმიზებულია.

თუმცა, თუ თქვენი აპლიკაციის ლოგიკა „მილსადენად" გამოისახება, რომლითაც მონაცემები მიედინება, TPL Dataflow უფრო ბუნებრივი არჩევანი შეიძლება იყოს. ბოლო ვარიანტია `AsyncProducerConsumerQueue<T>`, რომელსაც აზრი აქვს, თუ აპლიკაცია AsyncEx-ის სხვა ტიპებსაც უკვე იყენებს.

> [!TIP] პაკეტები
> Channels არის `System.Threading.Channels`-ში, `BufferBlock<T>` არის `System.Threading.Tasks.Dataflow`-ში, ხოლო `AsyncProducerConsumerQueue<T>` არის `Nito.AsyncEx`-ში.

> [!NOTE] Channel-ის ოპტიმიზაციის პარამეტრები
> `UnboundedChannelOptions`/`BoundedChannelOptions`-ში `SingleReader = true` და `SingleWriter = true` მნიშვნელოვან ოპტიმიზაციას რთავს, თუ ზუსტად იცით, რომ ერთი მკითხველი/ერთი მწერალია. `AllowSynchronousContinuations = true` კი ალოკაციებს ამცირებს, მაგრამ გაგრძელებებს მწერლის ნაკადზე უშვებს (სიფრთხილით).
