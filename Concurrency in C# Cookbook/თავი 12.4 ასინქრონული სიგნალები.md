## პრობლემა

შეტყობინების გაგზავნა გჭირდებათ კოდის ერთი ნაწილიდან მეორეში, და შეტყობინების მიმღებმა ის **ასინქრონულად** უნდა დაელოდოს.

## გადაწყვეტა

### ერთჯერადი სიგნალი: `TaskCompletionSource<T>`

თუ შეტყობინება მხოლოდ **ერთხელ** უნდა გაიგზავნოს, `TaskCompletionSource<T>` გამოიყენეთ. გამგზავნი კოდი `TrySetResult`-ს იძახებს, მიმღები კოდი კი მის `Task` თვისებას ელოდება:

```csharp
class MyClass
{
    private readonly TaskCompletionSource<object> _initialized =
        new TaskCompletionSource<object>();

    private int _value1;
    private int _value2;

    public async Task<int> WaitForInitializationAsync()
    {
        await _initialized.Task;
        return _value1 + _value2;
    }

    public void Initialize()
    {
        _value1 = 13;
        _value2 = 17;
        _initialized.TrySetResult(null);
    }
}
```

`TaskCompletionSource<T>` ტიპი **ნებისმიერი** სიტუაციის ასინქრონულად ლოდინისთვის გამოიყენება, ამ შემთხვევაში კოდის სხვა ნაწილიდან შეტყობინებისთვის. ეს კარგად მუშაობს, თუ სიგნალი მხოლოდ ერთხელ იგზავნება, მაგრამ **ცუდად მუშაობს**, თუ სიგნალის ჩართვაც გჭირდებათ და გამორთვაც.

### მრავალჯერადი სიგნალი: `AsyncManualResetEvent`

`Nito.AsyncEx` ბიბლიოთეკა შეიცავს ტიპს **`AsyncManualResetEvent`**, რომელიც ასინქრონული კოდისთვის `ManualResetEvent`-ის დაახლოებითი ეკვივალენტია:

```csharp
class MyClass
{
    private readonly AsyncManualResetEvent _connected =
        new AsyncManualResetEvent();

    public async Task WaitForConnectedAsync()
    {
        await _connected.WaitAsync();
    }

    public void ConnectedChanged(bool connected)
    {
        if (connected)
            _connected.Set();
        else
            _connected.Reset();
    }
}
```

## განხილვა

სიგნალები ზოგადი დანიშნულების შეტყობინების მექანიზმია. მაგრამ:

- თუ ეს „სიგნალი" **შეტყობინებაა**, რომელიც კოდის ერთი ნაწილიდან მეორეში მონაცემებს აგზავნის, განიხილეთ **მწარმოებელი/მომხმარებლის რიგი** ([[თავი 9.8 ასინქრონული რიგები|9.8]]).
- ასევე, **არ გამოიყენოთ** ზოგადი დანიშნულების სიგნალები მხოლოდ გაზიარებულ მონაცემებზე წვდომის კოორდინირებისთვის: ამ სიტუაციაში **ასინქრონული ბლოკირება** გამოიყენეთ ([[თავი 12.2 ასინქრონული ბლოკირებები|12.2]]).

> [!TIP] პაკეტი
> `AsyncManualResetEvent` ტიპი `Nito.AsyncEx` NuGet პაკეტშია.

> [!IMPORTANT] `RunContinuationsAsynchronously`
> `TaskCompletionSource<T>`-ის სიგნალად გამოყენებისას გახსოვდეთ, რომ `TrySetResult` ნაგულისხმევად ყველა მლოდინის გაგრძელებას **სინქრონულად** უშვებს იმ ნაკადზე, რომელზეც `Initialize` გამოიძახეს. თუ ბევრი მლოდინეა, ან `Initialize` ბლოკირების ქვეშ იძახება, ეს სერიოზული პრობლემაა. გამოსავალი:
> ```csharp
> new TaskCompletionSource<object>(TaskCreationOptions.RunContinuationsAsynchronously)
> ```

> [!NOTE] .NET 5+: არაგენერიკული ვერსია
> `TaskCompletionSource<object>`-ისა და `TrySetResult(null)`-ის ნაცვლად .NET 5-დან უბრალოდ `TaskCompletionSource`-ია (ტიპის პარამეტრის გარეშე) და `TrySetResult()`.
