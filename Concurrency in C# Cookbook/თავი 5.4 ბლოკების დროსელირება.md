## პრობლემა

dataflow ბადეში **განშტოების (fork)** სცენარი გაქვთ და გინდათ, მონაცემები **დატვირთვის დაბალანსებით** მიედინებოდეს.

## გადაწყვეტა

ნაგულისხმევად, როცა ბლოკი გამომავალ მონაცემს აწარმოებს, ის თავის **ყველა ბმულს ათვალიერებს** (შექმნის რიგით) და მონაცემის თითო ბმულით გატარებას ცდილობს. ასევე ნაგულისხმევად, ყოველი ბლოკი შემავალ ბუფერს ინახავს და **ნებისმიერი რაოდენობის** მონაცემს იღებს, მაშინაც კი, როცა მათ დამუშავებას ვერ ასწრებს.

ეს პრობლემას ქმნის განშტოების სცენარში, სადაც ერთი source ბლოკი ორ target ბლოკს უკავშირდება: **მეორე ბლოკი შიმშილობს**. როცა source ბლოკი მონაცემს აწარმოებს, ის ცდილობს მას ყოველი ბმულით გაატაროს. პირველი target ბლოკი ყოველთვის იღებს მონაცემს და ბუფერში ინახავს, ამიტომ source ბლოკი მეორემდე **ვერასოდეს აღწევს**.

პრობლემა **`BoundedCapacity`** პარამეტრით წყდება. ნაგულისხმევად ის `DataflowBlockOptions.Unbounded`-ია, რაც სწორედ იმას იწვევს, რომ პირველი target ბლოკი ყველა მონაცემს ბუფერავს, მაშინაც კი, როცა მათ დამუშავებას არ ასწრებს. `BoundedCapacity` ნებისმიერ დადებით მნიშვნელობაზე შეიძლება დაყენდეს. სანამ target ბლოკები source ბლოკის ტემპს აუწყობენ ფეხს, მარტივი მნიშვნელობა **`1`** საკმარისია:

```csharp
var sourceBlock = new BufferBlock<int>();

var options = new DataflowBlockOptions { BoundedCapacity = 1 };
var targetBlockA = new BufferBlock<int>(options);
var targetBlockB = new BufferBlock<int>(options);

sourceBlock.LinkTo(targetBlockA);
sourceBlock.LinkTo(targetBlockB);
```

## განხილვა

დროსელირება (throttling) სასარგებლოა განშტოებაში დატვირთვის დასაბალანსებლად, მაგრამ სხვაგანაც გამოგვადგება, სადაც კი ასეთი ქცევა გვინდა.

მაგალითად, თუ ბადეს **I/O ოპერაციიდან** ავსებთ მონაცემებით, `BoundedCapacity` ბადის ბლოკებზე უნდა დააყენოთ. ასე **ზედმეტად ბევრ I/O მონაცემს არ წაიკითხავთ**, სანამ ბადე მათთვის მზად არ იქნება, და ბადე ყველა შემავალ მონაცემს არ დაიბუფერებს დამუშავებამდე.

> [!IMPORTANT] უკუწნევა (backpressure)
> `BoundedCapacity` dataflow-ის **უკუწნევის** მექანიზმია: როცა ბლოკი გადატვირთულია, ის უარს ამბობს ახალ მონაცემზე, და ეს „უარი" ჯაჭვით უკან, წყარომდე გადადის. ამის გარეშე სწრაფი მწარმოებელი ნელ მომხმარებელს მეხსიერებას გადაუვსებს.

> [!TIP] `SendAsync`
> როცა ბლოკს `BoundedCapacity` აქვს, `Post()` შეიძლება `false`-ს დააბრუნოს (მონაცემი უარყოფილია). ასეთ დროს **`await block.SendAsync(item)`** სჯობს: ის ასინქრონულად დაელოდება, სანამ ბლოკში ადგილი გაჩნდება.
