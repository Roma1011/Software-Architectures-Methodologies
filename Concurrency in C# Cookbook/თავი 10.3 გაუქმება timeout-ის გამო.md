## პრობლემა

გაქვთ კოდი, რომელმაც **timeout-ის შემდეგ** უნდა შეწყვიტოს მუშაობა.

## გადაწყვეტა

გაუქმება timeout-ის სიტუაციების **ბუნებრივი** გადაწყვეტაა. timeout გაუქმების მოთხოვნის უბრალოდ ერთი სახეობაა. კოდი, რომელიც უნდა გაუქმდეს, გაუქმების token-ს ისევე აკვირდება, როგორც ნებისმიერი სხვა გაუქმებისას: მან **არც უნდა იცოდეს და არც აინტერესებდეს**, რომ გაუქმების წყარო ტაიმერია.

`CancellationTokenSource`-ს აქვს მოსახერხებელი მეთოდები, რომლებიც გაუქმების მოთხოვნას **ტაიმერის მიხედვით ავტომატურად** გასცემს. timeout-ს კონსტრუქტორში გადასცემთ:

```csharp
async Task IssueTimeoutAsync()
{
    using var cts = new CancellationTokenSource(TimeSpan.FromSeconds(5));
    CancellationToken token = cts.Token;
    await Task.Delay(TimeSpan.FromSeconds(10), token);
}
```

ან, თუ `CancellationTokenSource`-ის ეგზემპლარი უკვე გაქვთ, ამ ეგზემპლარისთვის timeout-ს `CancelAfter`-ით გაუშვებთ:

```csharp
async Task IssueTimeoutAsync()
{
    using var cts = new CancellationTokenSource();
    CancellationToken token = cts.Token;
    cts.CancelAfter(TimeSpan.FromSeconds(5));
    await Task.Delay(TimeSpan.FromSeconds(10), token);
}
```

## განხილვა

timeout-ით კოდის შესასრულებლად `CancellationTokenSource` და `CancelAfter` (ან კონსტრუქტორი) გამოიყენეთ. იმავეს გაკეთების სხვა გზებიც არსებობს, მაგრამ არსებული გაუქმების სისტემის გამოყენება ყველაზე **ადვილი და ეფექტური** ვარიანტია.

გახსოვდეთ, რომ გასაუქმებელმა კოდმა გაუქმების token-ს **უნდა დააკვირდეს**: არაგაუქმებადი კოდის ადვილად გაუქმება შეუძლებელია.

> [!NOTE] თანამედროვე .NET: `Task.WaitAsync`
> .NET 6-დან არსებობს `task.WaitAsync(TimeSpan)`, რომელიც **ლოდინს** აყენებს timeout-ს ქვემდებარე ოპერაციის გაუქმების გარეშე. ეს სხვა რამეა, ვიდრე `CancelAfter`:
> - **`CancelAfter`**: ნამდვილად აუქმებს სამუშაოს (თუ ის თანამშრომლობს).
> - **`WaitAsync(timeout)`**: მხოლოდ **ლოდინს** წყვეტს `TimeoutException`-ით, სამუშაო კი ფონში აგრძელებს.
>
> როცა ორივე გინდათ, `WaitAsync(timeout, cancellationToken)` გადატვირთვა არსებობს.

> [!WARNING] `HttpClient.Timeout`
> `HttpClient`-ს საკუთარი `Timeout` თვისებაც აქვს. თუ თქვენს token-ს `CancelAfter`-ითაც აყენებთ, ორი timeout მოქმედებს ერთდროულად. .NET 5-მდე `HttpClient`-ის timeout-ი `TaskCanceledException`-ს ისროდა, რაც მომხმარებლის გაუქმებისგან განუსხვავებელი იყო. .NET 5-დან მის `InnerException`-ში `TimeoutException`-ია.
