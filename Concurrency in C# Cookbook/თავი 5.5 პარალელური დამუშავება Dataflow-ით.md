## პრობლემა

გინდათ dataflow ბადეში **პარალელური დამუშავების** შესრულება.

## გადაწყვეტა

ნაგულისხმევად, ყოველი dataflow ბლოკი სხვა ბლოკებისგან **დამოუკიდებელია**. როცა ორ ბლოკს ვაკავშირებთ, ისინი დამოუკიდებლად მუშავდება. ამიტომ ყოველ dataflow ბადეს გარკვეული **ბუნებრივი პარალელიზმი** უკვე აქვს: სანამ ბლოკი 2 პირველ ელემენტს ამუშავებს, ბლოკი 1 მეორეზე მუშაობს.

თუ ამაზე მეტი გჭირდებათ, მაგალითად, თუ ერთი კონკრეტული ბლოკი მძიმე CPU გამოთვლებს აკეთებს, ამ ბლოკს შეგიძლიათ უთხრათ, შემავალ მონაცემებზე **პარალელურად** იმუშაოს, **`MaxDegreeOfParallelism`** პარამეტრით. ნაგულისხმევად ის `1`-ია, ამიტომ ყოველი ბლოკი ერთდროულად მხოლოდ ერთ მონაცემს ამუშავებს:

```csharp
var multiplyBlock = new TransformBlock<int, int>(
    item => item * 2,
    new ExecutionDataflowBlockOptions
    {
        MaxDegreeOfParallelism = DataflowBlockOptions.Unbounded
    });

var subtractBlock = new TransformBlock<int, int>(item => item - 2);

multiplyBlock.LinkTo(subtractBlock);
```

## განხილვა

`MaxDegreeOfParallelism` ბლოკის შიგნით პარალელურ დამუშავებას ამარტივებს. რთული ის კია, **რომელ ბლოკს სჭირდება ის**. ერთი ტექნიკაა dataflow-ის შესრულების დებაგერში შეჩერება, სადაც დაინახავთ, რამდენი ელემენტი დგას რიგში (ანუ ჯერ დაუმუშავებელი). მოულოდნელად დიდი რაოდენობა ნიშანია, რომ რესტრუქტურიზაცია ან პარალელიზება გამოადგება.

**ასინქრონულ ბლოკებთანაც მუშაობს.** `MaxDegreeOfParallelism` მაშინაც მოქმედებს, როცა ბლოკი ასინქრონულ დამუშავებას აკეთებს (`TransformBlock<TIn, TOut>` `async` დელეგატით). ამ შემთხვევაში ის **კონკურენტულობის დონეს** განსაზღვრავს: გარკვეული რაოდენობის „სლოტს". ყოველი ელემენტი სლოტს იკავებს დამუშავების დაწყებისას და ათავისუფლებს მხოლოდ მაშინ, როცა ასინქრონული დამუშავება **სრულად** დასრულდება.

> [!WARNING] თანმიმდევრობა
> `MaxDegreeOfParallelism > 1`-ის დროს ელემენტები შეიძლება **სხვა თანმიმდევრობით** დამუშავდეს. თუმცა `TransformBlock` ნაგულისხმევად შედეგებს **შემავალი რიგით** გამოუშვებს (`EnsureOrdered = true`). თუ თანმიმდევრობა არ გჭირდებათ და მაქსიმალური გამტარუნარიანობა გინდათ, დააყენეთ `EnsureOrdered = false`.

> [!TIP] ორი პარამეტრი ერთად
> პრაქტიკაში `MaxDegreeOfParallelism` და `BoundedCapacity` ერთად გამოიყენება: პირველი განსაზღვრავს, **რამდენი** მუშავდება ერთდროულად, მეორე კი, **რამდენი ელოდება** რიგში:
> ```csharp
> new ExecutionDataflowBlockOptions
> {
>     MaxDegreeOfParallelism = 4,
>     BoundedCapacity = 8
> }
> ```
