## პრობლემა

გაქვთ მოვლენა, რომელიც შეიძლება `async` დამმუშავებლებთან გამოიყენოთ, და უნდა დაადგინოთ, **დასრულდნენ თუ არა** ეს დამმუშავებლები.

> [!NOTE] ეს იშვიათი სიტუაციაა
> ჩვეულებრივ, როცა მოვლენას აღძრავთ, **არ გაინტერესებთ**, როდის სრულდება დამმუშავებლები.

## გადაწყვეტა

`async void` დამმუშავებლების დაბრუნების დადგენა შეუძლებელია, ამიტომ ალტერნატიული გზა გვჭირდება. Universal Windows პლატფორმამ შემოიტანა ცნება **deferral** (გადავადება), რომლითაც ასინქრონული დამმუშავებლების თვალყურის დევნებაა შესაძლებელი. ასინქრონული დამმუშავებელი **პირველ `await`-ამდე** იღებს deferral-ს და მოგვიანებით, დასრულებისას, ატყობინებს მას. სინქრონულ დამმუშავებლებს deferral არ სჭირდებათ.

`Nito.AsyncEx` ბიბლიოთეკა შეიცავს ტიპს **`DeferralManager`**, რომელსაც მოვლენის აღმძვრელი კომპონენტი იყენებს. ეს მენეჯერი დამმუშავებლებს deferral-ების აღების უფლებას აძლევს და თვალს ადევნებს, როდის დასრულდება ყველა მათგანი.

### ნაბიჯი 1: მოვლენის არგუმენტების ტიპის გაფართოება

```csharp
public class MyEventArgs : EventArgs, IDeferralSource
{
    private readonly DeferralManager _deferrals = new DeferralManager();

    // ... საკუთარი კონსტრუქტორები და თვისებები

    public IDisposable GetDeferral()
    {
        return _deferrals.DeferralSource.GetDeferral();
    }

    internal Task WaitForDeferralsAsync()
    {
        return _deferrals.WaitForDeferralsAsync();
    }
}
```

> [!TIP] არგუმენტების ტიპი thread-safe იყოს
> ასინქრონულ დამმუშავებლებთან მუშაობისას სჯობს, მოვლენის არგუმენტების ტიპი **thread-safe** გახადოთ. ამის უმარტივესი გზაა მისი **უცვლელობა** (ყველა თვისება მხოლოდ-კითხვადი).

### ნაბიჯი 2: მოვლენის აღძვრა და ლოდინი

```csharp
public event EventHandler<MyEventArgs> MyEvent;

private async Task RaiseMyEventAsync()
{
    EventHandler<MyEventArgs> handler = MyEvent;
    if (handler == null)
        return;

    var args = new MyEventArgs(...);
    handler(this, args);
    await args.WaitForDeferralsAsync();
}
```

### ნაბიჯი 3: დამმუშავებელი deferral-ს იღებს

```csharp
async void AsyncHandler(object sender, MyEventArgs args)
{
    using IDisposable deferral = args.GetDeferral();
    await Task.Delay(TimeSpan.FromSeconds(2));
}
```

*ნახაზი 11.5: deferral-ების მექანიზმი.*

ეს ოდნავ განსხვავდება იმისგან, როგორ მუშაობს Universal Windows-ის deferral-ები. Universal Windows API-ში ყოველი მოვლენა, რომელსაც deferral სჭირდება, **საკუთარ** deferral ტიპს განსაზღვრავს, და ამ ტიპს `IDisposable`-ის ნაცვლად აშკარა `Complete` მეთოდი აქვს.

## განხილვა

.NET-ში ლოგიკურად **ორი განსხვავებული სახის** მოვლენა გამოიყენება, სრულიად სხვადასხვა სემანტიკით. ავტორი მათ **შეტყობინების მოვლენებს** და **ბრძანების მოვლენებს** უწოდებს (ეს ოფიციალური ტერმინოლოგია არ არის, უბრალოდ სიცხადისთვის არჩეული სიტყვებია).

| | **შეტყობინების მოვლენა** | **ბრძანების მოვლენა** |
|---|---|---|
| დანიშნულება | სხვა კომპონენტების **ინფორმირება** | გამგზავნის სახელით **ფუნქციონალის შესრულება** |
| მიმართულება | ცალმხრივი | გამგზავნი პასუხს ელოდება |
| გამგზავნს აინტერესებს მიმღები? | არა | **დიახ** |
| მაგალითები | ღილაკზე დაწკაპუნება | ცხოვრების ციკლის მოვლენები, `BackgroundWorker.DoWork`, ASP.NET-ის გვერდის მოვლენები, `Application.PageAppearing`, Visitor შაბლონი |
| `async` მხარდაჭერა | **არაფერია საჭირო** | **deferral-ები** |

**შეტყობინების მოვლენებს** ასინქრონული დამმუშავებლებისთვის სპეციალური კოდი **არ სჭირდება**: დამმუშავებლები შეიძლება `async void` იყოს და კარგად იმუშავებს. როცა გამგზავნი მოვლენას აღძრავს, ასინქრონული დამმუშავებლები მაშინვე არ სრულდება, მაგრამ ამას მნიშვნელობა არ აქვს, რადგან ეს მხოლოდ შეტყობინებებია. ანუ თუ თქვენი მოვლენა შეტყობინების მოვლენაა, ასინქრონული დამმუშავებლების მხარდასაჭერად სამუშაოს საერთო რაოდენობაა: **არაფერი**.

**ბრძანების მოვლენები** სხვა ამბავია. როცა ბრძანების მოვლენა გაქვთ, გჭირდებათ გზა, რომ დაადგინოთ, როდის დასრულდნენ დამმუშავებლები. ზემოთ მოცემული deferral-ებიანი გადაწყვეტა **მხოლოდ ბრძანების მოვლენებისთვის** უნდა გამოიყენოთ.

> [!TIP] პაკეტი
> `DeferralManager` ტიპი `Nito.AsyncEx` NuGet პაკეტშია.

> [!IMPORTANT] deferral პირველ `await`-ამდე უნდა აიღოთ
> თუ `GetDeferral()`-ს პირველი `await`-ის **შემდეგ** გამოიძახებთ, `WaitForDeferralsAsync` შეიძლება უკვე დასრულებული იყოს: deferral აღარაფერს დაელოდება. სწორედ ამიტომ არის `using IDisposable deferral = args.GetDeferral();` დამმუშავებლის **პირველი სტრიქონი**.
