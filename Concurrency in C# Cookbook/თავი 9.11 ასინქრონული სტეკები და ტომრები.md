## პრობლემა

გჭირდებათ არხი, რომლითაც შეტყობინებებს ან მონაცემებს კოდის ერთი ნაწილიდან მეორეს გადასცემთ, მაგრამ არ გინდათ (ან არ გჭირდებათ), რომ არხს პირველი შემოსული, პირველი გამოსული სემანტიკა ჰქონდეს.

## გადაწყვეტა

`Nito.AsyncEx` ბიბლიოთეკა გვთავაზობს ტიპს **`AsyncCollection<T>`**, რომელიც ნაგულისხმევად ასინქრონული რიგივითაა, მაგრამ ნებისმიერი სახის მწარმოებელი/მომხმარებლის კოლექციად შეუძლია მუშაობა. ის `IProducerConsumerCollection<T>`-ის გარსია და .NET-ის `BlockingCollection<T>`-ის **ასინქრონული ეკვივალენტია** ([[თავი 9.7 მბლოკავი სტეკები და ტომრები|9.7]]).

`AsyncCollection<T>` ბოლო შემოსული, პირველი გამოსული (სტეკი) ან დაულაგებელი (ტომარა) სემანტიკას უჭერს მხარს, იმის მიხედვით, რა კოლექციას გადასცემთ კონსტრუქტორს:

```csharp
var _asyncStack = new AsyncCollection<int>(new ConcurrentStack<int>());
var _asyncBag = new AsyncCollection<int>(new ConcurrentBag<int>());
```

> [!WARNING] რიგითობის რბოლის მდგომარეობა
> სტეკში ელემენტების რიგითობის გარშემო რბოლის მდგომარეობაა. თუ ყველა მწარმოებელი მომხმარებლების დაწყებამდე დაასრულებს, ელემენტების რიგითობა ჩვეულებრივი სტეკისაა:

```csharp
// მწარმოებლის კოდი
await _asyncStack.AddAsync(7);
await _asyncStack.AddAsync(13);
_asyncStack.CompleteAdding();

// მომხმარებლის კოდი
// გამოიტანს "13"-ს და შემდეგ "7"-ს.
while (await _asyncStack.OutputAvailableAsync())
    Trace.WriteLine(await _asyncStack.TakeAsync());
```

როცა მწარმოებლები და მომხმარებლები **ერთდროულად** მუშაობს (რაც ჩვეულებრივი შემთხვევაა), მომხმარებელი ყოველთვის ბოლოს დამატებულ ელემენტს მიიღებს შემდეგად. ამის გამო კოლექცია მთლიანობაში **სრულიად სტეკივით არ იქცევა**. ტომრის კოლექციას კი, რა თქმა უნდა, რიგითობა საერთოდ არ აქვს.

### დროსელირება

`AsyncCollection<T>`-ს დროსელირების მხარდაჭერა აქვს, რაც აუცილებელია, თუ მწარმოებლები კოლექციაში უფრო სწრაფად ამატებენ, ვიდრე მომხმარებლები შლიან. უბრალოდ შესაბამისი მნიშვნელობით ააგეთ კოლექცია:

```csharp
var _asyncStack = new AsyncCollection<int>(
    new ConcurrentStack<int>(), maxCount: 1);
```

ახლა იგივე მწარმოებლის კოდი საჭიროებისამებრ ასინქრონულად დაელოდება:

```csharp
// ეს Add მაშინვე სრულდება.
await _asyncStack.AddAsync(7);

// ეს Add (ასინქრონულად) ელოდება 7-ის ამოღებას,
// სანამ 13-ს ჩააყენებს.
await _asyncStack.AddAsync(13);

_asyncStack.CompleteAdding();
```

მომხმარებლის მაგალითი `OutputAvailableAsync`-ს იყენებს, რომელსაც [[თავი 9.8 ასინქრონული რიგები|9.8]]-ში აღწერილი იგივე შეზღუდვა აქვს. რამდენიმე მომხმარებლის შემთხვევაში კოდი ჩვეულებრივ ასე გამოიყურება:

```csharp
while (true)
{
    int item;
    try
    {
        item = await _asyncStack.TakeAsync();
    }
    catch (InvalidOperationException)
    {
        break;
    }
    Trace.WriteLine(item);
}
```

## განხილვა

`AsyncCollection<T>` უბრალოდ `BlockingCollection<T>`-ის ასინქრონული ეკვივალენტია, ოდნავ განსხვავებული API-თ.

> [!TIP] პაკეტი
> `AsyncCollection<T>` ტიპი `Nito.AsyncEx` NuGet პაკეტშია.

> [!NOTE] ჩაშენებული ალტერნატივა არ არსებობს
> .NET-ის ბირთვში `Channel`-ს **სტეკის ან ტომრის რეჟიმი არ აქვს**: ის მხოლოდ FIFO-ა. თუ LIFO სემანტიკა გჭირდებათ და AsyncEx-ზე დამოკიდებულება არ გინდათ, `ConcurrentStack<T>`-ს `SemaphoreSlim`-ის `WaitAsync`-თან ერთად გამოიყენებთ, მაგრამ პრაქტიკაში ასინქრონული სტეკის საჭიროება ძალიან იშვიათია.
