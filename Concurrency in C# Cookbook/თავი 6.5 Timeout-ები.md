## პრობლემა

მოვლენას გარკვეულ დროში ელოდებით და უნდა უზრუნველყოთ, რომ პროგრამა დროულად მოახდენს რეაგირებას **მაშინაც კი, თუ მოვლენა არ მოვა**. ყველაზე ხშირად ასეთი მოსალოდნელი მოვლენა ერთი ასინქრონული ოპერაციაა (მაგალითად, ვებ-სერვისის პასუხი).

## გადაწყვეტა

**`Timeout`** ოპერატორი შემავალ ნაკადზე **მოცურავე ლოდინის ფანჯარას** აყენებს. ყოველი ახალი მოვლენის მოსვლისას ფანჯარა თავიდან იწყება. თუ ფანჯარა მოვლენის გარეშე ამოიწურა, `Timeout` ნაკადს **`OnError`** შეტყობინებით ასრულებს, რომელიც `TimeoutException`-ს შეიცავს.

```csharp
void GetWithTimeout(HttpClient client)
{
    client.GetStringAsync("http://www.example.com/").ToObservable()
        .Timeout(TimeSpan.FromSeconds(1))
        .Subscribe(
            x => Trace.WriteLine($"{DateTime.Now.Second}: ვნახე {x.Length}"),
            ex => Trace.WriteLine(ex));
}
```

ვებ-მოთხოვნის დასაწყებად კოდი `ToObservable`-ს იყენებს, რომ `Task<T>` `IObservable<T>`-ად აქციოს ([[თავი 8.6 System.Reactive-ის Observable გარსები|8.6]]).

`Timeout` იდეალურია ასინქრონული ოპერაციებისთვის, მაგრამ ნებისმიერ მოვლენათა ნაკადზე გამოიყენება:

```csharp
Observable.FromEventPattern<MouseEventHandler, MouseEventArgs>(
        handler => (s, a) => handler(s, a),
        handler => MouseMove += handler,
        handler => MouseMove -= handler)
    .Select(x => x.EventArgs.GetPosition(this))
    .Timeout(TimeSpan.FromSeconds(1))
    .Subscribe(
        x => Trace.WriteLine($"{DateTime.Now.Second}: ვნახე {x.X + x.Y}"),
        ex => Trace.WriteLine(ex));
```

შედეგი, თუ თაგვს ცოტა ხანს ვამოძრავებთ და შემდეგ წამით გავაჩერებთ:

```
16: ვნახე 180
16: ვნახე 178
16: ვნახე 177
System.TimeoutException: The operation has timed out.
```

> [!WARNING] ნაკადი მთავრდება
> როგორც კი `TimeoutException` `OnError`-ში გაიგზავნება, **ნაკადი დასრულებულია**. თაგვის მოძრაობები აღარ მოვა.

### ალტერნატიული ნაკადი timeout-ის შემდეგ

შეიძლება ეს ქცევა არ გვინდოდეს. `Timeout`-ს აქვს გადატვირთვები, რომლებიც timeout-ის დროს ნაკადს exception-ით არ ასრულებს, არამედ **მეორე ნაკადს** უშვებს მის ნაცვლად. ქვემოთ კოდი თაგვის მოძრაობებს აკვირდება, სანამ timeout არ მოხდება. timeout-ის შემდეგ ის თაგვის **დაწკაპუნებებს** აკვირდება:

```csharp
IObservable<Point> clicks =
    Observable.FromEventPattern<MouseButtonEventHandler, MouseButtonEventArgs>(
            handler => (s, a) => handler(s, a),
            handler => MouseDown += handler,
            handler => MouseDown -= handler)
        .Select(x => x.EventArgs.GetPosition(this));

Observable.FromEventPattern<MouseEventHandler, MouseEventArgs>(
        handler => (s, a) => handler(s, a),
        handler => MouseMove += handler,
        handler => MouseMove -= handler)
    .Select(x => x.EventArgs.GetPosition(this))
    .Timeout(TimeSpan.FromSeconds(1), clicks)
    .Subscribe(
        x => Trace.WriteLine($"{DateTime.Now.Second}: ვნახე {x.X}, {x.Y}"),
        ex => Trace.WriteLine(ex));
```

## განხილვა

`Timeout` არატრივიალურ აპლიკაციებში **აუცილებელი** ოპერატორია, რადგან პროგრამა ყოველთვის საპასუხო უნდა იყოს, მაშინაც კი, თუ დანარჩენი სამყარო არ არის. ის განსაკუთრებით სასარგებლოა ასინქრონულ ოპერაციებთან, მაგრამ ნებისმიერ მოვლენათა ნაკადზე გამოიყენება.

> [!WARNING] ოპერაცია არ უქმდება
> გაითვალისწინეთ, რომ ქვემდებარე **ოპერაცია რეალურად არ უქმდება**: timeout-ის შემთხვევაშიც ის აგრძელებს შესრულებას, სანამ არ დასრულდება წარმატებით ან შეცდომით. ნამდვილი გაუქმებისთვის `CancellationToken` გჭირდებათ ([[თავი 10.3 გაუქმება timeout-ის გამო|10.3]]).
