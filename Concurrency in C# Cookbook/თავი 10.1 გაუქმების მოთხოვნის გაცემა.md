> [!INFO] მე-10 თავის შესახებ
> .NET 4.0 ფრეიმვორკმა **ამომწურავი და კარგად გააზრებული** გაუქმების მხარდაჭერა შემოიტანა. ეს მხარდაჭერა **თანამშრომლობითია (cooperative)**, რაც ნიშნავს, რომ გაუქმება შეიძლება **მოთხოვნილ** იქნეს, მაგრამ კოდს **ვერ დაეკისრება** იძულებით. რადგან გაუქმება თანამშრომლობითია, კოდის გაუქმება შეუძლებელია, თუ ის გაუქმების მხარდაჭერით არ დაიწერა. ამიტომ ავტორი გირჩევთ, გაუქმებას საკუთარი კოდის რაც შეიძლება დიდ ნაწილში უჭერდეთ მხარს.
>
> გაუქმება **სიგნალის** სახეობაა და ორი მხარე აქვს: **წყარო**, რომელიც გაუქმებას იწვევს, და **მიმღები**, რომელიც გაუქმებაზე რეაგირებს. .NET-ში წყაროა `CancellationTokenSource`, მიმღები კი `CancellationToken`.
>
> გაუქმება **შეცდომის განსაკუთრებულ სახეობად** განიხილება. კონვენციაა, რომ გაუქმებული კოდი `OperationCanceledException` ტიპის (ან მისგან წარმოებულ, მაგალითად `TaskCanceledException`) გამონაკლისს ისვრის. ასე გამომძახებელ კოდს ეცოდინება, რომ გაუქმება **დაფიქსირდა**.
>
> იმის მისანიშნებლად, რომ თქვენი მეთოდი გაუქმებას უჭერს მხარს, `CancellationToken` პარამეტრად უნდა მიიღოთ. ეს პარამეტრი, როგორც წესი, **ბოლოა**, თუ მეთოდი პროგრესსაც არ ატყობინებს ([[თავი 2.3 პროგრესის შესახებ შეტყობინება|2.3]]). შეგიძლიათ გადატვირთვა ან ნაგულისხმევი მნიშვნელობა შესთავაზოთ მათ, ვისაც გაუქმება არ სჭირდება:
>
> ```csharp
> public void CancelableMethodWithOverload(CancellationToken cancellationToken)
> {
>     // კოდი აქაა.
> }
>
> public void CancelableMethodWithOverload()
> {
>     CancelableMethodWithOverload(CancellationToken.None);
> }
>
> public void CancelableMethodWithDefault(
>     CancellationToken cancellationToken = default)
> {
>     // კოდი აქაა.
> }
> ```
>
> **`CancellationToken.None`** წარმოადგენს token-ს, რომელიც **არასდროს** უქმდება, და ის `default(CancellationToken)`-ის ტოლფასია.

## პრობლემა

თქვენი კოდი გაუქმებად კოდს იძახებს (რომელიც `CancellationToken`-ს იღებს) და მისი გაუქმება გჭირდებათ.

## გადაწყვეტა

**`CancellationTokenSource`** ტიპი `CancellationToken`-ის **წყაროა**. token მხოლოდ იმას იძლევა, რომ კოდმა გაუქმების მოთხოვნას უპასუხოს. `CancellationTokenSource`-ის წევრები კი გაუქმების **მოთხოვნის** საშუალებას იძლევა.

ყოველი `CancellationTokenSource` სხვებისგან **დამოუკიდებელია** (თუ მათ არ დააკავშირებთ, [[თავი 10.8 გაუქმების მოთხოვნების ინექცია|10.8]]). `Token` თვისება ამ წყაროს `CancellationToken`-ს აბრუნებს, `Cancel` მეთოდი კი გაუქმების ნამდვილ მოთხოვნას გასცემს:

```csharp
void IssueCancelRequest()
{
    using var cts = new CancellationTokenSource();
    var task = CancelableMethodAsync(cts.Token);

    // ამ წერტილში ოპერაცია უკვე დაწყებულია.

    // გაუქმების მოთხოვნის გაცემა.
    cts.Cancel();
}
```

წინა მაგალითში `task` ცვლადი გაშვების შემდეგ იგნორირებულია. ნამდვილ კოდში ეს task, სავარაუდოდ, სადმე შეინახებოდა და მას დაელოდებოდნენ, რომ საბოლოო შედეგი მომხმარებელს გასცნობოდა.

### სამი შესაძლო შედეგი

> [!IMPORTANT] გაუქმება ყოველთვის რბოლაა
> როცა კოდს აუქმებთ, თითქმის ყოველთვის **რბოლის მდგომარეობაა**. გაუქმებადი კოდი შეიძლება სწორედ დასრულებას აპირებდა, როცა გაუქმების მოთხოვნა გაიცა, და თუ ის დასრულებამდე თავის token-ს არ შეამოწმებს, **წარმატებით დასრულდება**.

სინამდვილეში, კოდის გაუქმებისას სამი შესაძლებლობაა:

1. ის შეიძლება **უპასუხოს** გაუქმების მოთხოვნას (`OperationCanceledException`-ის დასროლით);
2. ის შეიძლება **წარმატებით დასრულდეს**;
3. ის შეიძლება **შეცდომით დასრულდეს**, რომელიც გაუქმებას არ უკავშირდება (სხვა გამონაკლისის დასროლით).

```csharp
async Task IssueCancelRequestAsync()
{
    using var cts = new CancellationTokenSource();
    var task = CancelableMethodAsync(cts.Token);

    // ამ წერტილში ოპერაცია მშვიდად მუშაობს.

    // გაუქმების მოთხოვნის გაცემა.
    cts.Cancel();

    // (ასინქრონულად) ველოდებით ოპერაციის დასრულებას.
    try
    {
        await task;
        // თუ აქ მოვხვდით, ოპერაცია წარმატებით დასრულდა
        // მანამ, სანამ გაუქმება ძალაში შევიდოდა.
    }
    catch (OperationCanceledException)
    {
        // თუ აქ მოვხვდით, ოპერაცია დასრულებამდე გაუქმდა.
    }
    catch (Exception)
    {
        // თუ აქ მოვხვდით, ოპერაცია შეცდომით დასრულდა
        // მანამ, სანამ გაუქმება ძალაში შევიდოდა.
        throw;
    }
}
```

### რეალისტური GUI მაგალითი

ჩვეულებრივ, `CancellationTokenSource`-ის მომზადება და გაუქმების გაცემა **სხვადასხვა მეთოდშია**. როგორც კი `CancellationTokenSource`-ის ეგზემპლარს გააუქმებთ, ის **სამუდამოდ გაუქმებულია**. თუ სხვა წყარო გჭირდებათ, ახალი ეგზემპლარი უნდა შექმნათ:

```csharp
private CancellationTokenSource _cts;

private async void StartButton_Click(object sender, RoutedEventArgs e)
{
    StartButton.IsEnabled = false;
    CancelButton.IsEnabled = true;
    try
    {
        _cts = new CancellationTokenSource();
        CancellationToken token = _cts.Token;
        await Task.Delay(TimeSpan.FromSeconds(5), token);
        MessageBox.Show("დაყოვნება წარმატებით დასრულდა.");
    }
    catch (OperationCanceledException)
    {
        MessageBox.Show("დაყოვნება გაუქმდა.");
    }
    catch (Exception)
    {
        MessageBox.Show("დაყოვნება შეცდომით დასრულდა.");
        throw;
    }
    finally
    {
        StartButton.IsEnabled = true;
        CancelButton.IsEnabled = false;
    }
}

private void CancelButton_Click(object sender, RoutedEventArgs e)
{
    _cts.Cancel();
    CancelButton.IsEnabled = false;
}
```

## განხილვა

ამ რეცეპტის ყველაზე რეალისტურმა მაგალითმა GUI აპლიკაცია გამოიყენა, მაგრამ არ დაგრჩეთ შთაბეჭდილება, რომ გაუქმება მხოლოდ მომხმარებლის ინტერფეისისთვისაა. გაუქმებას **სერვერზეც** აქვს თავისი ადგილი: მაგალითად, ASP.NET გვაწვდის გაუქმების token-ს, რომელიც მოთხოვნის timeout-ს ან კლიენტის გათიშვას წარმოადგენს. მართალია, გაუქმების token-ის წყაროები სერვერის მხარეს უფრო იშვიათია, მაგრამ მათი გამოყენება არაფერს უშლის ხელს: ისინი სასარგებლოა, თუ რაიმე მიზეზით უნდა გააუქმოთ, რასაც ASP.NET-ის გაუქმება არ ფარავს, მაგალითად, მოთხოვნის დამუშავების ერთი ნაწილის დამატებითი timeout.

> [!TIP] `CancellationTokenSource` `IDisposable`-ია
> `CancellationTokenSource` შიდა რესურსებს იკავებს (განსაკუთრებით timeout-ის შემთხვევაში), ამიტომ `using`-ით უნდა განთავისუფლდეს. ამ რეცეპტის GUI მაგალითში `_cts` ველია, ამიტომ იქ `using` არ არის: რეალურ კოდში ძველი ეგზემპლარი ახლის შექმნამდე უნდა განთავისუფლდეს.

> [!NOTE] `CancellationToken.None`
> როცა გაუქმება არ გჭირდებათ, `CancellationToken.None` გადაეცით. ეს არ არის „null token": ეს ნამდვილი token-ია, რომელიც უბრალოდ **არასდროს** უქმდება.
