## პრობლემა

გაქვთ ასინქრონული ოპერაცია, რომლის observable-თან გაერთიანებაც გსურთ.

## გადაწყვეტა

ნებისმიერი ასინქრონული ოპერაცია შეიძლება განვიხილოთ როგორც observable ნაკადი, რომელიც ორიდან ერთ რამეს აკეთებს:

- **ერთ ელემენტს** აწარმოებს და შემდეგ სრულდება
- **ჩავარდება** ელემენტის წარმოების გარეშე

### `ToObservable`: უკვე დაწყებული task

`System.Reactive` ბიბლიოთეკას `Task<T>`-დან `IObservable<T>`-ზე მარტივი გარდაქმნა აქვს:

```csharp
IObservable<HttpResponseMessage> GetPage(HttpClient client)
{
    Task<HttpResponseMessage> task =
        client.GetAsync("http://www.example.com/");

    return task.ToObservable();
}
```

`ToObservable` მიდგომა გულისხმობს, რომ `async` მეთოდი **უკვე გამოიძახეთ** და გასარდაქმნელი `Task` გაქვთ.

### `StartAsync`: მაშინვე იწყება, გაუქმებით

სხვა მიდგომაა `StartAsync`-ის გამოძახება. `StartAsync`-იც მაშინვე იძახებს `async` მეთოდს, მაგრამ **გაუქმებას უჭერს მხარს**: თუ ხელმოწერა (subscription) განადგურდა, `async` მეთოდი უქმდება:

```csharp
IObservable<HttpResponseMessage> GetPage(HttpClient client)
{
    return Observable.StartAsync(
        token => client.GetAsync("http://www.example.com/", token));
}
```

### `FromAsync`: ცივი observable

`ToObservable`-იც და `StartAsync`-იც ასინქრონულ ოპერაციას **მაშინვე იწყებს**, ხელმოწერის მოლოდინის გარეშე: observable **„ცხელია" (hot)**. „ცივი" (cold) observable-ის შესაქმნელად, რომელიც ოპერაციას მხოლოდ ხელმოწერისას დაიწყებს, `FromAsync` გამოიყენეთ (ისიც უჭერს მხარს გაუქმებას, `StartAsync`-ის მსგავსად):

```csharp
IObservable<HttpResponseMessage> GetPage(HttpClient client)
{
    return Observable.FromAsync(
        token => client.GetAsync("http://www.example.com/", token));
}
```

`FromAsync` საგრძნობლად განსხვავდება `ToObservable`-ისა და `StartAsync`-ისგან, რომლებიც **უკვე დაწყებული** ასინქრონული ოპერაციის observable-ს აბრუნებს. `FromAsync` **ყოველი ხელმოწერისას ახალ, დამოუკიდებელ** ასინქრონულ ოპერაციას იწყებს.

### `SelectMany`: ნაკადის ყოველ მოვლენაზე

დაბოლოს, `SelectMany`-ის სპეციალური გადატვირთვებით წყაროს ნაკადის **ყოველი მოვლენისთვის** მოსვლისთანავე ასინქრონულ ოპერაციას გავუშვებთ. `SelectMany`-ც უჭერს მხარს გაუქმებას:

```csharp
IObservable<HttpResponseMessage> GetPages(
    IObservable<string> urls, HttpClient client)
{
    return urls.SelectMany(
        (url, token) => client.GetAsync(url, token));
}
```

## განხილვა

`System.Reactive` `async`-ის შემოტანამდე არსებობდა, მაგრამ დაემატა ეს (და სხვა) ოპერატორები, რომ მას `async` კოდთან კარგი თავსებადობა ჰქონოდა. ავტორი გირჩევთ, სწორედ აღწერილი ოპერატორები გამოიყენოთ, მიუხედავად იმისა, რომ იმავე ფუნქციონალს სხვა `System.Reactive` ოპერატორებითაც ააგებთ.

| ოპერატორი | ოპერაცია იწყება | გაუქმება | ყოველი ხელმოწერა |
|---|---|---|---|
| `task.ToObservable()` | უკვე დაწყებულია | არა | ერთსა და იმავე შედეგს იზიარებს |
| `Observable.StartAsync(...)` | მაშინვე | დიახ | ერთსა და იმავე შედეგს იზიარებს |
| `Observable.FromAsync(...)` | ხელმოწერისას | დიახ | ახალ ოპერაციას იწყებს |
| `source.SelectMany(...)` | ყოველ მოვლენაზე | დიახ | წყაროს ნაკადს მიჰყვება |

> [!TIP] რომელი ავირჩიოთ
> თუ `CancellationToken`-ის მიღების საშუალება გაქვთ, `StartAsync` ან `FromAsync` აირჩიეთ: მაშინ ხელმოწერის გაუქმება **ნამდვილად აუქმებს** ოპერაციას. `ToObservable`-ის შემთხვევაში task განაგრძობს მუშაობას, თუნდაც აღარავინ უსმენდეს.

> [!NOTE] `SelectMany` და პარალელურობა
> `SelectMany` ყველა შემომავალ URL-ზე ოპერაციას **ერთდროულად** უშვებს. თუ პარალელურობის შეზღუდვა გჭირდებათ, `Merge(maxConcurrent)` გამოიყენეთ: `urls.Select(url => Observable.FromAsync(t => client.GetAsync(url, t))).Merge(4)`.
