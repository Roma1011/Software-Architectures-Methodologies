## პრობლემა

პარალელური ოპერაციის დასასრულს შედეგების **აგრეგირება** გჭირდებათ. აგრეგირების მაგალითებია მნიშვნელობების შეჯამება ან საშუალოს პოვნა.

## გადაწყვეტა

`Parallel` კლასი აგრეგირებას **ლოკალური მნიშვნელობების (local values)** ცნებით უჭერს მხარს. ეს ცვლადები პარალელური ციკლის შიგნით, ლოკალურად არსებობს. ეს ნიშნავს, რომ ციკლის სხეულს მათზე **სინქრონიზაციის გარეშე** მიუწვდება ხელი. როცა ციკლი ლოკალური შედეგების გაერთიანებისთვის მზადაა, ამას **`localFinally`** დელეგატით აკეთებს. სწორედ `localFinally`-ში სჭირდება საბოლოო შედეგის ცვლადს სინქრონიზაცია:

```csharp
// შენიშვნა: ეს ყველაზე ეფექტიანი იმპლემენტაცია არ არის.
// ეს მხოლოდ საკეტით გაზიარებული მდგომარეობის დაცვის მაგალითია.
int ParallelSum(IEnumerable<int> values)
{
    object mutex = new object();
    int result = 0;

    Parallel.ForEach(
        source: values,
        localInit: () => 0,
        body: (item, state, localValue) => localValue + item,
        localFinally: localValue =>
        {
            lock (mutex)
                result += localValue;
        });

    return result;
}
```

### PLINQ-ის ბუნებრივი აგრეგირება

Parallel LINQ-ს აგრეგირების უფრო ბუნებრივი მხარდაჭერა აქვს, ვიდრე `Parallel` კლასს:

```csharp
int ParallelSum(IEnumerable<int> values)
{
    return values.AsParallel().Sum();
}
```

ავტორის ხუმრობით, ეს „იაფი დარტყმაა", რადგან PLINQ-ს ბევრი გავრცელებული ოპერატორის ჩაშენებული მხარდაჭერა აქვს (მაგალითად, `Sum`). PLINQ-ს ზოგადი აგრეგირების მხარდაჭერაც აქვს **`Aggregate`** ოპერატორით:

```csharp
int ParallelSum(IEnumerable<int> values)
{
    return values.AsParallel().Aggregate(
        seed: 0,
        func: (sum, item) => sum + item);
}
```

## განხილვა

თუ უკვე `Parallel` კლასს იყენებთ, შეიძლება მისი აგრეგირების მხარდაჭერაც გამოიყენოთ. სხვა შემთხვევებში, უმეტესად, **PLINQ უფრო გამომსახველია და კოდიც უფრო მოკლეა**.

> [!TIP] `Interlocked` საკეტის ნაცვლად
> მარტივი რიცხვითი აგრეგირებისთვის `lock`-ის ნაცვლად `Interlocked` სჯობს:
> ```csharp
> localFinally: localValue => Interlocked.Add(ref result, localValue)
> ```

> [!NOTE] `Aggregate`-ის სრული ფორმა PLINQ-ში
> PLINQ-ის `Aggregate`-ს აქვს გადატვირთვა, რომელიც `Parallel`-ის `localInit`/`localFinally`-ის ანალოგია: `seed`, `updateAccumulatorFunc` (ლოკალურად), `combineAccumulatorsFunc` (ნაწილობრივი შედეგების გაერთიანება) და `resultSelector`. ის მაშინ გჭირდებათ, როცა აგრეგირების შუალედური ტიპი საბოლოოსგან განსხვავდება.
