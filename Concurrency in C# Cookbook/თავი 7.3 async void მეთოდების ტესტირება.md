## პრობლემა

გაქვთ `async void` მეთოდი, რომლის ერთეულოვანი ტესტირებაც გჭირდებათ.

## გადაწყვეტა

**გაჩერდით.**

ამ პრობლემის გადაწყვეტის ნაცვლად, ყველაფერი უნდა გააკეთოთ იმისთვის, რომ **თავიდან აიცილოთ** ის. თუ შესაძლებელია `async void` მეთოდის `async Task` მეთოდად გადაკეთება, გადააკეთეთ.

თუ მეთოდი **აუცილებლად** `async void` უნდა იყოს (მაგალითად, ინტერფეისის მეთოდის ხელმოწერის დასაკმაყოფილებლად), განიხილეთ **ორი მეთოდის** დაწერა: `async Task` მეთოდი, რომელიც მთელ ლოგიკას შეიცავს, და `async void` **გარსი**, რომელიც უბრალოდ `async Task` მეთოდს იძახებს და შედეგს ელოდება. `async void` მეთოდი არქიტექტურულ მოთხოვნას აკმაყოფილებს, `async Task` მეთოდი კი (მთელი ლოგიკით) ტესტირებადია.

```csharp
// ინტერფეისი async void-ს ითხოვს
public async void HandleEvent(EventArgs e) => await HandleEventAsync(e);

// მთელი ლოგიკა აქაა, და ეს მეთოდი ტესტირებადია
public async Task HandleEventAsync(EventArgs e)
{
    // ...
}
```

*ნახაზი 7.3: `async void`-ის რეფაქტორინგი ტესტირებადობისთვის.*

### უკიდურესი გამოსავალი

თუ მეთოდის შეცვლა შეუძლებელია და `async void` მეთოდი აუცილებლად უნდა დატესტოთ, გზა არსებობს: `Nito.AsyncEx` ბიბლიოთეკის **`AsyncContext`** კლასი:

```csharp
// არარეკომენდებული გადაწყვეტა, იხილეთ ქვემოთ.
[TestMethod]
public void MyMethodAsync_DoesNotThrow()
{
    AsyncContext.Run(() =>
    {
        var objectUnderTest = new Sut();
        objectUnderTest.MyVoidMethodAsync();
    });
}
```

`AsyncContext` ტიპი დაელოდება, სანამ **ყველა** ასინქრონული ოპერაცია დასრულდება (`async void` მეთოდების ჩათვლით), და გაავრცელებს მათ მიერ დასროლილ გამონაკლისებს.

> [!TIP] პაკეტი
> `AsyncContext` ტიპი `Nito.AsyncEx` NuGet პაკეტშია.

## განხილვა

`async` კოდის ერთ-ერთი მთავარი სახელმძღვანელო წესია **`async void`-ის თავიდან აცილება**. ავტორი მკაცრად გირჩევთ, კოდი გადააკეთოთ, ნაცვლად იმისა, რომ `async void` მეთოდების ტესტირებისთვის `AsyncContext` გამოიყენოთ.

> [!IMPORTANT] რატომ არის `async void` ასე პრობლემური ტესტებში
> `async void` მეთოდი დაუყოვნებლივ ბრუნდება პირველივე `await`-ზე, და მას **არაფერი** აქვს, რასაც დაელოდები. ტესტ-მეთოდი მისი დასრულებამდე დამთავრდება, ასე რომ assertion-ები შეიძლება საერთოდ არ შესრულდეს, ან სხვა ტესტის მიმდინარეობისას შესრულდეს. მისი გამონაკლისი `SynchronizationContext`-ზე პირდაპირ ისვრება, რაც ხშირად მთელ ტესტ-პროცესს ამხობს.

> [!NOTE] თანამედროვე .NET
> `async void`-ის ერთადერთი ლეგიტიმური გამოყენება მოვლენების დამმუშავებლებია (და ისიც თხელი გარსის სახით). ყველგან სხვაგან `async Task`-ია სწორი. ანალიზატორები (მაგალითად, `VSTHRD100`) `async void`-ს ავტომატურად აფრთხილებენ.
