> [!INFO] მე-11 თავის შესახებ
> თანამედროვე პროგრამებს ასინქრონული პროგრამირება სჭირდება: დღეს სერვერები უკეთესად უნდა მასშტაბირდებოდნენ, ვიდრე ოდესმე, და საბოლოო მომხმარებლის აპლიკაციები უფრო საპასუხონი უნდა იყვნენ. დეველოპერები აღმოაჩენენ, რომ ასინქრონული პროგრამირება უნდა ისწავლონ, და ამ სამყაროს კვლევისას აღმოჩნდება, რომ ის ხშირად **ეჯახება** იმ ტრადიციულ ობიექტზე ორიენტირებულ პროგრამირებას, რომელსაც მიჩვეულები არიან.
>
> ამის ძირითადი მიზეზი ისაა, რომ **ასინქრონული პროგრამირება ფუნქციურია**. „ფუნქციურში" ავტორს არ ესმის „ის მუშაობს": იგულისხმება პროგრამირების **ფუნქციური სტილი** პროცედურულის ნაცვლად. ბევრმა დეველოპერმა საბაზისო ფუნქციური პროგრამირება უნივერსიტეტში ისწავლა და მას შემდეგ თითქმის არ შეხებია. თუ კოდი `(car (cdr '(3 5 7)))` გაცივებთ, რადგან ჩახშობილი მოგონებები გაწყდებათ, შეიძლება სწორედ ამ კატეგორიაში იყოთ. მაგრამ ნუ შეგეშინდებათ: თანამედროვე ასინქრონული პროგრამირება იმდენად რთული არ არის, როგორც კი შეეჩვევით.
>
> `async`-ის მთავარი გარღვევა ისაა, რომ ასინქრონულად პროგრამირებისას **მაინც პროცედურულად შეგიძლიათ აზროვნება**. ეს ასინქრონული მეთოდების წერასა და გაგებას აადვილებს. თუმცა შიგნით ასინქრონული კოდი კვლავ ფუნქციური ბუნებისაა, და ეს პრობლემებს ქმნის, როცა ადამიანები `async` მეთოდებს **კლასიკურ ობიექტზე ორიენტირებულ დიზაინში** ცდილობენ ჩატევას. ამ თავის რეცეპტები სწორედ იმ **ხახუნის წერტილებს** ეხება, სადაც ასინქრონული კოდი ობიექტზე ორიენტირებულ პროგრამირებას ეჯახება. ეს წერტილები განსაკუთრებით შესამჩნევია არსებული OOP კოდის ბაზის async-მეგობრულად გადაქცევისას.

## პრობლემა

გაქვთ მეთოდი ინტერფეისში ან საბაზო კლასში, რომელიც ასინქრონული გინდათ გახადოთ.

## გადაწყვეტა

ამ პრობლემისა და მისი გადაწყვეტის გასაგები გასაღები იმის გაცნობიერებაა, რომ **`async` იმპლემენტაციის დეტალია**. `async` საკვანძო სიტყვა მხოლოდ იმპლემენტაციის მქონე მეთოდებზე გამოიყენება: მისი გამოყენება აბსტრაქტულ ან ინტერფეისის მეთოდებზე შეუძლებელია (თუ მათ ნაგულისხმევი იმპლემენტაცია არ აქვთ). თუმცა შეგიძლიათ განსაზღვროთ მეთოდი **იმავე ხელმოწერით**, რაც `async` მეთოდს აქვს, უბრალოდ `async` საკვანძო სიტყვის გარეშე.

> [!IMPORTANT] await-ადი არის ტიპი, და არა მეთოდი
> გახსოვდეთ, რომ **ტიპებია** await-ადი და არა მეთოდები. მეთოდის დაბრუნებულ `Task`-ს შეგიძლიათ დაელოდოთ, მიუხედავად იმისა, ეს მეთოდი `async`-ით არის განხორციელებული თუ არა. ასე რომ, ინტერფეისის ან აბსტრაქტულ მეთოდს უბრალოდ `Task` (ან `Task<T>`) შეუძლია დააბრუნოს, და ამ მეთოდის დასაბრუნებელი მნიშვნელობა await-ადი იქნება.

```csharp
interface IMyAsyncInterface
{
    Task<int> CountBytesAsync(HttpClient client, string url);
}

class MyAsyncClass : IMyAsyncInterface
{
    public async Task<int> CountBytesAsync(HttpClient client, string url)
    {
        var bytes = await client.GetByteArrayAsync(url);
        return bytes.Length;
    }
}

async Task UseMyInterfaceAsync(HttpClient client, IMyAsyncInterface service)
{
    var result = await service.CountBytesAsync(client, "http://www.example.com");
    Trace.WriteLine(result);
}
```

ასინქრონული მეთოდის ხელმოწერა მხოლოდ იმას ნიშნავს, რომ იმპლემენტაცია **შეიძლება** იყოს ასინქრონული. სავსებით შესაძლებელია, რომ რეალური იმპლემენტაცია სინქრონული იყოს, თუ მას ნამდვილი ასინქრონული სამუშაო არ აქვს. მაგალითად, ტესტის stub-მა შეიძლება იგივე ინტერფეისი (`async`-ის გარეშე) `FromResult`-ის მსგავსით განახორციელოს:

```csharp
class MyAsyncClassStub : IMyAsyncInterface
{
    public Task<int> CountBytesAsync(HttpClient client, string url)
    {
        return Task.FromResult(13);
    }
}
```

## განხილვა

`async` და `await` ფართოვდება. როგორც ასინქრონული მეთოდები უფრო გავრცელებული ხდება, ინტერფეისებსა და საბაზო კლასებში ასინქრონული მეთოდებიც უფრო გავრცელებული გახდება. მათთან მუშაობა არც ისე რთულია, თუ გახსოვთ, რომ await-ადი **დასაბრუნებელი ტიპია** (და არა მეთოდი), და რომ ასინქრონული მეთოდის განსაზღვრება შეიძლება განხორციელდეს **ასინქრონულადაც და სინქრონულადაც**.

> [!TIP] `async` ინტერფეისში არასდროს წერია
> ინტერფეისში `async Task<int> CountBytesAsync(...)` კომპილაციის შეცდომაა (ნაგულისხმევი იმპლემენტაციის გარეშე), და ეს **სწორია**: ინტერფეისი მხოლოდ იმას ამბობს, „ეს მეთოდი `Task<int>`-ს აბრუნებს". ის, თუ როგორ იქმნება ეს `Task`, გამომძახებელს არ ეხება.

> [!NOTE] დასახელების კონვენცია
> `Task`-ის დამბრუნებელი მეთოდის სახელს, კონვენციით, `Async` სუფიქსი აქვს, ინტერფეისშიც. თუ ინტერფეისს სინქრონული და ასინქრონული ვერსია ორივე აქვს, სახელები `CountBytes` და `CountBytesAsync` იქნება.
