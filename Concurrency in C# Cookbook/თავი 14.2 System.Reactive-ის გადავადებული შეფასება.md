## პრობლემა

გინდათ, **ახალი** წყარო observable შეიქმნას ყოველთვის, როცა ვინმე მას ხელს მოაწერს. მაგალითად, გინდათ, ყოველი ხელმოწერა ვებ-სერვისზე **სხვადასხვა მოთხოვნას** წარმოადგენდეს.

## გადაწყვეტა

`System.Reactive` ბიბლიოთეკას აქვს ოპერატორი **`Observable.Defer`**, რომელიც დელეგატს **ყოველი ხელმოწერისას** ასრულებს. ეს დელეგატი **ფაბრიკაა**, რომელიც observable-ს ქმნის:

```csharp
void SubscribeWithDefer()
{
    var invokeServerObservable = Observable.Defer(
        () => GetValueAsync().ToObservable());

    invokeServerObservable.Subscribe(_ => { });
    invokeServerObservable.Subscribe(_ => { });

    Console.ReadKey();
}

async Task<int> GetValueAsync()
{
    Console.WriteLine("სერვერს ვიძახებ...");
    await Task.Delay(TimeSpan.FromSeconds(2));
    Console.WriteLine("შედეგს ვაბრუნებ...");
    return 13;
}
```

## განხილვა

თქვენი საკუთარი კოდი, როგორც წესი, observable-ს **ერთზე მეტჯერ არ აწერს ხელს**, მაგრამ ზოგიერთი `System.Reactive` ოპერატორი ამას შიგნით აკეთებს. მაგალითად, `Observable.While` ოპერატორი წყაროს თანმიმდევრობას **ხელახლა აწერს ხელს** მანამ, სანამ მისი პირობა ჭეშმარიტია.

`Defer` საშუალებას გვაძლევს, განვსაზღვროთ observable, რომელიც **ხელახლა ფასდება** ყოველი ახალი ხელმოწერისას. ეს სასარგებლოა, თუ ამ observable-ის მონაცემების **განახლება ან რეფრეში** გჭირდებათ.

> [!TIP] `Defer` და `FromAsync`
> `Observable.FromAsync(token => ...)` ([[თავი 8.6 System.Reactive-ის Observable გარსები|8.6]]) არსებითად `Defer`-ის სპეციალიზებული ფორმაა ასინქრონული მეთოდებისთვის: ისიც ყოველ ხელმოწერაზე ახალ ოპერაციას იწყებს, ოღონდ გაუქმებასაც უჭერს მხარს.

> [!IMPORTANT] ცხელი და ცივი
> `Defer`-ის ძირითადი აზრია **„ცხელი" observable-ის „ცივად" გადაქცევა**. ცივი observable ყოველ ხელმომწერს საკუთარ, დამოუკიდებელ ნაკადს აძლევს; ცხელი კი ერთსა და იმავეს უზიარებს ყველას. საპირისპირო მიმართულებისთვის (ცივის გაზიარებისთვის) `Publish().RefCount()` არსებობს.
