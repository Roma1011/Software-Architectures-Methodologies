## პრობლემა

გაქვთ რამდენიმე task და გჭირდებათ, **ყველა** მათგანის დასრულებას დაელოდოთ.

## გადაწყვეტა

ფრეიმვორკს ამისთვის აქვს **`Task.WhenAll`**: ის რამდენიმე task-ს იღებს და აბრუნებს task-ს, რომელიც მაშინ სრულდება, როცა ყველა გადაცემული task დასრულდება:

```csharp
Task task1 = Task.Delay(TimeSpan.FromSeconds(1));
Task task2 = Task.Delay(TimeSpan.FromSeconds(2));
Task task3 = Task.Delay(TimeSpan.FromSeconds(1));

await Task.WhenAll(task1, task2, task3);
```

თუ ყველა task ერთი და იმავე ტიპის შედეგს აბრუნებს და ყველა წარმატებით სრულდება, `Task.WhenAll` **მასივს** აბრუნებს ყველა შედეგით:

```csharp
Task<int> task1 = Task.FromResult(3);
Task<int> task2 = Task.FromResult(5);
Task<int> task3 = Task.FromResult(7);

int[] results = await Task.WhenAll(task1, task2, task3);
// results შეიცავს { 3, 5, 7 }
```

*ნახაზი 2.4: `WhenAll` ყველაზე ნელ task-ს ელოდება, და არა მათ ჯამს.*

### LINQ-თან ერთად: „რეიფიკაცია"

`Task.WhenAll`-ს აქვს გადატვირთვა, რომელიც `IEnumerable<Task>`-ს იღებს, მაგრამ ავტორი მის პირდაპირ გამოყენებას **არ** გვირჩევს. როცა ასინქრონულ კოდს LINQ-თან ვურევთ, კოდი უფრო ცხადია, თუ თანმიმდევრობას აშკარად **„რეიფიცირებას"** (ანუ გამოთვლას და კოლექციად ქცევას) ვუკეთებთ:

```csharp
async Task<string> DownloadAllAsync(HttpClient client, IEnumerable<string> urls)
{
    // ვსაზღვრავთ, რა უნდა გაკეთდეს თითოეულ URL-ზე
    var downloads = urls.Select(url => client.GetStringAsync(url));
    // ჯერ არცერთი task არ დაწყებულა,
    // რადგან თანმიმდევრობა ჯერ არ გამოთვლილა.

    // ყველა ჩამოტვირთვას ერთდროულად ვიწყებთ
    Task<string>[] downloadTasks = downloads.ToArray();
    // ახლა ყველა task დაიწყო.

    // ასინქრონულად ველოდებით ყველა ჩამოტვირთვის დასრულებას
    string[] htmlPages = await Task.WhenAll(downloadTasks);

    return string.Concat(htmlPages);
}
```

> [!IMPORTANT] რატომ არის ეს მნიშვნელოვანი
> LINQ-ის `Select` **გადადებული (deferred)** შესრულებაა: სანამ თანმიმდევრობას არ გადავუვლით, არცერთი `GetStringAsync` არ გამოიძახება. `ToArray()`-ის გამოძახება ყველა ჩამოტვირთვას **ერთდროულად** იწყებს. თუ `ToArray()`-ს არ დავწერთ და `WhenAll`-ს პირდაპირ `IEnumerable`-ს გადავცემთ, ის თავად გადაუვლის მას (ანუ საბოლოო შედეგი იგივეა), მაგრამ კოდის კითხვისას არ ჩანს, **როდის** იწყება ოპერაციები. აშკარა რეიფიკაცია ამ ორაზროვნებას აქრობს.

## განხილვა: შეცდომები

თუ რომელიმე task exception-ს ისვრის, `Task.WhenAll` დაბრუნებულ task-ს ამ exception-ით „გაფუჭებულად" (faulted) ნიშნავს. თუ **რამდენიმე** task ისვრის exception-ს, **ყველა** მათგანი დაბრუნებულ `Task`-ზე თავსდება. მაგრამ როცა ამ task-ს `await`-ს ვუკეთებთ, მხოლოდ **ერთი** მათგანი გამოისვრება.

თუ ყველა exception გჭირდებათ, `Task.WhenAll`-ის დაბრუნებული task-ის `Exception` თვისება უნდა შეამოწმოთ:

```csharp
async Task ThrowNotImplementedExceptionAsync()
{
    throw new NotImplementedException();
}

async Task ThrowInvalidOperationExceptionAsync()
{
    throw new InvalidOperationException();
}

async Task ObserveOneExceptionAsync()
{
    var task1 = ThrowNotImplementedExceptionAsync();
    var task2 = ThrowInvalidOperationExceptionAsync();

    try
    {
        await Task.WhenAll(task1, task2);
    }
    catch (Exception ex)
    {
        // ex არის ან NotImplementedException, ან InvalidOperationException
    }
}

async Task ObserveAllExceptionsAsync()
{
    var task1 = ThrowNotImplementedExceptionAsync();
    var task2 = ThrowInvalidOperationExceptionAsync();

    Task allTasks = Task.WhenAll(task1, task2);
    try
    {
        await allTasks;
    }
    catch
    {
        AggregateException allExceptions = allTasks.Exception;
        // allExceptions.InnerExceptions შეიცავს ორივეს
    }
}
```

*ნახაზი 2.5: `WhenAll`-ის შეცდომების მოდელი.*

ავტორი აღნიშნავს, რომ უმეტესად **არ** აკვირდება ყველა exception-ს `Task.WhenAll`-ის გამოყენებისას: ჩვეულებრივ საკმარისია, პირველ შეცდომაზე ვიმოქმედოთ.

> [!NOTE] `async` მეთოდები exception-ს პირდაპირ არ ისვრიან
> ზემოთ მოცემულ მაგალითში `ThrowNotImplementedExceptionAsync` და `ThrowInvalidOperationExceptionAsync` exception-ს **პირდაპირ არ ისვრიან**: ისინი `async` საკვანძო სიტყვას იყენებს, ამიტომ მათი exception-ები დაიჭირება და ჩვეულებრივად დაბრუნებულ task-ზე თავსდება. ეს awaitable ტიპის დამბრუნებელი მეთოდების ნორმალური, მოსალოდნელი ქცევაა.

> [!TIP] პარალელიზმის შეზღუდვა
> `Task.WhenAll` ყველა ოპერაციას **ერთდროულად** უშვებს. თუ 10 000 URL გაქვთ, 10 000 ერთდროული მოთხოვნა სერვერს (ან თქვენს აპლიკაციას) დაამხობს. ერთდროულობის შესაზღუდად გამოიყენეთ `SemaphoreSlim` ([[თავი 12.5 დროსელირება|12.5]]) ან, .NET 6-იდან, `Parallel.ForEachAsync`-ის `MaxDegreeOfParallelism`.
