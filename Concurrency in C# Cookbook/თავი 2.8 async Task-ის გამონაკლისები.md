## პრობლემა

გამონაკლისების (exception) დამუშავება ნებისმიერი დიზაინის კრიტიკული ნაწილია. წარმატებული სცენარის დაპროექტება ადვილია, მაგრამ დიზაინი სწორი არ არის, სანამ ის **წარუმატებელ** შემთხვევებსაც არ ამუშავებს. საბედნიეროდ, `async Task` მეთოდების exception-ების დამუშავება მარტივია.

## გადაწყვეტა

exception-ები ჩვეულებრივი `try`/`catch`-ით იჭერება, ზუსტად ისე, როგორც სინქრონულ კოდში:

```csharp
async Task ThrowExceptionAsync()
{
    await Task.Delay(TimeSpan.FromSeconds(1));
    throw new InvalidOperationException("ტესტი");
}

async Task TestAsync()
{
    try
    {
        await ThrowExceptionAsync();
    }
    catch (InvalidOperationException)
    {
        // დამუშავება
    }
}
```

`async Task` მეთოდიდან გამოსროლილი exception-ები **დაბრუნებულ `Task`-ზე თავსდება**. ისინი მხოლოდ მაშინ „ისვრება", როცა ამ `Task`-ს `await`-ს ვუკეთებთ:

```csharp
async Task TestAsync()
{
    // მეთოდი exception-ს ისვრის და ის task-ზე თავსდება
    Task task = ThrowExceptionAsync();

    try
    {
        // exception ხელახლა აქ ისვრება, სადაც task-ს ველოდებით
        await task;
    }
    catch (InvalidOperationException)
    {
        // exception სწორად იჭერა
    }
}
```

## განხილვა

როცა `async Task` მეთოდიდან exception „გამოდის", ის იჭერს და დაბრუნებულ `Task`-ზე თავსდება. რადგან `async void` მეთოდებს `Task` არ აქვთ, სადაც exception-ს მოათავსებდნენ, მათი ქცევა განსხვავებულია ([[თავი 2.9 async void-ის გამონაკლისები|2.9]]).

**Stack trace.** როცა faulted `Task`-ს ველოდებით, მასზე მდებარე **პირველი** exception ხელახლა ისვრება. თუ exception-ების ხელახლა გასროლის პრობლემები გახსოვთ, stack trace-ზე ალბათ ინერვიულებთ. დამშვიდდით: ხელახლა გასროლისას **საწყისი stack trace სწორად ნარჩუნდება** (კომპილატორი `ExceptionDispatchInfo`-ს იყენებს).

ეს მექანიზმი რთულად ჟღერს, მაგრამ მთელი ეს სირთულე ერთად იმას ემსახურება, რომ **მარტივ სცენარს მარტივი კოდი** ჰქონდეს. უმეტესად თქვენი კოდი უბრალოდ უნდა გადასცემდეს (propagate) exception-ებს იმ ასინქრონული მეთოდებიდან, რომლებსაც იძახებს: საკმარისია, დაბრუნებულ task-ს `await` გაუკეთოთ, და exception ბუნებრივად გავრცელდება.

**რამდენიმე exception.** არის სიტუაციები (მაგალითად, `Task.WhenAll`), როცა `Task`-ს რამდენიმე exception აქვს, და `await` მხოლოდ პირველს ისვრის. ყველას დამუშავების მაგალითი [[თავი 2.4 Task-ების ნაკრების დასრულების ლოდინი|2.4]]-შია.

> [!WARNING] „გაუშვი და დაივიწყე"
> თუ `async Task` მეთოდს გამოიძახებთ და მის task-ს **არასოდეს** დაელოდებით, exception ჩუმად დაიკარგება: ის task-ზე დარჩება, და როცა task-ს garbage collector შეაგროვებს, არავინ შეიტყობს შეცდომის შესახებ. `TaskScheduler.UnobservedTaskException` მოვლენა ასეთი შემთხვევების ლოგირებაში დაგეხმარებათ.

> [!TIP] რამდენიმე `catch` და ფილტრები
> C# 6-იდან exception-ის ფილტრებიც მუშაობს ასინქრონულ კოდში:
> ```csharp
> try { await CallApiAsync(); }
> catch (HttpRequestException ex) when (ex.StatusCode == HttpStatusCode.NotFound)
> {
>     // მხოლოდ 404
> }
> ```
