> [!INFO] მე-5 თავის შესახებ
> **TPL Dataflow** ძლიერი ბიბლიოთეკაა, რომლითაც **ბადეს (mesh)** ან **კონვეიერს (pipeline)** ვქმნით და შემდეგ მასში მონაცემებს (ასინქრონულად) ვატარებთ. Dataflow ძალიან **დეკლარაციული** სტილია: ჯერ სრულად ვაღწერთ ბადეს და მხოლოდ შემდეგ ვიწყებთ მონაცემების დამუშავებას. ბადე ის სტრუქტურაა, რომელშიც მონაცემები მიედინება. ეს აპლიკაციაზე ცოტა სხვაგვარად ფიქრს მოითხოვს, მაგრამ ამ ნაბიჯის გადადგმის შემდეგ Dataflow ბევრი სცენარისთვის ბუნებრივი ხდება.
>
> ყოველი ბადე **ბლოკებისგან** შედგება, რომლებიც ერთმანეთს უკავშირდება. ცალკეული ბლოკი მარტივია და მონაცემების დამუშავების **ერთ ნაბიჯზეა** პასუხისმგებელი. როცა ბლოკი მონაცემზე მუშაობას ამთავრებს, შედეგს დაკავშირებულ ბლოკებს გადასცემს.
>
> TPL Dataflow-ის გამოსაყენებლად დააინსტალირეთ NuGet პაკეტი **`System.Threading.Tasks.Dataflow`**.

## პრობლემა

გჭირდებათ dataflow ბლოკების ერთმანეთთან **დაკავშირება**, რომ ბადე შექმნათ.

## გადაწყვეტა

TPL Dataflow-ის ბლოკები მხოლოდ ყველაზე საბაზისო წევრებს განსაზღვრავს. ბევრი სასარგებლო მეთოდი სინამდვილეში **გაფართოების მეთოდია**. **`LinkTo`** ბლოკების დაკავშირების მარტივ გზას იძლევა:

```csharp
var multiplyBlock = new TransformBlock<int, int>(item => item * 2);
var subtractBlock = new TransformBlock<int, int>(item => item - 2);

// დაკავშირების შემდეგ multiplyBlock-იდან გამოსული მნიშვნელობები
// subtractBlock-ში შედის
multiplyBlock.LinkTo(subtractBlock);
```

### დასრულების გავრცელება

ნაგულისხმევად დაკავშირებული ბლოკები მხოლოდ **მონაცემებს** გადასცემენ ერთმანეთს: **დასრულებას (და შეცდომებს) არა**. თუ თქვენი dataflow ხაზოვანია (კონვეიერი), სავარაუდოდ, დასრულების გავრცელებაც გინდათ. ამისთვის ბმულზე **`PropagateCompletion`** პარამეტრი უნდა ჩართოთ:

```csharp
var multiplyBlock = new TransformBlock<int, int>(item => item * 2);
var subtractBlock = new TransformBlock<int, int>(item => item - 2);

var options = new DataflowLinkOptions { PropagateCompletion = true };
multiplyBlock.LinkTo(subtractBlock, options);

// ...

// პირველი ბლოკის დასრულება ავტომატურად გადაეცემა მეორეს
multiplyBlock.Complete();
await subtractBlock.Completion;
```

## განხილვა

დაკავშირების შემდეგ მონაცემები ავტომატურად მიედინება source ბლოკიდან target ბლოკისკენ. `PropagateCompletion` მონაცემების გარდა დასრულებასაც ავრცელებს. თუმცა კონვეიერის ყოველ საფეხურზე „გაფუჭებული" ბლოკი თავის exception-ს შემდეგს **`AggregateException`-ში გახვეულს** გადასცემს. ამიტომ გრძელ კონვეიერში საწყისი შეცდომა შეიძლება რამდენიმე `AggregateException`-ში აღმოჩნდეს ჩალაგებული. `AggregateException`-ის `Flatten` ამაში გვეხმარება ([[თავი 5.2 შეცდომების გავრცელება|5.2]]).

ბლოკების დაკავშირება მრავალნაირად შეიძლება: ბადეს შეიძლება ჰქონდეს **განშტოებები (forks)**, **შეერთებები (joins)** და **ციკლებიც**. მაგრამ სცენარების უმეტესობისთვის მარტივი, ხაზოვანი კონვეიერი საკმარისია.

### `DataflowLinkOptions` და ფილტრები

`DataflowLinkOptions` ბმულის რამდენიმე პარამეტრს იძლევა (მაგალითად, `PropagateCompletion`), ხოლო `LinkTo`-ის გადატვირთვას **პრედიკატის** მიღებაც შეუძლია, რომლითაც ფილტრავთ, რომელი მონაცემი გაიაროს ბმულით:

```csharp
// ლუწი რიცხვები ერთი გზით, კენტები მეორეთი
sourceBlock.LinkTo(evenBlock, options, item => item % 2 == 0);
sourceBlock.LinkTo(oddBlock, options);        // დანარჩენი ყველაფერი
```

> [!WARNING] ფილტრი და „გაჭედილი" ელემენტი
> თუ მონაცემი ფილტრს არ გაივლის, ის **არ იკარგება**. ის სხვა ბმულით გავლას ცდილობს, და თუ სხვა ბმული არ არსებობს, ბლოკში **რჩება**. თუ ელემენტი ასე „გაიჭედა", ბლოკი სხვა ელემენტებს აღარ გამოუშვებს: მთელი ბლოკი **გაჩერდება**, სანამ ეს ელემენტი არ მოიხსნება. ამიტომ ფილტრებიან განშტოებას ყოველთვის ახლდეს „ნაგულისხმევი" ბმული ფილტრის გარეშე (ან `NullTarget` ბლოკი, რომელიც ყველაფერს იღებს და აგდებს).
