## პრობლემა

გადაწყვეტის ერთი ნაწილი ასინქრონულ ნაკადებს იყენებს, მეორე ნაწილი კი dataflow ბადეებს, და მათ შორის მონაცემების გადაცემა გჭირდებათ.

## გადაწყვეტა

**`Channel`**-ის ასინქრონულ ნაკადად მოხმარება პირდაპირ `Channel` ტიპებშია ჩაშენებული ([[თავი 9.8 ასინქრონული რიგები|9.8]]). **TPL Dataflow** ბლოკის ასინქრონულ ნაკადად მოხმარება ცოტა უფრო უხერხულია, მაგრამ ნამდვილად შესაძლებელი. ავტორს ყველაზე ადვილად მიაჩნია, ჯერ dataflow ბლოკებისთვის გაფართოების მეთოდი განისაზღვროს, რომელიც მათ API-ს `Channel`-ებს დაამსგავსებს, და შემდეგ ამ მეთოდით მოვიხმაროთ ისინი ასინქრონულ ნაკადად:

```csharp
public static class DataflowExtensions
{
    public static bool TryReceiveItem<T>(this ISourceBlock<T> block, out T value)
    {
        if (block is IReceivableSourceBlock<T> receivableSourceBlock)
            return receivableSourceBlock.TryReceive(out value);

        try
        {
            value = block.Receive(TimeSpan.Zero);
            return true;
        }
        catch (TimeoutException)
        {
            // ამჟამად ხელმისაწვდომი ელემენტი არ არის.
            value = default;
            return false;
        }
        catch (InvalidOperationException)
        {
            // ბლოკი დასრულებულია და მეტი ელემენტი აღარაა.
            value = default;
            return false;
        }
    }

    public static async IAsyncEnumerable<T> ReceiveAllAsync<T>(
        this ISourceBlock<T> block,
        [EnumeratorCancellation] CancellationToken cancellationToken = default)
    {
        while (await block
            .OutputAvailableAsync(cancellationToken).ConfigureAwait(false))
        {
            while (block.TryReceiveItem(out var value))
            {
                yield return value;
            }
        }
    }
}
```

`EnumeratorCancellation` ატრიბუტის დეტალები [[თავი 3.4 ასინქრონული ნაკადები და გაუქმება|3.4]]-შია.

ამ გაფართოების მეთოდით ნებისმიერი გამომავალი dataflow ბლოკის ასინქრონულ ნაკადად მოხმარება შესაძლებელია:

```csharp
var multiplyBlock = new TransformBlock<int, int>(value => value * 2);

multiplyBlock.Post(5);
multiplyBlock.Post(2);
multiplyBlock.Complete();

await foreach (int item in multiplyBlock.ReceiveAllAsync())
{
    Console.WriteLine(item);
}
```

### ნაკადი ბლოკის წყაროდ

ასინქრონული ნაკადის dataflow ბლოკის ელემენტების წყაროდ გამოყენებაც შესაძლებელია. სულ საჭიროა მარყუჟი, რომელიც ელემენტებს ამოიღებს და ბლოკში მოათავსებს. ქვემოთ მოცემულ კოდში ორი დაშვებაა, რომელიც ყველა სცენარისთვის შესაფერისი შეიძლება არ იყოს:

1. კოდი გულისხმობს, რომ გინდათ, **ბლოკი დასრულდეს, როცა ნაკადი დასრულდება**.
2. ის **გამომძახებელ ნაკადზე** იწყებს მუშაობას. ზოგ სცენარში შეიძლება გინდოდეთ, მთელი მარყუჟი ყოველთვის thread pool-ის ნაკადზე გაეშვას.

```csharp
public static async Task WriteToBlockAsync<T>(
    this IAsyncEnumerable<T> enumerable,
    ITargetBlock<T> block, CancellationToken token = default)
{
    try
    {
        await foreach (var item in enumerable
            .WithCancellation(token).ConfigureAwait(false))
        {
            await block.SendAsync(item, token).ConfigureAwait(false);
        }

        block.Complete();
    }
    catch (Exception ex)
    {
        block.Fault(ex);
    }
}
```

## განხილვა

ამ რეცეპტის გაფართოების მეთოდები **საწყის წერტილად** არის განკუთვნილი. კერძოდ, `WriteToBlockAsync` გაფართოების მეთოდი გარკვეულ დაშვებებს აკეთებს. აუცილებლად გაითვალისწინეთ ამ მეთოდების ქცევა და დარწმუნდით, რომ ის თქვენს სცენარს შეესაბამება, სანამ მათ გამოიყენებთ.

> [!TIP] რატომ `SendAsync` და არა `Post`
> `Post` მაშინვე ბრუნდება და `false`-ს აბრუნებს, თუ ბლოკმა ელემენტი არ მიიღო (მაგალითად, `BoundedCapacity` შევსებულია): ელემენტი **უხმაუროდ იკარგება**. `SendAsync` კი ელოდება, სანამ ბლოკი ადგილს გაათავისუფლებს, ანუ **ბუნებრივ დროსელირებას** გვაძლევს ([[თავი 5.4 ბლოკების დროსელირება|5.4]]).

> [!NOTE] `Channel` უფრო მარტივია
> თუ თქვენ თავად ირჩევთ ინფრასტრუქტურას, `System.Threading.Channels` ამ ხიდს საერთოდ არ საჭიროებს: `channel.Reader.ReadAllAsync()` პირდაპირ `IAsyncEnumerable<T>`-ია. TPL Dataflow-ს მაშინ ვიყენებთ, როცა მისი ბადის სემანტიკა გვჭირდება (მრავალი ბლოკი, განშტოებები, დაკავშირებები).
