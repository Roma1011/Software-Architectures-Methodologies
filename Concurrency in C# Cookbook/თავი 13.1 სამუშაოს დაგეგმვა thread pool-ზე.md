## პრობლემა

გაქვთ კოდის ნაწილი, რომლის **thread pool**-ის ნაკადზე შესრულებაც გინდათ აშკარად.

## გადაწყვეტა

შემთხვევათა აბსოლუტურ უმრავლესობაში `Task.Run`-ს გამოიყენებთ, რაც საკმაოდ მარტივია. ქვემოთ კოდი thread pool-ის ნაკადს 2 წამით ბლოკავს:

```csharp
Task task = Task.Run(() =>
{
    Thread.Sleep(TimeSpan.FromSeconds(2));
});
```

`Task.Run` **დასაბრუნებელ მნიშვნელობებსაც** იგებს და **ასინქრონულ ლამბდებსაც**. ქვემოთ დაბრუნებული task 2 წამში დასრულდება შედეგით 13:

```csharp
Task<int> task = Task.Run(async () =>
{
    await Task.Delay(TimeSpan.FromSeconds(2));
    return 13;
});
```

`Task.Run` აბრუნებს `Task`-ს (ან `Task<T>`-ს), რომელსაც ასინქრონული ან რეაქტიული კოდი ბუნებრივად მოიხმარს.

## განხილვა

`Task.Run` **იდეალურია UI აპლიკაციებისთვის**, როცა დროში მოცულობითი სამუშაო გაქვთ, რომლის შესრულებაც UI ნაკადზე შეუძლებელია. მაგალითად, [[თავი 8.4 პარალელური კოდის async გარსი|8.4]] `Task.Run`-ს პარალელური დამუშავების thread pool-ზე გადასაგდებად იყენებს.

> [!WARNING] ASP.NET-ზე ფრთხილად
> **არ გამოიყენოთ `Task.Run` ASP.NET-ზე**, თუ აბსოლუტურად დარწმუნებული არ ხართ, რომ იცით, რას აკეთებთ. ASP.NET-ზე მოთხოვნის დამმუშავებელი კოდი **უკვე** thread pool-ის ნაკადზე მუშაობს, ამიტომ მისი სხვა pool-ის ნაკადზე გადაგდება, როგორც წესი, **კონტრპროდუქტიულია**.

`Task.Run` ეფექტური ჩამნაცვლებელია `BackgroundWorker`-ის, `Delegate.BeginInvoke`-სა და `ThreadPool.QueueUserWorkItem`-ისთვის. ამ ძველი API-ებიდან **არცერთი არ უნდა გამოიყენოთ** ახალ კოდში: `Task.Run`-ის კოდის სწორად დაწერა და დროთა განმავლობაში შენახვა ბევრად ადვილია. გარდა ამისა, `Task.Run` `Thread`-ის გამოყენების შემთხვევების აბსოლუტურ უმრავლესობას ფარავს, ამიტომ `Thread`-ის უმეტესი გამოყენებაც `Task.Run`-ით ჩანაცვლდება (იშვიათი გამონაკლისია **single-thread apartment** ნაკადები).

პარალელური და dataflow კოდი ნაგულისხმევად thread pool-ზე სრულდება, ამიტომ `Parallel`-ის, Parallel LINQ-ის ან TPL Dataflow-ის კოდთან `Task.Run`-ის გამოყენება, როგორც წესი, **საჭირო არ არის**.

> [!IMPORTANT] დინამიკური პარალელიზმი: `Task.Factory.StartNew`
> თუ **დინამიკურ პარალელიზმს** ახორციელებთ, `Task.Run`-ის ნაცვლად `Task.Factory.StartNew` გამოიყენეთ. ეს აუცილებელია, რადგან `Task.Run`-ის დაბრუნებულ `Task`-ს ნაგულისხმევი პარამეტრები **ასინქრონული გამოყენებისთვის** აქვს კონფიგურირებული. ის ასევე არ უჭერს მხარს ისეთ გაფართოებულ ცნებებს, როგორიცაა **მშობელი/შვილი** task-ები, რაც უფრო გავრცელებულია დინამიკურ პარალელურ კოდში ([[თავი 4.4 დინამიკური პარალელიზმი|4.4]]).

| ძველი API | თანამედროვე ჩანაცვლება |
|---|---|
| `BackgroundWorker` | `Task.Run` + `IProgress<T>` |
| `Delegate.BeginInvoke` | `Task.Run` |
| `ThreadPool.QueueUserWorkItem` | `Task.Run` |
| `new Thread(...)` | `Task.Run` (გარდა STA ნაკადებისა და ხანგრძლივი ფონური სერვისებისა) |
