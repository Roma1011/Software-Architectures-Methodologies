## პრობლემა

გჭირდებათ კონტროლი იმაზე, **როგორ** სრულდება კოდის ცალკეული ნაწილები პარალელურ კოდში.

## გადაწყვეტა

როგორც კი შესაბამის `TaskScheduler` ეგზემპლარს შექმნით ([[თავი 13.2 კოდის შესრულება Task Scheduler-ით|13.2]]), მას იმ პარამეტრებში ჩართავთ, რომლებსაც `Parallel` მეთოდს გადასცემთ.

ქვემოთ მოცემული კოდი მატრიცების თანმიმდევრობების თანმიმდევრობას იღებს. ის ბევრ პარალელურ მარყუჟს იწყებს და უნდა შეზღუდოს **ყველა მარყუჟის ჯამური** პარალელურობა ერთდროულად, იმის მიუხედავად, რამდენი მატრიცაა თითოეულ თანმიმდევრობაში:

```csharp
void RotateMatrices(IEnumerable<IEnumerable<Matrix>> collections, float degrees)
{
    var schedulerPair = new ConcurrentExclusiveSchedulerPair(
        TaskScheduler.Default, maxConcurrencyLevel: 8);

    TaskScheduler scheduler = schedulerPair.ConcurrentScheduler;
    ParallelOptions options = new ParallelOptions { TaskScheduler = scheduler };

    Parallel.ForEach(collections, options,
        matrices => Parallel.ForEach(matrices, options,
            matrix => matrix.Rotate(degrees)));
}
```

## განხილვა

`Parallel.Invoke`-იც იღებს `ParallelOptions`-ის ეგზემპლარს, ამიტომ `TaskScheduler`-ს მას ისევე გადასცემთ, როგორც `Parallel.ForEach`-ს. თუ **დინამიკურ პარალელურ** კოდს წერთ, `TaskScheduler`-ს პირდაპირ `TaskFactory.StartNew`-ს ან `Task.ContinueWith`-ს გადასცემთ.

> [!WARNING] PLINQ scheduler-ს არ იღებს
> **Parallel LINQ-ისთვის (PLINQ) `TaskScheduler`-ის გადაცემის საშუალება არ არსებობს.** PLINQ ყოველთვის thread pool-ს იყენებს. თუ PLINQ-ის კონკურენტულობის შეზღუდვა გჭირდებათ, `WithDegreeOfParallelism` გამოიყენეთ ([[თავი 12.5 დროსელირება|12.5]]).

> [!TIP] `MaxDegreeOfParallelism` vs `TaskScheduler`
> ორივე ერთ `ParallelOptions`-ში შეიძლება იყოს. `MaxDegreeOfParallelism` **თითო მარყუჟს** ზღუდავს, `TaskScheduler` კი **ყველა მარყუჟს ერთად**, რომელიც მას იზიარებს. ჩალაგებულ ან მრავალჯერად მარყუჟებში სწორედ ეს უკანასკნელი გვჭირდება.
