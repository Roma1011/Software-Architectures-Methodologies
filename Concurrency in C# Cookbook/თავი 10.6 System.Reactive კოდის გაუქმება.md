## პრობლემა

გაქვთ რეაქტიული კოდი და გჭირდებათ, რომ ის გაუქმებადი იყოს.

## გადაწყვეტა

`System.Reactive` ბიბლიოთეკას observable ნაკადზე **ხელმოწერის (subscription)** ცნება აქვს. კოდს შეუძლია ხელმოწერა **განათავისუფლოს (dispose)**, რომ ნაკადს გამოეწეროს. ბევრ შემთხვევაში ეს საკმარისია ნაკადის ლოგიკური გაუქმებისთვის:

```csharp
private IDisposable _mouseMovesSubscription;

private void StartButton_Click(object sender, RoutedEventArgs e)
{
    IObservable<Point> mouseMoves = Observable
        .FromEventPattern<MouseEventHandler, MouseEventArgs>(
            handler => (s, a) => handler(s, a),
            handler => MouseMove += handler,
            handler => MouseMove -= handler)
        .Select(x => x.EventArgs.GetPosition(this));

    _mouseMovesSubscription = mouseMoves.Subscribe(value =>
    {
        MousePositionLabel.Content = "(" + value.X + ", " + value.Y + ")";
    });
}

private void CancelButton_Click(object sender, RoutedEventArgs e)
{
    if (_mouseMovesSubscription != null)
        _mouseMovesSubscription.Dispose();
}
```

საკმაოდ მოსახერხებელია, რომ `System.Reactive` `CancellationTokenSource`/`CancellationToken` სისტემასთან ვამუშაოთ, რომელსაც ყველა დანარჩენი იყენებს.

### `CancellationToken` → Rx: `ToTask`

პირველი მთავარი შემთხვევაა, როცა observable კოდი ასინქრონულ კოდშია გახვეული. ძირითადი მიდგომა [[თავი 8.5 System.Reactive Observable-ების async გარსი|8.5]]-შია, ახლა კი `CancellationToken`-ის მხარდაჭერის დამატება გვინდა. ზოგადად, ამის უმარტივესი გზაა, ყველა ოპერაცია რეაქტიული ოპერატორებით შევასრულოთ და შემდეგ **`ToTask`** გამოვიძახოთ, რომ ბოლო შედეგი await-ად task-ად გადავაქციოთ:

```csharp
CancellationToken cancellationToken = ...
IObservable<int> observable = ...

int lastElement = await observable.TakeLast(1).ToTask(cancellationToken);
// ან: int lastElement = await observable.ToTask(cancellationToken);
```

პირველი ელემენტის აღება ძალიან მსგავსია: უბრალოდ observable-ი `ToTask`-ის გამოძახებამდე შეცვალეთ:

```csharp
int firstElement = await observable.Take(1).ToTask(cancellationToken);
```

მთელი observable თანმიმდევრობის ასინქრონულად task-ად გადაქცევაც მსგავსია:

```csharp
IList<int> allElements = await observable.ToList().ToTask(cancellationToken);
```

### Rx → `CancellationToken`: `CancellationDisposable`

ბოლოს საპირისპირო სიტუაცია განვიხილოთ. აქამდე ვნახეთ, როგორ პასუხობს `System.Reactive` კოდი `CancellationToken`-ს, ანუ როგორ ითარგმნება `CancellationTokenSource`-ის გაუქმების მოთხოვნა **ხელმოწერის განთავისუფლებად**. შესაძლებელია საპირისპიროც: **გაუქმების მოთხოვნის გაცემა განთავისუფლების პასუხად**.

`FromAsync`, `StartAsync` და `SelectMany` ოპერატორები ყველა უჭერს მხარს გაუქმებას ([[თავი 8.6 System.Reactive-ის Observable გარსები|8.6]]). ეს ოპერატორები გამოყენების შემთხვევების აბსოლუტურ უმრავლესობას ფარავს. Rx ასევე გვთავაზობს **`CancellationDisposable`** ტიპს, რომელიც განთავისუფლებისას `CancellationToken`-ს აუქმებს:

```csharp
using (var cancellation = new CancellationDisposable())
{
    CancellationToken token = cancellation.Token;
    // token იმ მეთოდებს გადაეცემა, რომლებიც მას პასუხობს.
}
// ამ წერტილში token გაუქმებულია.
```

## განხილვა

`System.Reactive`-ს გაუქმების **საკუთარი** ცნება აქვს: ხელმოწერების განთავისუფლება. ამ რეცეპტმა რამდენიმე გზა აჩვენა, როგორ ვამუშაოთ Rx კარგად იმ უნივერსალურ გაუქმების ჩარჩოსთან, რომელიც .NET 4.0-მა შემოიტანა.

> [!IMPORTANT] მთავარი პრინციპი
> სანამ თქვენი კოდის Rx-ის ნაწილში ხართ, გამოიყენეთ **Rx-ის ხელმოწერა/განთავისუფლების სისტემა**. ყველაზე სუფთა მაშინაა, როცა `CancellationToken`-ის მხარდაჭერას მხოლოდ **საზღვრებზე** შემოიტანთ.
