## პრობლემა

გინდათ ასინქრონული ნაკადის დამუშავება **კარგად განსაზღვრული და კარგად ტესტირებული ოპერატორებით**.

## გადაწყვეტა

`IEnumerable<T>`-ს აქვს LINQ to Objects, `IObservable<T>`-ს კი LINQ to Events. ორივეს აქვს გაფართოების მეთოდების ბიბლიოთეკა, რომლითაც მოთხოვნებს ვაგებთ. `IAsyncEnumerable<T>`-საც აქვს LINQ-ის მხარდაჭერა, რომელიც .NET-ის საზოგადოებამ **`System.Linq.Async`** NuGet პაკეტში მოგვცა.

### ასინქრონული პრედიკატი: `WhereAwait`

LINQ-ის ერთ-ერთი გავრცელებული კითხვაა: როგორ გამოვიყენოთ `Where`, თუ პრედიკატი **ასინქრონულია**? ანუ თანმიმდევრობის გაფილტვრა ასინქრონული პირობით გვინდა: მაგალითად, ყოველი ელემენტი ბაზაში ან API-ში უნდა შევამოწმოთ. ჩვეულებრივი `Where` ამას ვერ აკეთებს, რადგან მისი დელეგატი **მყისიერ, სინქრონულ** პასუხს უნდა აბრუნებდეს.

ასინქრონულ ნაკადებს ამისთვის სპეციალური ოპერატორები აქვს. აქ სწორი არჩევანია **`WhereAwait`**:

```csharp
IAsyncEnumerable<int> values = SlowRange().WhereAwait(
    async value =>
    {
        // ასინქრონული სამუშაო იმის დასადგენად,
        // უნდა შევიდეს თუ არა ეს ელემენტი შედეგში
        await Task.Delay(10);
        return value % 2 == 0;
    });

await foreach (int result in values)
{
    Console.WriteLine(result);
}

// თანმიმდევრობა, რომელიც პროგრესთან ერთად ნელდება
async IAsyncEnumerable<int> SlowRange()
{
    for (int i = 0; i != 10; ++i)
    {
        await Task.Delay(i * 100);
        yield return i;
    }
}
```

### სინქრონული ოპერატორებიც მუშაობს

ასინქრონული ნაკადების LINQ ოპერატორებს **სინქრონული ვერსიებიც** აქვს: სავსებით აზრიანია სინქრონული `Where`-ის (ან `Select`-ის) გამოყენება ასინქრონულ ნაკადზე. შედეგი მაინც ასინქრონული ნაკადია:

```csharp
IAsyncEnumerable<int> values = SlowRange().Where(value => value % 2 == 0);

await foreach (int result in values)
{
    Console.WriteLine(result);
}
```

ყველა ძველი ნაცნობი აქაა: `Where`, `Select`, `SelectMany`, თვით `Join`-იც. ოპერატორების უმეტესობას ასინქრონული დელეგატის მიმღები ვერსიაც აქვს, როგორც ზემოთ ნაჩვენები `WhereAwait`.

## სახელების წესი: `Await` და `Async`

ასინქრონული ნაკადების LINQ ოპერატორების შესწავლისას შეამჩნევთ, რომ ზოგი სახელი `Async`-ით მთავრდება, ზოგი `Await`-ით. წესი ასეთია:

| სუფიქსი | მნიშვნელობა |
|---|---|
| **`Await`** | ოპერატორი **ასინქრონულ დელეგატს** იღებს (და მას `await`-ს უკეთებს) |
| **`Async`** | ოპერატორი აბრუნებს **awaitable-ს**, ანუ ერთ მნიშვნელობას და არა ასინქრონულ თანმიმდევრობას (ე.წ. **დამასრულებელი** ოპერატორი) |
| **ორივე** | ოპერატორი ასინქრონულ დელეგატსაც იღებს **და** ერთ მნიშვნელობასაც აბრუნებს |

*ნახაზი 3.4: ოპერატორების სახელების ორი განზომილება.*

დამასრულებელი ოპერატორის მაგალითია `CountAsync`, `Count`-ის ასინქრონული ვერსია, რომელიც პრედიკატის შესაბამისი ელემენტების რაოდენობას ითვლის:

```csharp
int count = await SlowRange().CountAsync(value => value % 2 == 0);
```

თუ პრედიკატიც ასინქრონულია, გამოიყენება `CountAwaitAsync`, რადგან ის **ასინქრონულ დელეგატსაც** იღებს და **ერთ საბოლოო მნიშვნელობასაც** აბრუნებს:

```csharp
int count = await SlowRange().CountAwaitAsync(
    async value =>
    {
        await Task.Delay(10);
        return value % 2 == 0;
    });
```

## განხილვა

ასინქრონული ნაკადები **pull**-ზეა აგებული, ამიტომ მათ არ აქვთ **დროსთან დაკავშირებული** ოპერატორები, როგორიც observable-ებს აქვს. `Throttle` და `Sample` აქ აზრს კარგავს, რადგან ელემენტები ნაკადიდან მოთხოვნისამებრ ამოიღება ([[თავი 6.4 მოვლენების ნაკადის დამორჩილება|6.4]]).

ასინქრონული ნაკადების LINQ მეთოდები **ჩვეულებრივი enumerable-ებისთვისაც** გამოდგება. თუ ასეთ სიტუაციაში აღმოჩნდებით, ნებისმიერ `IEnumerable<T>`-ზე გამოიძახეთ `ToAsyncEnumerable()`, და მიიღებთ ასინქრონული ნაკადის ინტერფეისს, რომელზეც `WhereAwait`, `SelectAwait` და სხვა ასინქრონულ დელეგატებიან ოპერატორებს გამოიყენებთ.

> [!TIP] NuGet პაკეტები
> ასინქრონული ნაკადების LINQ ოპერატორები **`System.Linq.Async`** პაკეტშია. დამატებითი ოპერატორები **`System.Interactive.Async`**-ში.

> [!NOTE] თანამედროვე .NET
> .NET 10-ში LINQ ოპერატორები `IAsyncEnumerable<T>`-ისთვის **პლატფორმაში** დაემატა (`System.Linq.AsyncEnumerable`), ამიტომ ახალ პროექტებში ცალკე პაკეტი შეიძლება აღარ დაგჭირდეთ. ასევე, EF Core-ს აქვს საკუთარი ასინქრონული ოპერატორები (`ToListAsync`, `AnyAsync` და სხვ.), რომლებიც ბაზაში ითარგმნება.
