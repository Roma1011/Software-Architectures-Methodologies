## პრობლემა

გაქვთ მაღალკონკურენტული კოდი, რომელიც სინამდვილეში **ზედმეტად** კონკურენტულია, და კონკურენტულობის დროსელირების გზა გჭირდებათ.

კოდი მაშინაა ზედმეტად კონკურენტული, როცა აპლიკაციის ზოგიერთი ნაწილი სხვა ნაწილებს **ვერ ეწევა**, რის გამოც მონაცემები გროვდება და მეხსიერებას ხარჯავს. ასეთ სცენარში კოდის ნაწილების დროსელირება მეხსიერების პრობლემებს აგვარიდებს.

## გადაწყვეტა

გადაწყვეტა დამოკიდებულია იმაზე, **რა სახის** კონკურენტულობას ახორციელებს თქვენი კოდი. ყველა ეს გადაწყვეტა კონკურენტულობას კონკრეტულ მნიშვნელობამდე ზღუდავს. Reactive Extensions-ს უფრო ძლიერი ვარიანტები აქვს, მაგალითად **მოცურავე დროის ფანჯრები** ([[თავი 6.4 მოვლენების ნაკადის დამორჩილება|6.4]]).

### Dataflow

```csharp
IPropagatorBlock<int, int> DataflowMultiplyBy2()
{
    var options = new ExecutionDataflowBlockOptions
    {
        MaxDegreeOfParallelism = 10
    };

    return new TransformBlock<int, int>(data => data * 2, options);
}
```

### Parallel LINQ (PLINQ)

```csharp
IEnumerable<int> ParallelMultiplyBy2(IEnumerable<int> values)
{
    return values.AsParallel()
        .WithDegreeOfParallelism(10)
        .Select(item => item * 2);
}
```

### `Parallel` კლასი

```csharp
void ParallelRotateMatrices(IEnumerable<Matrix> matrices, float degrees)
{
    var options = new ParallelOptions
    {
        MaxDegreeOfParallelism = 10
    };
    Parallel.ForEach(matrices, options, matrix => matrix.Rotate(degrees));
}
```

### ასინქრონული კოდი: `SemaphoreSlim`

```csharp
async Task<string[]> DownloadUrlsAsync(HttpClient client,
    IEnumerable<string> urls)
{
    using var semaphore = new SemaphoreSlim(10);

    Task<string>[] tasks = urls.Select(async url =>
    {
        await semaphore.WaitAsync();
        try
        {
            return await client.GetStringAsync(url);
        }
        finally
        {
            semaphore.Release();
        }
    }).ToArray();

    return await Task.WhenAll(tasks);
}
```

## განხილვა

დროსელირება შეიძლება საჭირო გახდეს, როცა აღმოაჩენთ, რომ თქვენი კოდი **ძალიან ბევრ რესურსს** იყენებს (მაგალითად, CPU-ს ან ქსელის შეერთებებს).

> [!IMPORTANT] მომხმარებლის მანქანა თქვენსაზე სუსტია
> გაითვალისწინეთ, რომ საბოლოო მომხმარებლებს ჩვეულებრივ დეველოპერებზე **ნაკლებად მძლავრი მანქანები** აქვთ, ამიტომ სჯობს, ცოტა **მეტად** დაადროსელიროთ, ვიდრე ნაკლებად.

> [!TIP] `Parallel.ForEachAsync`
> .NET 6-დან ასინქრონული სამუშაოს დროსელირებისთვის `SemaphoreSlim`-ის ხელით აწყობა ხშირად საჭირო აღარ არის:
> ```csharp
> await Parallel.ForEachAsync(urls,
>     new ParallelOptions { MaxDegreeOfParallelism = 10 },
>     async (url, token) => await client.GetStringAsync(url, token));
> ```
> ერთადერთი განსხვავებაა, რომ `ForEachAsync` შედეგებს არ აგროვებს: მათ თავად უნდა შეაგროვოთ thread-safe კოლექციაში.

> [!NOTE] `MaxDegreeOfParallelism = -1`
> ნაგულისხმევი მნიშვნელობა `-1`-ია, რაც „შეზღუდვის გარეშეს" ნიშნავს: TPL თავად წყვეტს ნაკადების რაოდენობას. აშკარა შეზღუდვა მაშინ დაგჭირდებათ, როცა გარე რესურსს (ბაზა, API) იცავთ, და არა მაშინ, როცა CPU-ს იყენებთ.
