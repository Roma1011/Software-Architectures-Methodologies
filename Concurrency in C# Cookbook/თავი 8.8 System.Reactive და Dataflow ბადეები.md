## პრობლემა

გადაწყვეტის ერთი ნაწილი `System.Reactive` observable-ებს იყენებს, მეორე ნაწილი dataflow ბადეებს, და გჭირდებათ, რომ ისინი ერთმანეთს დაუკავშირდნენ.

`System.Reactive` observable-ებსა და dataflow ბადეებს თითოეულს თავისი გამოყენება აქვს და გარკვეული კონცეპტუალური გადაფარვაც. ეს რეცეპტი აჩვენებს, რამდენად ადვილად მუშაობენ ისინი ერთად, ასე რომ თითოეული სამუშაოსთვის საუკეთესო ინსტრუმენტს გამოიყენებთ.

## გადაწყვეტა

### ბლოკი observable ნაკადის შესავალად

ჯერ განვიხილოთ dataflow ბლოკის გამოყენება observable ნაკადის შესავალად. კოდი ქმნის ბუფერის ბლოკს (რომელიც არაფერს ამუშავებს) და ამ ბლოკიდან observable ინტერფეისს **`AsObservable`**-ის გამოძახებით ქმნის:

```csharp
var buffer = new BufferBlock<int>();
IObservable<int> integers = buffer.AsObservable();

integers.Subscribe(data => Trace.WriteLine(data),
    ex => Trace.WriteLine(ex),
    () => Trace.WriteLine("დასრულდა"));

buffer.Post(13);
```

ბუფერის ბლოკებიც და observable ნაკადებიც შეიძლება ნორმალურად ან შეცდომით დასრულდეს, და `AsObservable` მეთოდი ბლოკის დასრულებას (ან ჩავარდნას) observable ნაკადის დასრულებად თარგმნის.

> [!WARNING] `AggregateException`-ში გახვევა
> თუ ბლოკი გამონაკლისით ჩავარდა, ეს გამონაკლისი observable ნაკადში გადაცემისას **`AggregateException`-ში გაიხვევა**. ეს იმის მსგავსია, როგორც დაკავშირებული ბლოკები ავრცელებენ თავიანთ ჩავარდნებს ([[თავი 5.2 შეცდომების გავრცელება|5.2]]).

### ბადე observable ნაკადის დანიშნულებად

ოდნავ უფრო რთულია ბადის observable ნაკადის **დანიშნულებად** გამოყენება. კოდი **`AsObserver`**-ს იძახებს, რომ ბლოკს observable ნაკადზე ხელმოწერის საშუალება მისცეს:

```csharp
IObservable<DateTimeOffset> ticks =
    Observable.Interval(TimeSpan.FromSeconds(1))
        .Timestamp()
        .Select(x => x.Timestamp)
        .Take(5);

var display = new ActionBlock<DateTimeOffset>(x => Trace.WriteLine(x));
ticks.Subscribe(display.AsObserver());

try
{
    display.Completion.Wait();
    Trace.WriteLine("დასრულდა.");
}
catch (Exception ex)
{
    Trace.WriteLine(ex);
}
```

როგორც ადრე, observable ნაკადის დასრულება ბლოკის დასრულებად ითარგმნება, და observable ნაკადის ნებისმიერი შეცდომა ბლოკის ჩავარდნად.

## განხილვა

Dataflow ბლოკები და observable ნაკადები ბევრ კონცეპტუალურ საფუძველს იზიარებს: ორივეში მონაცემები **გაივლის**, და ორივე იგებს **დასრულებასა** და **ჩავარდნას**. ისინი სხვადასხვა სცენარისთვის შეიქმნა: TPL Dataflow ასინქრონული და პარალელური პროგრამირების ნაზავისთვისაა განკუთვნილი, `System.Reactive` კი რეაქტიული პროგრამირებისთვის. თუმცა კონცეპტუალური გადაფარვა საკმარისად თავსებადია, რომ ისინი ძალიან კარგად და ბუნებრივად მუშაობდნენ ერთად.

| | TPL Dataflow | System.Reactive |
|---|---|---|
| ძირითადი დანიშნულება | ასინქრონული + პარალელური დამუშავება | მოვლენებზე რეაქცია |
| მონაცემები | ბლოკებში **ინახება** (ბუფერი) | **გაივლის**, არ ინახება |
| დროსელირება | `BoundedCapacity` (უკუწნევა) | `Throttle`/`Sample` (ელემენტების გადაგდება) |
| პარალელიზმი | `MaxDegreeOfParallelism` | `ObserveOn` + scheduler-ები |
| დროის ოპერატორები | არ აქვს | მდიდარი ნაკრები |

> [!TIP] პრაქტიკული ნაზავი
> გავრცელებული სცენარია: **Rx** მოვლენების მიღებისა და ფილტრაციისთვის (`Throttle`, `Buffer`), შემდეგ `AsObserver()` **Dataflow** ბადეში, სადაც მძიმე დამუშავება ხდება უკუწნევით და კონტროლირებადი პარალელიზმით.
