## პრობლემა

ერთი ნაკადიდან მეორეს შეტყობინების გაგზავნა გჭირდებათ.

## გადაწყვეტა

ყველაზე გავრცელებული და ზოგადი დანიშნულების ნაკადთაშორისი სიგნალია **`ManualResetEventSlim`**. ხელით ჩამოსაყრელი მოვლენა (manual-reset event) ორი მდგომარეობიდან ერთში შეიძლება იყოს: **სიგნალირებული** ან **არასიგნალირებული**. ნებისმიერ ნაკადს შეუძლია მოვლენა სიგნალირებულ მდგომარეობაში გადაიყვანოს ან არასიგნალირებულში ჩამოაყაროს. ნაკადს ასევე შეუძლია სიგნალირებას **დაელოდოს**.

ქვემოთ ორი მეთოდი სხვადასხვა ნაკადიდან იძახება: ერთი ნაკადი მეორისგან სიგნალს ელოდება:

```csharp
class MyClass
{
    private readonly ManualResetEventSlim _initialized =
        new ManualResetEventSlim();

    private int _value;

    public int WaitForInitialization()
    {
        _initialized.Wait();
        return _value;
    }

    public void InitializeFromAnotherThread()
    {
        _value = 13;
        _initialized.Set();
    }
}
```

## განხილვა

`ManualResetEventSlim` შესანიშნავი ზოგადი დანიშნულების სიგნალია ერთი ნაკადიდან მეორეზე, მაგრამ მხოლოდ მაშინ უნდა გამოიყენოთ, როცა **შესაფერისია**:

- თუ „სიგნალი" სინამდვილეში **შეტყობინებაა**, რომელიც ნაკადებს შორის მონაცემებს აგზავნის, განიხილეთ **მწარმოებელი/მომხმარებლის რიგი** ([[თავი 9.6 მბლოკავი რიგები|9.6]]).
- მეორე მხრივ, თუ სიგნალები მხოლოდ **გაზიარებულ მონაცემებზე წვდომის კოორდინირებას** ემსახურება, **ბლოკირება** უნდა გამოიყენოთ ([[თავი 12.1 ბლოკირებები|12.1]]).

.NET ფრეიმვორკში ნაკადთა სინქრონიზაციის სხვა სიგნალის ტიპებიც არის, ნაკლებად გავრცელებული. თუ `ManualResetEventSlim` თქვენს საჭიროებებს არ შეესაბამება, განიხილეთ:

| ტიპი | ქცევა |
|---|---|
| `AutoResetEvent` | ერთი მლოდინის გათავისუფლების შემდეგ **ავტომატურად** ჩამოიყრება |
| `CountdownEvent` | სიგნალირდება, როცა მთვლელი ნულამდე ჩამოვა (N ოპერაციის ლოდინი) |
| `Barrier` | რამდენიმე ნაკადი ერთმანეთს „ბარიერზე" ელოდება ფაზების მიხედვით |
| `SemaphoreSlim` | N ერთდროულ მონაწილეს უშვებს ([[თავი 12.2 ასინქრონული ბლოკირებები\|12.2]], [[თავი 12.5 დროსელირება\|12.5]]) |

`ManualResetEventSlim` **სინქრონული** სიგნალია, ამიტომ `WaitForInitialization` **დაბლოკავს** გამომძახებელ ნაკადს, სანამ სიგნალი არ გაიგზავნება. თუ სიგნალის ლოდინი ნაკადის დაბლოკვის გარეშე გინდათ, **ასინქრონული სიგნალი** გჭირდებათ ([[თავი 12.4 ასინქრონული სიგნალები|12.4]]).

> [!TIP] რატომ „Slim"
> `ManualResetEventSlim` ჯერ გარკვეული ხნის განმავლობაში **ტრიალებს (spin)** და მხოლოდ შემდეგ გადადის ბირთვის ნამდვილ ლოდინზე. ეს მოკლე ლოდინებს გაცილებით სწრაფს ხდის. ძველი `ManualResetEvent` (Slim-ის გარეშე) ბირთვის ობიექტია და მაშინაა საჭირო, როცა სიგნალი **პროცესებს შორის** უნდა გაზიაროთ ან `WaitHandle` გჭირდებათ.
