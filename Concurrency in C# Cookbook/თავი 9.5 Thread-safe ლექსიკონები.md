## პრობლემა

გაქვთ გასაღები/მნიშვნელობის კოლექცია (მაგალითად, მეხსიერებაში არსებული ქეში), რომელიც სინქრონულად უნდა შეინარჩუნოთ მაშინაც კი, როცა მრავალი ნაკადი მას **ერთდროულად კითხულობს და წერს**.

## გადაწყვეტა

.NET-ის **`ConcurrentDictionary<TKey, TValue>`** ტიპი მონაცემთა სტრუქტურების ნამდვილი მარგალიტია. ის thread-safe-ია და წვრილმარცვლოვან ბლოკირებებსა და ბლოკირების გარეშე ტექნიკებს აზავებს, რომ სცენარების აბსოლუტურ უმრავლესობაში სწრაფი წვდომა უზრუნველყოს.

მის API-ს შეჩვევა ცოტა დროს მოითხოვს. ის ძალიან განსხვავდება სტანდარტული `Dictionary<TKey, TValue>`-ისგან, რადგან მას მრავალი ნაკადის კონკურენტულ წვდომასთან უწევს გამკლავება. მაგრამ ამ რეცეპტის საფუძვლების შესწავლის შემდეგ `ConcurrentDictionary<TKey, TValue>` ერთ-ერთი ყველაზე სასარგებლო კოლექციის ტიპი გახდება თქვენთვის.

### ჩაწერა: `AddOrUpdate`

```csharp
var dictionary = new ConcurrentDictionary<int, string>();
string newValue = dictionary.AddOrUpdate(0,
    key => "ნული",
    (key, oldValue) => "ნული");
```

`AddOrUpdate` ცოტა რთულია, რადგან მას რამდენიმე რამის გაკეთება უწევს, კონკურენტული ლექსიკონის მიმდინარე შიგთავსის მიხედვით:

1. **პირველი** არგუმენტი გასაღებია.
2. **მეორე** არგუმენტი დელეგატია, რომელიც გასაღებს (აქ 0) ლექსიკონში დასამატებელ მნიშვნელობად გარდაქმნის (აქ `"ნული"`). ეს დელეგატი მხოლოდ მაშინ გამოიძახება, **თუ გასაღები ლექსიკონში არ არის**.
3. **მესამე** არგუმენტი კიდევ ერთი დელეგატია, რომელიც გასაღებსა (0) და ძველ მნიშვნელობას ლექსიკონში შესანახ განახლებულ მნიშვნელობად გარდაქმნის. ეს დელეგატი მხოლოდ მაშინ გამოიძახება, **თუ გასაღები ლექსიკონში არსებობს**.

`AddOrUpdate` ამ გასაღების **ახალ მნიშვნელობას** აბრუნებს (იმავე მნიშვნელობას, რომელიც ერთ-ერთმა დელეგატმა დააბრუნა).

> [!WARNING] დელეგატი შეიძლება რამდენჯერმე გამოიძახოს
> და ახლა ის ნაწილი, რომელიც ტვინს ატრიალებს: იმისთვის, რომ კონკურენტულმა ლექსიკონმა სწორად იმუშაოს, `AddOrUpdate`-ს შეიძლება **რომელიმე (ან ორივე) დელეგატის მრავალჯერ გამოძახება** დასჭირდეს. ეს ძალიან იშვიათია, მაგრამ ხდება.
>
> ამიტომ თქვენი დელეგატები **მარტივი, სწრაფი და გვერდითი ეფექტების გარეშე** უნდა იყოს: დელეგატმა მხოლოდ მნიშვნელობა უნდა შექმნას და აპლიკაციის სხვა ცვლადები არ უნდა შეცვალოს. იგივე პრინციპი მოქმედებს **ყველა** დელეგატზე, რომელსაც `ConcurrentDictionary<TKey, TValue>`-ის მეთოდებს გადასცემთ.

### ჩაწერა: ინდექსირების სინტაქსი

```csharp
// იგივე "dictionary".
// ამატებს (ან განაახლებს) გასაღებ 0-ს მნიშვნელობით "ნული".
dictionary[0] = "ნული";
```

ინდექსირების სინტაქსი **ნაკლებად ძლიერია**: ის არსებულ მნიშვნელობაზე დაყრდნობით განახლების საშუალებას არ იძლევა. სამაგიეროდ სინტაქსი უფრო მარტივია და კარგად მუშაობს, თუ შესანახი მნიშვნელობა უკვე გაქვთ.

### კითხვა: `TryGetValue`

```csharp
bool keyExists = dictionary.TryGetValue(0, out string currentValue);
```

`TryGetValue` `true`-ს დააბრუნებს და `out` მნიშვნელობას დააყენებს, თუ გასაღები ლექსიკონში მოიძებნა. თუ არ მოიძებნა, `false`-ს დააბრუნებს.

ინდექსირების სინტაქსითაც შეგიძლიათ კითხვა, მაგრამ ავტორს ის გაცილებით ნაკლებად სასარგებლოდ მიაჩნია, რადგან ის **გამონაკლისს ისვრის**, თუ გასაღები არ მოიძებნა. გახსოვდეთ, რომ კონკურენტულ ლექსიკონში მრავალი ნაკადი კითხულობს, ანახლებს, ამატებს და შლის მნიშვნელობებს: ბევრ სიტუაციაში ძნელია იმის ცოდნა, არსებობს თუ არა გასაღები, სანამ მის წაკითხვას არ სცდი.

### წაშლა: `TryRemove`

```csharp
bool keyExisted = dictionary.TryRemove(0, out string removedValue);
```

`TryRemove` თითქმის იდენტურია `TryGetValue`-სი, ოღონდ (რა თქმა უნდა) გასაღები/მნიშვნელობის წყვილს **შლის**, თუ გასაღები ლექსიკონში მოიძებნა.

## განხილვა

მიუხედავად იმისა, რომ `ConcurrentDictionary<TKey, TValue>` thread-safe-ია, ეს **არ ნიშნავს, რომ მისი ოპერაციები ატომურია**. თუ მრავალი ნაკადი `AddOrUpdate`-ს ერთდროულად იძახებს, შესაძლებელია, ორივემ დაინახოს, რომ გასაღები არ არსებობს, და ორივემ ერთდროულად შეასრულოს ახალი მნიშვნელობის შემქმნელი დელეგატი.

ავტორს `ConcurrentDictionary<TKey, TValue>` შესანიშნავად მიაჩნია, ძირითადად წარმოუდგენლად ძლიერი `AddOrUpdate` მეთოდის გამო. თუმცა ის ყველა სიტუაციას არ ერგება:

| სიტუაცია | საუკეთესო არჩევანი |
|---|---|
| მრავალი ნაკადი კითხულობს **და** წერს გაზიარებულ კოლექციაში | `ConcurrentDictionary<TK,TV>` |
| განახლებები **იშვიათია** | `ImmutableDictionary<TK,TV>` ([[თავი 9.4 უცვლელი ლექსიკონები\|9.4]]) |
| ზოგი ნაკადი მხოლოდ **ამატებს**, სხვები მხოლოდ **შლის** | მწარმოებელი/მომხმარებლის კოლექცია |

`ConcurrentDictionary<TKey, TValue>` ერთადერთი thread-safe კოლექცია არ არის. BCL ასევე გვთავაზობს `ConcurrentStack<T>`-ს, `ConcurrentQueue<T>`-სა და `ConcurrentBag<T>`-ს. thread-safe კოლექციები ხშირად მწარმოებელი/მომხმარებლის კოლექციებად გამოიყენება, რაც ამ თავის დანარჩენ ნაწილშია განხილული.

> [!TIP] `GetOrAdd`
> ქეშის სცენარისთვის ხშირად `GetOrAdd`-ია უფრო შესაფერისი: `dictionary.GetOrAdd(key, k => ExpensiveCompute(k))`. ისიც იმავე გაფრთხილებას ექვემდებარება: ძვირადღირებული ფაბრიკა შეიძლება **რამდენჯერმე** გაეშვას. თუ ეს დაუშვებელია, `Lazy<T>` შეინახეთ მნიშვნელობად: `dictionary.GetOrAdd(key, k => new Lazy<T>(() => Compute(k))).Value`.
