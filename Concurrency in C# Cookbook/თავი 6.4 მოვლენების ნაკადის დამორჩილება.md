## პრობლემა

რეაქტიული კოდის წერისას გავრცელებული პრობლემაა, როცა მოვლენები **ძალიან სწრაფად** მოდის. სწრაფად მოძრავმა მოვლენების ნაკადმა შეიძლება პროგრამის დამუშავების შესაძლებლობები გადააჭარბოს.

## გადაწყვეტა

`System.Reactive`-ს სპეციალური ოპერატორები აქვს მოვლენების ნიაღვართან გასამკლავებლად. **`Throttle`** და **`Sample`** სწრაფი შემავალი მოვლენების „დამორჩილების" ორ განსხვავებულ გზას იძლევა.

### `Throttle`: სიჩუმის ლოდინი

`Throttle` ოპერატორი **მოცურავე (sliding) ლოდინის ფანჯარას** ქმნის. როცა შემავალი მოვლენა მოდის, ის ფანჯარას **თავიდან უშვებს**. როცა ფანჯარა ამოიწურება, ის აქვეყნებს **ბოლო** მნიშვნელობას, რომელიც ფანჯარაში მოვიდა.

```csharp
Observable.FromEventPattern<MouseEventHandler, MouseEventArgs>(
        handler => (s, a) => handler(s, a),
        handler => MouseMove += handler,
        handler => MouseMove -= handler)
    .Select(x => x.EventArgs.GetPosition(this))
    .Throttle(TimeSpan.FromSeconds(1))
    .Subscribe(x => Trace.WriteLine($"{DateTime.Now.Second}: ვნახე {x.X + x.Y}"));
```

შედეგი მოვლენას მხოლოდ მაშინ აქვეყნებს, როცა თაგვი **მთელი წამის განმავლობაში უძრავად იდგა**:

```
47: ვნახე 139
49: ვნახე 137
51: ვნახე 424
56: ვნახე 226
```

`Throttle` ხშირად გამოიყენება **ავტომატური შევსების (autocomplete)** სცენარში: მომხმარებელი ტექსტს კრეფს, და ჩვენ ნამდვილი ძებნა არ გვინდა, სანამ ის კრეფას არ შეწყვეტს.

### `Sample`: რეგულარული ინტერვალი

`Sample` სხვა მიდგომას იყენებს: ის **რეგულარულ ინტერვალს** აყენებს და ყოველი ინტერვალის ბოლოს **უახლეს** მნიშვნელობას აქვეყნებს. თუ ინტერვალში მნიშვნელობა არ მოსულა, ამ პერიოდზე არაფერი ქვეყნდება.

```csharp
Observable.FromEventPattern<MouseEventHandler, MouseEventArgs>(
        handler => (s, a) => handler(s, a),
        handler => MouseMove += handler,
        handler => MouseMove -= handler)
    .Select(x => x.EventArgs.GetPosition(this))
    .Sample(TimeSpan.FromSeconds(1))
    .Subscribe(x => Trace.WriteLine($"{DateTime.Now.Second}: ვნახე {x.X + x.Y}"));
```

`Throttle`-ისგან განსხვავებით, აქ მონაცემების სანახავად თაგვის გაჩერება **საჭირო არ არის**:

```
12: ვნახე 311
17: ვნახე 254
18: ვნახე 269
19: ვნახე 342
```

## განხილვა

დროსელირება და შერჩევა (sampling) შემავალი ნიაღვრის დასამორჩილებლად აუცილებელი ინსტრუმენტებია. არ დაგავიწყდეთ, რომ ჩვეულებრივი LINQ-ის **`Where`** ოპერატორითაც ადვილად გაფილტრავთ მონაცემებს.

> [!IMPORTANT] სამივე ერთი ოჯახია
> `Throttle` და `Sample` `Where`-ის მსგავსია, ოღონდ ისინი **დროის ფანჯრებით** ფილტრავენ და არა მოვლენის მონაცემებით. სამივე სხვადასხვა გზით გვეხმარება სწრაფად მოძრავი შემავალი ნაკადების დამორჩილებაში.

| ოპერატორი | ფილტრავს | გამოყენება |
|---|---|---|
| `Where` | მონაცემის მიხედვით | არასაჭირო მოვლენების გაფილტვრა |
| `Throttle` | სიჩუმის ლოდინით | ავტომატური შევსება, ძებნის ველი, ფანჯრის ზომის ცვლილება |
| `Sample` | რეგულარული ინტერვალით | სენსორის მონაცემები, პროგრესის ინდიკატორი, ცოცხალი გრაფიკი |

> [!NOTE] სახელების დაბნეულობა
> Rx-ის `Throttle` სხვა ბიბლიოთეკებში ხშირად **„debounce"** ჰქვია, ხოლო Rx-ის `Sample` ხშირად „throttle". თუ სხვა ეკოსისტემიდან მოდიხართ (მაგალითად, JavaScript-იდან), ეს გაითვალისწინეთ.
