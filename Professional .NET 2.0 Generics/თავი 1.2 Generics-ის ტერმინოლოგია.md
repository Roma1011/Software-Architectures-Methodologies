კონცეფციების გარდა, მნიშვნელოვანია ზუსტი ლექსიკონიც. Generics-ის ტერმინები მთელ წიგნში გამოიყენება და ერთმანეთს ადვილად ერევა, ამიტომ თითოეულს ცალკე განვმარტავთ. საილუსტრაციოდ ავიღოთ მარტივი generic სტეკის კარკასი:

```csharp
public class Stack<T>
{
    private T[] _items;
    private int _count;

    public void Push(T item) { /* ... */ }
    public T Pop() { /* ... */ }
}
```

## ტიპის პარამეტრი (Type Parameter)

**ტიპის პარამეტრი** არის სახელი, რომელიც generic ტიპის **განსაზღვრებაში** ცხადდება. `Stack<T>`-ში ეს `T`-ა. ტიპს შეიძლება ერთი ან რამდენიმე ტიპის პარამეტრი ჰქონდეს (მაგალითად, `Dictionary<TKey, TValue>`) და ეს სია ტიპის ხელმოწერის (signature) ნაწილია. პარამეტრის სახელი შემდეგ მთელ იმპლემენტაციაში გამოიყენება: `Stack<T>`-ში `T` ჩანს ველის ტიპში, `Push`-ის პარამეტრში და `Pop`-ის დასაბრუნებელ ტიპში.

ტიპის პარამეტრი შეიძლება ჰქონდეს **კლასს, სტრუქტურას (struct), ინტერფეისს, დელეგატს და მეთოდს**. მაგრამ **indexer-ს, property-ს და event-ს საკუთარი ტიპის პარამეტრი არ შეიძლება ჰქონდეს**:

```csharp
public class Registry<T>
{
    // სწორია: property იყენებს გარე კლასის T-ს
    public T Current { get; set; }

    // არასწორია: property-ს საკუთარი ტიპის პარამეტრი ვერ ექნება
    // public U Other<U> { get; set; }     // კომპილაციის შეცდომა
}
```

ეს არ ნიშნავს, რომ ამ კონსტრუქციებმა ტიპის პარამეტრების შესახებ არაფერი იციან. მათ ხელმოწერაში გარე კლასის ტიპის პარამეტრი შეიძლება გამოვიყენოთ, უბრალოდ საკუთარს ვერ გამოაცხადებენ. შესაბამისად, property-ს გამოძახებისას ტიპის არგუმენტს ვერ გადავცემთ.

## ღია ტიპი (Open Type)

`Stack<T>` ბევრით ჰგავს ჩვეულებრივ კლასს, მაგრამ ტიპის პარამეტრი მას ახალ კონსტრუქციად აქცევს. ამიტომ მას **ღია ტიპს (open type)** ვუწოდებთ. „ღია" იმას ნიშნავს, რომ ტიპი ბოლომდე განსაზღვრული არ არის და სხვადასხვა კონკრეტული სახის მიღებისთვის „ღიაა". C++-ის templates-ის ცოდნით მოსულს შეიძლება „პარამეტრიზებული ტიპი" (parameterized type) უფრო ეცნოს, მაგრამ .NET-ში „ღია ტიპი" არის მიღებული ტერმინი.

ღია ტიპის ობიექტს ვერ შევქმნით: `new Stack<T>()` მხოლოდ მაშინ შეიძლება, როცა `T` თავად სხვა generic განსაზღვრების პარამეტრია.

## აგებული ტიპი (Constructed Type)

ღია ტიპი და ტიპის პარამეტრები generic ტიპის **სტრუქტურას** განსაზღვრავს. **აგებული ტიპი (constructed type)** კი ღია ტიპის კონკრეტული ვარიანტია:

```csharp
Stack<string> names = new Stack<string>();
```

`Stack<string>` აგებული ტიპია. ის ჩვეულებრივი .NET ტიპების თვისებების უმეტესობას იზიარებს, თუმცა სინტაქსური თავისებურებები აქვს, რომლებსაც შემდეგ თავებში განვიხილავთ.

## ტიპის არგუმენტი (Type Argument)

**ტიპის არგუმენტი** არის კონკრეტული ტიპი, რომელსაც აგებული ტიპის შექმნისას ტიპის პარამეტრის ადგილას ვაწვდით. `Stack<string>`-ში `string` ტიპის არგუმენტია.

ეს წყვილი ზუსტად ემთხვევა მეთოდების ტერმინოლოგიას:

| მეთოდები | Generics |
|---|---|
| პარამეტრი (`int x`), განსაზღვრებაში | ტიპის პარამეტრი (`T`), განსაზღვრებაში |
| არგუმენტი (`Square(5)`), გამოძახებისას | ტიპის არგუმენტი (`Stack<string>`), გამოყენებისას |

## ღია და დახურული აგებული ტიპები (Open and Closed Constructed Types)

აგებული ტიპის შექმნისას ტიპის არგუმენტი ყოველთვის კონკრეტული ტიპი არ არის:

```csharp
public class Warehouse<T>
{
    private List<int> _shelfNumbers;   // დახურული აგებული ტიპი
    private List<T> _goods;            // ღია აგებული ტიპი
}
```

- `List<int>` **დახურული აგებული ტიპია (closed constructed type)**. მისი ტიპის არგუმენტი ფიქსირებულია და შემდგომ განსაზღვრას აღარ ექვემდებარება: ის ყოველთვის `int` იქნება.
- `List<T>` **ღია აგებული ტიპია (open constructed type)**. ის ფორმალურად აგებული ტიპია, რადგან `List`-ს არგუმენტი გადავეცით, მაგრამ ეს არგუმენტი თავად `Warehouse`-ის ტიპის პარამეტრია. საბოლოო ტიპი გაირკვევა მხოლოდ მაშინ, როცა ვინმე `Warehouse<Product>`-ს შექმნის.

## Generic მეთოდები (Generic Methods)

აქამდე მხოლოდ generic კლასებზე ვსაუბრობდით, მაგრამ ტიპის პარამეტრი **ცალკეულ მეთოდსაც** შეიძლება ჰქონდეს, მაშინაც კი, როცა თავად კლასი generic არ არის:

```csharp
public class Converter
{
    public T FirstOrFallback<T>(T[] items, T fallback)
    {
        T result = items.Length > 0 ? items[0] : fallback;
        return result;
    }
}
```

generic მეთოდი, ისევე როგორც ღია ტიპი, ტიპის პარამეტრს იღებს და მას ხელმოწერაშიც და იმპლემენტაციაშიც იყენებს. ამ მაგალითში `T` გამოიყენება დასაბრუნებელ ტიპში, ორივე პარამეტრში და ლოკალურ ცვლადშიც. დეტალურად generic მეთოდებს [[თავი 5.1 Generic მეთოდების საფუძვლები|მე-5 თავში]] განვიხილავთ.

## ტიპის ინსტანცირება (Type Instantiation)

როცა Just-In-Time (JIT) კომპილატორი კოდში აგებულ ტიპს **პირველად** ხვდება, ის ამ ტიპის გაშვების დროის წარმოდგენას ქმნის. ამისთვის თითოეულ ტიპის არგუმენტს ამოწმებს და ღია ტიპის პარამეტრებს მათით ანაცვლებს. შედეგად მიიღება აგებული ტიპის ზუსტი, გაშვების დროის წარმოდგენა. ამ პროცესს **ტიპის ინსტანცირება** ჰქვია, რადგან ის აგებული ტიპის რეალურ „ეგზემპლარს" ქმნის.

მნიშვნელოვანია, არ აგვერიოს **ობიექტის ინსტანცირებაში** (`new`). ტიპის ინსტანცირება ტიპის დონეზე ხდება და ერთ აგებულ ტიპზე მხოლოდ ერთხელ. როგორ ზოგავს CLR კოდს სხვადასხვა ტიპის არგუმენტებს შორის, ამას [[თავი 11.3 სპეციალიზაცია და გაზიარება|მე-11 თავში]] ვნახავთ.

## Arity

**Arity** არის generic ტიპის ტიპის პარამეტრების რაოდენობა. `Stack<T>`-ის arity 1-ია, `Dictionary<TKey, TValue>`-ის 2, ჩვეულებრივი, არაgeneric კლასის კი 0. ეს ტერმინი ხშირად გვხვდება reflection-თან მუშაობისას. მაგალითად, IL-ში და reflection-ში `Dictionary<TKey, TValue>`-ის სახელი არის ``Dictionary`2``, სადაც ბრჭყალის შემდეგ მოცემული რიცხვი სწორედ arity-ა:

```csharp
Console.WriteLine(typeof(Dictionary<,>).Name);   // Dictionary`2
Console.WriteLine(typeof(List<>).Name);          // List`1
```

arity-ის წყალობით ერთ namespace-ში შეიძლება ერთი სახელის რამდენიმე ტიპი თანაარსებობდეს, მაგალითად `Tuple<T1>`, `Tuple<T1, T2>` და ა.შ. ამ თემას [[თავი 4.1 ტიპების პარამეტრიზაცია|მე-4 თავში]] დავუბრუნდებით.

## Generic ტიპები (Generic Types)

**Generic ტიპი** ამ წიგნში ყველაზე ხშირად გამოყენებული ტერმინია. ის აღნიშნავს ნებისმიერ კლასს, სტრუქტურას, ინტერფეისს ან დელეგატს, რომელიც ერთ ან მეტ ტიპის პარამეტრს იღებს. ეს ტერმინი ფორმალური ტერმინოლოგიის ნაწილი არ არის და თითქმის „ღია ტიპის" სინონიმია, მაგრამ მოსახერხებელია, როცა generic ქცევის მქონე ნებისმიერ ტიპზე ზოგადად გვინდა საუბარი.

## ყველაფერი ერთად

| ტერმინი | მაგალითი | განმარტება |
|---|---|---|
| ტიპის პარამეტრი | `T` `Stack<T>`-ში | ადგილის დამჭერი განსაზღვრებაში |
| ღია ტიპი | `Stack<T>` | generic ტიპის განსაზღვრება |
| ტიპის არგუმენტი | `string` `Stack<string>`-ში | კონკრეტული ტიპი, რომელიც პარამეტრს ანაცვლებს |
| აგებული ტიპი | `Stack<string>` | ღია ტიპი + ტიპის არგუმენტები |
| დახურული აგებული ტიპი | `List<int>` | ყველა არგუმენტი კონკრეტული ტიპია |
| ღია აგებული ტიპი | `List<T>` სხვა generic ტიპის შიგნით | არგუმენტი თავად ტიპის პარამეტრია |
| generic მეთოდი | `T First<T>(T[] a)` | მეთოდი საკუთარი ტიპის პარამეტრით |
| ტიპის ინსტანცირება | JIT ქმნის `Stack<string>`-ს | აგებული ტიპის გაშვების დროის წარმოდგენის შექმნა |
| arity | ``Dictionary`2`` | ტიპის პარამეტრების რაოდენობა |

ერთი წინადადებით: როცა generic ტიპს ვაცხადებთ, ის **ღია ტიპია** (`MyType<T>`). როცა მის **ტიპის პარამეტრებს** **ტიპის არგუმენტებს** ვაწვდით (`MyType<int>`), ვიღებთ **აგებულ ტიპს**.

## შეჯამება

ამ თავში Generics-ის შექმნისა და გამოყენების ძირითადი კონცეფციები გავიცანით. დავიწყეთ არაgeneric გადაწყვეტით და ვნახეთ მისი ნაკლოვანებები: `object`-ზე დაყრდნობა იწვევს cast-ებს, ტიპების უსაფრთხოების დაკარგვას და boxing-ს. ტიპზე მორგებული კლასები კი კოდს ამრავლებს. შემდეგ იგივე ამოცანა Generics-ით გადავწყვიტეთ და ვნახეთ, როგორ აერთიანებს ის ტიპების უსაფრთხოებას, ზოგადობას და წარმადობას. ბოლოს შემოვიღეთ ტერმინოლოგია, რომელსაც შემდეგ თავებში მუდმივად გამოვიყენებთ.
