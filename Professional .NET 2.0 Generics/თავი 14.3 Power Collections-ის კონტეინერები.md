ამ ნაწილში Power Collections-ის კონტეინერებს განვიხილავთ: რა არის თითოეულის არსი, როდის გამოვიყენოთ, და რა შეესაბამება მას თანამედროვე .NET-ში. წიგნში თითოეულ კლასს წევრების სრული ცხრილი ახლავს. აქ ყურადღება ცნებებსა და დამახასიათებელ ოპერაციებზეა.

## `Bag<T>`: ჩანთა (multiset)

`Bag<T>` კოლექციებიდან ყველაზე „მარტივია": ის მხოლოდ იმას გვპირდება, რომ ჩადებულ ელემენტს შეინახავს. კოლექციების უმეტესობას გარკვეული თანმიმდევრობა ან ინდექსით წვდომა აქვს, `Bag<T>`-ს კი **თანმიმდევრობა არ აინტერესებს**. ის **დუბლიკატებს უშვებს** და ყურადღებას კოლექციაზე, როგორც მთლიანზე, ამახვილებს.

### შექმნა და შევსება

```csharp
var tags = new Bag<string>(new[] { "ახალი", "ფასდაკლება", "ახალი" });
var prices = new Bag<double>(new[] { 232.23, 1.12, 99.21, 14.42, 99.21 },
                             EqualityComparer<double>.Default);

tags.Add("პოპულარული");
tags.AddMany(new[] { "ახალი", "ლიმიტირებული" });
tags.AddRepresentative("ახალი");
```

`Bag`-ს აქვს უპარამეტრო კონსტრუქტორი, საწყისი ელემენტების (ნებისმიერი `IEnumerable<T>`) მიმღები კონსტრუქტორი, და კონსტრუქტორი, რომელიც ტოლობის წესსაც იღებს. თუ comparer არ გადაეცა, ტიპის ნაგულისხმევი გამოიყენება.

### „წარმომადგენელი" ელემენტი

`Add()`-ის გამოყენებისას პირველი დამატებული ეგზემპლარი „წარმომადგენელი" ხდება, შემდგომი დუბლიკატები კი მხოლოდ მრიცხველს ზრდის. `AddRepresentative()`-ით კი დამატებული ეგზემპლარი ახალი წარმომადგენელი ხდება. ეს მნიშვნელოვანია, როცა ობიექტები „ტოლია" (comparer-ის მიხედვით), მაგრამ იდენტური არ არის. მაგალითად, რეგისტრისადმი გულგრილი comparer-ით `"ახალი"` და `"ᲐᲮᲐᲚᲘ"` ერთ ელემენტად ითვლება, და წარმომადგენელი განსაზღვრავს, რომელი დაბრუნდება.

### წვდომა

`Bag`-თან (და `Set`-თან) მუშაობისას ცალკეულ ელემენტებზე ნაკლებად, **მთლიან კოლექციაზე** მეტად ვმუშაობთ:

```csharp
IEnumerable<double> big = prices.FindAll(p => p > 50);      // 232.23, 99.21, 99.21
int bigCount = prices.CountWhere(p => p > 50);              // 3
bool anyTiny = prices.Exists(p => p < 5);                   // true
IEnumerable<double> distinct = prices.DistinctItems();      // თითოეული ერთხელ
int copies = prices.NumberOfCopies(99.21);                  // 2
```

`FindAll()` **ყოველ** ეგზემპლარს ცალ-ცალკე აბრუნებს, დუბლიკატების ჩათვლით, ამიტომ `99.21` ორჯერ ჩანს. თუ დუბლიკატები გვინდა უგულებელვყოთ, **`DistinctItems()`** თითოეულ მნიშვნელობას ერთხელ დააბრუნებს.

### წაშლა

`Remove()`, `Clear()` და `RemoveMany()` ჩვეულებრივად მუშაობს. ერთადერთი თავისებურებაა **`RemoveAllCopies()`**: `Remove(x)` `x`-ის **ერთ** ასლს შლის, `RemoveAllCopies(x)` კი **ყველას**.

### სიმრავლეების ოპერაციები

`Bag`-ს სიმრავლეების ოპერაციების სრული ნაკრები აქვს. სწორედ მათ გარეშე ის კიდევ ერთი, ჩვეულებრივი კონტეინერი იქნებოდა. თითოეულს ორი ფორმა აქვს: **`Union()`** ახალ `Bag`-ს აბრუნებს, **`UnionWith()`** კი მიმდინარე `Bag`-ს ცვლის.

| ოპერაცია | რას აკეთებს `Bag`-ზე | `{1.12, 1.12, 99.21}` და `{1.12, 5.0}` |
|---|---|---|
| `Union` | თითოეული ელემენტი **მაქსიმალური** რაოდენობით | `1.12, 1.12, 99.21, 5.0` |
| `Sum` | **ყველა** ელემენტი, რაოდენობების ჯამით | `1.12, 1.12, 1.12, 99.21, 5.0` |
| `Intersection` | საერთო ელემენტები **მინიმალური** რაოდენობით | `1.12` |
| `Difference` | პირველის ელემენტები მინუს მეორის | `1.12, 99.21` |
| `SymmetricDifference` | რაოდენობების სხვაობა ორივე მიმართულებით | `1.12, 99.21, 5.0` |
| `IsSubsetOf` / `IsSupersetOf` | ქვე-/ზესიმრავლე | |
| `IsProperSubsetOf` / `IsProperSupersetOf` | მკაცრი ქვე-/ზესიმრავლე (რაოდენობებიც ითვლება) | |
| `IsDisjointFrom` | საერთო ელემენტი არ აქვთ | |

> [!NOTE] Union და Sum
> `Union`-ში ელემენტის რაოდენობა ორიდან **უდიდესი** რაოდენობაა: თუ `"Item3"` პირველში ერთხელაა, მეორეში სამჯერ, შედეგში სამჯერ იქნება. `Sum` კი უბრალოდ ყველაფერს აერთიანებს: ოთხჯერ. `SymmetricDifference`-ში `1.12` იმიტომ ჩანს, რომ ერთ `Bag`-ში ორჯერაა, მეორეში ერთხელ: სხვაობა ერთი ასლია.

## `Set<T>`: სიმრავლე

`Set<T>`-ის ინტერფეისი `Bag<T>`-ისას თითქმის სრულად იმეორებს. მთავარი განსხვავება: **`Set<T>` დუბლიკატებს არ უშვებს**. თუ უკვე არსებული ელემენტის ტოლს დავამატებთ, ძველი ახლით ჩანაცვლდება.

შექმნა, შევსება და განახლება `Bag`-ის ნიმუშებს მიჰყვება, მაგრამ სიმრავლეების ოპერაციები ოდნავ განსხვავებულ შედეგს იძლევა: **`Union()`** ყოველ მნიშვნელობას ერთხელ შეიცავს, **`Intersection()`** მხოლოდ საერთოებს, **`SymmetricDifference()`** კი იმას, რაც საერთო **არ** არის. ეს ორი ოპერაცია ერთმანეთის საპირისპიროა.

```csharp
var a = new Set<double>(new[] { 232.23, 1.12, 99.21, 14.42 });
var b = new Set<double>(new[] { 1.12, 99.21, 9010.41 });

Set<double> both = a.Intersection(b);          // 1.12, 99.21
Set<double> either = a.Union(b);               // 232.23, 1.12, 99.21, 14.42, 9010.41
Set<double> onlyOne = a.SymmetricDifference(b); // 232.23, 14.42, 9010.41
```

> [!TIP] VB-ში
> `Set` VB-ის საკვანძო სიტყვაა, ამიტომ VB-ში ტიპი კვადრატულ ფრჩხილებში უნდა ჩაიწეროს: `Dim s As New [Set](Of Double)`.

> [!NOTE] BCL-ში
> `Set<T>`-ის ეკვივალენტი .NET 3.5-იდან **`HashSet<T>`**-ია, ხოლო `ISet<T>` (.NET 4.0) იგივე ოპერაციებს იძლევა: `UnionWith`, `IntersectWith`, `ExceptWith`, `SymmetricExceptWith`, `IsSubsetOf`, `Overlaps`. BCL-ში `Bag<T>`-ის პირდაპირი ეკვივალენტი არ არის: მას ჩვეულებრივ `Dictionary<T, int>`-ით (მნიშვნელობა → რაოდენობა) ვაკეთებთ.

## `OrderedBag<T>` და `OrderedSet<T>`

`OrderedBag<T>` `Bag<T>`-ის **დალაგებული** ვერსიაა, `OrderedSet<T>` კი `Set<T>`-ის. სინტაქსი, მექანიკა და ქცევა ძირითადად იგივეა, ოღონდ დალაგებასთან ერთად რამდენიმე ახალი მეთოდი ჩნდება:

```csharp
var salaries = new OrderedBag<decimal> { 3200, 850, 5400, 1200, 850, 2700 };
// გადავლა: 850, 850, 1200, 2700, 3200, 5400  (დამატების რიგი არ აქვს მნიშვნელობა)

decimal lowest = salaries.GetFirst();       // 850
decimal highest = salaries.GetLast();       // 5400
salaries.RemoveFirst();                     // ერთ 850-ს შლის
salaries.RemoveLast();                      // 5400-ს შლის

OrderedBag<decimal>.View mid  = salaries.Range(1000, true, 3500, false);   // 1200, 2700, 3200
OrderedBag<decimal>.View from = salaries.RangeFrom(2000, true);            // ≥ 2000
OrderedBag<decimal>.View to   = salaries.RangeTo(2000, false);             // < 2000
OrderedBag<decimal>.View desc = salaries.Reversed();                       // კლებადობით
```

`GetFirst()`, `GetLast()`, `RemoveFirst()` და `RemoveLast()` ელემენტების **დალაგებულ** პოზიციაზე მუშაობს, დამატების თანმიმდევრობის მიუხედავად.

**დიაპაზონის მეთოდები** განსაკუთრებით სასარგებლოა: **`Range()`** ორ საზღვარს შორის მდებარე ელემენტებს აბრუნებს (თითოეული საზღვარი შეიძლება ჩათვლილი იყოს ან არა), **`RangeFrom()`** მოცემულზე მეტს ან ტოლს, **`RangeTo()`** მოცემულზე ნაკლებს. **`Reversed()`** შებრუნებულ თანმიმდევრობას იძლევა.

> `OrderedSet<T>`-ის ეკვივალენტია `SortedSet<T>` (.NET 4.0), რომლის `GetViewBetween(lower, upper)` ზუსტად იგივე ცოცხალ ხედს იძლევა, ხოლო `Min`/`Max` და `Reverse()` შესაბამის ოპერაციებს. `OrderedBag<T>`-ის პირდაპირი ეკვივალენტი BCL-ში არ არის.

## `BigList<T>`: დიდი სია

სახელი ყველაფერს ამბობს. `BigList<T>` BCL-ის `List<T>`-ის მსგავსია, მაგრამ **დიდი მონაცემებისთვის** ოპტიმიზებული. სიები მცირე მონაცემებზე კარგად მუშაობს, მაგრამ ელემენტების ჩასმისა და წაშლისას კოლექციის განუწყვეტელი გადაწყობის საჭიროება დიდ მოცულობაზე წარმადობას ამცირებს ([[თავი 8.4 List კლასი|8.4]]).

`BigList<T>` შიგნით მასივის ნაცვლად **ხის სტრუქტურას** (rope/balanced tree) იყენებს. ამიტომ შუაში ჩასმა, წაშლა, კონკატენაცია და ქვესიის აღება **O(log n)**-ში ხდება, O(n)-ის ნაცვლად. ფასი ისაა, რომ მცირე კოლექციებზე ის `List<T>`-ზე ნელია. ავტორის წესი: **ნუ გამოიყენებთ `BigList<T>`-ს მცირე კოლექციებისთვის** (დაახლოებით 100 ელემენტზე ნაკლებისთვის).

```csharp
var data = new BigList<double>(new[] { 1.5, 2.5, 3.5 });
var repeated = new BigList<double>(data, 3);      // კონსტრუქტორი: 3 ასლი → 9 ელემენტი

repeated.Add(9.9);                                // ბოლოში
repeated.AddToFront(0.1);                         // თავში, O(log n)
repeated.AddRangeToFront(new[] { -2.0, -1.0 });   // დიაპაზონი თავში
repeated.InsertRange(5, new[] { 7.7, 8.8 });      // დიაპაზონი შუაში

BigList<double> slice = repeated.GetRange(2, 4);  // ქვესია, O(log n)
repeated.RemoveRange(0, 3);
```

კონსტრუქტორი მოსახერხებელ ვარიანტებსაც იძლევა, მაგალითად, მოცემული კოლექციის რამდენიმე ასლით შექმნას. ზოგადად `BigList<T>` ელემენტებზე წვდომის ყველა ჩვეულ მექანიზმს უჭერს მხარს: `Remove()` მნიშვნელობით, `RemoveAt()` ინდექსით, `RemoveRange()` დიაპაზონით.

> [!NOTE] თანამედროვე ეკვივალენტი
> BCL-ში პირდაპირი ეკვივალენტი არ არის. მსგავსი სტრუქტურაა `ImmutableList<T>` (`System.Collections.Immutable`), რომელიც ასევე ბალანსირებულ ხეზეა აგებული, ოღონდ უცვლელია.

## `Deque<T>`: ორმხრივი რიგი

`System.Collections.Generic`-ს `Queue<T>` აქვს, მაგრამ **ორმხრივი რიგი** (double-ended queue) არა. Power Collections ამ ხარვეზს `Deque<T>`-ით ავსებს. ის `BigList<T>`-ის მსგავსად წარმადობის პრობლემის მოსაგვარებლად შეიქმნა: სიაში თავში ჩასმისას ყველა ელემენტის გადაწევაა საჭირო, `Deque<T>` კი თავშიც და ბოლოშიც **O(1)**-ში ამატებს და იღებს (შიგნით წრიული ბუფერია).

```csharp
var tasks = new Deque<string>();
tasks.Add("ანგარიში");
tasks.AddToBack("ელფოსტა");               // ბოლოში
tasks.AddToFront("სასწრაფო ზარი");        // თავში
tasks.AddManyToFront(new[] { "A", "B" });
tasks.InsertRange(2, new[] { "X", "Y" });

string first = tasks.GetAtFront();
string last = tasks.GetAtBack();
string next = tasks.RemoveFromFront();
string undo = tasks.RemoveFromBack();
```

წაკითხვისა და წაშლის მეთოდები დამატების მეთოდებს პირდაპირ შეესაბამება: `GetAtFront()`/`GetAtBack()`, `RemoveFromFront()`/`RemoveFromBack()`. ინდექსით წვდომა (`this[i]`, `RemoveAt()`, `RemoveRange()`) ასევე არის, რადგან `Deque<T>` `ListBase<T>`-იდან მოდის. `TrimToSize()` შიდა ბუფერს რეალურ ზომამდე ამცირებს.

> [!NOTE] თანამედროვე ეკვივალენტი
> BCL-ს დღესაც არ აქვს საჯარო `Deque<T>`. ხშირად `LinkedList<T>` გამოიყენება (O(1) ორივე ბოლოზე, მაგრამ ინდექსის გარეშე), ან მესამე მხარის ბიბლიოთეკები.

## `MultiDictionary<TKey, TValue>`: რამდენიმე მნიშვნელობა ერთ გასაღებზე

ჩვეულებრივი ლექსიკონი ყოველ გასაღებს **ერთ** მნიშვნელობას უკავშირებს. `MultiDictionary<TKey, TValue>` კი ერთ გასაღებზე **რამდენიმე** მნიშვნელობის შენახვის საშუალებას იძლევა.

```csharp
var enrollments = new MultiDictionary<string, string>(false);   // false: დუბლიკატები არ დაიშვება

enrollments.Add("ალგებრა", "ნინო");
enrollments.Add("ალგებრა", "გიორგი");
```

ინტერფეისი ჩვეულებრივ ლექსიკონს ჰგავს, განსხვავება ქცევაშია:

- **`Add()`** არსებულ მნიშვნელობას **არ ანაცვლებს**, არამედ ახალს უმატებს გასაღების მნიშვნელობების კოლექციას. თუმცა ერთი გასაღების მნიშვნელობები, როგორც წესი, უნიკალური უნდა იყოს: დუბლიკატის დამატების მცდელობა ცვლილებას არ იწვევს (კონსტრუქტორის `allowDuplicateValues` პარამეტრი ამ ქცევას მართავს).
- **ინდექსატორი** (`this[key]`) მნიშვნელობების **კოლექციას** აბრუნებს.
- **`Remove(key, value)`** მხოლოდ ერთ მნიშვნელობას შლის. **`RemoveMany(key, values)`** რამდენიმეს. `Remove(key)` გასაღებს ყველა მნიშვნელობით შლის. თუ გასაღებს ბოლო მნიშვნელობა მოეშალა, გასაღებიც ქრება.
- **`Replace(key, value)`** გასაღების ყველა მნიშვნელობას ერთით ანაცვლებს.

**`OrderedMultiDictionary<TKey, TValue>`** იგივეა, ოღონდ **დალაგებული გასაღებებით** (და სურვილისამებრ დალაგებული მნიშვნელობებითაც, `ValueComparer`-ით), დიაპაზონის მეთოდებითა და `View`-ებით. **`ReadOnlyMultiDictionary<TKey, TValue>`** კი მისი მხოლოდ წასაკითხი ვერსიაა.

> [!NOTE] თანამედროვე ეკვივალენტი
> BCL-ში `Dictionary<TKey, List<TValue>>` ან `Dictionary<TKey, HashSet<TValue>>`, ხოლო მხოლოდ წასაკითხი ფორმით LINQ-ის `ToLookup()` (`ILookup<TKey, TElement>`).

## `OrderedDictionary<TKey, TValue>`: დალაგებული ლექსიკონი

`OrderedDictionary<TKey, TValue>` გასაღებით სწრაფ წვდომასა და დალაგებული კოლექციის თვისებებს აერთიანებს. ის `DictionaryBase<TKey, TValue>`-ის მემკვიდრეა. ყველა ოპერაცია გასაღებით ხდება, ჩანაწერები კი ყოველთვის **გასაღების მიხედვით დალაგებულია**, დამატების რიგის მიუხედავად:

```csharp
var catalog = new OrderedDictionary<string, decimal>();
catalog.Add("მონიტორი", 599m);
catalog.Add("კლავიატურა", 89m);
catalog.Add("ლეპტოპი", 2499m);
catalog.Add("კლავიატურა", 79m);          // არსებულს ანაცვლებს (BCL-ისგან განსხვავებით!)

decimal price = catalog["ლეპტოპი"];

bool existed = catalog.GetValueElseAdd("მაუსი", ref price);
// თუ "მაუსი" არსებობს: price-ში მისი მნიშვნელობა ჩაიწერება, existed = true
// თუ არა: დაემატება price-ით, existed = false

OrderedDictionary<string, decimal>.View some = catalog.Range("კ", true, "მ", false);
catalog.AddMany(otherCatalog);
```

- **`Add()`** არსებული გასაღების შემთხვევაში მნიშვნელობას **ანაცვლებს**. ეს BCL-ის `Dictionary.Add()`-ისგან განსხვავდება, რომელიც exception-ს ისვრის ([[თავი 8.5 Dictionary, SortedDictionary და SortedList|8.5]]).
- **`GetValueElseAdd()`** ძებნასა და დამატებას **ერთ გამოძახებაში** აერთიანებს: თუ გასაღები არსებობს, მის მნიშვნელობას აბრუნებს, თუ არა, ახალ წყვილს ამატებს. `bool` შედეგი გვეუბნება, რომელი მოხდა. ეს ძალიან მოსახერხებელია ქეშების და მრიცხველების დაწერისას.
- **`Range()`**, **`RangeFrom()`**, **`RangeTo()`**, **`Reversed()`**: დიაპაზონის ცოცხალი ხედები (`View`), წყარო ლექსიკონის შეცვლის გარეშე.
- **`AddMany()`**: სხვა ლექსიკონის ყველა ჩანაწერის დამატება.

> [!NOTE] თანამედროვე ეკვივალენტი
> `SortedDictionary<TKey, TValue>` ([[თავი 8.5 Dictionary, SortedDictionary და SortedList|8.5]]), თუმცა მას დიაპაზონის ხედები არ აქვს. `GetValueElseAdd()`-ის იდეა `ConcurrentDictionary.GetOrAdd()`-სა და `CollectionsMarshal.GetValueRefOrAddDefault()`-ში (.NET 6) გამოჩნდა. ყურადღება: .NET 9-ში BCL-ს დაემატა **სხვა** `OrderedDictionary<TKey, TValue>`, რომელიც **დამატების თანმიმდევრობას** ინახავს და არა დალაგებას.

## `Pair` და `Triple`

`Pair<TFirst, TSecond>` ორი ტიპის ერთ სტრუქტურაში „შეფუთვის" მარტივი საშუალებაა: ერთი, ტიპების მხრივ უსაფრთხო კლასი, რომელიც წყვილი ტიპების ნებისმიერ კომბინაციას იტევს. მის გარეშე ყოველი კომბინაციისთვის ცალკე სტრუქტურა დაგვჭირდებოდა. `Triple<TFirst, TSecond, TThird>` იგივეა სამი ტიპისთვის. ორივე `struct`-ია, აქვს `First`/`Second`/`Third` ველები, და `Equals()`, `GetHashCode()` და `CompareTo()` ყველა კომპონენტით, ამიტომ ლექსიკონის გასაღებადაც გამოდგება.

## საკუთარი კოლექციის შექმნა საბაზო კლასებით

Power Collections-ის საბაზო კლასები ([[თავი 14.1 Power Collections-ის სრული სურათი|14.1]]) საკუთარი კოლექციის შექმნას ამარტივებს. მაგალითად, `CollectionBase<T>`-ის მემკვიდრეს მხოლოდ ხუთი წევრი სჭირდება, დანარჩენს (`Contains`, `CopyTo`, `ToArray`, `FindAll`, `CountWhere`, `Exists`, `TrueForAll`, `RemoveAll`, `ForEach`, `ConvertAll`, `AsReadOnly`, `ToString`) უფასოდ იღებს:

```csharp
public class RingBuffer<T> : CollectionBase<T>
{
    private readonly T[] _items;
    private int _start, _count;

    public RingBuffer(int capacity) => _items = new T[capacity];

    public override void Add(T item)
    {
        _items[(_start + _count) % _items.Length] = item;
        if (_count < _items.Length) _count++;
        else _start = (_start + 1) % _items.Length;     // ყველაზე ძველი გადაიწერება
    }

    public override void Clear() { _start = 0; _count = 0; }

    public override bool Remove(T item) => throw new NotSupportedException();

    public override int Count => _count;

    public override IEnumerator<T> GetEnumerator()
    {
        for (int i = 0; i < _count; i++)
            yield return _items[(_start + i) % _items.Length];
    }
}

var recent = new RingBuffer<string>(3);
recent.Add("a"); recent.Add("b"); recent.Add("c"); recent.Add("d");
bool hasB = recent.Contains("b");                    // true  (საბაზოდან)
int longOnes = recent.CountWhere(s => s.Length > 0); // 3     (საბაზოდან)
```

## შეჯამება

მე-14 თავმა Power Collections-ის ბიბლიოთეკა დეტალურად განიხილა. მიზანი იყო იმის ჩვენება, როგორ შეიძლება generic ბიბლიოთეკა BCL-ზე ააგო: ის მჭიდროდ ეყრდნობა BCL-ის ინტერფეისებს, ამიტომ ორივე ერთად, თავისუფლად გამოიყენება. ბიბლიოთეკა Generics-ის პრაქტიკული გამოყენების შესანიშნავი მაგალითიცაა: აბსტრაქტული generic საბაზო კლასები, ტიპის პარამეტრებით ალგორითმები, generic დელეგატები და შეზღუდვები ერთ, თანმიმდევრულ სისტემაში.

| Power Collections | დანიშნულება | თანამედროვე BCL |
|---|---|---|
| `Bag<T>` | multiset, დუბლიკატებით | `Dictionary<T, int>` |
| `Set<T>` | უნიკალური ელემენტები | `HashSet<T>` |
| `OrderedSet<T>` | დალაგებული სიმრავლე, ხედები | `SortedSet<T>` (`GetViewBetween`) |
| `OrderedBag<T>` | დალაგებული multiset | პირდაპირი ეკვივალენტი არ არის |
| `BigList<T>` | დიდი სია, O(log n) ჩასმა | `ImmutableList<T>` (უცვლელი) |
| `Deque<T>` | ორმხრივი რიგი | `LinkedList<T>` |
| `MultiDictionary<K, V>` | რამდენიმე მნიშვნელობა გასაღებზე | `Dictionary<K, List<V>>`, `ILookup` |
| `OrderedDictionary<K, V>` | დალაგებული ლექსიკონი, ხედები | `SortedDictionary<K, V>` |
| `Pair`, `Triple` | ტიპების წყვილი/სამეული | `ValueTuple`, `record` |
| `BinaryPredicate<T>` | ორპარამეტრიანი პრედიკატი | `Func<T, T, bool>` |
| `Algorithms` | ~100 ალგორითმი | LINQ, `Array`, `List<T>` მეთოდები |
