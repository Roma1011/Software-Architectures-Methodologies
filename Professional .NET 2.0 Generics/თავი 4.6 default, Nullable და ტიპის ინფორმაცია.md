## `default` საკვანძო სიტყვა

Generic კლასის იმპლემენტაციისას ხშირად გვჭირდება ტიპის პარამეტრის **ნაგულისხმევი (default) მნიშვნელობა**. მაგრამ `T`-ის ტიპი წინასწარ უცნობია, ამიტომ არ ვიცით, რა არის მისთვის სწორი ნაგულისხმევი მნიშვნელობა. `null`-ს ვერ დავწერთ, რადგან `T` შეიძლება value type იყოს. `0`-ს ვერ დავწერთ, რადგან `T` შეიძლება `string` იყოს.

ამისთვის სპეციფიკაციამ შემოიღო `default(T)` გამოსახულება, რომელიც ნებისმიერი ტიპისთვის სწორ ნაგულისხმევ მნიშვნელობას აბრუნებს:

| `T`-ის სახე | `default(T)` | მაგალითი |
|---|---|---|
| reference type | `null` | `default(string)` → `null` |
| ჩაშენებული value type | ამ ტიპის ნაგულისხმევი მნიშვნელობა | `default(int)` → `0`, `default(bool)` → `false` |
| struct | struct, რომლის ყველა ველი თავის ნაგულისხმევ მნიშვნელობაშია | `default(DateTime)` → `0001-01-01 00:00:00` |
| `Nullable<T>` | მნიშვნელობის გარეშე (`HasValue == false`) | `default(int?)` → `null` |

ეს ზოგიერთი generic კლასის იმპლემენტაციისთვის აუცილებელია. მაგალითად, ქეშისთვის, რომელიც ვერნაპოვნ ელემენტზე ნაგულისხმევ მნიშვნელობას აბრუნებს:

```csharp
public class Lookup<TKey, TValue>
{
    private readonly Dictionary<TKey, TValue> _items = new Dictionary<TKey, TValue>();

    public TValue Find(TKey key)
    {
        TValue result;
        if (!_items.TryGetValue(key, out result))
            result = default(TValue);
        return result;
    }
}
```

`default` ასევე გამოდგება ტიპის პარამეტრის ცვლადების წინასწარი ინიციალიზაციისთვის.

> [!NOTE] ენები და ვერსიები
> - წიგნის დროს VB-ს `default`-ის ეკვივალენტი არ ჰქონდა. უახლოესი ვარიანტი იყო ცვლადისთვის `Nothing`-ის მინიჭება, რომელიც VB-ში ნებისმიერი ტიპის ნაგულისხმევ მნიშვნელობას ნიშნავს.
> - C# 7.1-იდან შეიძლება მოკლე ფორმა: `TValue result = default;`, ტიპი კონტექსტიდან გამოიყვანება.
> - `default(T)` და `null` ერთი და იგივე არ არის. `T : class` შეზღუდვის გარეშე `result == null` შედარება value type-ისთვის ყოველთვის `false`-ს მისცემს. ზოგადი შედარებისთვის `EqualityComparer<T>.Default.Equals(result, default)` გამოიყენეთ.

## `System.Nullable<T>`

.NET 2.0-მა ძველი პრობლემა გადაჭრა: **value type-ებს „ცარიელი" მნიშვნელობა არ ჰქონდათ**. ობიექტისთვის `null` მკაფიოდ ნიშნავს, რომ მნიშვნელობა არ არსებობს. `int`-ს კი ასეთი მნიშვნელობა არ აქვს: `0` შეიძლება რეალური მნიშვნელობა იყოს. ეს განსაკუთრებით მტკივნეული იყო ბაზებთან მუშაობისას, სადაც `NULL` ჩვეულებრივი მოვლენაა.

გამოსავალია generic სტრუქტურა `Nullable<T>`. ის თავისთავად Generics-ის კონცეფცია არ არის, მაგრამ Generics-ით არის აგებული. `Nullable<T>` თვალს ადევნებს, მიენიჭა თუ არა ქვედა ტიპს მნიშვნელობა:

```csharp
public static void PrintDiscount(Nullable<int> discount, int bonus)
{
    if (discount.HasValue)
        Console.WriteLine($"ფასდაკლება: {discount.Value}%");
    else
        Console.WriteLine("ფასდაკლება არ არის განსაზღვრული");

    if (bonus > 0)
        Console.WriteLine($"ბონუსი: {bonus}");
    else
        Console.WriteLine("ბონუსი... 0-ია თუ უბრალოდ არ მიუთითეს?");
}
```

`discount` nullable ტიპისაა, ამიტომ `HasValue` მკაფიოდ გვეუბნება, არის თუ არა მნიშვნელობა. `bonus`-ისთვის ასეთი საშუალება არ გვაქვს. შეიძლება ხელოვნური წესი შემოვიღოთ, მაგალითად „0 ნიშნავს, რომ მნიშვნელობა არ არის", მაგრამ ეს ჩვენ მიერ მოგონილი, კონკრეტულ კოდზე მიბმული წესია. `Nullable<T>` კი „მნიშვნელობის არარსებობის" **უნივერსალურ, ცალსახა** განსაზღვრებას იძლევა, რომელიც მთელ კოდში ერთნაირად მუშაობს.

`Nullable<T>` მხოლოდ **value type**-ებს იღებს (`int`, `double`, `DateTime`, struct-ები). მას `where T : struct` შეზღუდვა ადევს, რადგან reference type-ებს `null` უკვე აქვთ.

C#-ში მოკლე სინტაქსიც არსებობს: `int?` ნიშნავს `Nullable<int>`-ს. ავტორი აღნიშნავს, რომ მოკლე ფორმა ზოგისთვის წაკითხვადობას ამცირებს და ეს გემოვნების საკითხია. დღეს `int?` საყოველთაოდ მიღებული ფორმაა.

### რატომ ეპყრობა CLR `Nullable<T>`-ს განსაკუთრებულად

`Nullable<T>` ჩვეულებრივ generic კონტეინერს ჰგავს, მაგრამ **CLR მას განსაკუთრებულად ეპყრობა**. ადრეულმა მომხმარებლებმა ასეთი პრობლემა აღმოაჩინეს:

```csharp
int? amount = null;
object boxed = amount;       // boxing

if (boxed == null)
    Console.WriteLine("ცარიელია");
```

`Nullable<int>` struct-ია. ჩვეულებრივი struct-ის boxing heap-ზე ახალ ობიექტს ქმნის, და ეს ობიექტი არასოდეს არის `null`. ე.ი. `Nullable<T>` რომ ჩვეულებრივი generic ტიპი ყოფილიყო, boxing-ისას „ცარიელობა" დაიკარგებოდა და `boxed == null` იქნებოდა `false`. ცხადია, ეს მოსალოდნელი ქცევა არ არის.

ამიტომ CLR-მა `Nullable<T>` **გაშვების დროის შიდა (intrinsic) ტიპად** აქცია, და მისი boxing/unboxing სპეციალურად მუშავდება:

*ნახაზი 4.5: `Nullable<T>`-ის სპეციალური boxing. ცარიელი მნიშვნელობა `null` რეფერენსად იქცევა, არაცარიელი კი ქვედა ტიპის boxed მნიშვნელობად.*

ამავე ცვლილებით CLR-მა დაუშვა boxed მნიშვნელობის **პირდაპირ `Nullable<T>`-ად unboxing**-იც: `int? x = (int?)boxed;` სწორად მუშაობს, როგორც `null`-ისთვის, ისე boxed `int`-ისთვის. შედეგად `Nullable<T>` ინტუიციურად იქცევა.

## ტიპის ინფორმაციის მიღება

Generic ტიპების კონკრეტული ტიპის ინფორმაცია `typeof`-ით მიიღება:

```csharp
public class Solo<T> { }
public class Duo<T, U> { }

public class TypeInspector<A, B, C>
{
    public static void Dump()
    {
        Console.WriteLine(typeof(A));
        Console.WriteLine(typeof(B));
        Console.WriteLine(typeof(C));
        Console.WriteLine(typeof(Solo<string>));
        Console.WriteLine(typeof(Solo<A>));
        Console.WriteLine(typeof(Duo<B, int>));
        Console.WriteLine(typeof(Duo<A, C>));
    }
}

TypeInspector<string, int, decimal>.Dump();
```

შედეგი:

```
System.String
System.Int32
System.Decimal
Solo`1[System.String]
Solo`1[System.String]
Duo`2[System.Int32,System.Int32]
Duo`2[System.String,System.Decimal]
```

შედეგი თითქმის მოსალოდნელია. `typeof(A)` გაშვებისას ფაქტობრივ ტიპის არგუმენტს აბრუნებს, ანუ `T` გაშვების დროს „არ იკარგება" (Java-ს type erasure-ისგან განსხვავებით). ერთადერთი მოულოდნელი დეტალი ტიპის სახელის შემდეგ რიცხვია: `` `1 `` და `` `2 ``. ეს [[თავი 1.2 Generics-ის ტერმინოლოგია|arity-ა]], ანუ ტიპის პარამეტრების რაოდენობა. reflection-ს დეტალურად [[თავი 9.1 Reflection და Generics|მე-9 თავში]] განვიხილავთ.
