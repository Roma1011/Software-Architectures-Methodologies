უკვე ცხადია, რომ Generics და templates სხვადასხვა რამეა. C++-ის templates-ის სინტაქსი Generics-ს ჰგავს, მაგრამ მნიშვნელოვანი განსხვავებებიც აქვს. ამ თავში C++-ში (უფრო ზუსტად **C++/CLI**-ში) generic ტიპების შექმნისა და გამოყენების სინტაქსს განვიხილავთ: კლასები, მეთოდები, ინტერფეისები, დელეგატები. ბოლოს ვნახავთ, როგორ შეიძლება Generics-ისა და templates-ის **შერევა**, რომ templates-ის ძალა და Generics-ის თავსებადობა ერთად მივიღოთ.

> [!NOTE] რას ეხება ეს თავი
> აქ აღწერილი სინტაქსი (`generic`, `ref class`, `^`, `gcnew`) **C++/CLI**-ს ეკუთვნის, ანუ C++-ის გაფართოებას .NET-ისთვის (Visual Studio 2005+). სტანდარტულ (native) C++-ში Generics არ არსებობს. C++/CLI დღესაც მხარდაჭერილია Windows-ზე .NET-ისა და native კოდის დასაკავშირებლად, თუმცა ახალ პროექტებში იშვიათად გამოიყენება.

## Templates თუ Generics?

C++-ის პროგრამისტი შეიძლება იკითხოს: რატომ უნდა დავინტერესდე Generics-ით, თუ templates-ის სრული ძალა უკვე მაქვს, და Generics მხოლოდ შეზღუდავს ჩემს შესაძლებლობებს? მიუხედავად ამისა, C++-ის პროგრამისტს Generics-ით დაინტერესების ბევრი მიზეზი აქვს.

templates-ს ისეთი ძალა აქვს, რომელიც Generics-ში მიუღწეველია ([[თავი 3.1 Generics და Templates|მე-3 თავი]]), მაგრამ ამ ძალას ტვირთიც ახლავს. Generics-ის ეფექტიანობისა და ძლიერი მხარეების გათვალისწინებით, C++-ის პროგრამისტისთვის ღირს, ერთი ნაბიჯით უკან დადგეს და გადახედოს, როგორ შეიძლება Generics-მა generic ტიპებისადმი მის მიდგომაზე იმოქმედოს.

მთავარი აზრი ის კი არ არის, რომ Generics templates-ს უნდა ჩაენაცვლოს. Generics უბრალოდ ახალ პარამეტრებს შემოიტანს განტოლებაში, რომლებმაც შეიძლება შეცვალოს (ან არ შეცვალოს), როდის რომელს აირჩევთ. დახურულ, კონტროლირებად გარემოში, სავარაუდოდ, სუფთა templates-ზე დარჩებით. მაგრამ თუ ზომისა და **სხვა .NET ენებთან თავსებადობის** მოთხოვნები გაქვთ, Generics ღირებულებას მატებს.

| კრიტერიუმი | Templates | Generics |
|---|---|---|
| გამოყენება C#/VB-დან | ✗ | ✓ |
| assembly-ის საზღვრის გადაკვეთა | ✗ (ყოველ assembly-ში ცალკე ტიპი) | ✓ |
| სპეციალიზაცია, მეტაპროგრამირება | ✓ | ✗ |
| duck typing (შეზღუდვების გარეშე) | ✓ | ✗ |
| native ტიპები (`int*`, native კლასები) | ✓ | ✗ (მხოლოდ მართვადი ტიპები) |
| კოდის ზომა | თითო ვერსიაზე ცალკე | გაზიარება reference type-ებზე |

## ხაზების წაშლა

C++ Visual Studio 2005-ში მნიშვნელოვნად შეიცვალა. დაემატა ახალი საკვანძო სიტყვები, რომლებიც მართვად (managed) ტიპებთან ბუნებრივ მუშაობას უზრუნველყოფს. მიზანი ორმხრივი იყო: C++-ის ძალა CLI-ში, და CLI-ის შესაძლებლობები C++-ში. ასე C++ .NET-ზე სისტემური პროგრამირების ენა ხდება: მასზე „დაბალი" ენა .NET-ში არ უნდა არსებობდეს.

ეს ცვლილებები Generics-ის შექმნასა და გამოყენებაზეც პირდაპირ მოქმედებს. C++-ში Generics-ის იმპლემენტაცია C#-ისას **საოცრად ჰგავს**: მართვადი კოდის თვალსაზრისით ენებს შორის ხაზები თითქმის იშლება.

## შეზღუდვების გარეშე

C++-ში Generics-ის იმპლემენტაცია ძალიან სრულია: მცირე ვარიაციების გარდა, C++ VB-ისა და C#-ის **ყველა** generic შესაძლებლობას უჭერს მხარს. ამავდროულად C++ იმავე წესებსა და შეზღუდვებსაც იღებს. ყველა ეს ენა CLS-ის ფარგლებში Generics-ის ერთიან ხედვას მისდევს.

ამიტომ ქვემოთ მაგალითები ზოგად წესებს აღარ იმეორებს: ისინი წიგნის სხვა თავებშია. ყურადღება მხოლოდ **C++-ის სპეციფიკაზეა**.

## Generic კლასები C++-ში

C++-ში generic კლასი C#-ის generic კლასს ძალიან ჰგავს, მაგრამ templates-ის ფესვებიც აშკარად ჩანს:

```cpp
using namespace System;

generic <typename TKey, typename TValue>
ref class Entry {
public:
    TKey Key;
    TValue Value;

    Entry(TKey key, TValue value) {
        Key = key;
        Value = value;
    }

    TKey GetKey()     { return Key; }
    TValue GetValue() { return Value; }

    void Print() {
        Console::WriteLine(L"გასაღები: {0}", Key->ToString());
        Console::WriteLine(L"მნიშვნელობა: {0}", Value->ToString());
    }
};
```

სინტაქსის თავისებურებები:

| ელემენტი | მნიშვნელობა |
|---|---|
| `generic <...>` | კლასს მართვად, **generic** ტიპად აცხადებს (`template <...>` კი native template-ს) |
| `typename T` ან `class T` | ტიპის პარამეტრი. ორივე საკვანძო სიტყვა ურთიერთშემცვლელია |
| `ref class` | **მართვადი reference type** (C#-ის `class`). `value class` C#-ის `struct`-ია |
| `->` | ტიპის პარამეტრის წევრებზე წვდომა (handle-ის გავლით) |

`ref` generic-ის სპეციფიკა არ არის: ის ნებისმიერ მართვად reference type-ს აღნიშნავს, generic-ს თუ არა. კლასის დანარჩენი იმპლემენტაცია C++-ის templates-ის სინტაქსს ემსგავსება.

## Generic კლასების გამოყენება

C++-ში generic ტიპების გამოყენების სინტაქსი შეიძლება ცოტა მოულოდნელი იყოს:

```cpp
Entry<double, long>^ e1 = gcnew Entry<double, long>(19.99, 42L);
e1->Print();

Entry<String^, int>^ e2 = gcnew Entry<String^, int>(L"რაოდენობა", 7);
String^ key = e2->GetKey();
int count = e2->GetValue();
e2->Print();
```

ტიპის არგუმენტები კლასის სახელის შემდეგ კუთხოვან ფრჩხილებში იწერება, როგორც C#-სა და J#-ში. განსხვავება C++-ის მართვადი კოდის სპეციფიკურ ოპერატორებშია:

- **`^` (object handle)**: Visual Studio 2005-ში დამატებული სიმბოლო, რომელიც **მართვად ობიექტზე მიმართვას** აღნიშნავს და მას native მაჩვენებლისგან (`*`) განასხვავებს. `Entry<double, long>^` ნიშნავს: handle, რომელსაც CLR მართავს.
- handle-ის სიმბოლო **reference type-ის ტიპის არგუმენტსაც** სჭირდება: `String^`. value type-ს (`int`, `double`) კი არა. ზოგადად, თუ არგუმენტის ტიპი value type-ად ვერ გაირკვა, კომპილატორი მას reference type-ად თვლის და `^`-ს მოითხოვს.
- **`gcnew`**: ახალი ოპერატორი, რომელიც garbage collector-ის მიერ მართვად ობიექტს ქმნის. ყველა generic ტიპი მართვადია, ამიტომ ყველა `gcnew`-ით იქმნება (`new` native heap-ისთვისაა).

## მემკვიდრეობა

C++-ის generic კლასი generic და არაgeneric ტიპებიდანაც იღებს მემკვიდრეობას, და საბაზო კლასს ტიპის პარამეტრსაც გადასცემს და ტიპის არგუმენტსაც:

```cpp
generic <typename T>
ref class Node {
public:
    Node(T value) {}
};

generic <typename TTag, typename TValue>
ref class TaggedNode : Node<TValue> {
public:
    TaggedNode(TTag tag, TValue value) : Node<TValue>(value) {}
};

generic <typename TTag, typename TValue>
ref class LabelNode : Node<String^> {
public:
    LabelNode(TTag tag, TValue value) : Node<String^>(L"ლეიბლი") {}
};
```

`TaggedNode` საბაზო კლასს თავის `TValue`-ს გადასცემს, რითაც საბაზო კლასს ირიბად ამ ტიპზე აბამს. `LabelNode` კი კონკრეტულ `String^`-ს გადასცემს. ერთადერთი თავისებურება **ინიციალიზაციის სიაა** (`: Node<TValue>(value)`), რომელშიც ტიპის არგუმენტებიც უნდა ეწეროს. C++-ის დეველოპერისთვის ეს მოსალოდნელი სინტაქსია.

## ჩადგმული კლასები

C++ ჩადგმულ generic კლასებს სრულად უჭერს მხარს და VB-ისა და C#-ის ყველა წესს მიჰყვება ([[თავი 4.5 ჩადგმული კლასები და ხელმისაწვდომობა|4.5]]). მათზე წვდომის სინტაქსს კი აშკარად C++-ის „გემო" აქვს:

```cpp
generic <typename TOuter>
ref class Outer {
public:
    generic <typename TInner>
    ref class Inner {
    private:
        TOuter _owner;                // გარე კლასის პარამეტრი ხელმისაწვდომია
        static int _counter = 0;
    public:
        void Increment() { _counter++; }
        int GetCount()   { return _counter; }
    };
};

void TestNested() {
    Outer<int>::Inner<int>^ a = gcnew Outer<int>::Inner<int>();
    Outer<String^>::Inner<int>^ b = gcnew Outer<String^>::Inner<int>();

    a->Increment();
    a->Increment();
    Console::WriteLine(L"a: {0}", a->GetCount());   // 2

    b->Increment();
    Console::WriteLine(L"b: {0}", b->GetCount());   // 1, და არა 3!
}
```

ჩადგმულ ტიპზე წვდომა `::` ოპერატორით ხდება. შიდა კლასს გარე კლასის ტიპის პარამეტრზე (`TOuter`) წვდომა აქვს, თუ მისი საკუთარი პარამეტრის სახელი არ ემთხვევა.

`_counter` სტატიკურია, და ორივე ეგზემპლარი `Inner<int>`-ია, ამიტომ შეიძლება ვიფიქროთ, რომ ისინი ერთ ველს იზიარებს და მესამე გამოძახების შემდეგ მნიშვნელობა 3 იქნება. მაგრამ **გარე** კლასის ტიპის არგუმენტები განსხვავდება (`int` და `String^`), ამიტომ `Outer<int>::Inner<int>` და `Outer<String^>::Inner<int>` **სხვადასხვა ტიპია**, საკუთარი სტატიკური ველებით ([[თავი 4.3 ველები და სტატიკური მონაცემები|4.3]]).

## მეთოდები generic კლასებში

C++-ის generic კლასი თავის მეთოდებს განსაკუთრებულ შეზღუდვებს არ უწესებს. ნებისმიერი მეთოდი, რომელიც ჩვეულებრივ კლასში შეიძლება, generic კლასშიც შეიძლება. ტიპის პარამეტრი მეთოდის ხელმოწერის ნებისმიერ ადგილას და იმპლემენტაციაში გამოიყენება. generic კლასში generic მეთოდებიც შეიძლება, და მათზე [[თავი 4.4 მეთოდები Generic კლასებში|მე-4]] და [[თავი 5.2 Generic მეთოდების გადატვირთვა და გადაფარვა|მე-5 თავის]] ყველა წესი ვრცელდება.

## ნაგულისხმევი მნიშვნელობა

C#-ში ტიპის პარამეტრის ნაგულისხმევ მნიშვნელობას `default(T)` იძლევა ([[თავი 4.6 default, Nullable და ტიპის ინფორმაცია|4.6]]). C++-ში ამისთვის **`T()`** გამოიყენება:

```cpp
generic <typename T>
ref class Defaults {
public:
    Defaults() {
        T empty = T();       // C#-ის default(T)
        Console::WriteLine(L"ნაგულისხმევი: {0}", empty);
    }
};
```

შედეგი ტიპის არგუმენტზეა დამოკიდებული: `int`-ისთვის `0`, reference type-ისთვის `nullptr`. ასეთ მნიშვნელობებს **„ნაგულისხმევ ინიციალიზატორებს" (default initializers)** უწოდებენ.

> [!WARNING] შენიშვნა წიგნის მაგალითზე
> წიგნის მაგალითი `testVal->ToString()`-ს იძახებს. reference type-ის არგუმენტისთვის `T()` `nullptr`-ია, ამიტომ ეს `NullReferenceException`-ს გამოიწვევს. ზემოთ მნიშვნელობა პირდაპირ გადაეცემა `WriteLine`-ს, რომელიც `null`-ს სწორად ამუშავებს.

## Generic მეთოდები C++-ში

C#-სა და VB-ში ყველა მეთოდი რომელიმე ტიპის შიგნით უნდა იყოს: namespace-ში პირდაპირ მეთოდი ან ველი არ შეიძლება. C++-ში ეს შეზღუდვა არ არსებობს. შეიძლება თუ არა ასეთი **დამოუკიდებელი** მეთოდები generic იყოს? **დიახ.** ეს generic მეთოდებს დამატებით მოქნილობას აძლევს:

```cpp
generic <typename T>
T Echo(T value) {
    Console::WriteLine(L"მნიშვნელობა: {0}", value);
    return value;
}

generic <typename T>
T Echo(T value, String^ note) {                  // ✓ გადატვირთვა: დამატებითი პარამეტრი
    Console::WriteLine(L"{0} ({1})", value, note);
    return value;
}

// generic <class U>
// U Echo(U value) { ... }                        // ✗ შეცდომა: პირველის დუბლიკატი
```

სამივე ერთი `Echo()`-ს გადატვირთვაა. მეორე პირველს ახალი `String^` პარამეტრით განსხვავდება. მესამე პირველისგან მხოლოდ **ტიპის პარამეტრის სახელით** განსხვავდება (`U` და `T`), რაც საკმარისი არ არის ([[თავი 5.2 Generic მეთოდების გადატვირთვა და გადაფარვა|5.2]]), ამიტომ კომპილაციისას ჩავარდება.

generic მეთოდები კლასშიც შეიძლება:

```cpp
generic <typename T>
ref class Printer {
public:
    generic <typename U>
    void Print(U item) {
        Console::WriteLine(L"{0}", item);
    }

    generic <typename U, typename V>
    void Print(U item) {                         // ✓ გადატვირთვა: ტიპის პარამეტრების რაოდენობით
        Console::WriteLine(L"{0} / {1}", item, V::typeid);
    }
};

void TestMethods() {
    Echo<String^>(L"ტექსტი");
    Echo<int>(457, L"შენიშვნა");

    Printer<int>^ p = gcnew Printer<int>();
    p->Print<double>(521.12);
    p->Print<int, String^>(922);
}
```

`Print`-ის ორი ვერსია ტიპის პარამეტრების **რაოდენობით** განსხვავდება, რაც ხელმოწერის ნაწილია. `V::typeid` C++-ში C#-ის `typeof(V)`-ის ეკვივალენტია.

## Generic ინტერფეისები C++-ში

generic ინტერფეისები C++-ის უმარტივესი generic კონსტრუქციაა, თუმცა templates-თან შერევისას ([[თავი 12.2 შეზღუდვები, დელეგატები და Templates-თან შერევა|12.2]]) მათი მნიშვნელობა იზრდება:

```cpp
using namespace System::Collections::Generic;

generic <typename T>
interface class IRepository {
    bool IsValid();
    T Get(int id);
    List<T>^ FindById(int id);
    List<T>^ FindByName(String^ name);
    bool Insert(T item);
    bool InsertMany(List<T>^ items);
    T Update(T item);
};
```

გამოცხადება generic კლასის სინტაქსს თითქმის იმეორებს (`interface class` C#-ის `interface`-ია). ერთადერთი C++-ის თავისებურებაა handle-ები `List<T>^`-სა და `String^`-ზე.

`List<T>` აქ `System::Collections::Generic`-იდანაა: C++-ს BCL-ის generic ტიპებზე სრული წვდომა აქვს. C++-ში ეს არჩევანი დამატებით მნიშვნელობას იძენს, რადგან BCL-ის კოლექციები STL-ის კონტეინერებს უწევს კონკურენციას. რომელს აირჩევთ, ძირითადად იმაზეა დამოკიდებული, მართვად გადაწყვეტასთან ურთიერთობს თუ არა თქვენი კოდი.
