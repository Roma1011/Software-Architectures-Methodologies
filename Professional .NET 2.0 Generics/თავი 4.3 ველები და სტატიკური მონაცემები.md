Generic კლასის ველებზე იგივე სინტაქსური წესები მოქმედებს, რაც ჩვეულებრივზე. მთავარი სიახლე ისაა, რომ ველის ტიპში **ტიპის პარამეტრი** შეიძლება გამოვიყენოთ.

## ველები ტიპის პარამეტრებით

```csharp
public class KeyValue<TKey, TValue>
{
    private readonly TKey _key;
    private readonly TValue _value;

    public KeyValue(TKey key, TValue value)
    {
        _key = key;
        _value = value;
    }

    public TKey GetKey() => _key;
    public TValue GetValue() => _value;
}

var setting = new KeyValue<string, string>("theme", "dark");
Console.WriteLine(setting.GetKey());     // theme
Console.WriteLine(setting.GetValue());   // dark
```

ნებისმიერ ველს შეიძლება ჰქონდეს კლასის ნებისმიერი ტიპის პარამეტრის ტიპი. კონსტრუქტორი მათ ისევე ავსებს, როგორც ჩვეულებრივ ველებს.

## სტატიკური ველები: თითოეულ აგებულ ტიპს თავისი აქვს

სტატიკური ველები generic კლასში განსაკუთრებულ ყურადღებას მოითხოვს. მთავარი წესი ასეთია:

> [!IMPORTANT] წესი
> Generic კლასის სტატიკური ველი **თითოეული დახურული აგებული ტიპისთვის ცალკეა**. `Cache<string, string>`-ს და `Cache<string, int>`-ს თითოეულს საკუთარი სტატიკური ველი აქვს. მაგრამ `Cache<string, string>`-ის **ყველა ეგზემპლარი** ერთ სტატიკურ ველს იზიარებს.

ავაგოთ მარტივი ქეში, რომელიც `Dictionary`-ს იყენებს და ელემენტს, თუ ქეშში არ არის, საცავიდან იღებს:

```csharp
public class Cache<TKey, TValue>
{
    private static readonly Dictionary<TKey, TValue> _entries =
        new Dictionary<TKey, TValue>();

    private readonly Func<TKey, TValue> _loader;

    public Cache(Func<TKey, TValue> loader) => _loader = loader;

    public TValue Get(TKey key)
    {
        if (_entries.TryGetValue(key, out TValue value))
            return value;

        value = _loader(key);      // მაგალითად, ბაზიდან წაკითხვა
        _entries[key] = value;
        return value;
    }
}
```

გამოყენება:

```csharp
var names  = new Cache<string, string>(k => LoadNameFromDb(k));
var prices = new Cache<string, decimal>(k => LoadPriceFromDb(k));
var titles = new Cache<string, string>(k => LoadTitleFromDb(k));

names.Get("P-100");    // "ლეპტოპი"  (ბაზიდან, შეინახა)
titles.Get("P-100");   // "ლეპტოპი"  !!! ბაზას აღარ მიმართავს
```

`names` და `prices` სხვადასხვა აგებული ტიპია (`Cache<string, string>` და `Cache<string, decimal>`), ამიტომ მათ სხვადასხვა სტატიკური ლექსიკონი აქვთ. ეს სწორედ ის ქცევაა, რაც გვინდოდა.

პრობლემა `titles`-თანაა. ის **იმავე** აგებული ტიპისაა, რაც `names`, ამიტომ მათ **ერთი და იგივე სტატიკური `_entries`** აქვთ. სათაურების ქეში რეალურად სახელების ქეშს იყენებს. `titles.Get("P-100")` ბაზას საერთოდ არ მიმართავს და სახელს აბრუნებს.

*ნახაზი 4.3: სტატიკური ველი თითოეულ დახურულ აგებულ ტიპს ეკუთვნის. ერთნაირი ტიპის არგუმენტების მქონე ეგზემპლარები მას იზიარებენ.*

თუ ერთნაირი ტიპის არგუმენტებით ორი დამოუკიდებელი ქეში გვჭირდება, სტატიკური ველით ამას ვერ მივაღწევთ. ამ შემთხვევაში ველი ინსტანციის (არასტატიკური) უნდა იყოს.

ეს ქცევა თავისთავად შეზღუდვა არ არის, პირიქით, ხშირად სასარგებლოა (იხ. ქვემოთ). ის მნიშვნელოვანია, რადგან შეიძლება მოლოდინს არ ემთხვეოდეს და ძნელად მოსაძებნი შეცდომების წყარო გახდეს. როცა generic კლასში სტატიკურ მონაცემებს ვამატებთ, ეს აუცილებლად უნდა გავითვალისწინოთ. [[თავი 10.5 სხვადასხვა რეკომენდაციები|მე-10 თავის]] მე-19 რეკომენდაციაც სწორედ ამაზეა: სტატიკური წევრები სიფრთხილით გამოიყენეთ.

> [!WARNING] შენიშვნა წიგნის მაგალითზე
> წიგნის ქეშის მაგალითში სტატიკური ლექსიკონი **ინსტანციის კონსტრუქტორში** იქმნება. ეს ნიშნავს, რომ ყოველი ახალი ეგზემპლარის შექმნა იმავე აგებული ტიპის ყველა არსებული ეგზემპლარის ქეშს ასუფთავებს. სტატიკური ველი სტატიკურად უნდა ინიციალიზდეს: ან ველის გამოცხადებისას, როგორც ზემოთ, ან სტატიკურ კონსტრუქტორში.

### სასარგებლო გამოყენება: ტიპზე დამოკიდებული ქეში

იგივე ქცევა ცნობილი ოპტიმიზაციის საფუძველია. თითოეულ ტიპს საკუთარი სტატიკური ველი აქვს, ამიტომ generic სტატიკური კლასი ტიპზე დამოკიდებულ მონაცემებს ლექსიკონის გარეშე ინახავს:

```csharp
public static class TypeInfo<T>
{
    // გამოითვლება ერთხელ თითოეული T-სთვის
    public static readonly string DisplayName = typeof(T).Name.ToUpperInvariant();
    public static readonly bool IsValueType = typeof(T).IsValueType;
}

Console.WriteLine(TypeInfo<Order>.DisplayName);   // ORDER
Console.WriteLine(TypeInfo<int>.IsValueType);     // True
```

`TypeInfo<Order>` და `TypeInfo<int>` სხვადასხვა ტიპია, ამიტომ თითოეულს საკუთარი, ერთხელ გამოთვლილი მნიშვნელობა აქვს. ლექსიკონში ძებნა არ ხდება და მუშაობა ნაკადებისთვის (thread) უსაფრთხოა, რადგან სტატიკურ ინიციალიზაციას CLR იცავს. BCL-ში ამ ტექნიკას იყენებს, მაგალითად, `EqualityComparer<T>.Default` და `Comparer<T>.Default`.

## აგებული ტიპები ველებად

Generic კლასის შიგნით ველები, პარამეტრები და ლოკალური ცვლადები შეიძლება **ღია ან დახურული აგებული ტიპის** იყოს:

```csharp
public class Catalog<T>
{
    private List<T> _items = new List<T>();             // ღია აგებული
    private List<string> _tags = new List<string>();    // დახურული აგებული

    public T First(List<int> positions)                 // დახურული პარამეტრი
    {
        List<T> selected = new List<T>();               // ღია, ლოკალური
        foreach (int p in positions)
            selected.Add(_items[p]);
        return selected[0];
    }
}
```

როცა Generics-ს შეეჩვევით, აგებული ტიპები სხვა ნებისმიერ ტიპად აღიქმება და მათი სინტაქსური თავისებურებები თანდათან აღარ შეინიშნება.
