## შეზღუდვები C++-ში

შეზღუდვები Generics-სა და templates-ს შორის **ყველაზე მნიშვნელოვანი განსხვავებაა**. templates-ის სამყაროში შეზღუდვის ცნება არ არსებობს (C++20-ის concepts-მდე), ამიტომ ეს ის სფეროა, სადაც C++-ის პროგრამისტი ახალ ცნებას ხვდება.

შეზღუდვა ტიპის პარამეტრის ინტერფეისს აზუსტებს. მის გარეშე ტიპის პარამეტრზე მხოლოდ `System::Object`-ის მეთოდებია ხელმისაწვდომი, რაც მონაცემების კონტეინერების გარდა ხშირად საკმარისი არ არის. შესაძლებლობების გასაფართოებლად generic გამოცხადებას **`where`** ნაწილი ემატება:

```cpp
using namespace System;
using namespace System::Collections::Generic;

interface class IValidatable {
    bool IsValid();
};

generic <typename T>
where T : IValidatable
ref class ValidatedList : List<T> {
public:
    bool ValidateAll() {
        for (int i = 0; i < Count; i++) {
            T item = this->default[i];       // List<T>-ის ინდექსატორი
            if (!item->IsValid())
                return false;
        }
        return true;
    }
};

ref class Employee : IValidatable {
private:
    int _id;
    int _status;
    double _salary;
public:
    Employee() : _id(0) {}
    Employee(int id) : _id(id) {}
    Employee(int id, int status, double salary)
        : _id(id), _status(status), _salary(salary) {}

    virtual bool IsValid() { return _id > 0; }

    int GetStatus()              { return _status; }
    void SetStatus(int status)   { _status = status; }
    double GetSalary()           { return _salary; }
    void SetSalary(double value) { _salary = value; }
};
```

`IValidatable` ინტერფეისი ერთ `IsValid()` მეთოდს აცხადებს, რომელიც ობიექტების ერთგვაროვანი ვალიდაციისთვისაა. `ValidatedList<T>` `T`-ზე ამ ინტერფეისს შეზღუდვად ადებს. `where` ნაწილი ტიპის პარამეტრების გამოცხადებას მაშინვე მოსდევს და ერთ ან მეტ შეზღუდვას შეიცავს, ზუსტად C#-ის სინტაქსით. `Employee` `IValidatable`-ს ახორციელებს: `IsValid()` `false`-ს აბრუნებს, თუ Id დადებითი არ არის.

```cpp
void TestConstraints() {
    ValidatedList<Employee^>^ staff = gcnew ValidatedList<Employee^>();
    staff->Add(gcnew Employee(23));
    staff->Add(gcnew Employee(212));
    staff->Add(gcnew Employee());           // Id = 0, არავალიდური

    bool ok = staff->ValidateAll();         // false
}
```

კოლექცია ყველა ელემენტზე `IsValid()`-ს იძახებს. თუ ერთი მაინც არავალიდურია, `ValidateAll()` `false`-ს აბრუნებს. აქ ბოლო ელემენტის Id 0-ია, ამიტომ შედეგი `false`-ია.

> [!WARNING] შენიშვნა წიგნის მაგალითზე
> წიგნში ინდექსატორზე წვდომა `this[idx]`-ით ხდება, `SetSalary` კი `this->_salary = _salary`-ს წერს (ველს თავის თავს ანიჭებს, პარამეტრის ნაცვლად). C++/CLI-ში `this` handle-ია, ამიტომ `this[i]` ინდექსატორს არ იძახებს. სწორია `this->default[i]` ან `(*this)[i]`.

### C++-ის თავისებურებები

C++, C# და VB შეზღუდვებში ოდნავ განსხვავდება:

| ასპექტი | C++/CLI | C# |
|---|---|---|
| თანმიმდევრობა | **ნებისმიერი**: კლასი და ინტერფეისები ნებისმიერ რიგში | კლასი/`class`/`struct` პირველი, `new()` ბოლო |
| reference type | `where T : ref class` | `where T : class` |
| value type | `where T : value class` | `where T : struct` |
| კონსტრუქტორი | `where T : gcnew()` | `where T : new()` |

> [!NOTE] შენიშვნა წიგნის ტექსტზე
> წიგნი ამბობს, რომ C++-ში value type-ის შეზღუდვა არ არის. Visual Studio 2005-ის საბოლოო ვერსიაში C++/CLI-ს აქვს `where T : value class` (C#-ის `struct`-ის ეკვივალენტი) და `where T : ref class` (C#-ის `class`-ის ეკვივალენტი).

## Generic დელეგატები C++-ში

generic დელეგატები, ინტერფეისების მსგავსად, მარტივი კონსტრუქციაა. ტიპის პარამეტრით ერთი ხელმოწერა უამრავ იმპლემენტაციას ემსახურება, და ყოველი ხელმოწერისთვის ცალკე დელეგატი აღარ გვჭირდება. სირთულე ცოტაა, მაგრამ სარგებელი დიდი:

```cpp
generic <typename T>
delegate void Updater(T item);

void PromoteStatus(Employee^ e) {
    if (e->GetStatus() <= 2) {
        Console::WriteLine(L"სტატუსი განახლდა");
        e->SetStatus(999);
    }
}

void RaiseSalary(Employee^ e) {
    double before = e->GetSalary();
    e->SetSalary(before * 1.2);
    Console::WriteLine(L"ხელფასი: {0} → {1}", before, e->GetSalary());
}

generic <typename T>
ref class Batch : List<T> {
private:
    Updater<T>^ _updater;
public:
    Batch(Updater<T>^ updater) : _updater(updater) {}

    void SetUpdater(Updater<T>^ updater) { _updater = updater; }

    void Apply() {
        for (int i = 0; i < Count; i++)
            _updater->Invoke(this->default[i]);
    }
};
```

სამი ელემენტია:

1. **`Updater<T>`** დელეგატი ერთპარამეტრიანი ხელმოწერით.
2. ორი მეთოდი, რომლებიც `Employee^`-ს იღებს და მის მდგომარეობას ცვლის.
3. **`Batch<T>`** generic კოლექცია, რომელიც `Updater<T>`-ს იღებს და `Apply()`-ში კოლექციის ყოველ ელემენტზე იძახებს.

```cpp
void TestDelegates() {
    Updater<Employee^>^ promote = gcnew Updater<Employee^>(&PromoteStatus);

    Batch<Employee^>^ batch = gcnew Batch<Employee^>(promote);
    batch->Add(gcnew Employee(1, 3, 9292.33));
    batch->Add(gcnew Employee(2, 1, 7383.99));
    batch->Add(gcnew Employee(3, 2, 989.94));
    batch->Apply();

    batch->SetUpdater(gcnew Updater<Employee^>(&RaiseSalary));
    batch->Apply();
}
```

დელეგატი `gcnew`-ით იქმნება, და მეთოდის მისამართი `&`-ით გადაეცემა. ინსტანციის მეთოდისთვის ობიექტიც უნდა მიეთითოს: `gcnew Updater<Employee^>(obj, &Class::Method)`.

## Generics-ისა და Templates-ის შერევა

C++ **ორივე ტექნოლოგიის ერთად** გამოყენების საშუალებას იძლევა, თითოეულის ღირებულების აღიარებით. ეს იმით მიიღწევა, რომ **template კლასს შეუძლია generic ინტერფეისის იმპლემენტაცია**. ანუ ტიპებს გარე სამყაროსთვის **generic ინტერფეისს** ვაძლევთ, იმპლემენტაციაში კი templates-ის სრულ ძალას ვიყენებთ.

ჯერ generic ინტერფეისი:

```cpp
generic <typename T>
interface class IDataSet {
    int Count();
    void Add(T item);
    T Get(int index);
    bool Validate();
};
```

### Template იმპლემენტაცია

```cpp
template <class T>
ref class TemplateDataSet : IDataSet<T> {
private:
    List<T>^ _items;
public:
    TemplateDataSet() { _items = gcnew List<T>(); }

    virtual int Count()        { return _items->Count; }
    virtual void Add(T item)   { _items->Add(item); }
    virtual T Get(int index)   { return _items[index]; }

    virtual bool Validate() {
        for (int i = 0; i < _items->Count; i++)
            if (!_items[i]->IsValid())      // duck typing: შეზღუდვა არ არის!
                return false;
        return true;
    }
};
```

template კლასი generic ინტერფეისს იღებს მემკვიდრეობით და ახორციელებს. ეს უმნიშვნელოდ შეიძლება მოგეჩვენოთ, მაგრამ **ძალიან ძლიერი** შესაძლებლობაა: templates-ის მთელი ძალა გვაქვს, გარე სამყაროსთვის კი ტიპი generic ინტერფეისის სახით ჩანს.

### Generic იმპლემენტაცია

შედარებისთვის, იგივე ინტერფეისი generic კლასით. მეთოდები იდენტურია, განსხვავება მხოლოდ გამოცხადებაშია:

```cpp
generic <class T>
where T : IValidatable                      // შეზღუდვა აუცილებელია IsValid()-ისთვის
ref class GenericDataSet : IDataSet<T> {
private:
    List<T>^ _items;
public:
    GenericDataSet() { _items = gcnew List<T>(); }
    // ... იგივე მეთოდები
};
```

### განსხვავება გამოყენებისას

ორი იმპლემენტაცია თითქმის ერთნაირია. რეალური განსხვავება გამოყენებისას ჩანს:

```cpp
ref class Employee : IValidatable { /* ... virtual bool IsValid() ... */ };

ref class Draft {                           // IValidatable-ს არ ახორციელებს,
public:                                     // მაგრამ IsValid() აქვს

void TestHybrid() {

```

*ნახაზი 12.1: ერთი generic ინტერფეისი, ორი იმპლემენტაცია. template ვერსია `Draft`-ს იღებს, generic ვერსია კი არა.*

`Employee` `IValidatable`-ს ახორციელებს, `Draft`-ს კი `IsValid()` მეთოდი აქვს, მაგრამ ინტერფეისს **არ** ახორციელებს. `TemplateDataSet<T>`-მა **ორივე** მიიღო, `GenericDataSet<T>` კი `Draft^`-ზე კომპილაციისას ჩავარდა.

მიზეზი `Validate()`-შია, რომელიც ყოველ ელემენტზე `IsValid()`-ს იძახებს. **template** ვერსიისთვის კომპილატორმა კომპილაციის დროს ცალ-ცალკე შეამოწმა, აქვს თუ არა `Employee`-ს და `Draft`-ს `IsValid()` მეთოდი. აქვს, ამიტომ ორივე ვერსია სწორია (duck typing, [[თავი 3.1 Generics და Templates|3.1]]). **generic** ვერსიაში კი კომპილატორმა უნდა დაამტკიცოს, რომ გაშვების დროის **ნებისმიერი** სპეციალიზაცია სწორი იქნება, ამიტომ `IValidatable` შეზღუდვა დაგვჭირდა. `Draft` ამ ინტერფეისს არ ახორციელებს, ამიტომ მიუღებელია.

ეს შეზღუდვა ცხადყოფს, რატომ არის templates-ისა და Generics-ის შერევა ასე ძლიერი. template კლასებისთვის generic ინტერფეისის მხარდაჭერით ვიღებთ ტიპებს, რომლებიც გარედან generic-ია, შიგნით კი template-ის **შეუზღუდავ** ძალას იყენებს. შეზღუდვების გვერდის ავლა „ზოგადობის" შენარჩუნებით ნამდვილი ბონუსია, და თუ ამას template კლასების generic ტიპებად გამოჩენასაც დავუმატებთ, ადვილი გასაგებია, რატომ იქნება ეს პოპულარული.

> [!WARNING] შენიშვნა წიგნის მაგალითზე
> წიგნის `TemplateDataCollection::Validate()` ციკლის შემდეგ ყოველთვის `true`-ს აბრუნებს, `retVal`-ის ნაცვლად, ანუ ვალიდაციის შედეგს უგულებელყოფს. ზემოთ მოცემული ვერსია არავალიდურ ელემენტზე `false`-ს აბრუნებს.

> [!NOTE] template-ის შეზღუდვა assembly-ის საზღვარზე
> template ვერსიის **ინსტანცირება** მხოლოდ C++-ის კოდში შეიძლება: C#-ის კლიენტი `TemplateDataSet<Employee^>`-ს თავად ვერ შექმნის. მაგრამ თუ C++-ის assembly ქარხნის მეთოდით `IDataSet<Employee^>^`-ს დააბრუნებს, C#-ის კლიენტი მას ჩვეულებრივ, generic ინტერფეისად გამოიყენებს. სწორედ ეს არის შერევის არსი.

## STL.NET

.NET 2.0-თან ერთად C++-ს ახალი ბიბლიოთეკა დაემატა, **STL.NET**. ეს პოპულარული STL template ბიბლიოთეკის ახალი იმპლემენტაციაა, რომელიც templates-საც და Generics-საც იყენებს.

ეს ბიბლიოთეკა ბევრ კითხვას ბადებს. STL.NET templates-ისა და Generics-ის ბალანსს შექმნის, მაგრამ თავსებადობისა და სტანდარტიზაციის მხრივ დაბნეულობასაც. უნდა გამოიყენოს დეველოპერმა STL.NET, თუ `System::Collections::Generic`-ით შემოიფარგლოს, როგორც ფაქტობრივი სტანდარტით? დავა ბევრია, და ავტორის აზრით, ცალსახა პასუხი არ არსებობს. როგორც ყველაფერი პროგრამირებაში: **„დამოკიდებულია სიტუაციაზე"**.

დავისა და სტანდარტიზაციის მიუხედავად, STL.NET საინტერესო და ძლიერი მიდგომაა: STL-ის .NET-ვერსია, რომელსაც პლატფორმის სრული გამოყენება შეუძლია. ამ თვალსაზრისით ის C++-ის დეველოპერებისთვის მნიშვნელოვანი მიღწევაა.

> [!NOTE] ბედი
> STL.NET Visual Studio 2005-ში არ გამოვიდა. ის **STL/CLR**-ის სახელით Visual Studio 2008-ში დაემატა (`<cliext/vector>`, `cliext::vector<T>` და ა.შ.). ფართოდ ვერ გავრცელდა, და დღეს C++/CLI-ში ძირითადად BCL-ის კოლექციები გამოიყენება.

## შეჯამება

ამ თავმა აჩვენა, როგორ იქმნება და გამოიყენება generic ტიპები C++-ში. მაგალითები ამომწურავი არ იყო: მიზანი იყო ყველა generic კონსტრუქციის ზოგადი მიმოხილვა და იმის ჩვენება, სად განსხვავდება C++ სხვა ენებისგან:

| კონსტრუქცია | C++/CLI | C# |
|---|---|---|
| generic კლასი | `generic <typename T> ref class X` | `class X<T>` |
| ეგზემპლარი | `X<int>^ x = gcnew X<int>();` | `var x = new X<int>();` |
| reference type-ის არგუმენტი | `X<String^>` | `X<string>` |
| ნაგულისხმევი მნიშვნელობა | `T()` | `default(T)` |
| ტიპის ობიექტი | `T::typeid` | `typeof(T)` |
| შეზღუდვა | `where T : IFoo` (ნებისმიერ რიგში) | `where T : IFoo` |
| დამოუკიდებელი generic ფუნქცია | ✓ | ✗ (მხოლოდ ტიპის შიგნით) |
| template + generic ინტერფეისი | ✓ | ✗ |
