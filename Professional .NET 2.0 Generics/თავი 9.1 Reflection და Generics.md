Generics .NET-ის ტიპების სისტემის გაფართოებაა. როცა ტიპები ახალ ქცევას იძენს, ის API-ებიც უნდა განვითარდეს, რომლებიც ამ ტიპებთან მუშაობს. მე-9 თავი .NET Framework-ის სამ სფეროს განიხილავს, რომლებზეც Generics-მა პირდაპირ იმოქმედა: **reflection**, **სერიალიზაცია** და **remoting**. თავის უმეტესი ნაწილი reflection-ს ეძღვნება: როგორ ვქმნით, ვიკვლევთ და ვმართავთ generic ტიპებს დინამიკურად. სერიალიზაცია და remoting [[თავი 9.2 სერიალიზაცია და Remoting|9.2-შია]].

## Reflection

Reflection .NET-ის ერთ-ერთი ყველაზე ძლიერი ინსტრუმენტია. როგორც სახელი მიანიშნებს („არეკვლა"), ის კლიენტს ტიპის ყველა დეტალის გამოკვლევის საშუალებას აძლევს. მისი ყველაზე ძლიერი მხარეა **გვიანი მიბმა (late binding)**: ტიპების შექმნა გაშვების დროს, მათი სახელის მიხედვით. ამ მექანიზმზეა აგებული უამრავი გადაწყვეტა: DI კონტეინერები, ORM-ები, სერიალიზატორები, plugin-სისტემები.

reflection-ის სრული განხილვა ამ წიგნის ფარგლებს სცდება. მაგრამ Generics ტიპების სისტემის მნიშვნელოვანი გაფართოებაა, ამიტომ უნდა ვიცოდეთ, როგორ ვიკვლიოთ, შევქმნათ და ვმართოთ generic ტიპები reflection-ის API-ით.

### `System.Type`-ის გაფართოება

generic ტიპი არაgeneric ტიპების ქცევის უმეტესობას იზიარებს. ამიტომ ლოგიკურია, რომ reflection-ში generic მახასიათებლები არსებული **`System.Type`** კლასის გაფართოებად შემოვიდა. reflection-თან მთელი მუშაობა ამ კლასისა და მასთან დაკავშირებული კლასების წევრებით ხდება, რაც generic ტიპებზე გადასვლას ამარტივებს. `Type`-ის არსებული მეთოდების დიდი ნაწილი generic ტიპებზეც პირდაპირ მუშაობს. მაგალითად, `Type.GetType()` generic ტიპის ჩატვირთვისთვისაც გამოიყენება.

| წევრი | რას აბრუნებს |
|---|---|
| `IsGenericType` | `true`, თუ ტიპი generic-ია (ღიაც და დახურულიც) |
| `IsGenericTypeDefinition` | `true`, მხოლოდ ღია განსაზღვრებისთვის (`List<>`) |
| `ContainsGenericParameters` | `true`, თუ სადმე ჯერ კიდევ შეუვსებელი ტიპის პარამეტრია |
| `GetGenericArguments()` | ტიპის არგუმენტები ან პარამეტრები |
| `GetGenericTypeDefinition()` | დახურული ტიპის ღია განსაზღვრება |
| `MakeGenericType(params Type[])` | ღია ტიპიდან დახურულს ქმნის |
| `IsGenericParameter` | `true`, თუ ეს `Type` თავად ტიპის პარამეტრია (`T`) |
| `GenericParameterPosition` | პარამეტრის პოზიცია სიაში |
| `GenericParameterAttributes` | პარამეტრის სპეციალური შეზღუდვები |
| `GetGenericParameterConstraints()` | პარამეტრის ტიპური შეზღუდვები (კლასი, ინტერფეისები) |

### არის თუ არა ტიპი generic

generic ტიპებს reflection-ის კოდისთვის ხშირად ცალკე ლოგიკა სჭირდება, ამიტომ უნდა შეგვეძლოს მათი ამოცნობა. ამისთვისაა `IsGenericType`:

```csharp
Type t1 = new Dictionary<int, string>().GetType();
Type t2 = "ტექსტი".GetType();

Console.WriteLine(t1.IsGenericType);   // True
Console.WriteLine(t2.IsGenericType);   // False
```

### ღია და დახურული ტიპების შექმნა reflection-ით

reflection-ში ტიპების გაშვების დროს **სახელით** ჩატვირთვა ძალიან გავრცელებულია. ეს დიდ მოქნილობას იძლევა: კომპილირებული აპლიკაცია გაშვების დროს დინამიკურად ჩატვირთული ტიპებით შეიძლება გაფართოვდეს. generic ტიპებიც ამ სქემაში მონაწილეობს, და რამდენიმე ნიუანსის გარდა, ისინი ჩვეულებრივი ტიპებივით იქმნება.

მთავარი ნიუანსი **სახელია**. არაgeneric ტიპის ჩასატვირთად საკმარისია სრული სახელი. მაგრამ generic ტიპები შეიძლება „გადატვირთული" იყოს arity-ით ([[თავი 4.1 ტიპების პარამეტრიზაცია|4.1]]): `Report<T>` და `Report<T, U>` ერთი სახელის ორი ტიპია. ამიტომ `Type.GetType("Report")` საკმარისი აღარ არის. .NET ამ პრობლემას სახელზე **`` ` ``** სიმბოლოს და ტიპის პარამეტრების რაოდენობის დამატებით წყვეტს: ``Report`1`` არის `Report<T>`, ხოლო ``Report`2`` არის `Report<T, U>`. დებაგერშიც ზუსტად ამ სახელებს დავინახავთ. ლამაზი არ არის, მაგრამ მუშაობს.

მაგალითისთვის შევქმნათ ქარხანა (factory), რომელიც ტიპებს სახელით ქმნის:

```csharp
public static class GenericTypeFactory
{
    // სრული სახელი arity-ით: "Reports.Report`1"
    public static Type OpenType(string fullName)
    {
        int tick = fullName.IndexOf('`');
        if (tick < 0 || !int.TryParse(fullName.Substring(tick + 1), out _))
            return null;                    // arity არ არის მითითებული
        return Type.GetType(fullName);
    }

    // სახელი + arity ცალკე: ("Reports.Report", 2)
    public static Type OpenType(string name, int arity) =>
        Type.GetType(name + "`" + arity);

    // დახურული ტიპი: ("Reports.Report", "System.Int32", "System.String")
    public static Type ClosedType(string name, params string[] typeArgNames)
    {
        Type open = OpenType(name, typeArgNames.Length);
        if (open == null || !open.IsGenericTypeDefinition)
            return null;

        Type[] args = Array.ConvertAll(typeArgNames, Type.GetType);
        return open.MakeGenericType(args);
    }
}
```

- პირველი `OpenType` სრულ სახელს იღებს arity-ით და ამოწმებს, რომ `` ` ``-ის შემდეგ რიცხვი წერია. სხვა შემთხვევაში `null`-ს აბრუნებს.
- მეორე `OpenType` სახელს და arity-ს ცალ-ცალკე იღებს და სწორ სახელს თავად აწყობს. დიდ ღირებულებას არ მატებს, მაგრამ კლიენტს `` ` ``-ის წერისგან ათავისუფლებს.
- `ClosedType` ორ ნაბიჯად მუშაობს: ჯერ **ღია ტიპს** ქმნის (arity ტიპის არგუმენტების რაოდენობიდან გამოითვლება), შემდეგ **`MakeGenericType()`**-ით ტიპის არგუმენტებს აბამს და დახურულ ტიპს იღებს.

```csharp
namespace Reports
{
    public class Report<T> { }
    public class Report<T, U> { }
}

Type open1 = GenericTypeFactory.OpenType("Reports.Report`1");
Type open2 = GenericTypeFactory.OpenType("Reports.Report", 2);

Type closed1 = GenericTypeFactory.ClosedType("Reports.Report", "System.Int32");
Type closed2 = GenericTypeFactory.ClosedType("Reports.Report", "System.Int32", "System.String");

object r1 = Activator.CreateInstance(closed1);   // Report<int>
object r2 = Activator.CreateInstance(closed2);   // Report<int, string>
```

**ღია ტიპი მხოლოდ განსაზღვრებაა**, მისი ეგზემპლარის შექმნა შეუძლებელია (`Activator.CreateInstance(open1)` exception-ს ისვრის). ღია ტიპს ტიპის ზოგადი მახასიათებლების შესასწავლად ან დახურული ტიპების შესაქმნელად ვიყენებთ. დახურული ტიპის ობიექტი კი ჩვეულებრივ, `Activator.CreateInstance()`-ით იქმნება.

ვინც reflection-ს იცნობს, ამ მექანიზმს ნაცნობად მიიჩნევს. Generics-მა აქ მხოლოდ ერთი რამ შემოიტანა: ტიპის სახელის ცვლილება arity-ის მიხედვით. დანარჩენი არაgeneric ტიპების მექანიკას მიჰყვება.

> [!TIP] სახელი `Type.GetType()`-ისთვის
> სხვა assembly-ში მდებარე ტიპისთვის სახელს assembly-ის სახელიც უნდა ახლდეს: `"Reports.Report`1, Reports.Library"`. დახურული ტიპის სრულ სახელში ტიპის არგუმენტები კვადრატულ ფრჩხილებში იწერება: ``"System.Collections.Generic.List`1[[System.Int32]]"``. ჩადგმული ტიპი `+`-ით გამოიყოფა: `"Outer+Inner`1"`.

### დახურული ტიპიდან ღიაზე გადასვლა

ზოგჯერ დახურული ტიპი გვაქვს და იმ ღია ტიპზე წვდომა გვჭირდება, საიდანაც ის აიგო. ამისთვისაა `GetGenericTypeDefinition()`:

```csharp
Type closed = new List<double>().GetType();
Console.WriteLine(closed.IsGenericTypeDefinition);    // False

Type open = closed.GetGenericTypeDefinition();        // List`1
Console.WriteLine(open.IsGenericTypeDefinition);      // True

Type another = open.MakeGenericType(typeof(string));  // List<string>
```

`GetGenericTypeDefinition()` `List<T>`-ის განსაზღვრებას აბრუნებს, რომლიდანაც დახურული ტიპი აიგო. მიღებული ღია ტიპი სხვა არგუმენტზე შეიძლება მივაბათ და ახალი დახურული ტიპი მივიღოთ.

> [!TIP] პრაქტიკული გამოყენება: „არის თუ არა ეს სია?"
> ```csharp
> static bool IsListOfAnything(Type t) =>
>     t.IsGenericType && t.GetGenericTypeDefinition() == typeof(List<>);
> ```
> `typeof(List<>)` (ცარიელი კუთხოვანი ფრჩხილებით) C#-ში ღია ტიპის მიღების სინტაქსია. ორი პარამეტრისთვის `typeof(Dictionary<,>)`.

### პარამეტრებისა და არგუმენტების კვლევა

ტიპის პარამეტრების შემოღებამ reflection-ს ახალი წევრები დაუმატა, რომლებითაც generic ტიპის პარამეტრებს ან არგუმენტებს ვიკვლევთ:

```csharp
static void DumpTypeArguments(Type type)
{
    Console.WriteLine($"\nტიპი: {type.Name}");
    foreach (Type arg in type.GetGenericArguments())
    {
        if (arg.IsGenericParameter)
        {
            Console.WriteLine($"  პარამეტრი {arg.Name}, პოზიცია {arg.GenericParameterPosition}");

            GenericParameterAttributes special =
                arg.GenericParameterAttributes & GenericParameterAttributes.SpecialConstraintMask;

            if ((special & GenericParameterAttributes.ReferenceTypeConstraint) != 0)
                Console.WriteLine("    შეზღუდვა: class");
            if ((special & GenericParameterAttributes.NotNullableValueTypeConstraint) != 0)
                Console.WriteLine("    შეზღუდვა: struct");
            if ((special & GenericParameterAttributes.DefaultConstructorConstraint) != 0)
                Console.WriteLine("    შეზღუდვა: new()");

            foreach (Type c in arg.GetGenericParameterConstraints())
                Console.WriteLine($"    შეზღუდვა: {c.Name}");
        }
        else
        {
            Console.WriteLine($"  არგუმენტი: {arg.Name}");
        }
    }
}
```

`IsGenericParameter` გვეუბნება, ეს **ტიპის პარამეტრია** (ღია ტიპში, მაგალითად `T`) თუ **ტიპის არგუმენტი** (დახურულ ტიპში, მაგალითად `String`). ტიპის პარამეტრისთვის `GenericParameterPosition` პოზიციას იძლევა, `GenericParameterAttributes` სპეციალურ შეზღუდვებს (`class`, `struct`, `new()`), ხოლო `GetGenericParameterConstraints()` ტიპურ შეზღუდვებს (საბაზო კლასი, ინტერფეისები).

```csharp
public interface IValidatable { }
public interface IAuditable { }
public class Person { }
public class Employee : Person, IValidatable, IAuditable { }

public class Roster<T> where T : Person, IValidatable, IAuditable, new() { }
public class Roster<T, U> where T : Person, IValidatable, IAuditable, new()
                          where U : IComparable { }

DumpTypeArguments(typeof(Dictionary<string, long>));
DumpTypeArguments(typeof(Roster<>));
DumpTypeArguments(typeof(Roster<,>));
```


### Reflection და generic მემკვიდრეობა

მემკვიდრე ტიპებთან reflection ზოგჯერ მოულოდნელად იქცევა:

```csharp
public class Bag<T> { }
public class Index<TKey, TValue> : Bag<TValue> { }

Type open = typeof(Index<,>);
Type baseType = open.BaseType;          // Bag<TValue>

Console.WriteLine(baseType.IsGenericTypeDefinition);     // False !
Console.WriteLine(baseType.ContainsGenericParameters);   // True
```

`Index<TKey, TValue>` `Bag<T>`-ს იღებს მემკვიდრეობით და მას თავის `TValue`-ს გადასცემს. ეს სავსებით ჩვეულებრივი ნიმუშია. რას გვეტყვის reflection საბაზო კლასზე? ერთი შეხედვით, `Bag<TValue>`-ს კონკრეტული არგუმენტი არ აქვს, ამიტომ თითქოს განსაზღვრება (definition) უნდა იყოს.

მაგრამ `IsGenericTypeDefinition` `false`-ს აბრუნებს. `Bag<TValue>` [[თავი 1.2 Generics-ის ტერმინოლოგია|ღია აგებული ტიპია]]: მისი `T` ნებისმიერ ტიპს ვერ მიიღებს, ის **მიბმულია** ქვეკლასის `TValue`-ზე. ამიტომ ის „ნამდვილი" ღია განსაზღვრება არ არის, თუმცა კონკრეტულ ტიპამდე ჯერ არ მისულა. ამ მდგომარეობის ამოსაცნობად `ContainsGenericParameters`-ია, რომელიც `true`-ს აბრუნებს.

| ტიპი | `IsGenericType` | `IsGenericTypeDefinition` | `ContainsGenericParameters` |
|---|---|---|---|
| `Bag<>` | ✓ | ✓ | ✓ |
| `Bag<TValue>` (ქვეკლასის პარამეტრით) | ✓ | ✗ | ✓ |
| `Bag<int>` | ✓ | ✗ | ✗ |
| `string` | ✗ | ✗ | ✗ |

### Reflection generic მეთოდებზე

generic მეთოდებმა reflection-ს ახალი წევრები დაუმატა. თემები იგივეა, რაც generic კლასებში, ოღონდ ინფორმაცია **`MethodInfo`**-დან მოდის:

| `MethodInfo`-ს წევრი | ეკვივალენტი `Type`-ში |
|---|---|
| `IsGenericMethod` | `IsGenericType` |
| `IsGenericMethodDefinition` | `IsGenericTypeDefinition` |
| `ContainsGenericParameters` | `ContainsGenericParameters` |
| `GetGenericArguments()` | `GetGenericArguments()` |
| `GetGenericMethodDefinition()` | `GetGenericTypeDefinition()` |
| `MakeGenericMethod(params Type[])` | `MakeGenericType(params Type[])` |

```csharp
public class Converter
{
    public TOut Convert<TIn, TOut>(TIn value) => (TOut)(object)value;
}

MethodInfo open = typeof(Converter).GetMethod("Convert");
Console.WriteLine(open.IsGenericMethodDefinition);      // True

MethodInfo closed = open.MakeGenericMethod(typeof(int), typeof(object));
Console.WriteLine(closed.IsGenericMethodDefinition);    // False
foreach (Type a in closed.GetGenericArguments())
    Console.WriteLine(a.IsGenericParameter ? $"შეუვსებელი: {a.Name}" : $"მიბმული: {a.Name}");
// მიბმული: Int32, მიბმული: Object

object result = closed.Invoke(new Converter(), new object[] { 42 });   // 42

MethodInfo back = closed.GetGenericMethodDefinition();  // ისევ ღია
```

`GetGenericArguments()` მეთოდის ტიპის პარამეტრების მასივს აბრუნებს, და მათი დამუშავება ზუსტად ისეთივეა, როგორც კლასის პარამეტრებისა (იგივე `DumpTypeArguments`-ის ლოგიკა გამოდგება). **`MakeGenericMethod()`** ღია generic მეთოდს ტიპის არგუმენტებს აბამს, და ასე აგებულ მეთოდს `Invoke()`-ით ვიძახებთ.

> [!NOTE] ყურადღება `GetMethod`-ზე
> თუ კლასს ერთი სახელის generic და არაgeneric მეთოდი აქვს, `GetMethod("Name")` `AmbiguousMatchException`-ს ისვრის. ასეთ დროს `GetMethods()`-ით ყველა მეთოდს ვიღებთ და `IsGenericMethodDefinition`-ით ვფილტრავთ. .NET Core 2.1+-ში `GetMethod`-ს generic პარამეტრების რაოდენობის მიმღები გადატვირთვაც აქვს.

### შეხსენება obfuscation-ზე

დინამიკურად ჩატვირთული ტიპების სახელები, როგორც წესი, გაშვებისას მოდის (კონფიგურაციიდან, ბაზიდან). თუ ტიპის სრული სახელი კომპილაციისას ვიცით, ღირს ვიკითხოთ, რატომ ვიყენებთ reflection-ს საერთოდ. მაგრამ ზოგჯერ ტიპის სახელი ნაწილობრივ ან მთლიანად კოდში, სტრიქონად წერია, და მაშინ ის გაშვებისას **ზუსტად** უნდა ემთხვეოდეს.

obfuscation-ის გარეშე ეს პრობლემა არ არის. obfuscated კოდში კი ``Reports.Report`1`` შეიძლება გადაერქვას, ვთქვათ, ``a.b`1``-ად, და კოდში ჩაწერილი სტრიქონი აღარ იმუშავებს. ჩვეულებრივ ამას obfuscator-ის შერჩევითი კონფიგურაციით ვწყვეტთ: reflection-ით ხელმისაწვდომ ტიპებს სახელის შეცვლისგან ვიცავთ. ეს ტიპების ორ ჯგუფად სტრატეგიულ დაყოფასაც მოითხოვს: რაც reflection-ით ჩანს და რაც არა. ეს პრობლემა ნებისმიერ reflection-ს ეხება, generic ტიპებით თუ მათ გარეშე.

> [!TIP] `typeof` და `nameof` სტრიქონების ნაცვლად
> სადაც შესაძლებელია, სტრიქონების ნაცვლად `typeof(Report<>)` ან `nameof(Report<int>)` გამოიყენეთ. ასე კომპილატორი სახელის სისწორეს ამოწმებს, obfuscator-ი კი რეფერენსს სწორად გადაარქმევს.
