## `Dictionary<TKey, TValue>`

`Dictionary<TKey, TValue>` კოლექციაში **გასაღებებს მნიშვნელობებთან აკავშირებს** (mapping). ყოველი გასაღები უნიკალური უნდა იყოს, და გასაღებით ნებისმიერ მნიშვნელობაზე სწრაფად ვწვდებით. ეფექტიანობისა და ზოგადი ქცევის გამო ის ფასდაუდებელი ინსტრუმენტია უამრავი გამოყენებით.

`System.Collections`-ში მისი ფუნქციური ეკვივალენტი `Hashtable` იყო. `Dictionary` `Hashtable`-ის კონცეფციების უმეტესობას იზიარებს, მაგრამ იმპლემენტაცია თითქმის თავიდანაა დაწერილი, ამიტომ წარმადობის მახასიათებლებიც განსხვავებულია.

| წევრი | აღწერა |
|---|---|
| `Add(key, value)` | ამატებს წყვილს. თუ გასაღები უკვე არსებობს, `ArgumentException` |
| `this[key]` | კითხულობს მნიშვნელობას (თუ გასაღები არ არის, `KeyNotFoundException`), ან **ამატებს/ჩაანაცვლებს** |
| `ContainsKey(key)` | არის თუ არა გასაღები. სწრაფია, O(1) |
| `ContainsValue(value)` | არის თუ არა მნიშვნელობა. **ნელია**, O(n), ყველა ელემენტს ამოწმებს |
| `TryGetValue(key, out value)` | ერთი ოპერაციით ამოწმებს და იღებს |
| `Remove(key)` | შლის გასაღებით, აბრუნებს `true`-ს, თუ იპოვა |
| `Clear()`, `Count` | ყველაფრის წაშლა, რაოდენობა |
| `Keys`, `Values` | `KeyCollection` და `ValueCollection` |
| `GetEnumerator()` | `KeyValuePair<TKey, TValue>` წყვილების enumerator |
| `Comparer` | გასაღებების `IEqualityComparer<TKey>` |
| `GetObjectData()`, `OnDeserialization()` | სერიალიზაციის მხარდაჭერა |

### შექმნა

BCL-ის generic კლასებიდან ყველაზე მეტი კონსტრუქტორი `Dictionary<TKey, TValue>`-ს აქვს. განსაკუთრებით საინტერესოა ის ვერსიები, რომლებიც **ტოლობის comparer-ს** იღებს და გასაღებების შედარების წესს განსაზღვრავს:

```csharp
// 1. საკუთარი comparer: რეგისტრისადმი გულგრილი გასაღებები
var byCode = new Dictionary<string, Customer>(StringComparer.OrdinalIgnoreCase);
byCode["gold-77"] = new Customer(77, "ანა", "Gold");
Console.WriteLine(byCode["GOLD-77"].Name);   // ანა

// 2. კოპირება სხვა ლექსიკონიდან
var original = new Dictionary<int, Customer>
{
    [99] = new Customer(99, "ნიკა", "Platinum"),
    [55] = new Customer(55, "ლევანი", "Silver")
};
var copy = new Dictionary<int, Customer>(original);
copy[55] = new Customer(55, "თამარი", "Standard");
// original[55] ისევ ლევანია

// 3. საწყისი ტევადობა
var big = new Dictionary<int, Customer>(10_000);
```

> [!WARNING] შენიშვნა წიგნის მაგალითზე
> წიგნში ლექსიკონს `Comparer<int>.Default` გადაეცემა. ეს კომპილაციას ვერ გაივლის: `Dictionary` **`IEqualityComparer<TKey>`**-ს იღებს (ტოლობა და ჰეში), და არა `IComparer<TKey>`-ს (დალაგება). სწორია `EqualityComparer<int>.Default` ან, ზემოთ ნაჩვენების მსგავსად, `StringComparer.OrdinalIgnoreCase`. `IComparer<TKey>` `SortedDictionary`-ს და `SortedList`-ს სჭირდება.

**კოპირების კონსტრუქტორი** ახალ ლექსიკონს ქმნის საკუთარი ჩანაწერებით. ამიტომ `copy`-ში გასაღების **ახალ მნიშვნელობაზე მიბმა** `original`-ზე არ მოქმედებს. წიგნი ამას „ღრმა ასლს" უწოდებს, მაგრამ ზუსტად რომ ვთქვათ, ეს **ზედაპირული ასლია**: მნიშვნელობა-ობიექტები არ კლონირდება. თუ `copy[99].Name`-ს შევცვლით, `original[99].Name`-იც შეიცვლება, რადგან ორივე ერთ `Customer` ობიექტს მიუთითებს.

**ტევადობის** პარამეტრი საწყისი მეხსიერების გამოყოფას მართავს. თუ ლექსიკონი დიდი იქნება, ტევადობის წინასწარ მითითება წარმადობას აუმჯობესებს, რადგან შიდა ცხრილის განმეორებით გადაწყობას (rehash) თავიდან ვიცილებთ. ტევადობის მიუხედავად, ლექსიკონი ახალი ელემენტებისთვის ავტომატურად იზრდება.

### დამატება და განახლება

ლექსიკონის შიგთავსის მართვა სიებისგან განსხვავდება. ლექსიკონს **თანმიმდევრობა არ აქვს**: ელემენტები შიდა სტრუქტურაში „სადღაც" თავსდება, და არანაირი გარანტია არ არსებობს, სად. ამიტომ ყველა ოპერაცია გასაღებით ხდება.

```csharp
var customers = new Dictionary<int, Customer>();
customers[99] = new Customer(99, "ნიკა", "Platinum");     // ინდექსატორი: დამატება
customers[77] = new Customer(77, "ანა", "Gold");
customers.Add(11, new Customer(11, "თამარი"));            // Add: დამატება

// customers.Add(77, new Customer(77, "სხვა"));           // ArgumentException: გასაღები არსებობს
customers[77] = new Customer(77, "ანა", "Platinum");      // ინდექსატორი: ჩანაცვლება

Customer nika = customers[99];
nika.Tier = "Gold";            // ლექსიკონში შენახული ობიექტიც შეიცვალა
```

რატომ გვაქვს ორი მეთოდი, რომლებიც ერთსა და იმავეს აკეთებს? სწორედ მათი განსხვავების გაგებაა მნიშვნელოვანი:

| | ინდექსატორი `d[key] = v` | `Add(key, v)` |
|---|---|---|
| გასაღები არ არსებობს | ამატებს | ამატებს |
| გასაღები უკვე არსებობს | **ჩუმად ჩაანაცვლებს** | **`ArgumentException`** |

მკაცრი წესი არ არსებობს, მაგრამ ავტორის რჩევაა: ინდექსატორი არსებული მნიშვნელობების **წასაკითხად და განსაახლებლად** გამოიყენეთ, `Add()` კი **დასამატებლად**. ინდექსატორით დამატება ორაზროვნებას ქმნის: კოდის წაკითხვისას არ ჩანს, ამატებს თუ ანაცვლებს.

ბოლო ხაზები აჩვენებს, რომ ლექსიკონში შენახული **reference type-ები რეფერენსებად რჩება**. ლექსიკონიდან აღებული `Customer` იგივე ობიექტია, რაც ლექსიკონშია, ამიტომ მისი შეცვლა ლექსიკონის შიგთავსსაც ცვლის.

### ძებნა

ლექსიკონს აქვს მეთოდები, რომლებითაც ვამოწმებთ, არსებობს თუ არა გასაღები ან მნიშვნელობა. ვთქვათ, ლექსიკონში უკვე ასეთი მომხმარებლებია:

```
99 ნიკა Platinum · 77 ანა Gold · 55 ლევანი Silver · 88 ბესო Platinum · 11 თამარი Standard
```

და მოგვდის ახალი სია:

```
33 დავითი Platinum · 11 ეკა Standard · 55 ლევანი Silver · 51 გიგა Gold · 77 ნინი Silver
```

სამი მიდგომა:

```csharp
// 1. მხოლოდ Id-ით: თუ Id არ არის, დაამატე
public void MergeById(IEnumerable<Customer> incoming)
{
    foreach (Customer c in incoming)
    {
        if (!_customers.ContainsKey(c.Id))
            _customers.Add(c.Id, c);
        else
            Console.WriteLine($"Id-ის დუბლიკატი: {c.Id}");
    }
}

// 2. სრული მნიშვნელობით: თუ იგივე მომხმარებელი არ არის, დაამატე ან განაახლე
public void MergeByValue(IEnumerable<Customer> incoming)
{
    foreach (Customer c in incoming)
    {
        if (_customers.ContainsValue(c))
            Console.WriteLine($"სრული დუბლიკატი: {c.Id}");
        else
            _customers[c.Id] = c;     // არსებულ Id-ს განაახლებს, ახალს დაამატებს
    }
}

// 3. TryGetValue: შემოწმება და აღება ერთად
public List<Customer> FindExisting(IEnumerable<Customer> incoming)
{
    var result = new List<Customer>();
    foreach (Customer c in incoming)
    {
        if (_customers.TryGetValue(c.Id, out Customer existing))
            result.Add(existing);
    }
    return result;
}
```

- **`MergeById`** მხოლოდ Id-ს ამოწმებს `ContainsKey()`-ით. ის **სამ** დუბლიკატს იპოვის: 11, 55 და 77.
- **`MergeByValue`** უფრო მკაცრია: დუბლიკატად მხოლოდ სრულად დამთხვეულ მომხმარებელს თვლის, `ContainsValue()`-ით, რომელიც `Customer.Equals`-ს იყენებს. ის **ერთ** დუბლიკატს იპოვის: 55. 11 და 77 Id-ით ემთხვევა, მაგრამ სხვა მონაცემებით არა, ამიტომ ისინი **განახლდება**. ეს მიდგომა ისეთი მომხმარებლების განახლების საშუალებას იძლევა, რომელთა Id იგივეა, მაგრამ სხვა ატრიბუტები შეიცვალა.
- **`FindExisting`** `TryGetValue()`-ს იყენებს, რომელიც არსებობის შემოწმებასა და მნიშვნელობის აღებას **ერთ გამოძახებაში** აერთიანებს, exception-ების დამუშავების ან წინასწარი შემოწმების გარეშე. ის დააბრუნებს 11-ს, 55-ს და 77-ს.

> [!TIP] `ContainsKey` + ინდექსატორი თუ `TryGetValue`?
> `if (d.ContainsKey(k)) v = d[k];` ჰეშს **ორჯერ** ითვლის. `TryGetValue` ერთხელ. ხშირად გამოძახებად კოდში `TryGetValue` სჯობს.

### გასაღებების და მნიშვნელობების აღება

```csharp
Dictionary<int, Customer>.KeyCollection ids = customers.Keys;

foreach (KeyValuePair<int, Customer> pair in customers)
```

თითოეულ მათგანს ლექსიკონი თავის სპეციფიკურ ტიპად აბრუნებს: `KeyCollection`, `ValueCollection` და `KeyValuePair<TKey, TValue>`-ების enumerator. ყველა მათგანი **ცოცხალი ხედია (live view)**: ლექსიკონის შემდგომი ცვლილებები მათშიც აისახება.

### წაშლა

ყველა გასაღები უნიკალურია, ამიტომ ერთი ელემენტის წასაშლელად ერთი მეთოდი კმარა: **`Remove(key)`**. ის გასაღებს ეძებს, და თუ იპოვა, შლის და `true`-ს აბრუნებს. **`Clear()`** ყველაფერს შლის.

### `null` გასაღებები და მნიშვნელობები

`Hashtable` ყველაფერს `object`-ად ინახავდა, ამიტომ `null` მნიშვნელობას იღებდა (გასაღებად `null` მასაც არ შეეძლო).

წიგნი ამბობს, რომ `Dictionary`-ში null-ის ჩასაწერად `Nullable<T>` უნდა გამოვიყენოთ, როგორც გასაღებისთვის, ისე მნიშვნელობისთვის. ეს დაზუსტებას საჭიროებს:

| | reference type (`string`, `Customer`) | value type (`int`, `DateTime`) |
|---|---|---|
| **გასაღები** `null` | ✗ დაუშვებელია, `ArgumentNullException` | ✗ `Nullable<T>`-ითაც დაუშვებელია |
| **მნიშვნელობა** `null` | ✓ პირდაპირ დასაშვებია | ✓ `Nullable<T>`-ით: `Dictionary<string, int?>` |

ანუ `Nullable<T>` მხოლოდ value type-ის **მნიშვნელობებისთვის** გვჭირდება. `null` გასაღები `Dictionary`-ში არასოდეს შეიძლება.

## `SortedDictionary<TKey, TValue>`

`Dictionary` თავისთავად ძალიან სასარგებლოა, მაგრამ კლიენტი ელემენტების **თანმიმდევრობას ვერ აკონტროლებს**. სანამ ელემენტებთან მხოლოდ გასაღებით ვმუშაობთ, ეს პრობლემა არ არის. მაგრამ ზოგჯერ გვინდა, რომ ლექსიკონზე გადავლა **გარკვეული თანმიმდევრობით** ხდებოდეს. ამისთვისაა `SortedDictionary<TKey, TValue>`.

მისი ინტერფეისი თითქმის იგივეა, რაც `Dictionary`-ის (ორივე `IDictionary<TKey, TValue>`-ს ახორციელებს). განსხვავება:

- **`Comparer`** property: `IComparer<TKey>`, რომელიც გასაღებების **დალაგების** წესს განსაზღვრავს (კონსტრუქტორში გადაეცემა, ნაგულისხმევად `Comparer<TKey>.Default`).
- **`Keys`** და **`Values`**, ისევე როგორც enumerator, **გასაღების მიხედვით დალაგებულ** თანმიმდევრობას იძლევა.

```csharp
var plain = new Dictionary<int, Customer>
{
    [99] = new Customer(99, "ნიკა"),
    [77] = new Customer(77, "ანა"),
    [55] = new Customer(55, "ლევანი"),
    [88] = new Customer(88, "ბესო")
};
// გადავლის თანმიმდევრობა გარანტირებული არ არის

var sorted = new SortedDictionary<int, Customer>(plain);
foreach (Customer c in sorted.Values)
    Console.WriteLine(c);   // 55: ლევანი, 77: ანა, 88: ბესო, 99: ნიკა

sorted.Remove(88);
foreach (Customer c in sorted.Values)
    Console.WriteLine(c);   // 55: ლევანი, 77: ანა, 99: ნიკა
```

`SortedDictionary` დალაგებულ ლექსიკონს იძლევა და გასაღებით წვდომასაც ინარჩუნებს.

> [!WARNING] შენიშვნა წიგნის ცხრილზე
> წიგნის ცხრილში `SortedDictionary`-ს აქვს `Capacity` property, ხოლო `Keys`/`Values` `List<T>`-ს აბრუნებს. ეს .NET 2.0-ის საბოლოო ვერსიას არ შეესაბამება. `SortedDictionary`-ს `Capacity` **არ აქვს**, რადგან შიგნით ის **ბალანსირებული ორობითი ხეა** (red-black tree) და არა მასივი. `Keys`/`Values` კი `SortedDictionary<TKey, TValue>.KeyCollection`/`ValueCollection`-ს აბრუნებს.

## `SortedList<TKey, TValue>`

თუ უბრალოდ გასაღებით დალაგებული ლექსიკონი გვჭირდება, `SortedDictionary` საკმარისია. მაგრამ თუ **ინდექსით წვდომაც** გვინდა, არსებობს `SortedList<TKey, TValue>`: `List<T>`-ისა და `SortedDictionary`-ის ნახევრად ჰიბრიდი. ვინც არაgeneric `SortedList`-თან უმუშავია, ცნობილად მოეჩვენება.

განსხვავება `SortedDictionary`-სთან: `Keys` და `Values` აქ **`IList<TKey>`** და **`IList<TValue>`** ტიპისაა, ამიტომ მათზე ინდექსითაც ვწვდებით. ინდექსზე დაფუძნებული დამატებითი წევრები:

| წევრი | აღწერა |
|---|---|
| `IndexOfKey(key)` | გასაღების ინდექსი, ან `-1` |
| `IndexOfValue(value)` | პირველი ტოლი მნიშვნელობის ინდექსი, ან `-1` |
| `RemoveAt(index)` | ინდექსით წაშლა. არასწორ ინდექსზე `ArgumentOutOfRangeException` |
| `Keys[i]`, `Values[i]` | i-ური გასაღები და მნიშვნელობა დალაგებულ თანმიმდევრობაში |
| `Capacity`, `TrimExcess()` | ტევადობა (შიგნით მასივებია). `TrimExcess` 90%-ის წესით |

```csharp
var ranking = new SortedList<int, string>
{
    [3] = "ბრინჯაო",
    [1] = "ოქრო",
    [2] = "ვერცხლი"
};

Console.WriteLine(ranking.Keys[0]);          // 1
Console.WriteLine(ranking.Values[2]);        // ბრინჯაო
Console.WriteLine(ranking.IndexOfKey(2));    // 1
ranking.RemoveAt(0);                         // ოქროს წაშლა
```

### რომელი ავირჩიოთ?

| | `Dictionary` | `SortedDictionary` | `SortedList` |
|---|---|---|---|
| შიდა სტრუქტურა | ჰეშ-ცხრილი | წითელ-შავი ხე | ორი დალაგებული მასივი |
| ძებნა გასაღებით | O(1) | O(log n) | O(log n) (ორობითი ძებნა) |
| ჩასმა/წაშლა | O(1) | O(log n) | O(n): ელემენტების გადაწევა |
| დალაგებული გადავლა | ✗ | ✓ | ✓ |
| ინდექსით წვდომა | ✗ | ✗ | ✓ |
| მეხსიერება | საშუალო | მეტი (ხის კვანძები) | ყველაზე ნაკლები |
| გასაღების მოთხოვნა | `IEqualityComparer<TKey>` | `IComparer<TKey>` | `IComparer<TKey>` |

**წესი**: თუ თანმიმდევრობა არ გვჭირდება, `Dictionary`. თუ დალაგება და ხშირი ცვლილებები გვჭირდება, `SortedDictionary`. თუ დალაგება და ინდექსით წვდომა გვჭირდება, ხოლო მონაცემები ძირითადად ერთხელ ივსება (ან დალაგებული თანმიმდევრობით), `SortedList`.
