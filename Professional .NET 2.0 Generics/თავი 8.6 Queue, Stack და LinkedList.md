## `Queue<T>`

აქამდე განხილული კოლექციების უმეტესობა ინდექსით ან გასაღებით წვდომაზეა აგებული, და მათთვის არ აქვს მნიშვნელობა, რა თანმიმდევრობით მოხვდა ელემენტები კოლექციაში. `Queue<T>` კი ზუსტად ამ თანმიმდევრობისადმია მგრძნობიარე: ის **რიგია**, სადაც პირველი დამატებული ელემენტი პირველი გამოდის (**FIFO**, first-in-first-out). ინდექსის მეთოდები აქ აღარ არის. სამაგიეროდ, რიგში ჩაყენების და გამოყვანის მცირე ნაკრები გვაქვს:

| წევრი | აღწერა |
|---|---|
| `Enqueue(item)` | ამატებს ელემენტს რიგის ბოლოში |
| `Dequeue()` | იღებს და შლის ელემენტს რიგის თავიდან. ცარიელ რიგზე `InvalidOperationException` |
| `Peek()` | აბრუნებს თავში მდგომ ელემენტს წაშლის გარეშე |
| `Contains(item)`, `Count`, `Clear()` | შემოწმება, რაოდენობა, გასუფთავება |
| `CopyTo()`, `ToArray()` | კოპირება მასივში |
| `GetEnumerator()` | `Queue<T>.Enumerator`, თავიდან ბოლომდე |
| `TrimExcess()` | ტევადობის შემცირება, თუ 90%-ზე ნაკლებადაა შევსებული |

```csharp
var support = new Queue<Customer>(100);          // საწყისი ტევადობა
support.Enqueue(new Customer(99, "ნიკა"));
support.Enqueue(new Customer(77, "ანა"));
support.Enqueue(new Customer(55, "ლევანი"));

Customer next = support.Dequeue();               // ნიკა (პირველი შემოვიდა)
Console.WriteLine($"მომსახურება: {next}");

foreach (Customer c in support)
    Console.WriteLine($"რიგში: {c}");            // ანა, ლევანი

Customer peek = support.Peek();                  // ანა, რიგი არ იცვლება
support.Enqueue(new Customer(88, "ბესო"));       // ბოლოში: ანა, ლევანი, ბესო
```

ტიპური გამოყენება: დავალებების რიგი, შეტყობინებების ბუფერი, ხის სიგანეში გადავლა (BFS).

## `Stack<T>`

`Stack<T>` იგივე კატეგორიის კლასიკური სტრუქტურაა: **ბოლოს შემოსული, პირველი გამოდის (LIFO**, last-in-first-out). ყოველი ელემენტი სტეკზე „იდება" (push) და „იღება" (pop). თუ ეს კონცეფცია გესმით, `Stack<T>`-ის შესახებ ყველაფერი იცით.

| წევრი | აღწერა |
|---|---|
| `Push(item)` | ათავსებს ელემენტს სტეკის თავზე |
| `Pop()` | იღებს და შლის თავზე მდებარე ელემენტს. ცარიელზე `InvalidOperationException` |
| `Peek()` | აბრუნებს თავზე მდებარეს წაშლის გარეშე |
| `Contains(item)`, `Count`, `Clear()` | შემოწმება, რაოდენობა, გასუფთავება |
| `CopyTo()`, `ToArray()` | კოპირება მასივში (თავიდან ფსკერამდე) |
| `GetEnumerator()` | `Stack<T>.Enumerator` |
| `TrimExcess()` | ტევადობის შემცირება (90%-ის წესით) |

```csharp
var undo = new Stack<string>();
undo.Push("აკრიფა: გამარჯობა");
undo.Push("წაშალა: ა");
undo.Push("ჩასვა: სურათი");

Console.WriteLine(undo.Pop());    // ჩასვა: სურათი (ბოლო ქმედება)
Console.WriteLine(undo.Peek());   // წაშალა: ა
```

ტიპური გამოყენება: „გაუქმების" (undo) ისტორია, გამოსახულებების გარჩევა, ხის სიღრმეში გადავლა (DFS).

> [!TIP] `TryDequeue`, `TryPop`, `TryPeek`
> .NET Core 2.0-იდან `Queue<T>`-სა და `Stack<T>`-ს აქვს `TryDequeue(out T)`, `TryPop(out T)` და `TryPeek(out T)`, რომლებიც ცარიელ კოლექციაზე exception-ის ნაცვლად `false`-ს აბრუნებს. .NET 6-ში დაემატა `PriorityQueue<TElement, TPriority>`.

## `LinkedList<T>`

`LinkedList<T>` კომპიუტერული მეცნიერების „პირველი კურსის" ერთ-ერთი ძირითადი სტრუქტურაა, რომელიც ალბათ ოდესმე თავადაც დაგიწერიათ. ინდექსის ნაცვლად ყოველი ელემენტი **შემდეგ ელემენტზე რეფერენსს** ინახავს. ამიტომ ელემენტზე წვდომის ერთადერთი გზა ამ ბმულების გავლით გადაადგილებაა. რადგან სტრუქტურა რეფერენსების ჯაჭვია, ის ნებისმიერად იზრდება და მცირდება.

BCL-ის `LinkedList<T>` **ორმხრივად ბმული (doubly linked)** სიაა: ყოველ კვანძს წინა და შემდეგი კვანძის რეფერენსი აქვს, ამიტომ სიაზე ორივე მიმართულებით გადავლა შეიძლება.

კლასის მეთოდები კვანძების ბმულების იდეაზეა აგებული: ახალი კვანძი ემატება ან ჩაისმება **სხვა კვანძის მიმართ**:

| წევრი | აღწერა |
|---|---|
| `AddFirst(value)`, `AddLast(value)` | ამატებს სიის თავში ან ბოლოში, აბრუნებს ახალ კვანძს |
| `AddBefore(node, value)`, `AddAfter(node, value)` | ამატებს მოცემული კვანძის წინ ან შემდეგ |
| `First`, `Last` | პირველი და ბოლო **კვანძი** (`LinkedListNode<T>`) |
| `Find(value)`, `FindLast(value)` | პოულობს პირველ/ბოლო კვანძს ამ მნიშვნელობით, ან `null` |
| `Remove(value)`, `Remove(node)` | შლის მნიშვნელობით (`bool`) ან კვანძით |
| `RemoveFirst()`, `RemoveLast()` | შლის თავს ან ბოლოს |
| `Contains(value)`, `Count`, `Clear()` | შემოწმება, რაოდენობა, გასუფთავება |
| `CopyTo()`, `GetEnumerator()` | კოპირება, გადავლა |
| `GetObjectData()`, `OnDeserialization()` | სერიალიზაცია |

> [!WARNING] შენიშვნა წიგნის ცხრილზე
> წიგნის ცხრილში გვხვდება `AddHead`, `AddTail`, `RemoveHead`, `RemoveTail`, `Head` და `Tail`, ანუ .NET 2.0-ის ბეტა-ვერსიის სახელები. საბოლოო ვერსიაში დარჩა მხოლოდ `AddFirst`/`AddLast`, `RemoveFirst`/`RemoveLast` და `First`/`Last`. გარდა ამისა, `Find()` აბრუნებს `LinkedListNode<T>`-ს და არა `LinkedList<T>`-ს.

## `LinkedListNode<T>`

`LinkedListNode<T>` ბმული სიის კვანძის ტიპების მხრივ უსაფრთხო „გარსია". `LinkedList<T>`-ში ყველა ელემენტი შიგნით `LinkedListNode<T>`-ად არის წარმოდგენილი, და ბევრ მეთოდს ამ კვანძის მიმღები გადატვირთვაც აქვს.

| property | აღწერა |
|---|---|
| `List` | სია, რომელსაც კვანძი ეკუთვნის (ან `null`) |
| `Next` | შემდეგი კვანძი (ბოლოზე `null`) |
| `Previous` | წინა კვანძი (თავზე `null`) |
| `Value` | კვანძის მნიშვნელობა (`T`) |

```csharp
var route = new LinkedList<string>();
LinkedListNode<string> tbilisi = route.AddFirst("თბილისი");
route.AddLast("ბათუმი");
route.AddAfter(tbilisi, "ქუთაისი");          // თბილისი → ქუთაისი → ბათუმი

LinkedListNode<string> kutaisi = route.Find("ქუთაისი");
route.AddBefore(kutaisi, "გორი");              // თბილისი → გორი → ქუთაისი → ბათუმი

for (var node = route.Last; node != null; node = node.Previous)
    Console.Write(node.Value + " ← ");         // უკუღმა გადავლა
```

> [!NOTE] როდის ღირს `LinkedList<T>`
> `LinkedList<T>` ჩასმასა და წაშლას **O(1)**-ში აკეთებს, თუ კვანძი უკვე ხელთ გვაქვს. `List<T>`-ში შუაში ჩასმა O(n)-ია. მაგრამ `LinkedList<T>`-ს **ინდექსით წვდომა არ აქვს** (ელემენტის პოვნა O(n)-ია), ყოველ კვანძს დამატებითი მეხსიერება სჭირდება, და კვანძები მეხსიერებაში მიმოფანტულია, რაც პროცესორის ქეშისთვის ცუდია. პრაქტიკაში ის მხოლოდ მაშინ ღირს, როცა ხშირი ჩასმა/წაშლა სწორედ იმ კვანძებთან ხდება, რომლებზეც რეფერენსი უკვე გვაქვს (მაგალითად, LRU ქეში).

## `null` ელემენტები კოლექციებში

Generics-მდე BCL-ის კოლექციები ელემენტებს `object`-ად ინახავდა, ამიტომ `null`-ის შენახვა ყოველთვის შეიძლებოდა. Generics-ით კოლექციაში **value type-ების** შენახვაც შესაძლებელი გახდა, boxing-ის გარეშე, მაგრამ value type-ს `null` მნიშვნელობა არ აქვს.

| კოლექცია | `null` შეიძლება? |
|---|---|
| `List<string>`, `List<Customer>` | ✓ პირდაპირ |
| `List<int>` | ✗ |
| `List<int?>` | ✓ `Nullable<T>`-ით ([[თავი 4.6 default, Nullable და ტიპის ინფორმაცია|4.6]]) |
| `Dictionary`-ის გასაღები | ✗ არასოდეს |

ე.ი. value type-ების კოლექციაში `null` ქცევა `Nullable<T>`-ით მიიღწევა, და ეს boxing-ს არ იწვევს: `List<int?>` ელემენტებს `Nullable<int>` struct-ებად ინახავს.

## ტოლობის შემოწმების ხაფანგი

ბევრი კოლექციის მეთოდი (`Remove`, `Contains`, `IndexOf`) ობიექტს იღებს და კოლექციაში **ტოლ** ელემენტს ეძებს. თუ არ ვიცით, როგორ ხდება ეს შედარება, შედეგი შეიძლება მოულოდნელი იყოს: ობიექტები, რომლებიც, ჩვენი აზრით, უნდა დაემთხვეს, არ ემთხვევა. `Comparer`-ებსა და `IComparable`/`IEquatable`-ის სხვადასხვა იმპლემენტაციას შორის ბევრი მოულოდნელი გვერდითი ეფექტი შეიძლება წარმოიშვას. დეტალური ცხრილი [[თავი 8.2 Enumerator-ები და დელეგატები კოლექციებში|8.2-შია]].

## რა იქნება შემდეგ

ავტორის პროგნოზით, BCL-ის generic კლასები მხოლოდ „აისბერგის მწვერვალია": Microsoft ამ namespace-ს განავითარებს და საზოგადოების მოთხოვნილ ტიპებს დაამატებს. პარალელურად მესამე მხარის generic ბიბლიოთეკებიც ვითარდება, ბევრი მათგანი STL-ის მოყვარულებისგან, რომლებსაც საყვარელი ტიპების .NET-ში გადმოტანა სურთ. ერთ-ერთ მათგანს, **Power Collections**-ს, [[თავი 14.1 Power Collections-ის სრული სურათი|მე-14 თავში]] დეტალურად განვიხილავთ. ასეთი ბიბლიოთეკები ორ რამეს გვაძლევს: დამატებით generic ტიპებს და Generics-ის გამოყენების კიდევ ერთ კონკრეტულ მაგალითს.

პროგნოზი გამართლდა. შემდგომ ვერსიებში დაემატა:

| ვერსია | ახალი generic კოლექციები |
|---|---|
| .NET 3.5 | `HashSet<T>` |
| .NET 4.0 | `SortedSet<T>`, `ISet<T>`, `System.Collections.Concurrent` (`ConcurrentDictionary`, `ConcurrentQueue`, `BlockingCollection`) |
| .NET 4.5 | `IReadOnlyList<T>`, `IReadOnlyDictionary<TKey, TValue>`, `System.Collections.Immutable` (NuGet) |
| .NET 6 | `PriorityQueue<TElement, TPriority>` |
| .NET 8 | `FrozenDictionary<TKey, TValue>`, `FrozenSet<T>` |

## შეჯამება

ამ თავის მიზანი იყო BCL-ში დამატებული generic ტიპების დეტალური მიმოხილვა. დავიწყეთ ბიბლიოთეკის კლასების, ინტერფეისებისა და enumerator-ების ზოგადი სურათით, შემდეგ თითოეული კლასისთვის ვნახეთ მაგალითები და მისი წევრები. მექანიკის გარდა, ვცდილობდით გაგვერკვია, **როდის და როგორ** გამოვიყენოთ თითოეული ტიპი:

| ამოცანა | კლასი |
|---|---|
| ჩვეულებრივი სია, შიდა გამოყენება | `List<T>` |
| საჯარო API, გაფართოების შესაძლებლობით | `Collection<T>` |
| საჯარო API, მხოლოდ წასაკითხი | `ReadOnlyCollection<T>` |
| UI data binding | `BindingList<T>` |
| სწრაფი ძებნა გასაღებით | `Dictionary<TKey, TValue>` |
| გასაღები ელემენტშია, გაფართოებადი | `KeyedCollection<TKey, TItem>` |
| დალაგებული გასაღებები, ხშირი ცვლილებები | `SortedDictionary<TKey, TValue>` |
| დალაგებული + ინდექსით წვდომა | `SortedList<TKey, TValue>` |
| FIFO / LIFO | `Queue<T>` / `Stack<T>` |
| ხშირი ჩასმა/წაშლა ცნობილ კვანძთან | `LinkedList<T>` |
| შედარება და ტოლობა | `Comparer<T>`, `EqualityComparer<T>` |
