თუ `Collection<T>` საკუთარი კოლექციების გაფართოებად საბაზო კლასად შეიქმნა, **`List<T>`** კოლექციების მაქსიმალურად ოპტიმიზებული „სამუშაო ცხენია". ის თავიდანვე წარმადობის მაქსიმიზაციაზე ორიენტირებით აიგო. `List<T>` არაgeneric `ArrayList`-ის აშკარა მემკვიდრეა: შიგნით ის **მასივს** იყენებს, რომელიც საჭიროებისამებრ იზრდება.

## წევრები

| ჯგუფი | წევრები |
|---|---|
| ზომა | `Count`, `Capacity`, `TrimExcess()` |
| დამატება | `Add`, `AddRange`, `Insert`, `InsertRange`, `this[index]` |
| წაშლა | `Remove`, `RemoveAt`, `RemoveRange`, `RemoveAll(Predicate<T>)`, `Clear` |
| ძებნა (ტოლობით) | `Contains`, `IndexOf`, `LastIndexOf`, `BinarySearch` |
| ძებნა (პრედიკატით) | `Exists`, `Find`, `FindAll`, `FindIndex`, `FindLast`, `FindLastIndex`, `TrueForAll` |
| გარდაქმნა | `ConvertAll<TOutput>`, `CopyTo`, `ToArray`, `GetRange`, `AsReadOnly`, `ForEach(Action<T>)` |
| დალაგება | `Sort` (4 ვერსია), `Reverse` |

ეს ძალიან სრული კლასია, რომელიც სიის მართვის, დალაგებისა და ძებნის ფართო საშუალებებს იძლევა. ერთადერთი, რაც აკლია, **მოვლენების** მოდელია, რომელიც სიის ცვლილებისას შეტყობინებას გაგზავნიდა. ეს `BindingList<T>`-შია ([[თავი 8.3 Collection, KeyedCollection და ReadOnlyCollection|8.3]]).

## ზომას მნიშვნელობა აქვს

`List<T>` დინამიკური სიაა, მაგრამ მისი ზომის წინასწარ გამოყოფა შეიძლება **`Capacity`**-ით: property-ით ან კონსტრუქტორის პარამეტრით. თუ ვიცით, რომ სია დიდი იქნება, ეს ღირს.

`Capacity`-ის მითითების გარეშეც სიას შიდა ტევადობა აქვს. როცა ელემენტების რაოდენობა ტევადობას მიაღწევს, სია ახალ, **ორჯერ დიდ** მასივს ქმნის და ძველ ელემენტებს მასში აკოპირებს. `Count` ელემენტების რეალური რაოდენობაა, `Capacity` შიდა მასივის ზომა.

```csharp
int capacity = 2;
var list = new List<Customer>(capacity);

for (int i = 1; i <= 12; i++)
{
    list.Add(new Customer(i, "მომხმარებელი " + i));
    if (list.Capacity > capacity)
    {
        Console.WriteLine($"Count: {list.Count}, ძველი Capacity: {capacity}, ახალი: {list.Capacity}");
        capacity = list.Capacity;
    }
}

Console.WriteLine($"საბოლოო Count: {list.Count}, Capacity: {list.Capacity}");
list.TrimExcess();
Console.WriteLine($"TrimExcess-ის შემდეგ Capacity: {list.Capacity}");
```

> [!NOTE] `TrimExcess()`-ის ზღვარი
> `TrimExcess()` სიას მხოლოდ მაშინ ამცირებს, თუ ის **90%-ზე ნაკლებადაა** შევსებული. თითქმის სავსე სიის შემცირება კოპირების ფასს არ ამართლებს.

## დამატება და განახლება

`Collection<T>`-ისგან განსხვავებით, `List<T>`-ს **დიაპაზონების** (ranges) ჩასმის და დამატების მეთოდებიც აქვს. ასეთი „ჯგუფური" ოპერაციები კოლექციის მართვას ამარტივებს:

```csharp
var vip = new Collection<Customer>
{
    new Customer(99, "ნიკა"),
    new Customer(77, "ანა")
};

var newcomers = new List<Customer>
{
    new Customer(55, "ლევანი"),
    new Customer(44, "სოფო")
};

var master = new List<Customer>(vip);            // კონსტრუქტორი IEnumerable<T>-ს იღებს
master.AddRange(newcomers);                      // ბოლოში დიაპაზონის დამატება
master.Insert(2, new Customer(33, "თამარი"));    // ჩასმა 2-ე პოზიციაზე
master[3] = new Customer(88, "ბესო");            // მე-3 პოზიციის ჩანაცვლება
```

`Collection<T>`-იც და `List<T>`-იც `IEnumerable<T>`-ს ახორციელებს, ამიტომ ორივე შეიძლება გადაეცეს დიაპაზონის მიმღებ ნებისმიერ მეთოდს. `vip` კონსტრუქტორს გადაეცა, `newcomers` კი `AddRange()`-ს, რომელიც ელემენტებს ბოლოში ამატებს. `List<T>(IEnumerable<T>)` კონსტრუქტორი, `Collection<T>`-ისგან განსხვავებით, ელემენტებს **აკოპირებს** და გარსს არ ქმნის.

## წაშლა

ინდექსზე დაფუძნებული მეთოდების გარდა, `List<T>`-ს წაშლის უფრო რთული წესების მეთოდიც აქვს:

```csharp
var list = new List<Customer>
{
    new Customer(99, "ნიკა", "Platinum"),
    new Customer(77, "ანა", "Gold"),
    new Customer(55, "ლევანი", "Gold"),
    new Customer(44, "სოფო", "Standard"),
    new Customer(22, "ირაკლი", "Silver"),
    new Customer(88, "ბესო", "Platinum"),
    new Customer(11, "თამარი", "Standard")
};

list.RemoveAt(6);                 // ინდექსი 6: თამარი
list.RemoveRange(3, 2);           // ინდექსიდან 3 ორი ელემენტი: სოფო, ირაკლი
int removed = list.RemoveAll(c => c.Tier == "Gold");   // ანა, ლევანი; removed = 2

// დარჩა: ნიკა, ბესო
```

- **`RemoveAt()`** და **`RemoveRange()`** მარტივი, ინდექსზე დაფუძნებული ოპერაციებია. `RemoveRange(start, count)` მითითებული ინდექსიდან `count` ელემენტს შლის. არსებობს `Remove(item)`-იც, რომელიც ობიექტს ეძებს და შლის.
- **`RemoveAll()`** უფრო მოქნილია: ის **`Predicate<T>`** დელეგატს იღებს, ანუ ფილტრს, რომელიც ტიპების მხრივ უსაფრთხოდ აღწერს, რა უნდა წაიშალოს. დელეგატი თითოეულ ელემენტზე ერთხელ გამოიძახება, და თუ `true`-ს დააბრუნებს, ელემენტი წაიშლება. მეთოდი წაშლილი ელემენტების რაოდენობას აბრუნებს.

წიგნის C#-ის მაგალითი აქ **ანონიმურ მეთოდს** იყენებს, VB-ს კი (რომელსაც 2005 წელს ანონიმური მეთოდები არ ჰქონდა) ცალკე მეთოდის დაწერა სჭირდება. ავტორს C#-ის ვარიანტის წაკითხვადობა ურჩევნია. ზემოთ თანამედროვე ლამბდა-სინტაქსია.

`List<T>`-ის მეთოდებში generic დელეგატები სხვადასხვა როლში გამოიყენება: წაშლის, ძებნის და ელემენტებზე ოპერაციის კრიტერიუმად. ეს კარგი მაგალითია იმისა, როგორ შეიძლება Generics-ისა და დელეგატების კომბინაცია საკუთარ კლასებშიც.

> [!WARNING] `Capacity` წაშლისას არ მცირდება
> თუ სიაში 1000 ელემენტს დავამატებთ და 999-ს წავშლით, `Capacity` 1000-ის ფარგლებში დარჩება, თუმცა ერთადერთი ელემენტია. ეს პრობლემა არ არის, მაგრამ თუ სია დიდი ნაბიჯებით იზრდება და მცირდება, ღირს `TrimExcess()`-ის გამოძახება.

## ძებნა

ქვემოთ მოცემულ მაგალითებში `list` ისევ შვიდივე მომხმარებელს შეიცავს, ანუ წაშლამდე არსებულ მდგომარეობაშია.

`List<T>` ინდექსური კოლექციაა, მაგრამ შიგთავსში ძებნის მდიდარი საშუალებები აქვს. მათი უმეტესობა კრიტერიუმს დელეგატით იღებს. ეს მეთოდები ერთმანეთს ჰგავს და მხოლოდ დასაბრუნებელი ტიპით ან ძებნის არეალით განსხვავდება:

```csharp
int targetId = 22;

Customer c22 = list.Find(c => c.Id == targetId);                 // პირველი ნაპოვნი ან default
int idx22 = list.FindIndex(c => c.Id == targetId);               // ინდექსი ან -1
List<Customer> gold = list.FindAll(c => c.Tier == "Gold");       // ყველა ნაპოვნი (შეიძლება ცარიელი)
Customer lastPlat = list.FindLast(c => c.Tier == "Platinum");    // ბოლო ნაპოვნი
bool anyVip = list.Exists(c => c.Tier == "Platinum");            // არის თუ არა ერთი მაინც
bool allNamed = list.TrueForAll(c => c.Name.Length > 0);         // ყველა აკმაყოფილებს?

List<Customer> slice = list.GetRange(3, 3);                      // ინდექსიდან 3, სამი ელემენტი
```

| მეთოდი | აბრუნებს | თუ ვერ იპოვა |
|---|---|---|
| `Find` | პირველ ელემენტს | `default(T)` (კლასისთვის `null`) |
| `FindLast` | ბოლო ელემენტს | `default(T)` |
| `FindIndex` | პირველის ინდექსს | `-1` |
| `FindLastIndex` | ბოლოს ინდექსს | `-1` |
| `FindAll` | ახალ `List<T>`-ს | ცარიელ სიას |
| `Exists` | `bool` | `false` |

`FindIndex()`-ს სამი გადატვირთვა აქვს: მთელ სიაში, მითითებული ინდექსიდან და მითითებულ დიაპაზონში (საწყისი ინდექსი და რაოდენობა). `GetRange(index, count)` ელემენტების ქვესიმრავლეს აბრუნებს **ზედაპირული ასლის (shallow copy)** სახით.

> [!WARNING] `Find` და value type
> თუ `T` value type-ია, `Find` ვერნაპოვნის შემთხვევაში `default(T)`-ს აბრუნებს, მაგალითად `0`-ს. `List<int>`-ში `Find(x => x > 100)`-ის `0` შედეგი ვერ გვეტყვის, ელემენტი ვერ მოიძებნა თუ სიაში მართლა `0` არის. ასეთ დროს `FindIndex` ან `Exists` სჯობს.

## შიგთავსის გარდაქმნა

`List<T>`-ს შიგთავსის სხვა ფორმაში **კოპირების** და **გარდაქმნის** მეთოდები აქვს:

```csharp
List<string> labels = list.ConvertAll(c =>
{
    string stars = c.Tier == "Platinum" ? " ★★★★"
                 : c.Tier == "Gold"     ? " ★★★"
                 : " ★★";
    return c.Name + stars;
});
// ნიკა ★★★★, ანა ★★★, ლევანი ★★★, სოფო ★★, ...

string[] snapshot = new string[labels.Count];
labels.CopyTo(snapshot);

labels[0] = "შეცვლილი";
// labels:   შეცვლილი, ანა ★★★, ...
// snapshot: ნიკა ★★★★, ანა ★★★, ...   ← არ შეიცვალა

list.ForEach(c => c.Name = c.Name.ToUpper());   // ყოველ ელემენტზე მოქმედება
```

- **`ConvertAll()`** `Converter<T, TOutput>` დელეგატს იღებს: `T` სიის ტიპია, `TOutput` შედეგისა. აქ `Customer` `string`-ად გარდაიქმნება, და მიიღება ახალი `List<string>`.
- **`CopyTo()`** ელემენტებს მასივში აკოპირებს. ახალი მასივი დამოუკიდებელია: სიაში **ელემენტის ჩანაცვლება** მასივზე არ მოქმედებს.
- **`ForEach()`** `Action<T>` დელეგატს იღებს: ფუნქციას, რომელიც ელემენტს იღებს და არაფერს აბრუნებს, და მას ადგილზე ამუშავებს.

> [!WARNING] shallow და deep copy
> წიგნი ამბობს, რომ `CopyTo()` **ღრმა (deep)** ასლს ქმნის. ეს ზუსტი არ არის. `CopyTo()` ყოველთვის **ზედაპირულ (shallow)** ასლს აკეთებს: reference type-ის ელემენტებისთვის მასივში **იგივე ობიექტებზე რეფერენსები** კოპირდება.
>
> - სიაში ელემენტის **ჩანაცვლება** (`labels[0] = ...`) მასივზე არ მოქმედებს, რადგან მასივს საკუთარი სლოტები აქვს.
> - მაგრამ `Customer`-ების შემთხვევაში, თუ ობიექტს **შიგნიდან შევცვლით** (`list[0].Name = "x"`), ცვლილება მასივიდანაც ჩანს, რადგან ორივე ერთ ობიექტს მიუთითებს.
>
> წიგნის მაგალითში სტრიქონები უცვლელია (immutable), ამიტომ ეს განსხვავება არ ჩანს. ნამდვილი ღრმა ასლისთვის თითოეული ობიექტი ცალკე უნდა დაიკლონოს.

## დალაგება

`List<T>`-ს დალაგებისთვის ორი მეთოდი აქვს: **`Sort()`** რამდენიმე გადატვირთვით, და **`Reverse()`**, რომელიც თანმიმდევრობას აბრუნებს:

```csharp
list.Sort((a, b) => a.Id.CompareTo(b.Id));   // Id-ით, Comparison<T>
list.Reverse();                              // შებრუნება
```

`Sort()`-ის ოთხი ვერსია:

| ვერსია | როგორ ადარებს |
|---|---|
| `Sort()` | `Comparer<T>.Default`: ჯერ `IComparable<T>`, შემდეგ `IComparable`. თუ არცერთი არ აქვს, `InvalidOperationException` |
| `Sort(Comparison<T>)` | დელეგატით |
| `Sort(IComparer<T>)` | comparer ობიექტით |
| `Sort(index, count, IComparer<T>)` | მხოლოდ დიაპაზონს ალაგებს |

> [!NOTE] სტაბილურობა
> `List<T>.Sort()` **არასტაბილური** დალაგებაა (introsort): ტოლი ელემენტების საწყისი თანმიმდევრობა შეიძლება შეიცვალოს. თუ ეს მნიშვნელოვანია, LINQ-ის `OrderBy` გამოიყენეთ, რომელიც სტაბილურია.

> [!TIP] `BinarySearch`
> დალაგებულ სიაზე `BinarySearch(item)` ელემენტს O(log n) დროში პოულობს, `IndexOf`-ის O(n)-ის ნაცვლად. თუ ვერ იპოვა, **უარყოფით** რიცხვს აბრუნებს, რომლის ბიტური შებრუნება (`~result`) ის ინდექსია, სადაც ელემენტი უნდა ჩაისვას, რომ სია დალაგებული დარჩეს.
