Generics ერთი კლასის ფარგლებით არ შემოიფარგლება. ტიპის პარამეტრები მთელ იერარქიაში შეიძლება გავიდეს: generic კლასს შეუძლია generic ან ჩვეულებრივი კლასისგან მიიღოს მემკვიდრეობა, და პირიქით.

## ტიპის პარამეტრის გადაცემა საბაზო კლასისთვის

უმარტივესი შემთხვევა: ქვეკლასი თავის ტიპის პარამეტრს საბაზო კლასს „გადასცემს":

```csharp
public class Entity<TId>
{
    private readonly TId _id;

    public Entity() { }
    public Entity(TId id) => _id = id;

    public TId Id => _id;
}

public class AuditedEntity<TUser, TId> : Entity<TId>
{
    private readonly TUser _createdBy;

    public AuditedEntity() { }
    public AuditedEntity(TUser createdBy, TId id) : base(id)
        => _createdBy = createdBy;

    public TUser CreatedBy => _createdBy;
}
```

`Entity<TId>`-ს ერთი ტიპის პარამეტრი აქვს, `AuditedEntity<TUser, TId>`-ს ორი. მთავარი სინტაქსური დეტალი: ქვეკლასის ერთ-ერთი პარამეტრი (`TId`) საბაზო კლასის გამოცხადებაშიც გამოიყენება, `: Entity<TId>`. ასე `AuditedEntity<string, Guid>`-ის საბაზო კლასი `Entity<Guid>` იქნება.

## ტიპის არგუმენტის გადაცემა საბაზო კლასისთვის

საბაზო კლასს ტიპის პარამეტრის ნაცვლად **კონკრეტული ტიპიც** შეიძლება გადავცეთ:

```csharp
public class Entity<TId> { }

public class Product<TCategory> : Entity<int> { }
```

`Product<TCategory>`-ს ერთი ტიპის პარამეტრი აქვს, საბაზო კლასი კი ყოველთვის `Entity<int>`-ია. ე.ი. მემკვიდრეობა შეიძლება ღია ტიპისგანაც, დახურული აგებული ტიპისგანაც და შუალედური ვარიანტებისგანაც. generic კლასს, რა თქმა უნდა, ჩვეულებრივი, არაgeneric კლასისგანაც შეუძლია მემკვიდრეობის მიღება.

## რა არ მუშაობს

ჩვეულებრივი (არაgeneric) კლასი generic კლასისგან მემკვიდრეობას მხოლოდ **დახურული აგებული ტიპის** სახით მიიღებს:

```csharp
public class Entity<TId, TVersion> { }

public class Customer : Entity<TId, TVersion> { }     // შეცდომა
public class Supplier : Entity<int, long> { }         // სწორია
```

`Customer` ტიპის პარამეტრებს არ იღებს, ამიტომ კომპილატორმა არ იცის, რა არის `TId` და `TVersion`. მათი აღება არსაიდან შეიძლება. `Supplier`-იც არ იღებს ტიპის პარამეტრებს, მაგრამ კომპილირდება, რადგან მემკვიდრეობის გამოცხადებაში კონკრეტულ ტიპის არგუმენტებს იყენებს.

## აგებული ტიპი როგორც ტიპის არგუმენტი

ტიპის არგუმენტად სხვა აგებული ტიპიც შეიძლება გამოვიყენოთ, ტიპის პარამეტრებთან შერევითაც:

```csharp
public class Store<TItems, TIndex> { }

public class TagStore<T> : Store<List<T>, T> { }
public class TreeStore<T> : Store<List<T>, Dictionary<string, T>> { }
```

ეს უბრალოდ წინა მაგალითების ვარიაციაა. მთავარი ისაა, რომ აგებული ტიპი (`List<T>`) ნებისმიერი სხვა ტიპის არგუმენტივით აღვიქვათ.

## ტიპის პარამეტრისგან მემკვიდრეობა დაუშვებელია

generic კლასი საკუთარი ტიპის პარამეტრისგან მემკვიდრეობას ვერ მიიღებს:

```csharp
public class Decorated<T> : T { }   // შეცდომა
```

საბაზო კლასი უნდა იყოს არსებული, ღია ან დახურული ტიპი. როგორც [[თავი 3.1 Generics და Templates|მე-3 თავში]] ვნახეთ, ეს C++-ის templates-ის ის შესაძლებლობაა (mix-in), რომელიც .NET-ში არ არსებობს: CLR-მა ტიპის განლაგება (layout) და virtual მეთოდების ცხრილი წინასწარ უნდა იცოდეს.

## Protected წევრები

დახურული ტიპებისთვის protected წევრების წესები არ იცვლება. Generic კლასებში კი ერთი საინტერესო დეტალია:

```csharp
public class Entity<TId>
{
    protected TId _id;

    public Entity(TId id) => _id = id;
}

public class Document<TId, TBody> : Entity<TId>
{
    private readonly TBody _body;

    public Document(TId id, TBody body) : base(id) => _body = body;

    private void ReadOwn()
    {
        TId local = _id;             // ჩვეულებრივი წვდომა მემკვიდრეობით
    }

    private void ReadOthers()
    {
        var a = new Document<int, string>(1, "ხელშეკრულება");
        int idA = a._id;             // ესეც სწორია

        var b = new Document<Guid, byte[]>(Guid.NewGuid(), new byte[0]);
        Guid idB = b._id;            // და ესეც
    }
}
```

`ReadOwn()` მემკვიდრეობით მიღებულ protected ველს ჩვეულებრივ კითხულობს. `ReadOthers()` უფრო საინტერესოა: `Document<TId, TBody>`-ის შიგნით protected ველზე წვდომა შეიძლება **იმავე generic კლასის სხვა აგებული ტიპების** ეგზემპლარებითაც, მაგალითად `Document<int, string>`-ით ან `Document<Guid, byte[]>`-ით. C#-ის სპეციფიკაცია generic კლასის შიგნით protected წვდომას იმავე generic განსაზღვრებიდან აგებული ნებისმიერი ტიპის მეშვეობით უშვებს.

> [!NOTE] რატომ არის ეს მოულოდნელი?
> ჩვეულებრივ, protected ინსტანციის წევრზე წვდომა მხოლოდ მიმდინარე კლასის (ან მისი მემკვიდრის) ეგზემპლარით შეიძლება. `Document<int, string>` და `Document<Guid, byte[]>` გაშვების დროს სხვადასხვა ტიპია, მაგრამ ერთი generic განსაზღვრებიდან მომდინარეობს, ამიტომ კომპილატორი მათ protected წვდომის თვალსაზრისით „ერთი ოჯახის" წევრებად განიხილავს.
