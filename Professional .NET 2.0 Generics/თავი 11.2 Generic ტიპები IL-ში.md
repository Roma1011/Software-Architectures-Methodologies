.NET-ში Generics-ის იმპლემენტაციის გასაგებად ჯერ უნდა ვნახოთ, როგორ არის ის წარმოდგენილი **IL-ში** (Intermediate Language), რომელსაც CLR მართავს. IL-ში generic ტიპების წარმოდგენა განსაზღვრავს, როგორ გარდაიქმნება ეს IL საბოლოოდ შესრულებად კოდად. სწორედ მას ეფუძნება იმპლემენტაციის ბევრი წესი და ოპტიმიზაცია.

## Generic ტიპი თავისი generic ფორმით

რადგან ყოველი generic ტიპი **გამოცხადებისას** სრულად მოწმდება ([[თავი 11.1 CLR-ის მიზნები და პრინციპები|11.1]]), ის CLR-ში შეიძლება **პირდაპირ, თავისი generic ფორმით** იყოს წარმოდგენილი. .NET-ის generic კლასს წინასწარ არ სჭირდება იმის ცოდნა, რა ვერსიები შეიქმნება მისგან. ამიტომ generic ტიპებთან ჩვეულებრივი კლასებივით შეიძლება მოპყრობა: ეგზემპლარები საჭიროებისამებრ იქმნება.

გაშვების დროს generic ტიპების წარმოდგენა .NET-ის იმპლემენტაციის ერთ-ერთი მთავარი განმასხვავებელი თვისებაა. ავიღოთ მარტივი generic კლასი:

```csharp
public class Holder<T>
{
    private T _value;

    public Holder(T value) => _value = value;

    public T Get() => _value;
}
```

C#-ით იქნება დაწერილი თუ VB-ით, კომპილაციის შემდეგ ის IL-ში generic ფორმით წარმოდგება:

```
.class public auto ansi beforefieldinit Holder`1<T>
       extends [System.Runtime]System.Object
{
    .field private !T _value

    .method public hidebysig specialname rtspecialname
            instance void .ctor(!T 'value') cil managed
    {
        ldarg.0
        call     instance void [System.Runtime]System.Object::.ctor()
        ldarg.0
        ldarg.1
        stfld    !0 class Holder`1<!T>::_value
        ret
    }

    .method public hidebysig instance !T Get() cil managed
    {
        ldarg.0
        ldfld    !0 class Holder`1<!T>::_value
        ret
    }
}
```

კლასის generic მახასიათებლები IL-შიც გადადის. IL იმავე generic კონსტრუქციებს იყენებს, რაც .NET-ის ენებს დაემატა.

| IL-ის ელემენტი | მნიშვნელობა |
|---|---|
| ``Holder`1<T>`` | კლასის სახელი arity-ით და ტიპის პარამეტრის სახელით |
| `!0` ან `!T` | **კლასის** პირველი ტიპის პარამეტრი (ინდექსით ან სახელით) |
| `!!0` ან `!!T` | **მეთოდის** ტიპის პარამეტრი (ორი ძახილის ნიშანი) |
| ``class Holder`1<!T>`` | ღია აგებული ტიპი, რომელიც კლასის შიგნით ველზე მიმართვისას გამოიყენება |
| `ldelem.any`, `stelem.any`, `box !T`, `unbox.any !T` | ახალი ან გაფართოებული ინსტრუქციები, რომლებიც ნებისმიერ ტიპზე მუშაობს |
| `constrained. !T` | პრეფიქსი შეზღუდული ტიპის პარამეტრზე virtual გამოძახებისთვის ([[თავი 7.2 შეზღუდვების ტიპები|7.2]]) |

*ნახაზი 11.2: Generic ტიპის გზა წყაროდან მანქანურ კოდამდე.*

IL-ის ამ გაფართოებამ **გაშვების დროის generic ტიპები** შესაძლებელი გახადა. .NET Generics-ის ეს თვისება მისი ყველა ეფექტიანობისა და Just-In-Time მექანიზმის საფუძველია, და generic ტიპებს CLR-ში სრულფასოვან წევრებად აქცევს.

> [!TIP] ახლავე სცადეთ
> SharpLab.io-ზე ნებისმიერი generic კლასი ჩაწერეთ და შედეგის ფანჯარაში აირჩიეთ „IL". ასევე „JIT Asm" რეჟიმში ნახავთ, რა მანქანურ კოდს ქმნის JIT `Holder<int>`-ისთვის და `Holder<string>`-ისთვის. სწორედ ეს განსხვავება არის [[თავი 11.3 სპეციალიზაცია და გაზიარება|11.3-ის]] თემა.
