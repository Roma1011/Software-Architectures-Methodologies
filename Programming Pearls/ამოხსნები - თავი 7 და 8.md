**4.** კუმულატიური მასივი **Cum** ისე აინიციალიზეთ, რომ **Cum[I] = X[1] + ... + X[I]**.
- ქვევექტორ **X[L..U]**-ის ჯამი **ნულია**, თუ **Cum[L−1] = Cum[U]**.
- ამიტომ **ნულთან უახლოესი ჯამის** მქონე ქვევექტორი იპოვება **Cum-ში ორი უახლოესი ელემენტის** მოძებნით, რაც შეიძლება გაკეთდეს **O(N log N) დროში მასივის დალაგებით**.
- ეს შესრულების დრო **ოპტიმალურიდან მუდმივი კოეფიციენტის ფარგლებშია**, რადგან მისი ამოხსნის **ნებისმიერი ალგორითმი** შეიძლება გამოვიყენოთ **„ელემენტის უნიკალურობის"** (Element Uniqueness) ამოცანის ამოსახსნელად, ანუ იმის დასადგენად, **შეიცავს თუ არა მასივი განმეორებულ ელემენტებს** (**Dobkin**-მა და **Lipton**-მა აჩვენეს, რომ ამ ამოცანას **უარეს შემთხვევაში ამდენი დრო** სჭირდება **გადაწყვეტილების ხის გამოთვლით მოდელზე**).

**5.** **წრფივ ფასიან გზატკეცილზე** სადგურებს **I-სა და J-ს** შორის მთლიანი ფასი არის **Cum[J] − Cum[I−1]**, სადაც **Cum კუმულატიური მასივია**, როგორც ზემოთ.

**6.** ეს ამოხსნა **კიდევ ერთ კუმულატიურ მასივს** იყენებს. ციკლი

```
for I := L to U do
    X[I] := X[I]+V
```

**სიმულირდება** მინიჭებებით

```
Cum[U]   := Cum[U]+V
Cum[L-1] := Cum[L-1]-V
```

რომლებიც **სიმბოლურად** **V-ს X[1..U]-ს უმატებს** და შემდეგ **X[1..L−1]-ს აკლებს**. როცა **ყველა ასეთი ჯამი** აღებულია, მასივ **X**-ს ასე ვითვლით:

```
for I := N-1 downto 1 do
    X[I] := X[I+1]+Cum[I]
```

- ეს **N ჯამის** უარესი შემთხვევის დროს **O(N²)-დან O(N)-მდე** ამცირებს.
- ეს ამოცანა წარმოიშვა [[თავი 5.1 საქმის შესწავლა|5.1 ქვეთავში]] აღწერილი **Appel-ის N სხეულის პროგრამის სტატისტიკის შეგროვებისას**.
- ამ ამოხსნის ჩართვამ **სტატისტიკის ქვეპროგრამის** შესრულების დრო **ოთხი საათიდან ოც წუთამდე** შეამცირა; ეს აჩქარება **უმნიშვნელო** იქნებოდა, როცა პროგრამას **ერთი წელი** სჭირდებოდა, მაგრამ **მნიშვნელოვანი** იყო, როცა **სულ ერთი დღე** სჭირდებოდა.

**1.** **რვაბიტიანი ბაიტების** მქონე მანქანაზე **256-ბაიტიან ცხრილს** შეუძლია წარმოადგინოს სიმბოლოები **რვა (შესაძლოა გადაფარებულ) სიმბოლოების კლასში**. **J ბაიტის I-ური ბიტი** გვეუბნება, **არის თუ არა სიმბოლო J კლასში I**. კუთვნილების შემოწმება მოიცავს **მასივის ელემენტზე წვდომას**, **AND-ს ერთი ერთიანის შემცველ ბიტურ ნიმუშთან** და **შედეგის ნულთან შედარებას**.

**2.** მოცემული **N**-ისთვის (**ორის ხარისხი**) უნდა ავაინიციალიზოთ **C[0..N−1]** ისე, რომ **C[I]** იყოს **I-ის ორობით წარმოდგენაში ერთიანი ბიტების რაოდენობა**. ვიყენებთ ფაქტს: თუ **J < 2ᴷ**, მაშინ **C[J+2ᴷ] = C[J]+1**; ანუ **K-ური ბიტის ჩართვა რაოდენობას ერთს უმატებს**. ამ მიზეზით **მარჯვენა სვეტის ყოველი ელემენტი მარცხენა სვეტის შესაბამის ელემენტზე ზუსტად ერთით მეტია**.

```
C[0] = 0     C[8]  = 1
C[1] = 1     C[9]  = 2
C[2] = 1     C[10] = 2
C[3] = 2     C[11] = 3
C[4] = 1     C[12] = 2
C[5] = 2     C[13] = 3
C[6] = 2     C[14] = 3
C[7] = 3     C[15] = 4
```

ამიტომ ეს კოდი **ერთელემენტიანი ცხრილით** იწყება და მის ზომას **კოპირებითა და ერთის დამატებით განმეორებით აორმაგებს**; ის **O(N) დროში** მუშაობს.

```
C[0] := 0
P := 1
while M < N do
    /* Invariant: C[0..M-1] is correct */
    for J := 0 to P-1 do
        C[M+J] := C[J]+1
    P := P+P
```

*(კოდი წიგნის მიხედვითაა გადმოტანილი, ცვლადების სახელების ჩათვლით.)*

ამ ამოცანის *CACM*-ში გამოჩენის შემდეგ **Jim de Boer**-მა (Scarborough, Ontario) და **Rick Bonnett**-მა (Burlington, Vermont) **მსგავსი ერთციკლიანი ამოხსნები** იპოვეს. de Boer-ის კოდის **გასაღები** ის ფაქტია, რომ „**J-ის ზედა ერთიანი ბიტის მოცილებით მიღებული მთელი რიცხვი არის J−P**".

```
C[0] := 0
P := 1; PP := P+P
for J := 1 to N-1
    /* Invariant: P is a power of 2;
         PP = P+P; P <= J <= PP */
    if J = PP then
        P := PP; PP := P+P
    /* P is the greatest power of 2 <= J */
    C[J] := C[J-P]+1
```

კოდი **O(N) დროში** მუშაობს და **ნებისმიერი დადებითი მთელი N-ისთვის** სწორია.

**6.** „Programming Pearls" *CACM*-ის **1984 წლის სექტემბრის** ნომერში (გვ. 870–871) ესკიზურად აღწერს **R. G. Dromey**-ის მიერ პროგრამის გამოყვანას, რომელიც **მასივში მაქსიმალური ელემენტის** გამოსათვლელად **დარაჯებს** იყენებს. მიღებული კოდია:
