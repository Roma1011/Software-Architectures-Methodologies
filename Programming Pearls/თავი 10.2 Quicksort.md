## Quicksort: O(N log N) ალგორითმი

ეს ალგორითმი **C. A. R. Hoare**-მა აღწერა თავის კლასიკურ სტატიაში „Quicksort", *Computer Journal* 5, 1, 1962 წლის აპრილი, გვ. 10–15. ის [[თავი 7.3 დაყავი და იბატონე ალგორითმი|7.3 ქვეთავის]] ***„დაყავი და იბატონე"*** სქემას იყენებს: მასივის დასალაგებლად მას **ორ პატარა ნაწილად ვყოფთ** და მათ **რეკურსიულად ვალაგებთ**.

მაგალითად, რვაელემენტიანი მასივის დასალაგებლად

```
[55][41][59][26][53][58][97][93]
  ↑                           ↑
  1                           8
```

მას **პირველი ელემენტის (55) გარშემო *ვყოფთ*** (partition) ისე, რომ **55-ზე ნაკლები ყველა ელემენტი მის მარცხნივ** იყოს, **ყველა უფრო დიდი კი მარჯვნივ**:

```
[41][26][53][55][59][58][97][93]
    <55       ↑       >55
              4
```

თუ შემდეგ **1-დან 3-მდე** ქვემასივს და **5-დან 8-მდე** ქვემასივს **დამოუკიდებლად, რეკურსიულად** დავალაგებთ, **მთელი მასივი დალაგებული იქნება**.

ამ ალგორითმის **საშუალო** შესრულების დრო ჩასმით დალაგების **O(N²)** დროზე **გაცილებით ნაკლებია**, რადგან **დაყოფის ოპერაცია მიმდევრობის დალაგებისკენ დიდ გზას გადის**. N ელემენტის **ტიპური დაყოფის** შემდეგ დაყოფის მნიშვნელობის **ზემოთ დაახლოებით N/2** ელემენტია და **ქვემოთ N/2**. **მსგავს** შესრულების დროში ჩასმით დალაგების „ჩაცრის" ოპერაცია **მხოლოდ ერთი დამატებითი ელემენტის** სწორ ადგილზე მოთავსებას ახერხებს.

## რეკურსიული ქვეპროგრამის ესკიზი

ზემოთ მოცემული იდეა **რეკურსიული ქვეპროგრამის ესკიზამდე** მიდის. მასივის იმ ნაწილს, რომელთანაც ვმუშაობთ, **ორი ინდექსით L და U** წარმოვადგენთ, **ქვედა და ზედა** საზღვრებისთვის. რეკურსია **ჩერდება**, როცა **ორ ელემენტზე ნაკლები** მასივის მივდივართ. ასე რომ კოდია:

```
procedure QSort(L,U)
    if L >= U then
        /* at most one element, do nothing */
      else
        /* partition array around a given
           value, which is eventually
           placed in its correct position P
        */
        QSort(L, P-1)
        QSort(P+1, U)
```

## Lomuto-ს დაყოფის სქემა

მასივის **T მნიშვნელობის გარშემო** დასაყოფად გამოვიყენებთ **მარტივ სქემას**, რომელიც ავტორმა **Nico Lomuto**-სგან (Alsys, Inc.) ისწავლა. ამ საქმისთვის **უფრო სწრაფი პროგრამებიც** არსებობს¹, მაგრამ ეს ფუნქცია **ისე ადვილი გასაგებია**, რომ **ძნელია არასწორად დაწერა**, და **სულაც არ არის ნელი**.

მოცემული T მნიშვნელობისთვის უნდა **გადავაწყოთ X[A..B]** და გამოვთვალოთ ინდექსი **M** („middle"-ისთვის, შუა) ისე, რომ **T-ზე ნაკლები ყველა ელემენტი M-ის ერთ მხარეს** იყოს, **დანარჩენი ყველა კი მეორე მხარეს**. ამას **მარტივი `for` ციკლით** გავაკეთებთ, რომელიც მასივს **მარცხნიდან მარჯვნივ** სკანირებს და ცვლადებით **I** და **M** მასივ X-ში შემდეგ **ინვარიანტს** ინარჩუნებს:

```
┌──────────────┬───────────┬───────────┐
│      <T      │    ≥T     │     ?     │
└──────────────┴───────────┴───────────┘
↑              ↑           ↑           ↑
A              M           I           B
```

როცა კოდი **I-ურ ელემენტს** ამოწმებს, **ორი შემთხვევაა** განსახილველი.
- თუ **X[I] ≥ T**, ყველაფერი რიგზეა; ინვარიანტი **ისევ ჭეშმარიტია**.
- მეორე მხრივ, როცა **X[I] < T**, ინვარიანტს შეგვიძლია **აღვადგინოთ** **M-ის ერთით გაზრდით**, რომ პატარა ელემენტის **ახალ მდებარეობას** მიუთითოს, და შემდეგ ამ ელემენტის **X[I]-თან გაცვლით**.

სრული დაყოფის კოდია:

```
M := A-1
for I := A to B do
    if X[I] < T then
        M := M+1
        Swap(X[M], X[I])
```

> ¹ *ავტორის სქოლიო:* Quicksort-ის **წარმოდგენების უმეტესობა** იყენებს დაყოფის სქემას, რომელიც **ორ ერთმანეთისკენ მოძრავ ინდექსს** ეფუძნება, როგორიც [[თავი 10.4 ამოცანები|ამოცანა 3]]-შია აღწერილი. თუმცა იმ სქემის **ძირითადი იდეა მარტივია**, ავტორი მის დეტალებს **ყოველთვის რთულად** მიიჩნევდა: ერთხელ **ორი დღის უკეთესი ნაწილი** დახარჯა **მოკლე დაყოფის ციკლში დამალული ბაგის** დევნაზე. წინასწარი ვერსიის ერთმა მკითხველმა **იჩივლა**, რომ სტანდარტული **ორინდექსიანი** მეთოდი სინამდვილეში **Lomuto-ს მეთოდზე მარტივია**, და თავისი აზრის დასამტკიცებლად **კოდის ესკიზი** გააკეთა; ავტორმა **ძებნა შეწყვიტა მას შემდეგ, რაც ორი ბაგი იპოვა**.

## Quicksort-ში გამოყენება

Quicksort-ში მასივ **X[L..U]**-ს **T = X[L]** მნიშვნელობის გარშემო დავყოფთ, ასე რომ **A იქნება L+1** და **B იქნება U**. ამრიგად, დაყოფის ციკლის ინვარიანტი ასე გამოისახება:

```
┌───┬──────────┬──────────┬──────────┐
│ T │    <T    │    ≥T    │    ?     │
└───┴──────────┴──────────┴──────────┘
↑              ↑          ↑          ↑
L              M          I          U
```

როცა ციკლი **სრულდება**, გვაქვს:

```
┌───┬─────────────────────┬──────────┐
│ T │         <T          │    ≥T    │
└───┴─────────────────────┴──────────┘
↑                         ↑          ↑
L                         M          U
```

შემდეგ **X[L]-ს X[M]-თან ვცვლით** და ვიღებთ²:

```
┌─────────────────────┬───┬──────────┐
│         <T          │ T │    ≥T    │
└─────────────────────┴───┴──────────┘
↑                     ↑              ↑
L                     M              U
```

ახლა შეგვიძლია ფუნქცია **რეკურსიულად გამოვიძახოთ** პარამეტრებით **(L, M−1)** და **(M+1, U)**.

> ² *ავტორის სქოლიო:* **მაცდურია** ამ ნაბიჯის უგულებელყოფა და რეკურსიის გამოძახება პარამეტრებით **(L, M)** და **(M+1, U)**; ეს **უსასრულო ციკლს** იძლევა, როცა **T ქვემასივის მკაცრად უდიდესი ელემენტია**. ავტორი ამ ბაგს **დაიჭერდა**, დასრულების შემოწმება რომ ეცადა, მაგრამ **გამჭრიახი მკითხველი მიხვდება**, როგორ აღმოაჩინა ის სინამდვილეში. **Miriam Jacob**-მა **არასისწორის ელეგანტური დამტკიცება** იპოვა: რადგან **X[L] არასდროს გადაადგილდება**, დალაგებას მხოლოდ მაშინ შეუძლია მუშაობა, თუ მასივის **მინიმალური ელემენტი თავიდანვე X[1]-შია**.

## შემთხვევითი დაყოფის ელემენტი

ზემოთ მოცემული ალგორითმი **ყოველთვის მასივის პირველი ელემენტის გარშემო** ყოფს. ამ არჩევანმა ზოგი **გავრცელებული** შემავალი მონაცემისთვის შეიძლება **ზედმეტი დრო და მეხსიერება** მოითხოვოს, მაგალითად, **უკვე დალაგებული** მასივებისთვის.
- **გაცილებით უკეთესია** დაყოფის ელემენტის **შემთხვევით არჩევა**; ამას ვაკეთებთ **X[L]-ის X[L..U]-ის შემთხვევით ჩანაწერთან გაცვლით**.
- თუ ქვემოთ კოდში გამოყენებული **RandInt** ფუნქცია არ გაქვთ, შეგიძლიათ ის შექმნათ ფუნქციით **Rand**, რომელიც **[0,1)-ში თანაბრად განაწილებულ** შემთხვევით ნამდვილ რიცხვს აბრუნებს, გამოსახულებით **L + int(Rand × (U+1−L))**.
- **ნაკლებად სავარაუდო** შემთხვევაში, თუ თქვენს სისტემას **ეს ფუნქციაც კი არ აქვს**, ჩაიხედეთ Knuth-ის *Seminumerical Algorithms*-ში.
- მაგრამ **სისტემის ფუნქციას** იყენებთ თუ **საკუთარს** ქმნით, **ფრთხილად იყავით**, რომ **RandInt-მა L..U დიაპაზონის** მნიშვნელობა დააბრუნოს: **დიაპაზონს გარეთ მნიშვნელობა მზაკვრული ბაგია**.

## Quicksort 1

საბოლოო კოდი, **Quicksort 1**, ქვემოთაა. მასივ **X[1..N]**-ის დასალაგებლად ვიძახებთ პროცედურას

```
QSort(1,N)
```

```
procedure QSort(L,U)
    if L < U then
        Swap(X[L], X[RandInt(L,U)])
        T := X[L]
        M := L
        for I := L+1 to U do
            /* Invariant: X[L+1..M] < T and
                          X[M+1..I-1] >= T */
            if X[I] < T then
                M := M+1
                Swap(X[M], X[I])
        Swap(X[L], X[M])
        /* X[L..M-1] < X[M] <= X[M+1..U] */
        QSort(L, M-1)
        QSort(M+1, U)
```

## სისწორე და წარმადობა

ამ პროგრამის სისწორის დამტკიცების **უმეტესი ნაწილი მის გამოყვანაში** იყო მოცემული (რაც, რა თქმა უნდა, **მისი სათანადო ადგილია**). დამტკიცება **ინდუქციით** მიმდინარეობს:
- **გარე `if`** ბრძანება **ცარიელ და ერთელემენტიან** მასივებს სწორად ამუშავებს;
- **დაყოფის კოდი** დიდ მასივებს რეკურსიული გამოძახებებისთვის **სწორად ამზადებს**;
- პროგრამა **რეკურსიული გამოძახებების უსასრულო მიმდევრობას ვერ შექმნის**, რადგან **X[M] ელემენტი ყოველ გამოძახებაზე გამოირიცხება**; ეს **იგივე არგუმენტია**, რაც [[თავი 4.3 პროგრამის გაგება|4.3 ქვეთავმა]] ბინარული ძებნის დასრულების საჩვენებლად გამოიყენა.

ახლა **პროგრამის წარმადობას** მივხედოთ. ავტორი დეტალებს აქ არ იძლევა, მაგრამ Quicksort **საშუალოდ O(N log N) დროში და O(log N) სტეკის მეხსიერებაში** მუშაობს, **განსხვავებული ელემენტების მქონე ნებისმიერი** შემავალი მასივისთვის.
- მათემატიკური არგუმენტები [[თავი 7.3 დაყავი და იბატონე ალგორითმი|7.3 ქვეთავის]] არგუმენტების მსგავსია, და **ამოხსნა 10** ერთი რეალიზაციის მონაცემებს შეიცავს.
- **შემთხვევითი** წარმადობა **შემთხვევითი რიცხვების გენერატორის გამოძახების** შედეგია, და არა შემავალი მონაცემების განაწილებაზე **დაშვების**.
- **ამოცანები 3, 5 და 11** Quicksort-ის **უარესი შემთხვევის** წარმადობის გაუმჯობესების გზებს აჩვენებს.
- ალგორითმების **სახელმძღვანელოების უმეტესობა** Quicksort-ის შესრულების დროს **მათემატიკურად** აანალიზებს და ასევე ამტკიცებს **ქვედა საზღვარს**, რომ ნებისმიერ **შედარებაზე დაფუძნებულ** დალაგებას **O(N log N)** შედარება უნდა დასჭირდეს; ამიტომ Quicksort **ოპტიმალურთან ახლოსაა**.

## დახვეწა: Quicksort 2

**თავი 8**-ის თაყვანისმცემლებმა, ალბათ, **Quicksort-ის კოდის დასაჩქარებლად რამდენიმე გზა** შენიშნეს.
- **უმარტივესი** მითითებულია **ამოხსნა 8.10**-ში: **შიდა ციკლში Swap პროცედურის კოდი უნდა გავშალოთ** (რადგან **Swap-ის დანარჩენი ორი გამოძახება შიდა ციკლში არ არის**, მათ სტრიქონში ჩაწერას სიჩქარეზე **უმნიშვნელო გავლენა** ექნებოდა). ავტორის სისტემაზე ამან შესრულების დრო **წინანდელის ორ მესამედამდე** შეამცირა.
- ასევე შეგვიძლია შევნიშნოთ, რომ **ბევრი დრო იხარჯება ძალიან პატარა ქვემასივების დალაგებაზე**. მათი **ჩასმით დალაგების მსგავსი მარტივი მეთოდით** დალაგება **უფრო სწრაფი** იქნებოდა, **Quicksort-ის მთელი მექანიზმის ამუშავების** ნაცვლად.

**Bob Sedgewick**-მა ამ იდეის **განსაკუთრებით ჭკვიანური რეალიზაცია** შეიმუშავა. როცა Quicksort **პატარა ქვემასივზე** იძახება (ანუ როცა **U და L ახლოსაა**), **არაფერს ვაკეთებთ**. ამას Quicksort-ის პროცედურაში **პირველი `if` ბრძანების** შეცვლით ვახერხებთ:

```
if U-L > CutOff then
```

სადაც **CutOff პატარა მთელი რიცხვია**.
- როცა პროგრამა დასრულდება, მასივი **დალაგებული არ იქნება**, მაგრამ **შემთხვევითი რიგის მნიშვნელობების პატარა გროვებად** იქნება დაჯგუფებული ისე, რომ **ერთი გროვის ელემენტები მისგან მარჯვნივ მყოფი ნებისმიერი გროვის ელემენტებზე ნაკლებია**.
- გროვების **შიგნით დალაგება სხვა მეთოდით** უნდა გავაკეთოთ; რადგან მასივი **თითქმის დალაგებულია**, **ჩასმით დალაგება ზუსტად შესაფერისია**.

მთელ მასივს ვალაგებთ კოდით:

```
QSort(1,N)
InsertionSort
```

**CutOff-ის საუკეთესო არჩევანის** დასადგენად ავტორმა პროგრამა **ორჯერ** გაუშვა **CutOff-ის ყველა მნიშვნელობაზე 1-დან 50-მდე**, **N ფიქსირებული 5000**-ით.

*(წიგნის გრაფიკი: ჰორიზონტალურად CutOff-ის მნიშვნელობა 0-დან 50-მდე, ვერტიკალურად შესრულების დრო წამებში, დაახლოებით 2-დან 3-მდე. წერტილები CutOff = 1-ზე 3 წამთან ახლოსაა, 10–20 შუალედში ყველაზე დაბლა, დაახლოებით 2 წამზე ცოტა ქვემოთ ეშვება, შემდეგ ნელა ისევ იზრდება.)*

- CutOff-ის **კარგი მნიშვნელობა 15** იყო; **10-სა და 20-ს შორის** მნიშვნელობები ამ დანაზოგს **რამდენიმე პროცენტის სიზუსტით** იძლევა.
- ამ ცვლილებამ პროგრამა, რომელსაც **Quicksort 2**-ს ვუწოდებთ, **თავდაპირველი დროის ნახევრამდე** შეამცირა, ანუ **Swap პროცედურის სტრიქონში ჩაწერის შემდეგ კიდევ ოცდახუთი პროცენტით**.
