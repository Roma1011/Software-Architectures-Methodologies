## სქემა

ჩვენი **პირველი სუბკვადრატული** ალგორითმი **რთულია**; თუ მის დეტალებში ჩაიჭედებით, შემდეგ ქვეთავზე გადასვლით **ბევრს არ დაკარგავთ**. ის **„დაყავი და იბატონე"** (divide-and-conquer) სქემას ეფუძნება:

> ***N ზომის ამოცანის ამოსახსნელად, რეკურსიულად ამოხსენით ორი ქვეამოცანა, დაახლოებით N/2 ზომისა, და მათი ამოხსნები გააერთიანეთ, რომ სრული ამოცანის ამოხსნა მიიღოთ.***

ამ შემთხვევაში თავდაპირველი ამოცანა **N ზომის ვექტორს** ეხება, ასე რომ მისი ქვეამოცანებად დაყოფის **ყველაზე ბუნებრივი გზაა** **დაახლოებით ტოლი ზომის ორი ქვევექტორის** შექმნა, რომლებსაც **A** და **B** ვუწოდებთ.

```
┌──────────────────┬──────────────────┐
│        A         │        B         │
└──────────────────┴──────────────────┘
```

შემდეგ **რეკურსიულად** ვპოულობთ მაქსიმალურ ქვევექტორებს A-ში და B-ში, რომლებსაც **M_A** და **M_B** ვუწოდებთ.

```
┌──┬──────────┬────┬──────┬────┬──────┐
│  │   M_A    │    │      │M_B │      │
└──┴──────────┴────┴──────┴────┴──────┘
```

## მესამე შესაძლებლობა: საზღვრის გადამკვეთი

**მაცდურია** იმის ფიქრი, რომ ამოცანა ამოვხსენით, რადგან მთელი ვექტორის მაქსიმალური ჯამის ქვევექტორი **ან M_A უნდა იყოს, ან M_B**, და ეს **თითქმის სწორია**.

სინამდვილეში მაქსიმუმი **ან მთლიანად A-შია, ან მთლიანად B-ში, ან A-სა და B-ს შორის საზღვარს კვეთს**; ამ უკანასკნელს **M_C**-ს ვუწოდებთ, საზღვრის **გადამკვეთი** (crossing) მაქსიმუმისთვის.

```
┌───────────────┬───────────┬─────────┐
│               │    M_C    │         │
└───────────────┴───────────┴─────────┘
                ↑ საზღვარი გადის M_C-ის შიგნით
```

ამრიგად, ჩვენი „დაყავი და იბატონე" ალგორითმი **M_A**-სა და **M_B**-ს **რეკურსიულად** გამოთვლის, **M_C**-ს კი **სხვა საშუალებით**, და შემდეგ **სამიდან მაქსიმუმს** დააბრუნებს.

## დეტალები

ეს აღწერა კოდის დასაწერად **თითქმის საკმარისია**. დაგვრჩა მხოლოდ იმის გადაწყვეტა, **როგორ დავამუშაოთ პატარა ვექტორები** და **როგორ გამოვთვალოთ M_C**.

- **პირველი ადვილია:** **ერთელემენტიანი** ვექტორის მაქსიმუმი ვექტორის **ერთადერთი მნიშვნელობაა**, ან **ნული**, თუ ეს რიცხვი უარყოფითია; **ნულელემენტიანი** ვექტორის მაქსიმუმი კი ადრე **ნულად** განვსაზღვრეთ.
- **M_C-ის გამოსათვლელად** შევნიშნავთ, რომ მისი **A-ში მყოფი კომპონენტი** არის **უდიდესი ქვევექტორი, რომელიც საზღვარზე იწყება და A-ში ვრცელდება**, და ანალოგიურად მისი **B-ში მყოფი კომპონენტისთვის**.

ამ ფაქტების გაერთიანება ალგორითმ 3-ის შემდეგ კოდამდე მიგვიყვანს, რომელსაც თავდაპირველად ასე ვიძახებთ:

```
Answer := MaxSum(1,N)
```

```
recursive function MaxSum(L, U)
    if L > U then      /* Zero-element vector */
        return 0.0
    if L = U then      /* One-element vector */
        return max(0.0, X[L])

    M := (L+U)/2       /* A is X[L..M], B is X[M+1..U] */
    /* Find max crossing to left */
        Sum := 0.0; MaxToLeft := 0.0
        for I := M downto L do
            Sum := Sum + X[I]
            MaxToLeft := max(MaxToLeft, Sum)
    /* Find max crossing to right */
        Sum := 0.0; MaxToRight := 0.0
        for I := M+1 to U do
            Sum := Sum + X[I]
            MaxToRight := max(MaxToRight, Sum)
    MaxCrossing := MaxToLeft + MaxToRight

    MaxInA := MaxSum(L,M)
    MaxInB := MaxSum(M+1,U)
    return max(MaxCrossing, MaxInA, MaxInB)
```

## ანალიზი

კოდი **რთულია და ადვილად შეიძლება არასწორად დაიწეროს**, მაგრამ ამოცანას **O(N log N)** დროში ხსნის. ამ ფაქტის დამტკიცების **რამდენიმე გზა** არსებობს.

- **არაფორმალური არგუმენტი:** ალგორითმი რეკურსიის **O(log N) დონიდან თითოეულზე O(N)** სამუშაოს აკეთებს.
- არგუმენტი შეიძლება **უფრო ზუსტი** გახდეს **რეკურენტული თანაფარდობებით**. თუ **T(N)** N ზომის ამოცანის ამოხსნის დროს აღნიშნავს, მაშინ **T(1) = O(1)** და

```
T(N) = 2T(N/2) + O(N).
```
