## Bitmap წარმოდგენა

თუ ამოცანას ამ კუთხით შევხედავთ, სიმრავლის **bitmap** (იგივე **bit vector**) წარმოდგენა თავისთავად მოგვდის თავში.

ფაილს **27 000 ბიტისგან შემდგარი სტრიქონით** წარმოვადგენთ, რომელშიც **I-ური ბიტი ჩართულია მაშინ და მხოლოდ მაშინ, როცა რიცხვი I ფაილშია**.

პროგრამისტმა **11 000 თავისუფალი ბიტი** იპოვა. შემთხვევა, როცა 16 000 მკაცრი ზღვარია, [[თავი 1.6 ამოცანები|ამოცანა 1]]-შია განხილული.

ეს წარმოდგენა ამ ამოცანის **სამ თვისებას** იყენებს, რომლებიც დალაგების ამოცანებში ჩვეულებრივ არ გვხვდება:

1. შემავალი მონაცემები **პატარა დიაპაზონიდანაა**;
2. **დუბლიკატებს არ შეიცავს**;
3. ერთი მთელი რიცხვის გარდა, ჩანაწერთან **სხვა მონაცემი არ არის** დაკავშირებული.

## სამი ფაზა

როცა ფაილის რიცხვების სიმრავლე bitmap მონაცემთა სტრუქტურით არის წარმოდგენილი, პროგრამა **სამ ბუნებრივ ფაზად** იწერება:

1. **პირველი ფაზა** სიმრავლეს **ცარიელად აინიციალიზებს**: ყველა ბიტს გამორთავს.
2. **მეორე ფაზა** სიმრავლეს **აგებს**: ფაილიდან კითხულობს ყოველ რიცხვს და შესაბამის ბიტს რთავს.
3. **მესამე ფაზა** **დალაგებულ გამომავალ ფაილს** ქმნის: ამოწმებს ყოველ ბიტს და, თუ ბიტი 1-ია, შესაბამის რიცხვს წერს.

თუ **N** ვექტორში ბიტების რაოდენობაა (ამ შემთხვევაში 27 000), პროგრამა ფსევდოკოდით ასე გამოიხატება:

```
/* ფაზა 1: სიმრავლის ინიციალიზაცია ცარიელად */
for I := 1 to N do
    Bit[I] := 0

/* ფაზა 2: არსებული ელემენტების ჩასმა სიმრავლეში */
for each integer I in the input file
    Bit[I] := 1

/* ფაზა 3: დალაგებული შედეგის გამოტანა */
for I := 1 to N do
    if Bit[I] = 1 then
        write I on the output file
```

ეს ესკიზი პროგრამისტისთვის **საკმარისი აღმოჩნდა**, რომ თავისი პრობლემა გადაეჭრა. რეალიზაციის ზოგიერთი დეტალი, რომელსაც ის წააწყდა, აღწერილია [[თავი 1.6 ამოცანები|ამოცანებში]] 1, 2 და 6.
