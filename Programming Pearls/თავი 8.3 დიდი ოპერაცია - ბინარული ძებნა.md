## პირველი შემთხვევის ბინარული ძებნა (86-ე გვერდიდან)

*(85-ე გვერდზე დაწყებული აზრის გაგრძელება:)* ... თუ T მასივშია, მისი **პირველი შემთხვევა U პოზიციაზეა**; ეს ფაქტი უფრო ფორმალურად **`assert` კომენტარშია** ჩამოყალიბებული. ბოლო ორი ბრძანება **P-ს ანიჭებს X-ში T-ს პირველი შემთხვევის ინდექსს**, თუ ის არის, და **ნულს**, თუ არ არის. (ბოლო ბრძანებამ უნდა გამოიყენოს **„პირობითი or"**, რომელიც **მეორე პუნქტს არ ითვლის, თუ პირველი ჭეშმარიტია**; იხ. **ამოცანა 10.2**.)

მართალია, ეს ბინარული ძებნა **წინა პროგრამაზე უფრო რთულ ამოცანას** ხსნის, მაგრამ ის **პოტენციურად უფრო ეფექტურია**: ციკლის ყოველ იტერაციაზე **T-ს X-ის ელემენტთან მხოლოდ ერთ შედარებას** აკეთებს. წინა პროგრამას ზოგჯერ **ორი ასეთი შედეგის** შემოწმება უწევდა.

## დიაპაზონის ახალი წარმოდგენა

პროგრამის **შემდეგი ვერსია** დიაპაზონის **სხვა წარმოდგენას** იყენებს: **L..U**-ს მისი **ქვედა და ზედა მნიშვნელობებით** წარმოდგენის ნაცვლად, მას წარმოვადგენთ მისი **ქვედა მნიშვნელობით L** და **ნამატით I**, ისე რომ **L + I = U**.

- კოდი უზრუნველყოფს, რომ **I ყოველთვის ორის ხარისხი** იყოს; ეს თვისება **ადვილი შესანარჩუნებელია**, როცა ის **უკვე გვაქვს**, მაგრამ **თავდაპირველად მისი მიღება რთულია** (რადგან მასივის ზომაა **N = 1000**).
- ამიტომ პროგრამას წინ უძღვის **მინიჭება და `if` ბრძანება**, რომ საძებნი დიაპაზონი თავდაპირველად **512 ზომისა** იყოს, **1000-ზე ნაკლები ორის უდიდესი ხარისხი**; ამრიგად, **L და L+I** არის ან **0..512**, ან **489..1001**.

წინა პროგრამის დიაპაზონის ამ ახალ წარმოდგენაზე თარგმნა ამ კოდს იძლევა:

```
I := 512
if X[512] >= T then
    L := 0
  else
    L := 1000+1-512
while I ≠ 1 do
    /* Invariant: X[L] < T and X[L+I] >= T and I = 2**j */
    NextI := I div 2
    if X[L+NextI] < T then
        L := L + NextI; I := NextI
      else
        I := NextI
/* assert I = 1 and X[L] < T and X[L+I] >= T */
P := L+1
if P > 1000 or X[P] ≠ T then P := 0
```

ამ პროგრამის სისწორის დამტკიცებას **ზუსტად იგივე მსვლელობა** აქვს, რაც წინა პროგრამისას. ეს კოდი ჩვეულებრივ **წინამორბედზე ნელია**, მაგრამ **მომავალი აჩქარებებისთვის კარს აღებს**.

## გამარტივება

შემდეგი პროგრამა ზემოთ მოცემულის **გამარტივებაა** და შეიცავს ზოგიერთ ოპტიმიზაციას, რომელსაც **ჭკვიანი კომპილატორი** შეიძლება აკეთებდეს:
- **პირველი `if` ბრძანება** გამარტივებულია;
- ცვლადი **NextI** მოცილებულია;
- **NextI-ზე მინიჭებები** შიდა `if` ბრძანებიდან მოცილებულია.

```
I := 512; L := 0
if X[512] < T then L := 1000+1-512
while I ≠ 1 do
    /* Invariant: X[L] < T and X[L+I] >= T and I = 2**j */
    I := I div 2
    if X[L+I] < T then
        L := L+I
/* assert I = 1 and X[L] < T and X[L+I] >= T */
P := L+1
if P > 1000 or X[P] ≠ T then P := 0
```

მართალია, კოდის სისწორის არგუმენტს **ისევ იგივე სტრუქტურა** აქვს, მაგრამ მისი მოქმედება ახლა **უფრო ინტუიციურ დონეზე** შეგვიძლია გავიგოთ. როცა **პირველი შემოწმების პირობა მცდარია და L ნულად რჩება**, პროგრამა **P-ს ბიტებს მარცხნიდან მარჯვნივ** ითვლის, **უფროსი ბიტიდან** დაწყებული.

## საბოლოო ვერსია: ციკლის სრული გაშლა

კოდის საბოლოო ვერსია **გულსუსტებისთვის არ არის**. ის **ციკლის მართვის ხარჯს** და **I-ის ორზე გაყოფას** **მთელი ციკლის გაშლით** (unrolling) აშორებს. სხვა სიტყვებით, რადგან ამ კონკრეტულ ამოცანაში **I მხოლოდ რამდენიმე განსხვავებულ მნიშვნელობას** იღებს, შეგვიძლია ისინი **ყველა პირდაპირ პროგრამაში ჩავწეროთ** და ამით **შესრულებისას მათი ისევ და ისევ გამოთვლა** ავიცილოთ.

```
L := 0
if X[512]   < T then L := 1000+1-512
   /* assert X[L] < T and X[L+512] >= T */
if X[L+256] < T then L := L+256
   /* assert X[L] < T and X[L+256] >= T */
if X[L+128] < T then L := L+128
if X[L+64]  < T then L := L+64
if X[L+32]  < T then L := L+32
if X[L+16]  < T then L := L+16
if X[L+8]   < T then L := L+8
if X[L+4]   < T then L := L+4
if X[L+2]   < T then L := L+2
   /* assert X[L] < T and X[L+2]   >= T */
if X[L+1]   < T then L := L+1
   /* assert X[L] < T and X[L+1]   >= T */
P := L+1
if P > 1000 or X[P] ≠ T then P := 0
```

ამ კოდის გაგება შეგვიძლია **მტკიცებების სრული მიმდევრობის** ჩასმით, როგორიც **X[L+256]-ის შემოწმებას** ახლავს. როცა **ორშემთხვევიან ანალიზს** გააკეთებთ, რომ ნახოთ, როგორ იქცევა ეს `if` ბრძანება, **დანარჩენი ყველა `if` ბრძანება თავის ადგილზე დგება**.

## შეფასება

ეს გამოყვანა კოდის დახვეწის **იდეალიზებული აღწერაა, მის ყველაზე უკიდურეს ფორმაში**. **აშკარა** ბინარული ძებნის პროგრამა (რომელსაც, როგორც ჩანს, **ბევრი „ზედმეტი ცხიმი" არ აქვს**) შევცვალეთ **ზედმეტად გამხდარი** ვერსიით, რომელიც **რამდენჯერმე სწრაფია**.¹

ამ ამოცანაში **თავი 4**-ის პროგრამის ვერიფიკაციის ხელსაწყოებმა **გადამწყვეტი როლი** ითამაშა. რადგან ისინი გამოვიყენეთ, შეგვიძლია **გვჯეროდეს, რომ საბოლოო პროგრამა სწორია**; როცა ავტორმა საბოლოო კოდი პირველად ნახა (**ვერიფიკაციის გარეშე წარმოდგენილი**), ის მას **თვეების განმავლობაში მაგიად** მიიჩნევდა.
