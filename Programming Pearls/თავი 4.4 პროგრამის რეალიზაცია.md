## რეალურ ენაზე: BASIC

აქამდე პროგრამასთან **მაღალი დონის ფსევდოენაზე** ვმუშაობდით; შესაფერისი მართვის სტრუქტურების გამოყენების მზაობამ საშუალება მოგვცა, **კონკრეტული რეალიზაციის ენის დეტალები უგულებელვყოთ** და ამოცანის **არსზე** გავამახვილოთ ყურადღება. მაგრამ საბოლოოდ პროგრამა **რეალურ ენაზე** უნდა დავწეროთ.

რომ არ იფიქროთ, თითქოს ავტორმა ენა **ამოცანის გასაადვილებლად** აირჩია, მან ბინარული ძებნა **BASIC**-ზე დაწერა. მართალია, ეს ენა ზოგი ამოცანისთვის კარგია, მაგრამ მისი **მართვის სტრუქტურების სიმწირე** და **გლობალური (და, როგორც წესი, მოკლე) ცვლადების სახელები** რეალური პროგრამების აგებისთვის **არსებითი ბარიერებია**.

ამ პრობლემების მიუხედავადაც, ზემოთ მოცემული ფსევდოკოდი BASIC-ის დიალექტზე **ადვილად გამოიხატება**. სტრიქონები **1010–1045** ფუნქციის **ლაკონიურ სპეციფიკაციას** იძლევა.

```basic
1000 '
1010 ' BINARY SEARCH FOR T IN X(1..N)
1020 '   PRE:  X(1..N) IS SORTED IN NONDECREASING ORDER
1030 '   POST: P=0  =>  T IS NOT IN X(1..N)
1040 '         P>0  =>  P<N+1 AND X(P)=T
1045 '   SIDE EFFECTS: L, U AND M ARE ALTERED
1050 '
1060 L=1: U=N
1070 ' MAIN LOOP
1080     ' INVARIANT: IF T IS ANYWHERE IN THE ARRAY,
1090     '            THEN IT MUST BE IN X(L..U)
1100     IF L>U THEN P=0: RETURN
1110     M=CINT((L+U)/2)
1120     IF X(M)<T THEN L=M+1: GOTO 1070
1130     IF X(M)>T THEN U=M-1: GOTO 1070
1140     ' X(M)=T
1150                     P=M:   RETURN
```

*(კომენტარების შინაარსი: **PRE**, ანუ წინაპირობა: X(1..N) დალაგებულია არაკლებადი რიგით. **POST**, ანუ შემდგომი პირობა: P=0 ნიშნავს, რომ T არ არის X(1..N)-ში; P>0 ნიშნავს, რომ P<N+1 და X(P)=T. **გვერდითი ეფექტები**: L, U და M იცვლება. **ინვარიანტი**: თუ T სადმე არის მასივში, ის X(L..U)-ში უნდა იყოს.)*

## ტესტირება

რადგან ავტორმა ეს პროგრამა **ფრთხილად შემოწმებული ფსევდოკოდიდან** თარგმნა, მას ჰქონდა **კარგი საფუძველი** ეფიქრა, რომ ის სწორია. მაგრამ, სანამ მას აპლიკაციაში **გამოიყენებდა** (ან **გამოაქვეყნებდა**), **გატესტავდა**. ამიტომ დაწერა **მარტივი სატესტო პროგრამა**, **BASIC-ის დაახლოებით ოცდახუთი სტრიქონი**, შემდეგი სტრუქტურით:

```
declare X[0..11]
for I := 0 to 11 do X[I] := I
for N := 0 to 10 do
    print N
    for I := 1 to N do
        Assert(BSearch(I)    = I)
        Assert(BSearch(I-.5) = 0)
        Assert(BSearch(I+.5) = 0)
    Assert(BSearch(0)    = 0)
    Assert(BSearch(N+1)  = 0)
```

ფუნქცია **`Assert`** **არაფერს აკეთებს**, თუ მისი არგუმენტი ჭეშმარიტია, მაგრამ **ხმამაღლა ჩივის**, თუ მცდარია. პროგრამის **პირველმა ვერსიამ** ეს ტესტი **უპრობლემოდ** გაიარა.

### რას ამოწმებს ტესტი

ეს ტესტები პროგრამის **უმეტეს ნაწილს** „ჩხრეკს":
- ამოწმებს **ყველა შესაძლო პოზიციას** როგორც **წარმატებული**, ისე **წარუმატებელი** ძებნისთვის;
- ამოწმებს შემთხვევას, როცა ელემენტი **მასივშია, მაგრამ ძებნის საზღვრებს გარეთ**;
- **N-ის ნულიდან ათამდე** შემოწმება მოიცავს **ცარიელ მასივს**, ბაგებისთვის **გავრცელებულ ზომებს** (ერთი, ორი და სამი), **ორის რამდენიმე ხარისხს** და **ბევრ რიცხვს, რომელიც ორის ხარისხისგან ერთით განსხვავდება**.

ხელით ეს ტესტები **საშინლად მოსაწყენი** (და, შესაბამისად, ალბათ **შეცდომიანი**) იქნებოდა, მაგრამ მათ **უმნიშვნელო კომპიუტერული დრო** დასჭირდა.

### რატომ არის ავტორი დარწმუნებული

ბევრი ფაქტორი განაპირობებს ავტორის აზრს, რომ BASIC პროგრამა სწორია:
1. ფსევდოკოდის გამოსაყვანად **საღი პრინციპები** გამოიყენა;
2. მისი სისწორის „**ვერიფიკაციისთვის**" **ანალიტიკური ტექნიკები** გამოიყენა;
3. შემდეგ **კომპიუტერს მისცა ის საქმე, რაშიც ის კარგია**, და პროგრამა **სატესტო შემთხვევებით დაბომბა**.
