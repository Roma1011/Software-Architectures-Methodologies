## თავი 3: პროგრამები მონაცემთა სტრუქტურებზე (Data Structures Programs)

პროგრამისტების უმეტესობას უნახავს ისინი, და კარგი პროგრამისტების უმეტესობა აცნობიერებს, რომ **ერთი მაინც თავადაც დაუწერია**: **უზარმაზარი, არეული, მახინჯი პროგრამები**, რომლებიც **მოკლე, სუფთა, ლამაზი** პროგრამები უნდა ყოფილიყო.

ავტორმა ერთხელ ნახა COBOL პროგრამა, რომლის „შიგნეულობა" ასეთი იყო:

```
IF THISINPUT IS EQUAL TO 001 ADD 1 TO COUNT001.
IF THISINPUT IS EQUAL TO 002 ADD 1 TO COUNT002.
     ...
IF THISINPUT IS EQUAL TO 500 ADD 1 TO COUNT500.
```

პროგრამა სინამდვილეში ცოტა უფრო რთულ ამოცანას ასრულებდა, მაგრამ შეცდომაში არ შეგვიყვანს, თუ მას განვიხილავთ, როგორც პროგრამას, რომელიც **ითვლის, რამდენჯერ გვხვდება ფაილში ყოველი მთელი რიცხვი 1-დან 500-მდე**. ის **დაახლოებით 1600 სტრიქონ კოდს** შეიცავდა:

|სტრიქონები|დანიშნულება|
|---|---|
|500|ცვლადების `COUNT001`-დან `COUNT500`-მდე გამოცხადება|
|500|ზემოთ ნაჩვენები დათვლა|
|500|იმის დაბეჭდვა, რამდენჯერ იქნა ნაპოვნი თითოეული რიცხვი|
|100|სხვადასხვა ბრძანება|

იფიქრეთ ერთი წუთით, როგორ შეასრულებდით იმავე ამოცანას **ზომით მცირე ნაწილის** პროგრამით, **სხვა მონაცემთა სტრუქტურის** გამოყენებით: **500 ელემენტიანი მასივით**, რომელიც 500 ცალკეულ ცვლადს შეცვლის.

*(პროგრამისტებს, რომლებსაც კოდის სტრიქონზე უხდიან, შეიძლება ეს სავარჯიშო უგულებელყოფა მოუნდეთ; მენეჯერებს, რომლებიც სტრიქონზე იხდიან, შეიძლება გული წაუვიდეთ.)*

### სათაურის მნიშვნელობა

აქედან მოდის ამ თავის სათაური: **მონაცემებზე სწორი ხედვა მართლაც აყალიბებს (structures) პროგრამებს**.

ეს თავი აღწერს რამდენიმე **საშუალო ზომის პროგრამას**, რომლებიც **შიდა მონაცემების რესტრუქტურიზაციით** უფრო პატარა (და უკეთესი) გახდა. პროგრამები, როგორც წესი, **რამდენიმე ათასი სტრიქონიდან რამდენიმე ასეულამდე** შემცირდა.

პრინციპები **დიდ პროგრამულ სისტემებსაც** ეხება: ვნახავთ, როგორ დაეხმარა მონაცემთა სტრუქტურის სწორი დიზაინი ერთი სისტემის დამუშავების დროის შემცირებას **250 კაც-წლიდან 80 კაც-წლამდე**.

ყოველი ეთნიკური ჯგუფისთვის მამრობითი და მდედრობითი სქესის რაოდენობების ჯამი **ცოტა ნაკლებია ჯამზე**, რადგან ზოგმა ზოგ კითხვას არ უპასუხა.

### რეალური ამოცანა

რეალური გამომავალი მონაცემები უფრო რთული იყო:
- აქ ნაჩვენებია შვიდივე სტრიქონი და ჯამის სტრიქონი, მაგრამ მხოლოდ **ექვსი სვეტი**, რომლებიც ჯამებს და ორ სხვა კატეგორიას წარმოადგენს: **მოქალაქეობის სტატუსს და სქესს**;
- რეალურ ამოცანაში **ოცდახუთი სვეტი** იყო, რომლებიც **რვა კატეგორიას** წარმოადგენდა, და გამომავალი მონაცემების **სამი მსგავსი გვერდი**: თითო **ორი ცალკეული კამპუსისთვის** და ერთი **ორივეს ჯამისთვის**;
- უნდა დაბეჭდილიყო რამდენიმე სხვა, მჭიდროდ დაკავშირებული ცხრილიც, მაგალითად, **სტუდენტების რაოდენობა, რომლებმაც თითოეულ კითხვაზე პასუხი არ გასცეს**.

ყოველი კითხვარი **პერფობარათით** იყო წარმოდგენილი:
- **პირველი სვეტი** შეიცავდა ეთნიკურ ჯგუფს, დაშიფრულს მთელ რიცხვად **ერთიდან რვამდე** (შვიდი კატეგორიისთვის და „უარი");
- **მეორე სვეტი** შეიცავდა მოქალაქეობის სტატუსს;
- და ასე შემდეგ **მეცხრე სვეტამდე**.

### როგორ წერდა პროგრამისტი

პროგრამისტმა COBOL პროგრამა **სისტემური ანალიტიკოსის ბლოკ-სქემით** დაწერა. **ორი თვის** მუშაობის და **ათასი სტრიქონი კოდის** შექმნის შემდეგ მან შეაფასა, რომ **ნახევარი** ჰქონდა გაკეთებული.

ავტორს მისი გაჭირვება მაშინ გაუგო, როცა **ხუთგვერდიანი ბლოკ-სქემა** ნახა: პროგრამა **350 განსხვავებული ცვლადის** გარშემო იყო აგებული: **25 სვეტი × 7 სტრიქონი × 2 გვერდი**. ცვლადების გამოცხადების შემდეგ პროგრამა **ლოგიკის „ვირთხის ბუდისგან"** შედგებოდა, რომელიც წყვეტდა, **რომელი ცვლადები გაზრდილიყო** ყოველი შემავალი ჩანაწერის წაკითხვისას.

იფიქრეთ ერთი წუთით, როგორ დაწერდით ამ პროგრამას.

### სწორი გადაწყვეტა

**გადამწყვეტი გადაწყვეტილება** ისაა, რომ რიცხვები **მასივში** უნდა ინახებოდეს.

**შემდეგი გადაწყვეტილება უფრო რთულია:** მასივი განლაგდეს მისი **გამომავალი სტრუქტურის** მიხედვით (სამი განზომილებით: **კამპუსი, ეთნიკური ჯგუფი და ოცდახუთი სვეტი**), თუ **შემავალი სტრუქტურის** მიხედვით (ოთხი განზომილებით: **კამპუსი, ეთნიკური ჯგუფი, კატეგორია და მნიშვნელობა კატეგორიის შიგნით**)?

*(წიგნის ნახაზზე, კამპუსის განზომილების გარეშე, ორი მიდგომაა ნაჩვენები: მარცხნივ ერთი ბრტყელი ცხრილი, სადაც ყველა სვეტი გვერდიგვერდაა; მარჯვნივ ერთმანეთზე დაწყობილი, სხვადასხვა ზომის ცხრილები, თითო კატეგორიისთვის.)*

**ორივე მიდგომა მუშაობს.** ავტორის პროგრამაში **სამგანზომილებიანმა** ხედვამ მონაცემების **წაკითხვისას** ცოტა მეტი სამუშაო გამოიწვია და **ჩაწერისას** ცოტა ნაკლები. პროგრამას **150 სტრიქონი FORTRAN** დასჭირდა:

|სტრიქონები|დანიშნულება|
|---|---|
|80|ცხრილების აგება|
|30|აღწერილი გამომავალი მონაცემების შექმნა|
|40|სხვა ცხრილების შექმნა|

## რა საერთო აქვს ორ პროგრამას

დათვლის პროგრამა და გამოკითხვის პროგრამა **ორი ზედმეტად დიდი პროგრამა** იყო: ორივე შეიცავდა **უამრავ ცვლადს**, რომლებიც **ერთი მასივით** შეიცვალა.

- კოდის სიგრძის **რიგით შემცირებამ** მიგვიყვანა **სწორ პროგრამებამდე**, რომლებიც **სწრაფად დამუშავდა** და **ადვილად იტესტებოდა და ინახებოდა**.
- და თუმცა არცერთ აპლიკაციაში ამას დიდი მნიშვნელობა არ ჰქონდა, **ორივე პატარა პროგრამა შესრულების დროითაც და მეხსიერებითაც უფრო ეფექტური იყო**, ვიდრე დიდები.

### რატომ წერენ პროგრამისტები დიდ პროგრამებს

რატომ წერენ პროგრამისტები დიდ პროგრამებს, როცა პატარაც საკმარისია?

- **ერთი მიზეზი:** მათ აკლიათ ის **მნიშვნელოვანი სიზარმაცე**, რომელიც [[თავი 2.5 პრინციპები|2.5 ქვეთავში]] იყო ნახსენები: ისინი თავიანთი **პირველი იდეის** კოდად ქცევისკენ მიიჩქარიან.
- **უფრო ღრმა პრობლემა:** ორივე აღწერილ შემთხვევაში პროგრამისტები თავიანთ ამოცანებზე **COBOL-ის ტერმინებით ფიქრობდნენ**, და ბევრი COBOL პროგრამისტი მასივებს განიხილავს, როგორც **ფიქსირებულ ცხრილებს**, რომლებიც პროგრამის დასაწყისში ინიციალიზდება და **არასდროს იცვლება**.

### ავტორის საკუთარი შეცდომა

პროგრამისტები ამ შეცდომებს **ბევრი სხვა მიზეზითაც** უშვებენ. როცა ავტორი ამ თავის დასაწერად ემზადებოდა, **მსგავსი მაგალითი საკუთარ კოდში** იპოვა, გამოკითხვის პროგრამაში. მთავარ შემავალ ციკლს **ორმოცი სტრიქონი** ჰქონდა, **რვა ხუთბრძანებიან ბლოკად**, რომელთაგან პირველი ორი ასე შეიძლება გამოიხატოს:

```
if InputColumn(2) = Refused then
    add 1 to Declined(EthnicGroup, 1)
  else
    ThisIndex := 1 + InputColumn(2)
    add 1 to Count(Campus, EthnicGroup, ThisIndex)
if InputColumn(3) = Refused then
    add 1 to Declined(EthnicGroup, 2)
  else
    ThisIndex := 4 + InputColumn(3)
    add 1 to Count(Campus, EthnicGroup, ThisIndex)
```

ავტორს შეეძლო ეს ორმოცი სტრიქონი **ექვსით** შეეცვალა, მას შემდეგ რაც მასივ `Offset`-ს **1, 4, 6, ...** მნიშვნელობებით შეავსებდა:

```
for I := 1 to 8 do
    if InputColumn(I+1) = Refused then
        add 1 to Declined(EthnicGroup, I)
      else
        ThisIndex := Offset(I) + InputColumn(I+1)
        add 1 to Count(Campus, EthnicGroup, ThisIndex)
```

ავტორი იმდენად კმაყოფილი იყო კოდის სიგრძის **ერთი რიგით** შემცირებით, რომ **მეორე ასეთი შემცირება**, რომელიც პირდაპირ თვალწინ ჰქონდა, **გამორჩა**.
