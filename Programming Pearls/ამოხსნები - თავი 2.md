## ამოხსნები შერჩეულ ამოცანებზე: თავი 2

*(ამოცანების პირობები: [[თავი 2.1 სამი ამოცანა]] და [[თავი 2.6 ამოცანები]])*

**A.** სასარგებლოა ეს ბინარული ძებნა განვიხილოთ **ოცი ბიტის** ტერმინებით, რომლებიც ყოველ რიცხვს წარმოადგენს. ალგორითმის **პირველ გავლაზე** ვკითხულობთ (მაქსიმუმ) **მილიონ შემავალ რიცხვს** და **წამყვანი ნულოვანი ბიტის** მქონეებს **ერთ ლენტზე** ვწერთ, **წამყვანი ერთიანი ბიტის** მქონეებს კი **მეორეზე**.

```
                         ┌──► (Zero Bits)
(Current Input) ──► [One Probe]
                         └──► (One Bits)
```

- ამ ორი ლენტიდან **ერთი მაქსიმუმ 500 000 რიცხვს** შეიცავს, ამიტომ შემდეგ **ამ ლენტს ვიყენებთ მიმდინარე შემავლად** და შემოწმების პროცესს **ვიმეორებთ**, მაგრამ **ამჯერად მეორე ბიტზე**.
- თუ თავდაპირველი შემავალი ლენტი **N ელემენტს** შეიცავს, **პირველი გავლა N** რიცხვს წაიკითხავს, **მეორე მაქსიმუმ N/2**-ს, **მესამე მაქსიმუმ N/4**-ს, და ასე შემდეგ, ამიტომ **მთლიანი შესრულების დრო N-ის პროპორციულია**.
- დაკარგული რიცხვის პოვნა შეიძლებოდა **ლენტზე დალაგებით და შემდეგ სკანირებით**, მაგრამ ამას **N log N-ის პროპორციული** დრო დასჭირდებოდა.
- ეს ამოცანა და ამოხსნა **Ed Reingold**-ს (University of Illinois) ეკუთვნის.

**B.** იხილეთ [[თავი 2.3 პრიმიტივების ძალა|2.3 ქვეთავი]].

**C.** იხილეთ [[თავი 2.4 ყველაფრის გაერთიანება - დალაგება|2.4 ქვეთავი]].

**1.** მოცემული სიტყვის ყველა ანაგრამის საპოვნელად **ჯერ მის ხელმოწერას ვითვლით**.
- თუ **წინასწარი დამუშავება დაუშვებელია**, **მთელი ლექსიკონი მიმდევრობით** უნდა წავიკითხოთ, **ყოველი სიტყვის ხელმოწერა** გამოვთვალოთ და **ორი ხელმოწერა შევადაროთ**; **მთვლელების მასივი**, ალბათ, **კარგი ხელმოწერის სქემაა**.
- **წინასწარი დამუშავებით** **ბინარულ ძებნას** ვაკეთებთ **წინასწარ გამოთვლილ ფაილში**, რომელიც **(ხელმოწერა, სიტყვა) წყვილებს ხელმოწერით დალაგებულს** შეიცავს.

**2.** ბინარული ძებნა **მინიმუმ ორჯერ გამოჩენილ ელემენტს** პოულობს **ქვეინტერვალის რეკურსიული ძებნით**, რომელიც **რიცხვების ნახევარზე მეტს** შეიცავს.
- ავტორის **თავდაპირველი ამოხსნა გარანტიას არ იძლეოდა**, რომ **რიცხვების რაოდენობა ყოველ იტერაციაზე ნახევრდება**, ამიტომ მისი **log₂ N გავლის უარესი შემთხვევის** შესრულების დრო **N log N-ის პროპორციული** იყო.
- **Jim Saxe**-მა (Carnegie-Mellon University) ეს **წრფივ დრომდე** შეამცირა: მან შენიშნა, რომ ძებნას შეუძლია **ზედმეტად ბევრი დუბლიკატის თან ტარება** თავიდან აიცილოს. როცა მისმა ძებნამ იცის, რომ დუბლიკატი **M რიცხვის მიმდინარე დიაპაზონში** უნდა იყოს, ის თავის მიმდინარე სამუშაო ლენტზე **მხოლოდ M+1 რიცხვს** შეინახავს; **დანარჩენ რიცხვებს**, რომლებიც ლენტზე მოხვდებოდა, მისი პროგრამა **უბრალოდ აგდებს**.
- მართალია, მისი მეთოდი **შემავალ ცვლადებს ხშირად უგულებელყოფს**, მაგრამ მისი სტრატეგია **საკმარისად კონსერვატიულია**, რომ უზრუნველყოს **მინიმუმ ერთი დუბლიკატის** პოვნა.

**3.** ეს **„ჟონგლიორობის"** კოდი **X[1..N]**-ს **RotDist-ით მარცხნივ** აბრუნებს.

```
for I := 1 to GCD(RotDist,N) do
    /* Move I-th values of blocks */
    This := I
    Temp := X[This]
    Next := This + RotDist
    if Next > N then Next := Next-N
    while Next ≠ I do
        X[This] := X[Next]
        This := Next
        Next := Next + RotDist
        if Next > N then Next := Next-N
    X[This] := Temp
```

**I-სა და N-ის უდიდესი საერთო გამყოფი** არის **გადასანაცვლებელი ციკლების რაოდენობა** (თანამედროვე ალგებრის ტერმინებით, ეს არის **მობრუნების მიერ ინდუცირებული გადანაცვლებების ჯგუფის მოსაზღვრე კლასების (cosets) რაოდენობა**).

შემდეგი პროგრამა **Gries-ის *Science of Programming*-ის 18.1 ქვეთავიდანაა**; ის ვარაუდობს, რომ ქვეპროგრამა **Swap(A,B,L)** **X[A..A+L−1]**-ს **X[B..B+L−1]**-თან ცვლის.

```
P := RotDist+1
I := RotDist; J := N-RotDist
while I ≠ J do
    /* Invariant:
        X[1    ..P-I-1] is in final position
        X[P-I..P-1    ] = A is to be swapped with B
        X[P   ..P+J-1 ] = B is to be swapped with A
        X[P+J..N      ] is in final position
    */
    if I > J then
        Swap(P-I, P, J);      I := I-J
      else
        Swap(P-I, P+J-I, I);  J := J-I
Swap(P-I, P, I)
```

ციკლის ინვარიანტები **თავი 4**-შია აღწერილი. კოდი **იზომორფულია** I-სა და J-ს უდიდესი საერთო გამყოფის გამოსათვლელი (**ნელი, მაგრამ სწორი**) **ადიტიური ევკლიდეს ალგორითმისა**:

```
function GCD(I,J)
    while I ≠ J
        if I > J then
            I := I-J
          else
            J := J-I
    return I
```

**Gries** და **Mills** **სამივე** მობრუნების ალგორითმს შეისწავლიან სტატიაში „**Swapping Sections**", Cornell University Computer Science Technical Report 81-452.

**4.** მართალია, ჟონგლიორობის კოდი **კრიტიკული ოპერაციების მხოლოდ ნახევარს** აკეთებდა, მაგრამ მისი **რეალიზაციის ხარჯი ორჯერ მეტი** იყო, ვიდრე **უფრო მარტივი შებრუნების** ალგორითმისა.
- N-ის **კრიტიკულ მნიშვნელობაზე** მანქანას **რეალური მეხსიერება ამოეწურა** და **დისკზე გვერდების ჩანაცვლება** მოუწია.
- **შებრუნების** ალგორითმი **გვერდების ჩანაცვლებისთვის კარგად არის მორგებული**: შებრუნების ოპერაციის **ლოკალურობის** გამო ის **ყოველ დისკურ გვერდს ორჯერ** წაიკითხავს.
- მეორე მხრივ, **ჟონგლიორობის** ალგორითმი გვერდების ჩანაცვლებისთვის **ზუსტად „პესიმალურია"**: ის დისკიდან გვერდს კითხულობს, გვერდზე **ერთ ელემენტზე** მუშაობს და გვერდს **მხოლოდ მას შემდეგ უბრუნდება, რაც ყველა სხვა გვერდს მიმართავს**.

**6.** სახელის **ხელმოწერა მისი ღილაკების კოდირებაა**, ასე რომ `LESK*M*`-ის ხელმოწერაა `5375*6*`.
- ცნობარში **ცრუ დამთხვევების** საპოვნელად ყოველ სახელს **ღილაკების კოდირებით „ვაწერთ ხელს"**, **ხელმოწერით ვალაგებთ** (და **ტოლი ხელმოწერების შიგნით სახელით**), შემდეგ კი დალაგებულ ფაილს **მიმდევრობით ვკითხულობთ**, რომ **განსხვავებული სახელების მქონე ტოლი ხელმოწერები** ვაჩვენოთ.
- სახელის **ღილაკების კოდის** მიხედვით მოსაძებნად ვიყენებთ **შუალედურ ფაილს**, რომელიც **ხელმოწერებსა და სხვა მონაცემებს** შეიცავს. მართალია, შეგვეძლო ეს ფაილი დაგველაგებინა და შემდეგ ღილაკების კოდი **ბინარული ძებნით** მოგვეძებნა, მაგრამ **რეალურ სისტემაში**, ალბათ, **ჰეშირებას ან დისკური ფაილების პაკეტს** გამოვიყენებდით.

**7.** **სტრიქონებით ჩაწერილი** მატრიცის ტრანსპონირებისთვის Vyssotsky-მ ყოველ ჩანაწერს **სვეტისა და სტრიქონის ნომერი წინ დაურთო**, **სისტემის ლენტის დალაგება** გამოიძახა **ჯერ სვეტით, შემდეგ სტრიქონით** დასალაგებლად, და შემდეგ **სვეტისა და სტრიქონის ნომრები მესამე პროგრამით მოაშორა**.

**8.** ამ ამოცანის **„აჰა!" მიგნება** ისაა, რომ **რომელიმე K-ელემენტიანი ქვესიმრავლის ჯამი მაქსიმუმ T-ა მაშინ და მხოლოდ მაშინ**, როცა **K უმცირესი ელემენტისგან შემდგარი ქვესიმრავლისა**.
- ეს ქვესიმრავლე შეიძლება ვიპოვოთ **N log N-ის პროპორციულ** დროში **თავდაპირველი სიმრავლის დალაგებით**, ან **N-ის პროპორციულ** დროში **არჩევის ალგორითმით** (იხ. **ამოხსნა 10.9**).
- როცა Ullman-მა ეს **საკლასო სავარჯიშოდ** მისცა, სტუდენტებმა დააპროექტეს ალგორითმები **ზემოთ ნახსენები ორივე შესრულების დროით**, ასევე **O(N log K)**, **O(NK)**, **O(N²)** და **O(Nᴷ)**-ით. **შეგიძლიათ იპოვოთ ბუნებრივი ალგორითმები** ამ შესრულების დროებისთვის?

**10.** Edison-მა გარსი **წყლით აავსო** და **გრადუირებულ ცილინდრში** ჩაცალა. (როგორც მინიშნებამ შეიძლება შეგახსენათ, **არქიმედესაც წყლით** გამოუთვლია მოცულობები; მის დროს **„აჰა!" მიგნებებს** **„ევრიკა!"-ს ყვირილით** აღნიშნავდნენ.)

შეგიძლიათ გამოთვალოთ **ორგანზომილებიანი ობიექტის სიმძიმის ცენტრი** (სცადეთ **მყარ წიგნზე**) **ცერის, საჩვენებელი და შუა თითების საყრდენ სამფეხად** გამოყენებით. როცა სამფეხს **შეკრავთ**, ცენტრიდან **ყველაზე შორს მყოფი თითი ყველაზე ნაკლებ წონას** დაიჭერს, **ყველაზე ნაკლები ხახუნი** ექნება და **ყველაზე სავარაუდოდ გადაადგილდება**; ამიტომ სამფეხი **სიმძიმის ცენტრზე შეიკვრება**. **Kee Dewdney** **ანალოგური გამოთვლის მოწყობილობებს** განიხილავს თავის რუბრიკებში „**Computer Recreations**", *Scientific American*-ის **1984 და 1985 წლების ივნისის** ნომრებში.
