## ორი „აშკარა" გზა

პროგრამისტების უმეტესობას ალგორითმ 1-ზე **ერთნაირი რეაქცია** აქვს: „**მისი ბევრად დაჩქარების აშკარა გზა არსებობს**". მაგრამ **ორი აშკარა გზა** არსებობს, და თუ ერთი მოცემული პროგრამისტისთვის აშკარაა, **მეორე ხშირად არ არის**.

- ორივე ალგორითმი **კვადრატულია**: N ზომის შემავალ მონაცემზე **O(N²)** ნაბიჯს დგამს;
- ორივე ამ დროს აღწევს იმით, რომ **X[L..U]-ის ჯამს მუდმივი რაოდენობის ნაბიჯებში** ითვლის, ალგორითმ 1-ის **U−L+1** ნაბიჯის ნაცვლად;
- მაგრამ ორი კვადრატული ალგორითმი ჯამის მუდმივ დროში გამოსათვლელად **ძალიან განსხვავებულ მეთოდებს** იყენებს.

## ალგორითმი 2: წინა ჯამის გამოყენება

**პირველი** კვადრატული ალგორითმი ჯამს **სწრაფად** ითვლის, რადგან შენიშნავს, რომ **X[L..U]-ის ჯამი მჭიდროდაა დაკავშირებული** ადრე გამოთვლილ ჯამთან, **X[L..U−1]-ის** ჯამთან. ამ კავშირის გამოყენება **ალგორითმ 2-მდე** მიგვიყვანს.

```
MaxSoFar := 0.0
for L := 1 to N do
    Sum := 0.0
    for U := L to N do
        Sum := Sum + X[U]
        /* Sum now contains the sum of X[L..U] */
        MaxSoFar := max(MaxSoFar, Sum)
```

**პირველი ციკლის** შიგნით ბრძანებები **N-ჯერ** სრულდება, **მეორე ციკლის** შიგნით კი გარე ციკლის ყოველ შესრულებაზე **მაქსიმუმ N-ჯერ**, ასე რომ მთლიანი შესრულების დრო **O(N²)**-ია.

## ალგორითმი 2b: კუმულატიური მასივი

**ალტერნატიული** კვადრატული ალგორითმი შიდა ციკლში ჯამს ითვლის **მონაცემთა სტრუქტურაზე მიმართვით**, რომელიც **გარე ციკლის შესრულებამდე** აიგება.

- **CumArray**-ს **I-ური ელემენტი** შეიცავს **X[1..I]-ის მნიშვნელობების კუმულატიურ ჯამს**;
- ამიტომ **X[L..U]-ის მნიშვნელობების ჯამი** შეიძლება ვიპოვოთ **CumArray[U] − CumArray[L−1]**-ის გამოთვლით.

ეს ალგორითმ **2b**-სთვის შემდეგ კოდს იძლევა:

```
CumArray[0] := 0.0
for I := 1 to N do
    CumArray[I] := CumArray[I-1] + X[I]
MaxSoFar := 0.0
for L := 1 to N do
    for U := L to N do
        Sum := CumArray[U] - CumArray[L-1]
        /* Sum now contains the sum of X[L..U] */
        MaxSoFar := max(MaxSoFar, Sum)
```

ეს კოდი **O(N²)** დროს ხარჯავს; ანალიზი **ზუსტად ისეთივეა**, როგორც ალგორითმ 2-ისა.

## კვადრატული ბარიერი

აქამდე ნანახი ალგორითმები ქვევექტორების **საწყისი და საბოლოო მნიშვნელობების ყველა შესაძლო წყვილს** ამოწმებს და ამ ქვევექტორში რიცხვების ჯამს განიხილავს. რადგან **O(N²) ქვევექტორი** არსებობს, ნებისმიერ ალგორითმს, რომელიც **ყველა ასეთ მნიშვნელობას** ამოწმებს, **მინიმუმ კვადრატული დრო** სჭირდება.

შეგიძლიათ მოიფიქროთ გზა, რომ ამ პრობლემას **გვერდი აუაროთ** და მიიღოთ ალგორითმი, რომელიც **ნაკლებ დროში** მუშაობს?
