## ამოხსნები შერჩეულ ამოცანებზე: თავი 10

*(ამოცანების პირობები: [[თავი 10.4 ამოცანები]])*

**1.** **N მცურავმძიმიანი რიცხვის მინიმუმის ან მაქსიმუმის** საპოვნელად დალაგება ჩვეულებრივ **ზედმეტია**. **ამოხსნა 9** აჩვენებს, როგორ შეიძლება **მედიანის დალაგების გარეშე უფრო სწრაფად** პოვნა, მაგრამ ზოგ სისტემაზე **დალაგება შეიძლება უფრო ადვილი** იყოს. დალაგება **მოდის საპოვნელად ჩვეულებრივ ზუსტად შესაფერისია**. თუმცა **საშუალოს** პოვნის აშკარა კოდს **N-ის პროპორციული** დრო სჭირდება, მიდგომამ, რომელიც **ჯერ ალაგებს**, შეიძლება სამუშაო **უფრო მეტი რიცხვითი სიზუსტით** შეასრულოს; იხ. **ამოცანა 12.3.ბ**.

**2.** მოცემული კოდი **ჩავარდება**, როცა სისტემა **მასივის საზღვრების შემოწმებას** იძლევა და **ორივე კონიუნქტი გამოითვლება**, თუნდაც **პირველი მცდარი** იყოს. მსგავსი სიტუაცია ჩნდება [[თავი 10.1 ჩასმით დალაგება|10.1 ქვეთავის]] ჩასმით დალაგებაში, როცა **J = 1**. ჩავარდნა შეიძლება **რამდენიმე გზით** აირიდოთ, მაგალითად:
- **პირობითი AND ოპერატორის** გამოყენებით;
- **X[0]-ის გამოცხადებით** (და, შესაძლოა, **დარაჯად** გამოყენებით);
- **ძირითადი დალაგების გამოძახებამდე მინიმალური მნიშვნელობის X[1]-ში** მოთავსებით;
- ან **ლოგიკური ცვლადის** გამოყენებით.

**3.** თუ **ყველა ელემენტი ტოლია**, თავის Quicksort **N რეკურსიული გამოძახებიდან თითოეულზე მხოლოდ ერთ ელემენტს** აშორებს. **Sedgewick**-ის კოდს ეს ინვარიანტი აქვს:

```
┌───┬──────────┬──────────┬──────────┬────┐
│ T │    ≤T    │    ?     │    ≥T    │ >T │
└───┴──────────┴──────────┴──────────┴────┘
↑              ↑          ↑               ↑
L              I          J               U
```

**ტოლ ელემენტებზე გაცვლების „ფლანგვით"** ის **დუბლიკატი გასაღებების ქვემასივს ზუსტად ანახევრებს**.

**4.** **Bob Sedgewick**-მა შენიშნა, რომ **Lomuto-ს დაყოფის სქემა** შეიძლება შეიცვალოს, რომ **მარჯვნიდან მარცხნივ** იმუშაოს, შემდეგი ინვარიანტით:

```
┌───┬──────────┬──────────┬──────────┐
│ T │    ?     │    <T    │    ≥T    │
└───┴──────────┴──────────┴──────────┘
↑              ↑          ↑          ↑
L              I          M          U
```

მაშინ დაყოფის კოდია:

```
M := U+1
for I := U downto L do
    if X[I] >= T then
        M := M-1
        Swap(X[M], X[I])
```

დასრულებისას ვიცით, რომ **X[M] = T**, ამიტომ შეგვიძლია რეკურსია გამოვიძახოთ პარამეტრებით **(L, M−1)** და **(M+1, U)**; **დამატებითი Swap საჭირო არ არის**. Sedgewick-მა ასევე გამოიყენა **X[L] დარაჯად**, რომ შიდა ციკლიდან **ერთი შემოწმება** მოეშორებინა:

```
M := U+1
I := U+1
repeat
    repeat I := I-1 until X[I] >= T
    M := M-1
    Swap(X[M], X[I])
  until I = L
```

**6.** **McIlroy**-ის პროგრამა **დასალაგებელი მონაცემების რაოდენობის პროპორციულ** დროში მუშაობს, რაც **უარეს შემთხვევაში ოპტიმალურია**. ის ვარაუდობს, რომ **X[1..N]**-ის ყოველ ჩანაწერს აქვს **მთელი რიცხვი Length** და **მიმთითებელი მასივზე Bit[1..Length]**.

```
procedure Sort(L, U, Depth)
    if L < U then
        for I := L to U do
            if X[I].Length < Depth then
                Swap(X[I], X[L])
                L := L+1
        M := L
        for I := L to U do
            if X[I].Bit[Depth] = 0 then
                Swap(X[I], X[M])
                M := M+1
        Sort(L, M-1, Depth+1)
        Sort(M, U, Depth+1)
```

- პროცედურა თავდაპირველად იძახება **Sort(1, N, 1)**-ით.
- ეს პროგრამა **პარამეტრებსა და `for` ციკლების განმსაზღვრელ ცვლადებს** მნიშვნელობებს ანიჭებს; თუმცა ეს **ბევრ ენაში დასაშვებია**, **სხვებში აკრძალულია** (მაგალითად, **Pascal-ში**).
- **წრფივი შესრულების დრო** **ძლიერ არის დამოკიდებული** იმ ფაქტზე, რომ **Swap ოპერაცია ბიტურ სტრიქონებზე მიმთითებლებს გადაადგილებს**, და **არა თავად ბიტურ სტრიქონებს**.

**8.** ამ კითხვაზე პასუხი **საკმაოდ არის დამოკიდებული თქვენს კონკრეტულ სისტემაზე**. **საფუძვლიანი, მაგრამ ცოტა მოძველებული** პასუხისთვის იხილეთ **W. A. Martin**-ის სტატიის „**Sorting**" **170-ე გვერდი**, *Computing Surveys* 3, 4, **1971 წლის დეკემბერი**.

**9.** ეს ალგორითმი **C. A. R. Hoare**-ს ეკუთვნის; ის განხილულია „Programming Pearls"-ში, *Communications of the ACM*-ის **1985 წლის ნოემბრის** ნომერში.

```
procedure Select(L, U, K)
        pre  L <= K <= U
        post X[L..K-1] <= X[K] <= X[K+1..U]
    if L < U then
        Swap(X[L], X[RandInt(L,U)])
        T := X[L]
        M := L
        for I := L+1 to U do
            /* Invariant: X[L+1..M] < T
                  and X[M+1..I-1] >= T */
            if X[I] < T then
                M := M+1
                Swap(X[M], X[I])
        Swap(X[L], X[M])
        /* X[L..M-1] <= X[M] <= X[M+1..U] */
        if      M < K then Select(M+1, U, K)
        else if M > K then Select(L, M-1, K)
```

კოდი **ბევრი გზით** შეიძლება გაუმჯობესდეს. მაგალითად, **ამოცანა 10.3-ის** დაყოფის კოდი **ძვირ უარეს შემთხვევას** აცილებს. რადგან რეკურსია **პროცედურის ბოლო მოქმედებაა**, ის შეიძლება **`while` ციკლად** გარდაიქმნას:

```
procedure Select(K)
        post X[1..K-1] <= X[K] <= X[K+1..N]
    L := 1; U := N
    while L < U do
        /* Invariant: X[1..L-1] <= X[L..U] <= X[U+1..N] */
            ... loop body here ...
        /* Invariant and X[L..M-1] <= X[M] <= X[M+1..U] */
        if M <= K then L := M+1
        if M >= K then U := M-1
```

*Sorting and Searching*-ის **ამოცანა 5.2.2-32**-ში **Knuth** აჩვენებს, რომ პროგრამა **N ელემენტის მედიანის** საპოვნელად **საშუალოდ 3.4N შედარებას** იყენებს; **ალბათური არგუმენტი** სულისკვეთებით **ამოხსნა 2.A-ს უარესი შემთხვევის** არგუმენტს ჰგავს. წარმადობაზე **ინტუიციისთვის** ავტორმა ეს მონაცემები **16-სტრიქონიანი AWK პროგრამით** შეაგროვა, რომელიც **შემთხვევით მონაცემებს აგენერირებდა**, ალგორითმს უშვებდა და **სტატისტიკას აგროვებდა**.

*(წიგნის გრაფიკი: ჰორიზონტალურად N = 25, 50, 100, 200; ვერტიკალურად „შედარებები ელემენტზე", 2-დან 6-მდე. თითოეულ N-ზე წერტილები ძირითადად 2-სა და 4-ს შორისაა, მხოლოდ რამდენიმეა 4-ზე ზემოთ.)*

პროგრამას N-ელემენტიანი მასივის მედიანის საპოვნელად **მხოლოდ იშვიათად** სჭირდება **4N-ზე მეტი შედარება**. (შეადარეთ ეს **„ბრტყელი" მონაცემები შემდეგი ამოხსნის მეორე გრაფიკის ზრდად ტენდენციას**.)

**10.** **ზედა გრაფიკი** **Quicksort 2-ის შესრულების დროს** აჩვენებს, როგორც **შემავალი მასივის ზომის, N-ის** ფუნქციას. **N-ის ასი მნიშვნელობა** **ლოგარითმულ შკალაზე თანაბრად** არის განაწილებული. **პატარა დროები დისკრეტულია**, რადგან ავტორის სისტემა შესრულების დროს **წამის სამოცედებში** ზომავს. გრაფიკი აჩვენებს, რომ შესრულების დრო **შემავალ ზომასთან ძლიერ კორელირებს**, მაგრამ **ამის მიღმა ცოტა ხედვას** იძლევა.

*(წიგნის ორი გრაფიკი: ჰორიზონტალურად N = 100, 200, 500, 1000, 2000, 5000 ლოგარითმულ შკალაზე. ზედა: შესრულების დრო, 10 მილიწამიდან 1 წამამდე, წერტილები თითქმის სწორ ხაზად ადის. ქვედა: მიკროწამები ელემენტზე, 100-დან 400-მდე; პატარა N-ზე წერტილები 100–200-ს შორისაა და ეცემა, შემდეგ კი, დაახლოებით 500-დან, სწორი ხაზით ნელა ადის 300–400-მდე.)*

**ქვედა გრაფიკის y-შკალა** **მასივის ერთ ელემენტზე შესრულების დროა მიკროწამებში** (ანუ **მთლიანი დრო გაყოფილი N-ზე**). ეს გრაფიკი აჩვენებს **შემთხვევითი Swap-ით** გამოწვეულ შესრულების დროის **ფართო ვარიაციას**. მონაცემების **სისწორე** (**500-ის შემდეგ მაინც**) მიუთითებს, რომ **ელემენტზე შესრულების დრო ლოგარითმულად იზრდება**, რაც გულისხმობს, რომ Quicksort-ის **მთლიანი შესრულების დრო O(N log N)**-ია. **ალგორითმების სახელმძღვანელოების უმეტესობა** ამ ფაქტის **მათემატიკურ დამტკიცებას** იძლევა.

**12.** *Scientific American*-ის **გავრცელების განყოფილება** **ფოსტის დიდ მოცულობას** იღებს. (**„კონვერტის უკანა მხარის" ვიქტორინა: დღეში რამდენ წერილს იღებს ჟურნალი?**)
- კორესპონდენციის **უმეტესობა ნახევარ დუჟინ ძირითად კატეგორიაში** ხვდება: **ანგარიშების გადახდები**, **ხელმოწერების განახლებები**, **პირდაპირი საფოსტო აქციების პასუხები**, **ჟურნალში ჩადებული საფოსტო ბარათების პასუხები** და ა.შ.
- ფოსტა ამ ჯგუფებად უნდა **დალაგდეს**, სანამ მას **მონაცემთა შემყვანი ოპერატორები** დაამუშავებენ.
- ფოსტის **ხელით დალაგება ძვირია**, ამიტომ ჟურნალი ამ საქმეს **აშშ-ის საფოსტო სამსახურს აკეთებინებს**: ისინი **ყოველი ძირითადი კატეგორიისთვის სხვა საფოსტო ყუთის ნომერს** იყენებენ (თითოეული ყუთი **წელიწადში დაახლოებით ასი დოლარი** ჯდება).
