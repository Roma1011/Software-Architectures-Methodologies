## ამოცანა 1

რაც არ უნდა შრომატევადი იყო ბინარული ძებნის ჩვენი დამტკიცება, ზოგიერთი სტანდარტით ის **ჯერ კიდევ დაუსრულებელია**.

- როგორ დაამტკიცებდით, რომ პროგრამა **შესრულების დროის შეცდომებისგან თავისუფალია** (მაგალითად, **ნულზე გაყოფა**, **სიტყვის გადავსება**, **ცვლადის მნიშვნელობა გამოცხადებული დიაპაზონის გარეთ**, ან **მასივის ინდექსები საზღვრებს გარეთ**)?
- თუ **დისკრეტული მათემატიკის** ცოდნა გაქვთ, შეგიძლიათ დამტკიცება **ლოგიკურ სისტემაში** ფორმალიზოთ?

## ამოცანა 2

თუ თავდაპირველი ბინარული ძებნა ზედმეტად ადვილი იყო თქვენთვის, სცადეთ **ვარიანტი**, რომელიც P-ში აბრუნებს მასივ X-ში **T-ს პირველი შემთხვევის პოზიციას** (თუ T რამდენჯერმე გვხვდება, თავდაპირველი ალგორითმი **ნებისმიერ ერთს** აბრუნებს).

თქვენი კოდი მასივის ელემენტებს **ლოგარითმული რაოდენობით** უნდა ადარებდეს; შესაძლებელია ამის გაკეთება **log₂ N** ასეთ შედარებაში.

## ამოცანა 3

დაწერეთ და შეამოწმეთ **რეკურსიული** ბინარული ძებნის პროგრამა. კოდისა და დამტკიცების **რომელი ნაწილები რჩება იგივე**, რაც იტერაციულ ვერსიაში, და **რომელი იცვლება**?

## ამოცანა 4

თქვენს ბინარული ძებნის პროგრამას დაუმატეთ **ფიქტიური „დროის ცვლადები"**, რომლებიც მის მიერ შესრულებული **შედარებების რაოდენობას** დაითვლის, და **პროგრამის ვერიფიკაციის ტექნიკებით** დაამტკიცეთ, რომ მისი შესრულების დრო **მართლაც ლოგარითმულია**.

## ამოცანა 5

დაამტკიცეთ, რომ ეს პროგრამა **სრულდება**, როცა მისი შემავალი მონაცემი **დადებითი მთელი რიცხვია**.

while X ≠ 1 do

## ამოცანა 6

*[C. Scholten]* **David Gries** ამას თავის *Science of Programming*-ში **„ყავის ქილის ამოცანას"** (Coffee Can Problem) უწოდებს.

თავდაპირველად გაძლევენ **ყავის ქილას**, რომელშიც **რამდენიმე შავი და რამდენიმე თეთრი მარცვალია**, და **„დამატებითი" შავი მარცვლების დიდ გროვას**. შემდეგ იმეორებთ შემდეგ პროცესს, სანამ ქილაში **ერთი მარცვალი** არ დარჩება:

> ქილიდან **შემთხვევით ამოიღეთ ორი მარცვალი**. თუ **ერთი ფერისაა**, ორივე გადააგდეთ და ქილაში **ერთი დამატებითი შავი მარცვალი** ჩადეთ. თუ **სხვადასხვა ფერისაა**, **თეთრი მარცვალი ქილაში დააბრუნეთ**, შავი კი გადააგდეთ.

- დაამტკიცეთ, რომ პროცესი **სრულდება**.
- რისი თქმა შეგიძლიათ **ბოლოს დარჩენილი მარცვლის ფერზე**, ქილაში თავდაპირველად არსებული **შავი და თეთრი მარცვლების რაოდენობების მიხედვით**?

## ამოცანა 8

ბინარული ძებნა **ფუნდამენტურად უფრო სწრაფია**, ვიდრე მიმდევრობითი ძებნა: N ელემენტიან ცხრილში ძებნისთვის ის დაახლოებით **log₂ N** შედარებას აკეთებს, მიმდევრობითი ძებნა კი დაახლოებით **N/2**-ს.

მართალია, ხშირად ის **საკმარისად სწრაფია**, მაგრამ **რამდენიმე შემთხვევაში** ბინარული ძებნა **კიდევ უფრო სწრაფი** უნდა გახდეს. მიუხედავად იმისა, რომ ალგორითმის მიერ გაკეთებული შედარებების **ლოგარითმულ რაოდენობას** ვერ შეამცირებთ, შეგიძლიათ ბინარული ძებნის კოდი **ისე გადაწეროთ, რომ უფრო სწრაფი** იყოს? კონკრეტულობისთვის ჩათვალეთ, რომ **N = 1000 მთელი რიცხვის** დალაგებულ ცხრილში უნდა მოძებნოთ.

## ამოცანა 9

პროგრამის ვერიფიკაციის სავარჯიშოებად **ზუსტად განსაზღვრეთ** შემდეგი პროგრამის ფრაგმენტებიდან თითოეულის **შეტანა-გამოტანის ქცევა** და აჩვენეთ, რომ კოდი **თავის სპეციფიკაციას აკმაყოფილებს**.

**პირველი** პროგრამა **ვექტორების შეკრებას** A := B + C ახორციელებს:

```
I := 1
while I <= N do
    A[I] := B[I] + C[I]
    I := I+1
```

**შემდეგი** ფრაგმენტი ვექტორ X-ში **მაქსიმალურ მნიშვნელობას** ითვლის:

```
I := 2
Max := X[1]
while I <= N do
    if X[I] > Max then Max := X[I]
    I := I+1
```

ეს **მიმდევრობითი ძებნის** პროგრამა აბრუნებს **T-ს პირველი შემთხვევის პოზიციას** ვექტორ X[1..N]-ში. `while` ბრძანებაში **`and` პირობითია**, ისევე როგორც ამ წიგნში შემდგომ ყველა `and` და `or`: **თუ პირველი პუნქტი მცდარია, მეორე არ გამოითვლება**.

```
I := 1
while I <= N and X[I] ≠ T do
    I := I+1
if I > N then P := 0 else P := I
```

ეს პროგრამა X-ის **N-ურ ხარისხს** **N-ის ლოგარითმის პროპორციულ დროში** ითვლის. ეს **რეკურსიული** პროგრამა **მარტივი დასაწერი და შესამოწმებელია**; **იტერაციული** ვერსია კი **ფაქიზია** და **დამატებით ამოცანად** რჩება.

```
function Exp(X,N)
        pre  N >= 0
        post result = X**N
    if N = 0 then
        return 1
      else if Even(N) then
        return Square(Exp(X,N/2))
      else
        return X*Exp(X,N-1)
```
