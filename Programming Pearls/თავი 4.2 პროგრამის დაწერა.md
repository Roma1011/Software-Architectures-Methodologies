## მთავარი იდეა: MustBe

ბინარული ძებნის **მთავარი იდეა** ისაა, რომ **ყოველთვის ვიცით**: თუ T სადმე არის X[1..N]-ში, ის X-ის **გარკვეულ დიაპაზონში** უნდა იყოს.

გამოვიყენებთ შემოკლებას **MustBe(range)**, რაც ნიშნავს: **თუ T სადმე არის მასივში, ის `range`-ში უნდა იყოს**. ამ აღნიშვნით ბინარული ძებნის ზემოთ მოცემული აღწერა **პროგრამის ესკიზად** შეგვიძლია ვაქციოთ:

```
initialize range to 1..N
loop
    { Invariant: MustBe(range) }
    if range is empty,
        return that T is nowhere in the array
    compute M, the middle of the range
    use M as a probe to shrink the range
        if T is found during the shrinking process,
        return its position
```

## ციკლის ინვარიანტი

ამ პროგრამის **გადამწყვეტი ნაწილია ციკლის ინვარიანტი** (loop invariant), რომელიც `{}` ფრჩხილებშია მოთავსებული.

პროგრამის მდგომარეობის შესახებ ამ **მტკიცებას** (assertion) **ინვარიანტი** ჰქვია, რადგან ის **ციკლის ყოველი იტერაციის დასაწყისშიც და ბოლოსაც ჭეშმარიტია**; ის **ფორმალიზებს** იმ ინტუიციურ წარმოდგენას, რომელიც ზემოთ გვქონდა.

## პროგრამის დახვეწა

ახლა პროგრამას **დავხვეწთ** და დავრწმუნდებით, რომ **ყველა მოქმედება ინვარიანტს პატივს სცემს**.

**დიაპაზონის წარმოდგენა.** პირველი საკითხი, რომელსაც უნდა შევეჭიდოთ, **დიაპაზონის წარმოდგენაა**: გამოვიყენებთ ორ ინდექსს **L**-სა და **U**-ს („lower" ქვედა და „upper" ზედა), რომ დიაპაზონი **L..U** წარმოვადგინოთ. (დიაპაზონის სხვა შესაძლო წარმოდგენებიც არსებობს, მაგალითად, მისი **საწყისი პოზიცია და სიგრძე**.)

**ინიციალიზაცია.** რა მნიშვნელობები უნდა ჰქონდეს L-სა და U-ს, რომ **MustBe(L,U)** ჭეშმარიტი იყოს? აშკარა არჩევანია **1 და N**: MustBe(1,N) ამბობს, რომ თუ T სადმე არის X-ში, ის **X[1..N]**-შია, რაც **ზუსტად ის არის, რაც პროგრამის დასაწყისში ვიცით**. ამიტომ ინიციალიზაცია მინიჭებებისგან შედგება: **`L := 1`** და **`U := N`**.

**ცარიელი დიაპაზონი.** შემდეგი ამოცანებია **ცარიელი დიაპაზონის შემოწმება** და **ახალი შუა წერტილის, M-ის** გამოთვლა. დიაპაზონი L..U **ცარიელია, თუ L > U**; ამ შემთხვევაში P-ში სპეციალურ მნიშვნელობას **0**-ს ვინახავთ და ციკლს ვასრულებთ:

```
if L > U then
    P := 0; break
```

ბრძანება `break` **გარემომცველ** `loop`-ს ასრულებს.

**შუა წერტილი.** ეს ბრძანება დიაპაზონის შუა წერტილს, **M**-ს ითვლის:

```
M := (L+U) div 2
```

ოპერატორი **div მთელრიცხვა გაყოფას** ასრულებს: **6 div 2** არის 3, ისევე როგორც **7 div 2**.

პროგრამა ახლა ასეთია:

```
L := 1; U := N
loop
    { Invariant: MustBe(L,U) }
    if L > U then
        P := 0; break
    M := (L+U) div 2
    use M as a probe to shrink the range L..U
        if T is found during the shrinking process,
        note its position and break
```

## სამი შემთხვევა

ციკლის ტანის ბოლო სამი სტრიქონის დახვეწა მოითხოვს **T-სა და X[M]-ის შედარებას** და **შესაბამის მოქმედებას ინვარიანტის შესანარჩუნებლად**. ამიტომ კოდს ასეთი ფორმა ექნება:

```
case
    X[M] < T:   Action A
    X[M] = T:   Action B
    X[M] > T:   Action C
```

- **Action B:** ვიცით, რომ T **M პოზიციაზეა**, ამიტომ **P-ს M-ს ვანიჭებთ** და ციკლს `break`-ით ვწყვეტთ.
- დანარჩენი ორი შემთხვევა **სიმეტრიულია**, ამიტომ **პირველზე** გავამახვილებთ ყურადღებას და **ვენდობით**, რომ ბოლო სიმეტრიით გამოვა (ეს ნაწილობრივ იმის მიზეზიცაა, რომ შემდეგ ქვეთავში კოდს **ზუსტად** შევამოწმებთ).
- **Action A:** თუ **X[M] < T**, მაშინ ვიცით, რომ **X[1] ≤ X[2] ≤ ... ≤ X[M] < T**, ამიტომ T **X[1..M]-ში ვერსად იქნება**. ამის გაერთიანებით იმ ცოდნასთან, რომ T **X[L..U]-ს გარეთ არ არის**, ვიცით, რომ თუ ის სადმეა, **X[M+1..U]**-ში უნდა იყოს, რასაც ასე ვწერთ: **MustBe(M+1,U)**. შემდეგ ინვარიანტ **MustBe(L,U)**-ს **აღვადგენთ**, L-ს **M+1**-ს მივანიჭებთ.

ამ შემთხვევების წინა ესკიზში ჩასმით **საბოლოო ფუნქციას** ვიღებთ:

```
L := 1; U := N
loop
    { MustBe(L,U) }
    if L > U then
        P := 0; break
    M := (L+U) div 2
    case
        X[M] < T:  L := M+1
        X[M] = T:  P := M; break
        X[M] > T:  U := M-1
```

## შეფასება

ეს **მოკლე პროგრამაა**: **ათი სტრიქონი კოდი და ერთი ინვარიანტის მტკიცება**.

პროგრამის ვერიფიკაციის საბაზისო ტექნიკები, ანუ **ინვარიანტის ზუსტი ფორმულირება** და კოდის ყოველი სტრიქონის წერისას **ინვარიანტის შენარჩუნებაზე თვალის დევნება**, **ძალიან დაგვეხმარა**, როცა ალგორითმის ესკიზი ფსევდოკოდად ვაქციეთ.

ეს პროცესი პროგრამის მიმართ **გარკვეულ ნდობას** გვაძლევს, მაგრამ მის სისწორეში **სულაც არ ვართ დარწმუნებული**. რამდენიმე წუთი დაუთმეთ საკუთარი თავის დარწმუნებას, რომ კოდი **სპეციფიკაციის მიხედვით** იქცევა, სანამ კითხვას გააგრძელებთ.
