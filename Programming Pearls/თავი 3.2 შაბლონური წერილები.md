## ამოცანა

შემდეგ პროგრამას მიეწოდება **სახელებისა და მისამართების ფაილი**, და ის ფაილის ყოველი ჩანაწერისთვის **პერსონალიზებულ შაბლონურ წერილს** (form letter) ქმნის. მაგალითად, ამ რვაველიანი შემავალი ჩანაწერისთვის

```
Public|John Q.|Mr.|600|Maple Street|Your Town|Iowa|12345
```

(სადაც `|` ჩანაწერის შიგნით ველებს ჰყოფს) პროგრამამ უნდა შექმნას წერილი, რომელიც ასე იწყება:

```
Mr. John Q. Public
600 Maple Street
Your Town, Iowa 12345

Dear Mr. Public:

I am sure that the Public family is anxious
to be the first family on Maple Street to own a
microprocessor-controlled clothesline.
```

*(წერილის შინაარსი: „დარწმუნებული ვარ, Public-ების ოჯახს სურს, Maple Street-ზე პირველი ოჯახი იყოს, რომელსაც მიკროპროცესორით მართული სარეცხის თოკი ექნება".)*

ეს ამოცანა **ბევრი სხვა ამოცანისთვისაც ტიპურია**, არა მხოლოდ შაბლონური წერილებისთვის: **ცოტა გამოთვლა ბევრ გამომავალ მონაცემს ქმნის**.

## აჩქარებული პროგრამისტის გზა

აჩქარებულ პროგრამისტს შეიძლება გაუჩნდეს ცდუნება, დაწეროს პროგრამა, რომელიც ასე იწყება:

```
loop until end of input
  read LastName, FirstName, Title, StreetNum,
       StreetName, Town, State, Zip
  skip to new page
  print Title, " ", FirstName, " ", LastName
  print StreetNum, " ", StreetName
  print Town, ", ", State, " ", Zip
  print
  print "Dear ", Title, " ", LastName
  print
  print "I am sure that the ", LastName, " family is anxious"
  print "to be the first family on ", StreetName, " to own a"
  print "microprocessor-controlled clothesline."
```

- ასეთი პროგრამა **მომაბეზრებელია** ენაში, რომელიც შეტანა-გამოტანის ბრძანებებში **ცვლადი სიგრძის სტრიქონებს** უჭერს მხარს, და **საშინელია** ენაში, რომელსაც ეს თვისება არ აქვს.
- **ორივე შემთხვევაში** პროგრამის მოვლა **საზარელია**: აბზაცის დასაწყისთან რამდენიმე სიტყვის დამატებამ შეიძლება მთელი აბზაცის **ხელით, მძიმე შრომით გადაფორმატება** მოითხოვოს.

## ელეგანტური გზა: შაბლონის სქემა

უფრო ელეგანტური მიდგომაა **„შაბლონური წერილების გენერატორის"** დაწერა, რომელიც **შაბლონური წერილის სქემას** (form letter schema) ეყრდნობა:

```
$3 $2 $1
$4 $5
$6, $7 $8

Dear $3 $1:

I am sure that the $1 family is anxious
to be the first family on $5 to own a
microprocessor-controlled clothesline.
```

აღნიშვნა **`$i`** შემავალი ჩანაწერის **i-ურ ველს** ეხება, ასე რომ **`$1`** გვარია და ა.შ.

სქემას შემდეგი ფსევდოკოდი ინტერპრეტირებს. ის ვარაუდობს, რომ **ლიტერალური `$` სიმბოლო** შემავალ სქემაში **`$$`**-ით იწერება.

```
read Schema from schema file
loop until end of input file
    for I := 1 to NumFields do
        read Field[I] from input file
    skip to new page
    loop from start to end of Schema
        C := next character in Schema
        if C ≠ "$" then
            printchar C
          else
            C := next character in Schema
            case C of
                "$":       printchar "$"
                "1" - "9": printstring Field[C]
                other:     Error("Bad Schema")
```

- სქემა პროგრამაში **სიმბოლოების ერთი გრძელი მასივითაა** წარმოდგენილი, რომელშიც ტექსტის სტრიქონები **„ახალი სტრიქონის" სიმბოლოებით** მთავრდება.
- როგორც ადრე, ინტერპრეტატორის რეალიზაცია **ადვილია**, თუ ენა ცვლადი სიგრძის სტრიქონებს უჭერს მხარს, და **უფრო რთული**, თუ არა. მიუხედავად ამისა, ცვლადი სიგრძის სტრიქონები ახლა **მხოლოდ ერთ ადგილას** უნდა დამუშავდეს, ნაცვლად სქემაში **ყოველ შემთხვევაზე**.

## როდის ღირს

ენაში, რომელიც ცვლადი სიგრძის გამომავალ სტრიქონებს უჭერს მხარს, გენერატორისა და სქემის დაწერა შეიძლება **ცოტა მეტი სამუშაო** იყოს, ვიდრე აშკარა პროგრამის დაწერა. მაგრამ ბევრ ვითარებაში ეს დამატებითი შრომა **კარგად აინაზღაურებს თავს**: თუ წერილი **გადაკეთდება**, სქემის შეცვლა **ტექსტური რედაქტორით** შეიძლება, და **მეორე შაბლონური წერილის** მომზადება მართლაც მარტივი იქნება.

## ავტორის COBOL გამოცდილება

ანგარიშის სქემის (report schema) კონცეფციას შეეძლო **მნიშვნელოვნად გაემარტივებინა 5300-სტრიქონიანი COBOL პროგრამა**, რომელსაც ავტორი ერთ დროს უვლიდა.
- პროგრამის **შემავალი მონაცემი** ოჯახის **ფინანსური მდგომარეობის** აღწერა იყო;
- **გამომავალი** კი **ბროშურა**, რომელიც მდგომარეობას აჯამებდა და **სამომავლო პოლიტიკას** გვირჩევდა.

რამდენიმე რიცხვი:

|პარამეტრი|მნიშვნელობა|
|---|---|
|შემავალი ველები|120, ათ ბარათზე|
|გამომავალი სტრიქონები|400, 18 გვერდზე|
|შემავალი მონაცემების გასუფთავების კოდი|300 სტრიქონი|
|გამოთვლის კოდი|800 სტრიქონი|
|გამომავალი მონაცემების ჩაწერის კოდი|4200 სტრიქონი|

ერთ ადგილას პროგრამამ **113 სტრიქონი კოდი** გამოიყენა, რომ სტრიქონის შუაში ჩაეწერა ტექსტი, რომლის სიგრძე **ერთიდან ათ სიმბოლომდე** იცვლებოდა.

ავტორის შეფასებით, **გამომავალი მონაცემების 4200 სტრიქონი** შეიძლებოდა შეცვლილიყო **მაქსიმუმ ორასიოდე სტრიქონი COBOL-ის ინტერპრეტატორით** (თანამედროვე ენაზე გაცილებით ნაკლებით) და **400-სტრიქონიანი სქემით**. თავიდანვე ამ ფორმით დაწერილი პროგრამა **მაქსიმუმ მესამედის ზომის** იქნებოდა და **გაცილებით ადვილად მოსავლელი**.
