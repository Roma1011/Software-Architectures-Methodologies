## მიდგომა

როცა ავტორი **ფაქიზ საპროგრამო ამოცანას** აწყდება, ის ცდილობს კოდი დაახლოებით **იმ დეტალიზაციის დონეზე** გამოიყვანოს, რაც ახლა ვნახეთ. შემდეგ **ვერიფიკაციის მეთოდებს** იყენებს, რომ კოდის სისწორეში **ნდობა გაზარდოს**. ამ დონის ვერიფიკაციას თავებში 8, 10 და 12 გამოვიყენებთ.

ამ ქვეთავში ბინარული ძებნის კოდის **ვერიფიკაციის არგუმენტს** **წვრილმანებამდე დეტალურ დონეზე** შევისწავლით; პრაქტიკაში ავტორი **გაცილებით ნაკლებად ფორმალურ** ანალიზს გააკეთებდა. პროგრამის ვერსია ქვემოთ **(ზედმეტად) მძიმედაა ანოტირებული** მტკიცებებით, რომლებიც იმ ინტუიციურ წარმოდგენებს აფორმალებს, რომლებიც კოდის თავდაპირველი წერისას გამოვიყენეთ.

კოდის დამუშავება **ზემოდან ქვემოთ** (top-down) მიმდინარეობდა (ზოგადი იდეიდან დაწყებული და ცალკეულ სტრიქონებამდე დახვეწილი), სისწორის ეს ანალიზი კი **ქვემოდან ზემოთ** (bottom-up) იქნება: ვნახავთ, როგორ მუშაობს **ცალკეული სტრიქონები ერთად** ამოცანის ამოსახსნელად.

> [!WARNING] გაფრთხილება
> წინ **მოსაწყენი მასალაა**. როცა ძილი მოგერევათ, **4.4 ქვეთავზე** გადადით.

## ანოტირებული პროგრამა

```
 1.  { MustBe(1,N) }
 2.  L := 1; U := N
 3.  { MustBe(L,U) }
 4.  loop
 5.      { MustBe(L,U) }
 6.      if L > U then
 7.          { L > U and MustBe(L,U) }
 8.          { T is nowhere in the array }
 9.          P := 0; break
10.      { MustBe(L,U) and L <= U }
11.      M := (L+U) div 2
12.      { MustBe(L,U) and L <= M <= U }
13.      case
14.          X[M] < T:
15.                  { MustBe(L,U) and CantBe(1,M) }
16.                  { MustBe(M+1,U) }
17.                  L := M+1
18.                  { MustBe(L,U) }
19.          X[M] = T:
20.                  { X[M] = T }
21.                  P := M; break
22.          X[M] > T:
23.                  { MustBe(L,U) and CantBe(M,N) }
24.                  { MustBe(L,M-1) }
25.                  U := M-1
26.                  { MustBe(L,U) }
27.      { MustBe(L,U) }
```

## სტრიქონები 1–3

სტრიქონ 1-ის მტკიცება, რომ **MustBe(1,N)**, ჭეშმარიტია **MustBe-ს განსაზღვრებით**: თუ T სადმე არის მასივში, ის X[1..N]-ში უნდა იყოს. ამიტომ სტრიქონ 2-ის მინიჭებები `L := 1` და `U := N` სტრიქონ 3-ის მტკიცებას იძლევა: **MustBe(L,U)**.

## ციკლი: სამი ნაწილი

ახლა **რთულ ნაწილს** მივადექით: ციკლს სტრიქონებში 4–27. მისი სისწორის არგუმენტს **სამი ნაწილი** აქვს, და თითოეული **ციკლის ინვარიანტთან** მჭიდროდაა დაკავშირებული:

- **ინიციალიზაცია (Initialization).** ინვარიანტი ჭეშმარიტია, როცა ციკლი **პირველად** სრულდება.
- **შენარჩუნება (Preservation).** თუ ინვარიანტი იტერაციის **დასაწყისში** სრულდება და ციკლის ტანი სრულდება, ინვარიანტი ციკლის ტანის დასრულების **შემდეგაც** ჭეშმარიტი დარჩება.
- **დასრულება (Termination).** ციკლი **დასრულდება** და სასურველი შედეგი შესრულდება (ამ შემთხვევაში, სასურველი შედეგია, რომ **P-ს სწორი მნიშვნელობა** ჰქონდეს). ამის საჩვენებლად ინვარიანტით დადგენილ ფაქტებს გამოვიყენებთ.

**ინიციალიზაციისთვის** აღვნიშნავთ, რომ სტრიქონ 3-ის მტკიცება **იგივეა**, რაც სტრიქონ 5-ისა.

დანარჩენი ორი თვისების დასადგენად **სტრიქონ 5-დან სტრიქონ 27-მდე** ვიმსჯელებთ. როცა სტრიქონებს **9 და 21** (`break` ბრძანებებს) განვიხილავთ, **დასრულების** თვისებებს დავადგენთ, და თუ **სტრიქონ 27-მდე** მივაღწევთ, **შენარჩუნებას** დავადგენთ, რადგან ის სტრიქონ 5-ის **იგივეა**.

## სტრიქონები 6–9

სტრიქონ 6-ის **წარმატებული** შემოწმება სტრიქონ 7-ის მტკიცებას იძლევა: თუ T სადმე არის მასივში, ის **L-სა და U-ს შორის** უნდა იყოს, და **L > U**. ეს ფაქტები სტრიქონ 8-ს გულისხმობს: **T მასივში არსად არის**. ამიტომ ციკლს სტრიქონ 9-ში **სწორად ვასრულებთ**, P-ს ნულის მინიჭების შემდეგ.

## სტრიქონები 10–12

თუ სტრიქონ 6-ის შემოწმება **ვერ სრულდება**, სტრიქონ 10-ზე მივდივართ. ინვარიანტი **ისევ სრულდება** (მის შესაცვლელად არაფერი გაგვიკეთებია), და რადგან შემოწმება ვერ შესრულდა, ვიცით, რომ **L ≤ U**.

სტრიქონი 11 M-ს ანიჭებს **L-ისა და U-ს საშუალოს**, **უახლოეს მთელამდე ქვემოთ დამრგვალებულს**. რადგან საშუალო **ყოველთვის ორ მნიშვნელობას შორისაა** და დამრგვალება მას **L-ზე ქვემოთ ვერ ჩამოწევს**, სტრიქონ 12-ის მტკიცებას ვიღებთ.

## case ბრძანება: სტრიქონები 13–27

`case` ბრძანების ანალიზი სტრიქონებში 13–27 მის **სამივე შესაძლო არჩევანს** განიხილავს.

**მეორე ალტერნატივა (სტრიქონი 19)** ყველაზე ადვილად გასაანალიზებელია. სტრიქონ 20-ის მტკიცების გამო **სწორად ვანიჭებთ P-ს M-ს** და ციკლს ვასრულებთ. ეს **ორი ადგილიდან მეორეა**, სადაც ციკლი სრულდება, და **ორივე სწორად ასრულებს** მას, ამიტომ ციკლის **დასრულების სისწორე** დავადგინეთ.

**სიმეტრიული შტოები.** შემდეგ `case` ბრძანების **ორ სიმეტრიულ შტოს** მივადექით. რადგან კოდის დამუშავებისას **პირველ შტოზე** გავამახვილეთ ყურადღება, ახლა სტრიქონებს **22–26** მივხედავთ.

- განვიხილოთ სტრიქონ 23-ის მტკიცება. **პირველი პუნქტი** ინვარიანტია, რომელიც პროგრამას არ შეუცვლია.
- **მეორე პუნქტი** ჭეშმარიტია, რადგან **T < X[M] ≤ X[M+1] ≤ ... ≤ X[N]**, ამიტომ ვიცით, რომ T მასივში **M−1 პოზიციის ზემოთ ვერსად იქნება**; ეს შემოკლებით გამოიხატება: **CantBe(M,N)**.
- ლოგიკა გვეუბნება: თუ T **L-სა და U-ს შორის უნდა იყოს** და **M-ზე ან მის ზემოთ ვერ იქნება**, მაშინ ის **L-სა და M−1-ს შორის** უნდა იყოს (თუ საერთოდ არის X-ში); აქედან **სტრიქონი 24**.
- სტრიქონ 25-ის შესრულება, როცა სტრიქონი 24 ჭეშმარიტია, სტრიქონ 26-ს **ჭეშმარიტს ტოვებს**: ეს **მინიჭების განსაზღვრებაა**.
- ამიტომ `case` ბრძანების ეს არჩევანი ინვარიანტს სტრიქონ 27-ში **აღადგენს**.

**სტრიქონები 14–18**-ის არგუმენტს **ზუსტად იგივე ფორმა** აქვს, ასე რომ `case` ბრძანების **სამივე არჩევანი** გავაანალიზეთ. **ერთი** ციკლს **სწორად ასრულებს**, დანარჩენი **ორი ინვარიანტს ინარჩუნებს**.

## დასრულების დამტკიცება

კოდის ეს ანალიზი აჩვენებს, რომ **თუ ციკლი დასრულდება**, ის **P-ში სწორი მნიშვნელობით** დასრულდება. მაგრამ მას შეიძლება მაინც **უსასრულო ციკლი** ჰქონდეს; სინამდვილეში, სწორედ ეს იყო **ყველაზე გავრცელებული შეცდომა** პროფესიონალი პროგრამისტების დაწერილ პროგრამებში.

ჩვენი **დასრულების დამტკიცება** დიაპაზონ L..U-ს **სხვა ასპექტს** იყენებს:
- ეს დიაპაზონი თავდაპირველად **გარკვეული სასრული ზომისაა (N)**;
- სტრიქონები 6–9 უზრუნველყოფს, რომ ციკლი დასრულდება, როცა დიაპაზონი **ერთ ელემენტზე ნაკლებს** შეიცავს.

ამიტომ დასრულების დასამტკიცებლად უნდა ვაჩვენოთ, რომ დიაპაზონი **ციკლის ყოველ იტერაციაზე მცირდება**.
- სტრიქონი 12 გვეუბნება, რომ **M ყოველთვის მიმდინარე დიაპაზონშია**;
- `case` ბრძანების **ორივე ციკლური შტო** (სტრიქონები 14 და 22) M პოზიციის მნიშვნელობას **მიმდინარე დიაპაზონიდან გამორიცხავს** და ამით მის ზომას **მინიმუმ ერთით ამცირებს**.

ამიტომ პროგრამა **აუცილებლად უნდა გაჩერდეს**.
