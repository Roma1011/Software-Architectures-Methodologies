## პროგრამის აგებულება

ავტორმა ანაგრამების პროგრამა **UNIX** სისტემაზე დაწერა, რომელიც ამ ამოცანისთვის **განსაკუთრებით მოსახერხებელია**. მისი პროგრამის შესახებ წაკითხვის შემდეგ იფიქრეთ, როგორ დაწერდით მსგავს პროგრამას თქვენს საყვარელ სისტემაზე.

პროგრამა **სამსაფეხურიანი „pipeline"**-ის სახითაა ორგანიზებული, რომელშიც ერთი პროგრამის გამომავალი მონაცემები მომდევნოს შემავალ მონაცემებად მიეწოდება:

1. პირველი პროგრამა სიტყვებს **ხელს აწერს** (`sign`);
2. მეორე ხელმოწერილ ფაილს **ალაგებს** (`sort`);
3. მესამე ერთი ანაგრამის კლასის სიტყვებს **ერთ სტრიქონზე „ტკეპნის"** (`squash`).

აი პროცესი ექვსსიტყვიან ლექსიკონზე:

```
pans          anps pans          anps pans
pots          opst pots          anps snap          pans snap
opt  → sign → opt opt   → sort → opt opt  → squash → opt
snap          anps snap          opst pots          pots stop tops
stop          opst stop          opst stop
tops          opst tops          opst tops
```

გამომავალი მონაცემები **სამ ანაგრამის კლასს** შეიცავს.

## sign

შემდეგი `sign` პროგრამა ვარაუდობს, რომ არცერთ სიტყვაში **ასზე მეტი ასო** არ არის და შემავალი ფაილი **მხოლოდ პატარა ასოებსა და ახალი სტრიქონის სიმბოლოებს** შეიცავს. (ამიტომ ავტორმა სისტემის ლექსიკონი წინასწარ დაამუშავა **ერთსტრიქონიანი ტრანსლიტერაციის პროგრამით**, რომელმაც დიდი ასოები პატარად შეცვალა.)

```c
#define WORDMAX 101
main()
{   char thisword[WORDMAX], sig[WORDMAX];
    while (scanf("%s", thisword) != EOF) {
        strcpy(sig, thisword);
        qsort(sig, strlen(sig), 1, compchar);
        printf("%s %s\n", sig, thisword);
    }
}
```

- `while` ციკლი სტრიქონს `thisword`-ში კითხულობს, სანამ ფაილის ბოლოს არ მიაღწევს.
- `strcpy` ფუნქცია შემავალ სიტყვას სიტყვა `sig`-ში აკოპირებს, რომლის სიმბოლოები შემდეგ სისტემის დალაგების ფუნქციით **`qsort`** ლაგდება. პარამეტრებია: დასალაგებელი მასივის სახელი, მისი სიგრძე, **ბაიტების რაოდენობა ერთ სიმბოლოზე** და **ორი სიმბოლოს შესადარებელი ფუნქციის** სახელი.
- ბოლოს `printf` ბრძანება ბეჭდავს **ხელმოწერას**, შემდეგ **თავად სიტყვას** და ახალი სტრიქონის სიმბოლოს `\n`.

## sort და squash

სისტემის `sort` პროგრამა **ერთნაირი ხელმოწერის ყველა სიტყვას ერთად შეკრებს**. `squash` პროგრამა მათ **ერთ სტრიქონზე** ბეჭდავს. მას **AWK**-ზე, ფაილების დამუშავებისთვის შექმნილ **„ნიმუში-მოქმედება" (pattern-action)** ენაზე, **სულ სამი სტრიქონი** დასჭირდა:

```awk
$1 != prev  { prev = $1; if (NR > 1) printf "\n" }
            { printf "%s ", $2 }
END         { printf "\n" }
```

- სამუშაოს **უმეტეს ნაწილს მეორე ბრძანება** ასრულებს: ყოველი შემავალი სტრიქონისთვის ბეჭდავს **მეორე ველს** (`$2`) და მის შემდეგ ჰარს.
- **პირველი სტრიქონი ცვლილებებს იჭერს**: თუ პირველი ველი (`$1`) `prev`-ისგან (მისი წინა მნიშვნელობისგან) განსხვავდება, `prev` ახლდება და, თუ ეს ჩანაწერი ფაილში **პირველი არ არის** (მიმდინარე ჩანაწერის ნომერია `NR`), იბეჭდება ახალი სტრიქონის სიმბოლო.
- **მესამე სტრიქონი ფაილის ბოლოს** სრულდება და საბოლოო ახალი სტრიქონის სიმბოლოს წერს.

## ყველაფრის ერთად გაშვება

ამ მარტივი ნაწილების **პატარა შემავალ ფაილებზე** ტესტირების შემდეგ ავტორმა ანაგრამების სია ასე ააგო:

```
sign <dictionary | sort | squash >gramlist
```

ეს ბრძანება ფაილ `dictionary`-ს `sign` პროგრამას აწვდის, `sign`-ის გამომავალს **pipe**-ით `sort`-ს გადასცემს, `sort`-ის გამომავალს `squash`-ს, `squash`-ის გამომავალს კი ფაილ `gramlist`-ში წერს.

მთელ საქმეს დასჭირდა **C-ს ხუთი შესრულებადი სტრიქონი**, **AWK-ის სამი სტრიქონი** და **ერთი ბრძანების სტრიქონი**. ეს ლაკონიურია, რადგან UNIX სისტემა გვთავაზობს **ენების ძლიერ ნაკრებს** და სხვადასხვა ენაზე დაწერილი პროგრამების **ერთმანეთთან დაკავშირების მოსახერხებელ მექანიზმს**.

## შედეგი

პროგრამა **27 წუთს** მუშაობდა: **6** `sign`-ში, **6** `sort`-ში და **15** `squash`-ში.

ავტორს შეეძლო მთლიანი დრო **განეახევრებინა** `squash`-ის C-ზე გადაწერით (ინტერპრეტირებადი AWK ჩვეულებრივ C-ზე **რიგით ნელია**), მაგრამ რადგან ეს **ერთჯერადი პროგრამაა**, ძალისხმევად **არ ღირდა**.
