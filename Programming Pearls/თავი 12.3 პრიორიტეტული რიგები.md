## აბსტრაქცია და რეალიზაცია

ნებისმიერ მონაცემთა სტრუქტურას **ორი მხარე** აქვს.
- **გარედან** რომ შევხედოთ, მისი ***აბსტრაქცია*** გვეუბნება, **რას აკეთებს**: რიგი ინახავს ელემენტების მიმდევრობას და მასზე **ჩასმისა და ამოღების** ოპერაციებს იძლევა.
- **შიგნით** მისი ***რეალიზაცია*** გვეუბნება, **როგორ აკეთებს**: რიგმა შეიძლება **მასივი ან მიბმული სია** გამოიყენოს.

პრიორიტეტული რიგების შესწავლას **მათი აბსტრაქტული თვისებების სპეციფიცირებით** დავიწყებთ, შემდეგ კი **რეალიზაციებზე** გადავალთ.

## სპეციფიკაცია

პრიორიტეტული რიგი ელემენტების **თავდაპირველად ცარიელ სიმრავლეს**¹ ამუშავებს, რომელსაც **S**-ს ვუწოდებთ. **Insert** პროცედურა სიმრავლეში **ახალ ელემენტს** ჩასვამს; ამის უფრო ზუსტად განსაზღვრა მისი **წინა და შემდგომი პირობებით** შეგვიძლია:

```
procedure Insert(T)
        pre   |S| < MaxSize
        post  Current S = Original S ∪ {T}
```

პროცედურა **ExtractMin** სიმრავლის **უმცირეს ელემენტს წაშლის** და ამ მნიშვნელობას თავის **ერთადერთ პარამეტრ T-ში** აბრუნებს.

```
procedure ExtractMin(T)
        pre   |S| > 0
        post  Original S = Current S ∪ {T}
              and T = min(Original S)
```

ეს პროცედურა, რა თქმა უნდა, შეიძლება შეიცვალოს, რომ **მაქსიმალური** ელემენტი, ან **სრული დალაგების** პირობებში **ნებისმიერი უკიდურესი** ელემენტი მოგვცეს.

> ¹ *ავტორის სქოლიო:* რადგან სიმრავლე შეიძლება **ერთი და იგივე ელემენტის რამდენიმე ასლს** შეიცავდეს, უფრო ზუსტი იქნებოდა მას **„მულტისიმრავლე"** (multiset) ან **„ჩანთა"** (bag) გვეწოდებინა. გაერთიანების ოპერატორი ისეა განსაზღვრული, რომ **{2,3} ∪ {2} = {2,2,3}**.

## გამოყენებები

პრიორიტეტული რიგები **ბევრ აპლიკაციაში** სასარგებლოა.
- **ოპერაციულმა სისტემამ** შეიძლება ასეთი სტრუქტურა **ამოცანების სიმრავლის** წარმოსადგენად გამოიყენოს; ისინი **ნებისმიერი რიგით** ჩაისმება, ხოლო **უმაღლესი პრიორიტეტის** ამოცანა **შესასრულებლად ამოიღება**.
- **დისკრეტული მოვლენების სიმულაციაში** ელემენტები **მოვლენების დროებია**: სიმულაციის ციკლი **უმცირესი დროის მოვლენას** იღებს და, შესაძლოა, რიგს **მეტ მოვლენას** უმატებს.

**ორივე** აპლიკაციაში ძირითადი პრიორიტეტული რიგი უნდა **გამდიდრდეს**, რომ სიმრავლის ელემენტების გარდა **დამატებითი ინფორმაცია** შეიცავდეს; ჩვენს განხილვაში ამ **„რეალიზაციის დეტალს"** უგულებელვყოფთ.

## მიმდევრობითი რეალიზაციები

**მიმდევრობითი სტრუქტურები**, როგორიცაა **მასივები ან მიბმული სიები**, პრიორიტეტული რიგების რეალიზაციის **აშკარა კანდიდატებია**. თუ მიმდევრობა **დალაგებულია**, მინიმუმის ამოღება **ადვილია**, მაგრამ ახალი ელემენტის ჩასმა **რთული**; **დაულაგებელი** სტრუქტურებისთვის სიტუაცია **პირიქითაა**. ეს ცხრილი სტრუქტურების წარმადობას **N-ელემენტიან სიმრავლეზე** აჩვენებს.

|მონაცემთა სტრუქტურა|1 Insert|1 ExtractMin|თითოეული N-ჯერ|
|---|:-:|:-:|:-:|
|დალაგებული მიმდევრობა|O(N)|O(1)|O(N²)|
|Heap-ები|O(log N)|O(log N)|O(N log N)|
|დაულაგებელი მიმდევრობა|O(1)|O(N)|O(N²)|

- მართალია, ბინარულ ძებნას შეუძლია დალაგებულ მასივში ჩასასმელი ელემენტის პოზიცია **O(log N)** დროში იპოვოს, მაგრამ **ძველი ელემენტების გადაადგილებას** ახლისთვის ადგილის გასათავისუფლებლად შეიძლება **O(N)** ნაბიჯი დასჭირდეს.
- თუ **O(N²)** და **O(N log N)** ალგორითმებს შორის სხვაობა დაგავიწყდათ, გადახედეთ [[თავი 7.5 რა მნიშვნელობა აქვს|7.5 ქვეთავს]]: **N = 100 000**-ისთვის ამ პროგრამების შესრულების დროებია **1.5 დღე** და **1.3 წუთი**.

## Heap-ზე რეალიზაცია

პრიორიტეტული რიგების **heap-ზე რეალიზაცია** **ორ მიმდევრობით უკიდურესობას შორის შუალედს** იძლევა. ის N-ელემენტიან სიმრავლეს **heap-ის თვისების მქონე** მასივში **X[1..N]** წარმოადგენს, სადაც X გამოცხადებულია, როგორც **X[1..MaxSize]**.

- სიმრავლეს **ცარიელად** ვაინიციალიზებთ მინიჭებით **N:=0**.
- ახალი ელემენტის ჩასასმელად **N-ს ვზრდით** და ახალ ელემენტს **X[N]-ში** ვათავსებთ. ეს ის სიტუაციაა, რომლის გამოსასწორებლადაც **SiftUp** შეიქმნა: **Heap(1,N−1)**. ამიტომ ჩასმის კოდია:

```
procedure Insert(T)
    if N >= MaxSize then error
    N := N+1; X[N] := T
    /* Heap(1,N-1) */
    SiftUp(N)
    /* Heap(1,N) */
```

პროცედურა **ExtractMin** სიმრავლეში **მინიმალურ ელემენტს პოულობს, წაშლის** და მასივს **heap-ის თვისების მქონედ გადააწყობს**.
- რადგან მასივი heap-ია, **მინიმალური ელემენტი X[1]-შია**.
- სიმრავლეში დარჩენილი **N−1** ელემენტი ახლა **X[2..N]**-შია, რომელსაც heap-ის თვისება აქვს.
- **Heap(1,N)**-ს **ორ ნაბიჯში** აღვადგენთ: ჯერ **X[N]-ს X[1]-ში გადავიტანთ** და **N-ს ვამცირებთ**; სიმრავლის ელემენტები ახლა **X[1..N]**-შია, და **Heap(2,N)** ჭეშმარიტია. **მეორე ნაბიჯი SiftDown-ს იძახებს**.

კოდი **პირდაპირია**:

```
procedure ExtractMin(T)
    if N < 1 then error
    T := X[1]
    X[1] := X[N]; N := N-1
    /* Heap(2,N) */
    SiftDown(N)
    /* Heap(1,N) */
```

**Insert-საც და ExtractMin-საც** N ელემენტის შემცველ heap-ებზე გამოყენებისას **O(log N)** დრო სჭირდება.
