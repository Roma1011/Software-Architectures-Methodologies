## პროგრამა 2: სიმრავლეში ჩასმა

**ერთი ამოხსნა** შემთხვევით რიცხვებს **თავდაპირველად ცარიელ სიმრავლეში** ჩასვამს, **სანამ საკმარისი არ იქნება**. ფსევდოკოდით:

```
Initialize set S to empty
Size := 0
while Size < M do
    T := RandInt(1,N)
    if T is not in S then
        Insert T in S
        Size := Size + 1
Print the elements of S in sorted order
```

ალგორითმი **არცერთი კონკრეტული ელემენტისკენ არ არის მიკერძოებული**; მისი გამომავალი მონაცემი **შემთხვევითია**. **სიმრავლე S-ის რეალიზაციის** პრობლემა გვრჩება; **იფიქრეთ შესაფერის მონაცემთა სტრუქტურაზე**.

[[თავი 1.4 რეალიზაციის ესკიზი|1.4 ქვეთავში]] აღწერილი **bitmap** მონაცემთა სტრუქტურა **განსაკუთრებით ადვილი რეალიზებადია**. სიმრავლე S-ს წარმოვადგენთ **ბიტების მასივით**, რომელშიც **I-ური ბიტი ერთია მაშინ და მხოლოდ მაშინ, როცა რიცხვი I სიმრავლეშია**. მას ვაინიციალიზებთ ქვეპროგრამით **InitToEmpty**, რომელიც **ყველა ბიტს გამორთავს**:

```
for I := 1 to N do
    Bit[I] := 0
```

ფუნქცია **Member(T)** გვეუბნება, არის თუ არა T S-ში, **Bit[T]-ის დაბრუნებით**, პროცედურა **Insert(T)** კი T-ს S-ში ჩასვამს მინიჭებით **Bit[T] := 1**. ბოლოს, ფუნქცია **PrintInOrder** S-ის ელემენტებს ბეჭდავს:

```
for I := 1 to N do
    if Bit[I] = 1 then
        print I
```

ეს ქვეპროგრამები **პროგრამა 2-ის** უფრო ზუსტი ფსევდოკოდის დაწერის საშუალებას გვაძლევს:

```
InitToEmpty
Size := 0
while Size < M do
    T := RandInt(1,N)
    if not Member(T) then
        Insert(T)
        Size := Size + 1
PrintInOrder
```

### ანალიზი

- პროგრამა 2-ის bitmap-ები **b-ბიტიანი მეხსიერების N/b სიტყვას** იყენებს.
- ინიციალიზაციისა და ბეჭდვის ფუნქციების **აშკარა რეალიზაციებს** **N-ის პროპორციული** დრო სჭირდება, მაგრამ ეს შეიძლება **N/b-მდე** შემცირდეს **სიტყვის ყველა b ბიტზე ერთდროული მოქმედებით** (ეს მართებულია, სანამ **M < N/b**; მალე განვიხილავთ, **რა ვქნათ, როცა M N-თან ახლოსაა**).
- **Insert** პროცედურის გამოძახება **ყოველთვის ზუსტად M**-ია, მაგრამ **Member**-ის გამოძახება **შეიძლება მეტი** იყოს, რადგან **RandInt-ის ზოგი შემთხვევითი რიცხვი უკვე სიმრავლეში შეიძლება იყოს**.
- [[თავი 11.5 ამოცანები|ამოცანა 2]] აჩვენებს, რომ სანამ **M < N/2**, **Member**-ის ტესტების **მოსალოდნელი რაოდენობა 2M-ზე ნაკლებია**.
- **Member**-საც და **Insert**-საც ოპერაციაზე **მუდმივი დრო** სჭირდება, ამიტომ მათი მთლიანი ფასი **M-ის პროპორციულია**.
- ამრიგად, პროგრამა 2-ის **მოსალოდნელი მთლიანი შესრულების დრო O(N/b)**-ია.

## აბსტრაქტული მონაცემთა ტიპი

თუმცა წარმადობის ანალიზი ვარაუდობდა, რომ სიმრავლე **bitmap-ით** იყო რეალიზებული, **პროგრამა 2-ში ამის შესახებ არაფერი წერია**. ოპერაციები **InitToEmpty, Member, Insert და PrintInOrder** ყველა სიმრავლეების **„აბსტრაქტულ მონაცემთა ტიპს"** ეხება (ამ ოპერაციებიან სიმრავლეს ჩვეულებრივ ***ლექსიკონს*** (*dictionary*) უწოდებენ; ამაზე მეტი **12.5 ქვეთავში**). **ამ ოთხი ქვეპროგრამის შეცვლას** შეუძლია სიმრავლეების **წარმოდგენის** და, შესაბამისად, პროგრამის **წარმადობის** შეცვლა.

ეს ნახაზი რამდენიმე შესაძლო მონაცემთა სტრუქტურას აჩვენებს გაშვების **ბოლოს**, რომელშიც **M = 5, N = 10** და **RandInt(1,10)** აბრუნებს მიმდევრობას **3, 1, 4, 1, 5, 9**:

```
Bit Vector:            Unsorted Array:      Sorted Array:
[1011100010]           [3 1 4 5 9]          [1 3 4 5 9]

Bins:                  Binary Search Tree:
                                 (3)
 ┌──┬──┬──┬──┬──┐               /   \
 │ 1│ 3│  │  │ 9│             (1)   (4)
 │  │ 4│  │  │  │                      \
 │  │ 5│  │  │  │                      (5)
 └──┴──┴──┴──┴──┘                        \
                                         (9)
```

*(წიგნის ნახაზზე „Bins" ხუთი უჯრაა: პირველში 1, მეორეში 3, 4 და 5, მეხუთეში 9.)*

- **ბინარული ძებნის ხეები** ალგორითმებისა და მონაცემთა სტრუქტურების **სახელმძღვანელოების უმეტესობაშია** აღწერილი. რადგან ხეში ჩასმები **შემთხვევითი რიგით** ხდება, **ნაკლებად სავარაუდოა**, რომ ის **ბალანსიდან ძალიან გადაიხრება**; ამიტომ **რთული ბალანსირების სქემები** ამ აპლიკაციაში **საჭირო არ არის**.
- **M „ურნა"** (bins) შეიძლება განვიხილოთ, როგორც **ჰეშირების** სახე, რომელშიც **1..N/M დიაპაზონის რიცხვები პირველ ურნაში** თავსდება, და რიცხვი **I** **(დაახლოებით) I×M/N ურნაში** ჰეშირდება. ურნები **მიბმული სიების მასივად** რეალიზდება. რადგან რიცხვები **თანაბრად არის განაწილებული**, ყოველ მიბმულ სიას **მოსალოდნელი სიგრძე ერთი** აქვს.

სხვადასხვა სქემის **საშუალო** წარმადობა, როცა **M < N/b**, ასეთია:

|სიმრავლის წარმოდგენა|Init|Member|Insert|Print|მთლიანი დრო|მეხსიერება სიტყვებში|
|---|:-:|:-:|:-:|:-:|:-:|:-:|
|Bit Vector|N/b|1|1|N/b|O(N/b)|N/b|
|Unsorted Array|1|M|1|M log M|O(M²)|M|
|Sorted Array|1|log M|M|M|O(M²)|M|
|Binary Tree|1|log M|log M|M|O(M log M)|3M|
|Bins|M|1|1|M|O(M)|3M|

*(Init, Member, Insert, Print: დრო ერთ ოპერაციაზე, O-აღნიშვნით.)*

## პროგრამა 3: არევა (Shuffle)

შემთხვევითი რიცხვების **დალაგებული ქვესიმრავლის** გენერირების **კიდევ ერთი მიდგომაა**: **1..N** რიცხვების შემცველი **N-ელემენტიანი მასივის არევა** (shuffle) და შემდეგ **პირველი M-ის დალაგება** გამომავალ მონაცემად. Knuth-ის **3.4.2 ქვეთავის ალგორითმი P** მასივ **X[1..N]**-ს ურევს:

```
for I := 1 to N do
    Swap(X[I], X[RandInt(I,N)])
```

**Ashley Shepherd**-მა და **Alex Woronow**-მა (University of Houston) შენიშნეს, რომ ამ ამოცანაში **მასივის მხოლოდ პირველი M ელემენტის არევაა** საჭირო, რაც **პროგრამა 3-ს** იძლევა:

```
for I := 1 to N do X[I] := I
for I := 1 to M do
    Swap(X[I], X[RandInt(I,N)])
Sort(1, M)
```

- დალაგებული სია **X[1..M]**-შია.
- ალგორითმი **N სიტყვა მეხსიერებას** და **O(N + M log M)** დროს იყენებს, მაგრამ **ამოცანა 1.8-ის** ტექნიკა ამას **O(M log M)** დრომდე ამცირებს.
- ეს ალგორითმი შეგვიძლია განვიხილოთ, როგორც **პროგრამა 2-ის ალტერნატივა**, რომელშიც **არჩეული ელემენტების სიმრავლეს X[1..I]-ში** წარმოვადგენთ, **არაარჩეულებისას კი X[I+1..N]-ში**. **არაარჩეული ელემენტების ცხადად წარმოდგენით** ვერიდებით შემოწმებას, **ხომ არ იყო ახალი ელემენტი ადრე არჩეული**.

## დიზაინის სივრცე ამით არ ამოიწურება

**პროგრამები 1, 2 და 3** ამოცანის **სხვადასხვა ამოხსნას** გვთავაზობს, მაგრამ **შესაძლო დიზაინების სივრცეს სულაც არ ფარავს**. **კიდევ ერთი მიდგომა** სიმრავლეში **თანმიმდევრულ რიცხვებს შორის „ღრიჭოებს"** (gaps) აგენერირებს. **J. S. Vitter**-ის „**Faster Methods for Random Sampling**" (*Communications of the ACM*, **1984 წლის ივლისი**) **M დალაგებულ შემთხვევით რიცხვს O(M) დროში და მუდმივ მეხსიერებაში** აგენერირებს; ეს რესურსების საზღვრები **ოპტიმალურიდან მუდმივი კოეფიციენტის ფარგლებშია**.
