
ზოგჯერ მოდელირების სიტუაცია მოითხოვს ისეთ ოპერაციას, რომელიც ბიზნეს წესებს იყენებს, მაგრამ რომლის იმპლემენტაცია იმ ტიპის წევრად, რომელზეც ის მოქმედებს, არაპრაქტიკულია. ეს ხდება მაშინ, როცა: ოპერაციას სჭირდება მეტი ქცევა, ვიდრე ტიპური instance-მეთოდისთვისაა მოსალოდნელი; ოპერაცია ერთი და იმავე ტიპის ორ ან მეტ instance-ს კვეთს; ან ოპერაციას სჭირდება ორი ან მეტი განსხვავებული ტიპის instance-ის გამოყენება. ასეთ სიტუაციაში გამოიყენება **Domain Service**. Domain Service გვთავაზობს ერთ ან მეტ ოპერაციას, რომლებიც აშკარად არ ეკუთვნის Entity-ს ან Value Object-ს (როგორც ეს ჩვეულებრივ იქნებოდა მოსალოდნელი), და თავად სერვისს არანაირი ოპერაციული მდგომარეობა არ გააჩნია — Entity-ისა თუ Value Object-ისგან განსხვავებით.

**ნახაზი 7.2**-ზე ნაჩვენებია Domain Service სახელწოდებით `QuoteGenerator`. ის პასუხისმგებელია, მიიღოს ერთი პარამეტრი, სახელად `PremiumRates`, გადათარგმნოს ის ერთ ან მეტ `QuoteLine` instance-ად (რომლებიც კონკრეტულ დაფარვასა და პრემიას მოიცავს), და ჩაწეროს თითოეული `PolicyQuote` Aggregate-ზე. აღსანიშნავია, რომ როცა ბოლო `QuoteLine` ჩაიწერება, გამოიცემა `QuoteGenerated` Event.

### Domain Service ≠ Application Service

მნიშვნელოვანი განსხვავებაა Application Service-სა და Domain Service-ს შორის: Application Service **არასდროს** არ უნდა შეიცავდეს ბიზნეს ლოგიკას, ხოლო Domain Service — **ყოველთვის** შეიცავს. თუ Application Service გამოიყენება ამ use case-ის კოორდინირებისთვის, სწორედ ის მართავს ტრანზაქციასაც — Domain Service-ს ეს ფუნქცია არასდროს ეკისრება.
