
**Value Object** — მოდელირებული კონცეფცია ერთი ან მეტი მონაცემის ატრიბუტით/თვისებით, რომლებიც ერთად ერთ მთლიან მნიშვნელობას ქმნიან — ანუ, ეს არის მუდმივი, უცვლელი (immutable) მდგომარეობა. Entity-სგან განსხვავებით, რომელსაც უნიკალური იდენტობა აქვს, Value Object-ის იდენტობა უნიკალური არ არის განზრახული. შეიძლება ითქვას, რომ მნიშვნელობას (value) იდენტობა არ გააჩნია — მაგრამ მას მაინც აქვს იდენტობის ცნება: მისი იდენტობა განისაზღვრება მისი ტიპის სახელითა და ყველა შემადგენელი ატრიბუტით/თვისებით ერთად — ანუ, მისი მთლიანი მდგომარეობა ავლენს თითოეულ მნიშვნელობას. Value Object-ებისთვის, იდენტობის უნიკალურობა არ არის მოსალოდნელი — ორი მნიშვნელობა, ერთი და იმავე იდენტობით, ტოლია. მთავარი, რაც აქ უნდა გავითვალისწინოთ, არის ის, რომ ორ ან მეტ მნიშვნელობას შორის თანასწორობა (equality) სავსებით ჩვეულებრივი მოვლენაა.

Value-ის მაგალითია, თუნდაც, მთელი რიცხვი 1. ორი, ცალკე აღებული, `1` მნიშვნელობა ტოლია, და ერთ პროგრამულ პროცესში შეიძლება ბევრი `1` არსებობდეს ერთდროულად. სხვა მაგალითია ტექსტური სტრიქონი `"one"`. ზოგიერთ თანამედროვე პროგრამირების ენაში, მთელი რიცხვი `1` სკალარია — ერთ-ერთი საბაზისო, ერთი მნიშვნელობის ტიპი. სხვა სკალარებია `long`, `boolean` და `char`/`character`. Value-ის ტიპებია `ApplicationId` და `Progress`-იც, რომლებიც ნახაზ 7.1-ში იყო ნაჩვენები.

### Progress — Value Object-ის იმუტაბელობის მაგალითი

`Progress` აღრიცხავს `Application` Entity-ზე მიმდინარე workflow-ის დამუშავების ნაბიჯების პროგრესს. ყოველი ნაბიჯის დასრულებისას, `Progress` აღბეჭდავს ცალკეულ ნაბიჯს, უკვე მომხდარ ნაბიჯებთან ერთად. ამ თვალყურის დევნების მისაღწევად, `Progress`-ის მიმდინარე მდგომარეობა **არ იცვლება** — ამის ნაცვლად, წინა ნაბიჯების მიმდინარე მდგომარეობა (თუ ასეთი არსებობს) ახალ ნაბიჯთან ერთად აყალიბებს ახალ `Progress` მდგომარეობას. სწორედ ასე ინარჩუნებს Value Object-ი უცვლელობის შეზღუდვას.

> [!TIP] მარტივი ანალოგია
> წარმოიდგინეთ რიცხვი `1`. მისი შეცვლა შეუძლებელია — ის ყოველთვის `1`-ია. აზრი არ ექნებოდა, რომ რიცხვმა `1`-მა თავად შეიცვალოს და გახდეს `3` ან `10`. ეს, რა თქმა უნდა, არ ეხება ცვლადს, მაგალითად, `total`-ს, რომელსაც შეუძლია, ჯერ `1` შეიცავდეს, მოგვიანებით — `3`, შემდეგ კი — `10`. განსხვავება ისაა, რომ თავად ცვლადი `total` შეიძლება შეიცვალოს, მაგრამ ის უცვლელი მნიშვნელობა, რომელსაც ის ატარებს (მაგალითად, `1`), მუდმივია. `Progress` მდგომარეობა, თუმცა რიცხვზე გაცილებით რთულია, ზუსტად ამავე პრინციპითაა დაპროექტებული — მისი შეცვლა შეუძლებელია, მაგრამ მისგან ახალი `Progress` მნიშვნელობის „გამოყვანა" შესაძლებელია.
